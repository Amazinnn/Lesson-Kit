# 2026-08-27 计划与量化进度随想

这是一份讨论记录，不是当前实现规格，也不是已经批准的功能清单。

下一版打开后的第一要务，是给出一个按顺序排列的短队列，而不是只丢给学生一个孤立动作。这个队列可以随完成情况、可用时间和临近考试的状态变化，但不应细化成操作手册。

计划分成几层：课程或考试给出外部约束；学生确认长周期目标；Agent 根据进度提出或调整阶段性建议；系统用真实完成情况重新安排下一段。长周期目标不由 Agent 擅自替代，Agent 负责规划和维护进度。

短目标应保持整体性，例如完成一轮章节复习、处理某部分主要内容、完成一次考前检验。可以有数量、覆盖率和截止时间，但不要规定“做几道题后辨析一次、隔几天重测一次”这类过细动作。

学生看到的量化进度暂定只保留：完成度、课程范围覆盖率、距离考试的阶段状态。UI 可以用多阶段进度条和倒计时日程呈现，但它们只是帮助理解进度的组件，不应变成额外的任务管理负担。

一个必须矫枉过正的判断原则：逐题主观反馈天然稀疏、偏斜且不稳定，不能作为 Agent 调优和学习判断的主要依据。学生不可能为数万道题逐题反馈；学生指出的某个薄弱点也不能覆盖未指出的盲区，更不能让 Agent 因信息不足而把推荐范围越缩越窄。

因此采用“粗粒度目标，适度量化，内部证据辅助但不支配”的方向。细节可以用于校正和发现风险，但不能直接决定学生必须完成的微动作，也不能把一次偶然反馈当成全局结论。
