### 1.5.3 ⚠️ 两个容易被做错方向的地方

1. **§8 密度不是「缺一个切换开关」。**
   delta 的 `Density zoning` 条款原文：「The density of a surface SHALL be decided by
   **the kind of content it carries**, not by the page it sits on.」
   ⇒ §8 的 30 行分区表是**逐区块的规则表**（哪种内容配哪种疏密），
   **不需要用户可切的模式**。按「找开关」去审计会误判成「零机制 = 0 分」。
   实际要做的是：**把 30 个区块的几何值改到各自那一行**。
2. **`layout-spec.md` 自己有两处内部打架**（§1.3 R2 vs §1.5 表；§1.3 地板 360 vs §1.4/§7.8 的 340）。
   已按 **A-136 / A-137** 裁（以**逐格可验**的那张表为准），并登记 **CD-179 / CD-180**。

## 8.5 停止 subagent 的**已知问题**（2026-10-23 实录，下一会话别踩）

### 8.5.1 停止 = **不可恢复**（不能用 SendMessage 唤醒）

关机时我停了两个 agent；开机后我用 `SendMessage` 想把它们唤醒，返回：

```
No active local_agent task found for target agent_...
```

⇒ **停掉的 agent 无法原地唤醒，上下文全部丢失。**
只能**重新派全新的 agent**、把上下文从头重述一遍。
**它们停之前已提交的成果保住了**；但「它当时在想什么、下一步要做什么」全没了。

⇒ **停之前必须做两件事**：
1. 让它**先提交**（明确路径 + `git commit -- <路径>`）**并回一句话**（做了什么 / 没做什么 / 工作区干不干净）；
2. 停掉后**立刻把它的状态写进交接文档**（下一会话就不必从聊天记录里考古）。

### 8.5.2 停在**改到一半**的位置 = 留了一颗没拆的雷

停 C1 那个 agent 时，它在 `workbench.css` 里留着 **241 行未提交改动**。
下一个 agent（C1b）接手时必须「在其上改、**不要回退别人的改动**」，
而它**无法判断哪些行是谁的**。
**更要命的是：那些未提交的改动里就藏着 `:where()` 那个 bug**
（主按钮 40px → 36px、命中区 44px → 40px），是 C1b **自己实测才发现的**。

⇒ **别在 agent 正改文件的时候停它**；要么让它自己收尾，要么停了之后**由主会话逐行接管**。

### 8.5.3 停止 + 并发编辑叠加 ⇒ 重复派发

我在 C1 **还在跑**的时候就派了 C1b 做**同一批活** ⇒ 两个 agent 同改一个 CSS。
撞出来的那个 `:where()` 回归就是这么来的。

⇒ **派任何收尾波之前，先确认上一棒已经结束**（收到 completion 通知，或 `TaskStop` 过）。
派发消息里也要写明「**上一棒已结束**」，否则新 agent 无法判断。

### 8.5.4 还有两种**不是停止**但同样留半成品**的死法**

- **provider 认证失败**：最早的 W2i agent 是这么死的（`Provider authentication failed`）——
  死时**没提交**，留下一堆未提交改动；
- **agent 自己说「没有 commit」**（那次它说"约 45 分钟"，然后就没了）。

⇒ **任何 agent 交工前，工作区必须由主会话核对**（`git status` + `git diff --stat`），
**不能只信它的自述**。
