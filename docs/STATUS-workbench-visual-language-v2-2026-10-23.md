### 1.3 走查执行器的两条探针修好了（**A-114 / A-117**）

| 判据 | 改前 | 改后 |
|---|---|---|
| 3.4-1 hover 反馈 | PASS（38 样本） | **PASS（47 样本 / 越界 0）** |
| 3.4-2 按下反馈 | PASS（5 个元素，**靠蒙**） | **PASS（10 个元素，读的是候选元素本身）** |
| 3.4-3 骨架屏 | FAIL「没有尺寸（0×0）」（**探针从没采过宽高**） | **FAIL「有体积 ✔，动效是 `::after` 横扫 ✖」**（= 真的产品未达标） |
| 3.7-1 只动 transform/opacity | PASS | **PASS** |

- `3.4-2` 的根因：探针用 `elementFromPoint` 取到的是**最内层**元素（`.nav-item` 里的 `<a>`），
  而 `:active` 规则挂在 `.nav-item` / `button` 上 ⇒ 恒测不出差异。
  **产品行为本来是对的**（Chromium 的 `:active` 命中被按下元素的**祖先**）。
- `3.4-3` 的根因：`SKELETON_JS` **从不采集 width/height**，而判定读的就是这两个字段。
- **3.4-3 现在判 FAIL 是正确的**：产品动效在改呼吸式之前是横扫 ⇒ 按 A-115 判不过。
  ⇒ **待办：产品改完后重跑，它应转 PASS。**
- 判据口径（A-117 定稿）：**有体积** 且 **块的自身表面**（`background-color` 或 `opacity`）
  随时间变化；**`::after` 横扫不算**；降级档只判有体积；**不要求底色必须变**（优先 opacity）。
