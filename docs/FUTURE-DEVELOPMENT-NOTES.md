# 后续开发方向随想

> 这不是当前实现规范，也不是承诺的路线图。这里专门存放后续讨论中的想法、灵感、疑问和暂时没有答案的方向。真正要实现的内容，仍需另行讨论、落 OpenSpec 并确认范围。

## 总的愿望

lesson-kit 已经接近日常可用。后续的重点不是继续堆页面和按钮，而是让它更像一个真正的学习工作台：知识池是事实来源，图谱帮助发现和选择，练习活动负责执行，外部 Agent 负责解释、追问和陪练。

“能用”始终比“理论上优秀”重要。任何新功能都应该先做出一个小而可靠的版本，再根据真实学习中的问题继续改。

## DeepTutor / NotebookLM 参照

- DeepTutor 值得借鉴的重点是教学过程的分层：课程层决定当前方向，会话层决定本轮目标，回合层决定下一步追问或检查。
- NotebookLM 值得借鉴的重点是把材料加工成不同粒度的学习活动，而不是把整份材料原样摊给学生。
- 不直接复制多智能体或产品功能清单。lesson-kit 仍然保持外部 Agent 可替换、确定性学习核心不依赖 AI。

## 更有限的插件化

当前架构已经有 Shell、Domain、Data、Content、Bridge 的边界，但还不是完整的插件生态。

未来可以考虑只为以下能力建立内部注册点：

- `PracticeMode`：试卷、Micro Quiz、Yes/No、记忆卡片等；
- `GraphProjection`：结构视图、薄弱度视图、复习紧迫度视图、题量视图；
- `GraphMetric`：为图谱位置、颜色、大小提供可解释指标；
- `IngestOperation`：OCR 材料整理、结构化、补解、审计、入池；
- `AgentProvider`：Codex、Claude 以及未来其他本地 Agent。

不急于支持第三方动态安装。先让内置能力遵守清晰契约，就能获得大部分模块化收益。SQLite、反馈、调度、正式内容门禁和基础关系模型不应为了“Everything is a plugin”而被拆散。

## 学习型知识图谱

图谱的基本结构不变：知识点是节点，真实关系是边。变化的是观察方式。

可以让同一张图谱按照不同参数产生不同的二维投影：

- 越生疏的知识点越靠近中心，或越醒目；
- 越重要的知识点越靠近中心；
- 到期复习项聚集到某个区域；
- 题目数量决定节点大小；
- 掌握证据和薄弱度决定颜色或透明度；
- 关系强度决定边长、聚拢程度或局部展开程度；
- 未来也可以使用平面直角坐标轴，把两个指标分别映射到 X/Y。

这些形态变化必须来自可追溯的学习证据，不能把内部字段随意包装成“掌握度”。掌握算法可以是实验性的，但不能伪装成精确测量。

可能的视图：

```text
结构视图
薄弱度视图
复习紧迫视图
题量分布视图
```

图谱适合发现和选择，列表仍适合精确搜索、窄屏和无障碍访问。两者不必互相替代。

一个很自然的学习动作是：多选节点 → 形成知识点集合 → 进入限定范围的连续练习。现有 `pull` 已能接收多个 `kp_ids`，因此这条路径的后端基础并不难。

## 练习活动的分化

### 试卷模式

- 使用正式题池中的完整题目；
- 适合证明、推导、建模、综合应用；
- 允许长答案和较深思考；
- 更接近当前已有的练习流程。

### Micro Quiz / 小测模式

- 一张卡只考察一个较小概念；
- 题干短，反馈快；
- 可以使用选择、判断、匹配和简短回答；
- 更像 NotebookLM 的学习卡片，而不是把长题硬截短。

Yes/No 更适合作为 Micro Quiz 的一种回答类型，而不是单独维护一整套会话系统：

```text
micro_quiz
├── yes_no
├── single_choice
├── multiple_choice
├── closest_answer
└── short_answer
```

真正的小测需要新的内容单位：短题干、选项、正确答案、错误原因、来源证据、原子知识点和题型。不能只把现有长题的前几十个字拿来冒充小测。

## 内容摄取的拆解

原先“一次性完成 OCR、清洗、结构化、补解、审计、入池、生成视图”的流程，对于多变的书籍和试题过于僵硬。

更灵活的方向是把它拆成可以单独运行的工作：

```text
原始材料
→ 准备 / 清洗
→ 结构化
→ 补解
→ 独立审计
→ 门禁
→ 显式入池
→ 生成视图
```

OCR 只是可选原材料，不应成为核心依赖。中间产物用明确的 UTF-8 文件交接，默认零写入，只有显式 apply 才进入 SQLite。

## Agent 教学能力

- 普通对话不应该绑死在练习、诊断或讲解某一个活动上；会话可以自由探索。
- Agent 通过 `wb data` 获取权威材料，Lesson Kit 负责数据边界和写入门禁。
- 页面上下文可以提供当前工作区、知识点、题目、练习范围和最近浏览对象；未提交草稿默认不进入长期记录。
- Agent 可以解释、追问、比较、帮助规划，但不应绕过正式内容门禁直接制造可信度不明的正式题。
- 会话记忆、外部 Provider 原生上下文和 Lesson Kit 的显式问答镜像需要继续保持边界。

## 暂时没有答案的问题

- 掌握证据怎样稳定地映射为图谱颜色、大小和位置？
- 两个图谱指标同时变化时，怎样避免视觉上漂亮但学习上误导？
- Micro Quiz 的最小可信内容契约应该是什么？
- 小测生成后的错误选项如何进行来源审计？
- 哪些练习结果可以反过来改变图谱形态，哪些只能作为一次性提示？
- 插件注册点应该在 Python Domain、前端视图，还是两者之间的共享契约？
- 如何保持多种学习模式增长，而不让界面变成“飞机驾驶舱”？

## 当前优先级直觉

如果学期开始前只能做少量事情，优先考虑：

1. 图谱多选知识点并进入现有连续练习；
2. 建立内部 `GraphProjection` / `GraphMetric` 边界；
3. 设计一个来源可审计的最小 Micro Quiz，先只支持 Yes/No；
4. 在真实学习反馈之后，再决定是否扩展插件注册体系。
