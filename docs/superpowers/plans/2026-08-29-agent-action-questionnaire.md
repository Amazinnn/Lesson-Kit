- [ ] 其他：

  感觉这个Action Graph还是不够详细。之前好像有一篇长长的产品说明书文档，这是我给他的比喻，但总之他应该是把东西写详细了。而我觉得这个Action Graph这个图就旨在处理各种可能的情况，对吧？它不是说要事无巨细地把功能都弄下来，它是说用户每个可能的工作流，它会构成一定的流程。就比如说，用户可能突然不想干这个，他可能要想要回退，那这个action graph就是要处理这种回退的可能性。你要把它可视化，而不能仅仅把用户想象得那么理所当然，认为他就会按部就班地干完某些事情，然后得到理想的结果以及合理的工作流程。不是这样的，用户可能会有超级多自己的想法，这些时候你就要考虑到了。我担心你没有理解，我再举一个例子，比如说用户进入练习之后发现可能选错题目了，或者说题目不理想，那他就可以直接点击跳过，然后直接跳到最后，然后直接再点击再练同类题目，这样就可以退出那个练习的界面了。但是有的时候这个逻辑它未必成立，对吧？就有的时候用户未必会那么按部就班，他可能就直接退出那个练习的界面。所以这就是我所说的意外，这里你就要考虑到了，你就要在那个Mermaid图反映出来。我再举另外的一个例子吧，就是当前的那个设定计划的，或者说那个阶段目标，还是什么长期目标，就设定目标的那个功能，它暂时不支持让Agent来辅助设计，这个我知道，但是它填写了字段之后，它并不支持删除，也并不支持修改，这就非常的frustrating。总而言之，我希望你不仅仅只是把这个大概图画出来，你需要像Vivado的分层设计的那种视图那样，把整个电路从底层到顶层都刻画出来。呃，我这么说你能懂吧？你可以多弄几个文件，这个我不介意。嗯，总之你一定要把事情都搞搞清楚。
