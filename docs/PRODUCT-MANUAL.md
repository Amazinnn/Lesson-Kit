# PRODUCT-MANUAL — lesson-kit 产品说明书

## 试卷独立进度与内容修改

「试卷」页列出已有 Paper，并显示每卷独立的未完成进度。A 做一半切到 B，再回 A，会恢复 A 的题序、游标、答案展示方式、已作答状态和未提交的文本/选项；不要求先做完 A，也不会因为切卷产生结束记录。刷新或重启后仍可继续。每张 Paper 都保留自己的未完成执行；继续时恢复原答案展示方式。每题按自身选择、判断或开放题内容呈现。

继续前，系统会核对当前试卷的题目名单与顺序、题目内容是否变化、引用题目是否可用，也会检查当前试卷能否通过校验。检查不匹配时，页面会说明原因，把当前试卷题数与旧执行题数分开展示，并把旧进度和较长的不可用题号放在折叠详情中；不会把旧进度套到当前试卷、自动改绑题目或清除旧执行。只要当前试卷本身仍有效，改名、导出和删除仍可单独操作；无法安全继续只会禁用续练操作。

学生页面不提供手工添加、删除或重排 Paper 题目的控件。若 Agent 提议改动已有 Paper 的名单或顺序，页面仍会先展示影响并等待明确批准；取消不修改。命令行 Paper 更新继续使用显式 ps-NNN 和预览确认。原卷保留 ID，清理仅针对该卷未完成进度，不删除历史作答或启动新一轮。改题面、选项、答案键或作答类型只重置所有未完成卷中的该题；改解析、来源、KP、难度不清进度。旧页面提交会提示内容变化，应重新加载后作答。

删除试卷只删容器和它的未完成进度，题目及历史作答保留。删除题目会把它从所有当前卷中移除，但其他题进度保留；历史记录注明题目已删除。删到空卷、或卷引用了缺失题号时，卷仍可查看、改名、修复或删除，不能开始或导出。已有缺失作答的旧数据不会自动补造或挂到新题号。

Agent 修正原卷题目名单或题序时应提交审批方案，由你在页面批准后更新（见 8.5）。手工从命令行修正原卷仍使用显式 ps-NNN：`lesson-kit papers <工作区> preview <ps-NNN> --input <清单>`，确认影响后 `update <ps-NNN> --input <清单> --confirmation <预览JSON>`；`save` 始终新建。题目修正使用现有题号的 `data update problem` 或 `problem-patch`，不能因改成客观题而换题号。

> **这是一份面向使用者的功能说明书**，讲「这个东西怎么用、每一步会发生什么」，不讲实现。目标是用足够的细节让使用者对每个操作都有准确预期——宁长勿略。
>
> **写作纪律（与 AGENTS.md 同步）：**
> 1. 正文里的每一个设计名词必须在 `docs/GLOSSARY.md` 有条目；没有就去补条目，不许裸用。
> 2. 行为描述不确定时，写「以 openspec 规格为准」并附规格文件名；**禁止编造未实现的行为**。
> 3. 每章头部标注：目标深度 / 当前完成度 / 权威规格。
> 4. 每次功能变更交付时，同步补写对应章节（AGENTS.md 交付纪律）。目标态是极详尽（十万字量级），靠逐次变更长出来，不一次编成。

**全书的恒等式（先记住这一句）**：浏览、导航和未提交草稿不产生学习记录。`per_item` 中明确提交答案或标记「不会」会立即记录该题；`on_submit` 中标记「不会」只保存可修改草稿，普通 Paper 的未提交答案和仍标记为「不会」的题在明确整卷交卷后记录。1–5 自评是可选的显式学习反馈；图谱状态编辑仍是另一条明确写入路径。调度只影响排序与建议，永不锁题；普通 Paper 的答案锁定遵循答案展示方式与提交状态。

## 1. 这是什么

**目标深度：短。完成度：✅ 已成文。权威：README、philosophy。**

lesson-kit 把你的课程材料变成一个可以天天用的学习台：知识点、题目、你的作答与评分记录、一条只做背景提醒的遗忘曲线，加上一个可以提问的 Agent 对话栏。练习页管理已有 Paper；需要新题目时，由你明确要求 Agent / CLI authoring。普通 Paper 开始时你选择答案展示方式，自评可以跳过，系统不替你把阅读或建议变成练习。

它明确**不**承诺的事：不自动判开放题；不替你安排计划外的任务（建议永远可无视）；不显示任何算法参数（没有间隔、难度系数、掌握度百分比——你只会看到「重点练习」「可以复习」这样的人话）。调度不会锁题；普通 Paper 里的答案锁定由答案展示方式和显式提交决定。自评可跳过，不是完成练习的条件。

工作台是五页结构：**练习**（主页）、**试卷**、**知识点**（列表与详情）、**知识图谱**、**记录**，外加一条常驻右侧的 **Agent 对话**栏。没有藏起来的第二套学习入口。

视觉采用柔和蒙德里安 v2 语言：暖色打底（浅奶油纸面），三栏靠大圆角与柔影分开，
界面与标题用无衬线、长正文用衬线；蓝色用于主要动作、链接与当前选中，黄色用于
当前项与复习强调，红色用于失败与阻塞——黄色只承载面积与形状，不承载文字。颜色
旁始终还有几何提示（状态圆点一类的形状），不要求靠辨色理解状态。外观偏好见第 10 章。

**怎么把它跑起来**：在仓库根目录 `lesson-kit daemon start`（后台服务，进程号与日志记在用户级目录），`lesson-kit dashboard` 一步到位——没在跑就起、然后打开浏览器；`lesson-kit daemon status` 看状态、`daemon stop` 收工。想看着日志占用一个终端就换 `lesson-kit serve`（前台运行，Ctrl+C 停）。全新开始很简单：**站进课程文件夹跑 `lesson-kit init`**——文件夹名是 ASCII 时直接当课程缩写，文件夹里已有池则用池名，中文名的文件夹自动分到一个顺序短码（`c01`、`c02`…，只当机器内部的下标）。它会建好池和骨架再注册，文件夹名会成为工作区名（中文也可以，顶栏显示的就是这个名）。要换课程或章节，`lesson-kit use <课> <章>`，不用重新注册。感觉哪里不对劲（页面打不开、Agent 不出现）先跑 `lesson-kit doctor`：它只读地检查注册表、每个池数据库、各 Agent 可执行文件和服务端口，把有问题的条目逐行列出来，但不会自己动手改任何东西。

**一个工作区 = 一门课**：这是本项目的硬性局限，不是建议。工作区的池、附图、会话镜像、计划与目标文件都只在自己的文件夹里，页面/命令/Agent 桥构造的路径全部限定在这个文件夹内，跨工作区的会话或内容 id 会被直接拒收——所以两个学科各自建一个文件夹、各自 `lesson-kit init`（中文名文件夹照样零参可用）。要在两门课之间切换，就在 Dashboard 的工作区列表里点另一个，或者给命令带上工作区名（多个工作区存在时，不带名的命令会拒绝执行并把可粘贴的命令写给你）。同一个文件夹里出现多份 `pool/*.db` / `.lessonkit/pool/*.db`（例如备份副本）时，`init` 不会替你猜哪份是主库，而是让你用 `--course` 指名。

---

同一工作区内，通过左侧导航或中栏链接切换页面，以及使用浏览器前进/后退，只替换中栏内容。Agent 右栏的对话、未发送输入、滚动位置和运行中任务保持原位；上下文标签随中栏更新，之后新发送使用当前页上下文，已提交请求仍使用发送时的上下文。切换工作区和站外链接按完整页面导航；下载、新窗口和带修饰键点击由浏览器按原生方式处理；手动刷新会重新加载整个工作台。

## 2. 开始一天的学习（练习页）

**目标深度：极详。完成度：✅ 首批成文。权威：workbench-ui spec、consolidate-practice-views（专题 19）。**

打开工作台，默认落在**练习页**。它是你的主页，从上到下回答一个问题：今天做什么。

### 2.1 学习安排：长期与阶段目标

「目标与时间安排」默认收起；展开后可查看你的**目标卡**：每张卡有标题、截止日期（如「截止 2026-08-31」），写了解说的目标还能展开「查看说明与范围」看原文。没有目标时会如实显示「暂无已设置的长期或阶段目标」——系统不会替你编造目标，也不会生成「课程规划」之类的空话。

点「▶ 添加目标」展开表单：填目标名称、选类型（阶段目标 / 长期目标）、选可选开始日期与截止日期、写说明，保存后立即成为一张真实持久化的目标卡。开始日期不能晚于截止日期，填反时会在表单里就地提示。目标会在下方「时间安排」的月历上显示为从开始日延伸到截止日的跑道（见第 5 章）；旧目标没有开始日期也无需迁移，会显示为截止日上的单日跑道。目标卡片可以直接「编辑」「删除」；说不清字段时，在表单里用一句话让 Agent 代填——它填在表单里，你确认后才保存。

### 2.2 已有 Paper：开始或继续

「试卷」页管理已有 Paper，不提供手工选题、条件组卷、数量设置或题目名单/顺序编辑。Paper 卡片默认收起；可以展开题目预览、改名、导出、删除 Paper 容器，或开始/继续练习。预览不改变题目、顺序或练习进度。

每张 Paper 都有独立的未完成进度。切到另一张 Paper 会暂停当前卷；回到它时继续原有题序、当前位置、草稿和答案展示方式。继续前仍会检查 Paper 与执行是否一致；不匹配时说明原因，不把旧进度套到新题目上。

### 2.3 建议、每日计划与时间安排

到期、薄弱和每日计划可以提供只读建议，但它们不会选择题目、改变 Paper 或直接开始练习。练习页的「目标与时间安排」默认收起；展开后可以查看每日计划、目标和复习负荷。建议可无视。

### 2.4 组卷：由 Agent / CLI authoring

需要新 Paper 时，可明确要求 Agent 按知识点范围、来源、难度、薄弱、到期或错题等条件组卷；Agent 与 CLI 的现有组卷、清单导出、保存和精确题号能力保留。普通阅读、知识点列表、图谱筛选与节点聚焦不会选题或隐式建立组卷范围。

命令行 `lesson-kit pull` 是确定性组卷引擎。例如：

```bash
lesson-kit pull <工作区> --kp dmath-ch06-kp-002 --n 8
lesson-kit pull <工作区> --source-kind final --exam-year 2023
lesson-kit pull <工作区> --origin-kinds source_problem --origin-kinds adapted_problem
lesson-kit pull <工作区> --wrong --n 20
```

`--problem <id>` 仍保留为 **Agent/CLI 作者工具**，用于组卷时精确固定某一道题。浏览器不提供手工挑题入口。

`pull --plan` / `pull --print` 继续用于导出可复现清单与打印稿；`lesson-kit papers <工作区> save --input <清单>` 把一张 Paper 保存进当前兼容存储。`.lessonkit/practice-sets/`、`ps-NNN` 和 manifest 的 `kind: practice-set` 是迁移期实现名，不等于产品层的 Practice Set（题单）。

**组卷报告会告诉你差在哪**：一轮组卷结束后，练习页给出一张报告——本轮组到几道（已组 / 请求数）、逐题的入选依据（作者指定 / 此前答错 / 到期复习 / 薄弱点优先 / 范围匹配），以及**可用题数少于请求量的知识点**。最后一项目前显示的是**知识点 id**（形如 `kp-2`），不是知识点名字：名字映射随早已退役的练习范围托盘一起下线，至今没有接上（`contract-drift.md` CD-166）。看到 id 就说明那个知识点下的正式题不够——补题或放宽筛选条件，系统不会虚构题目顶上。

### 2.5 开始与结束

选择已有 Paper 后，开始新一轮时选择**答案展示方式**：逐题显示，或交卷后统一显示。继续未完成练习时恢复原设置，不能中途改。普通 Paper 按题目自身的作答形式呈现，不再要求整卷选择一个内容模式。

普通 Paper 只有显式「提交试卷」才会完成。到达最后一题、上一题/下一题导航或暂停都不会自动交卷。成功交卷后显示完成页；可以查看本次答卷、返回完成页、再练一次或回试卷列表。再练一次会创建新的独立 Practice Run，不覆盖已完成答卷。

### 2.6 一个完整的开场例子

1. 请 Agent 按「链式法则」和「隐函数求导」组一张 Paper，并保存到工作区；必要时也可用 `lesson-kit pull` 与 `lesson-kit papers save`。
2. 在「试卷」页展开 Paper 预览，检查题目后选择开始。
3. 新一轮选择「做一题显示一题」或「交卷后统一显示」；已有未完成轮次则直接继续原设置。
4. 用上一题、下一题或题号点在整张 Paper 中自由移动；导航保存输入，但不会提交答案。
5. 需要时显式提交单题或标记「不会」，最后点击「提交试卷」完成；完成页仍可回到本次答卷查看。

## 3. 阅读与查找：知识点页与知识图谱

工作台不会用省略号隐藏知识点名称、题目、目标或备注。长文本会在自己的栏内
完整换行；代码块、宽公式和表格如果超过栏宽，只在自身区域横向滚动，不会把
中栏或 Agent 右栏撑宽。

**目标深度：详。完成度：✅ 首批成文。权威：workbench-ui spec。**

知识点页与知识图谱页是阅读和查找入口。它们的搜索、排序、状态筛选、节点聚焦和详情导航都不会选题、建立组卷范围或改变已有 Paper。新 Paper 由 Agent / CLI 根据明确的 authoring 请求组装。

### 3.1 章透镜：顶栏那个「章」开关

工作区的池是**一门课一整本**（单库多章）。顶栏工作区名旁边有个「**章**」开关，决定"现在看哪部分"：

- 关着 = 全课程，所有章的内容都在眼前（默认）。
- 打开 = 只看一章；旁边的下拉列出**池里真有的章**（跟着内容走：新章内容一入池就出现在下拉里，不用登记、不用建表）。

透镜管的是"看"：知识点页、知识图谱页与阅读建议都按它取数，页头的「学习 / 当前章节」或「学习 / 全课程」、章节标题下的「本章知识点 / 全部知识点」会如实说明当前在哪一层。它不会约束或组装 Paper；Agent / CLI 的显式 authoring 请求负责确定范围与题目。

开关与命令行 `lesson-kit use <课> <章>`（`""` = 全课程）写的是同一个值，网页上切完，CLI 与 Agent 看到的就是同一章。Hub 首页卡片上的知识点/题目/待复习数字始终是**整门课**口径（回答"这个工作区有什么"），不随透镜缩小。

页面不再提供跨页练习范围托盘或将阅读选择加入练习的控件。

### 3.2 知识点页

左侧导航点「知识点」。本章所有知识点列成清单，每行显示知识点名称（可点进详情页）、关联题目数（如「12 题」）和一个**状态标记**——有明确薄弱证据的标「重点练习」、到期的标「可以复习」、已掌握标「掌握」，三者都没有就什么都不标。状态不写成文字标签，而由**颜色加形状**表达（冗余状态通道），读屏时读到的名字仍是那三个词。列表用于阅读和定位，不含练习选择框。

进入详情后，正文使用更大的阅读字号、宽行距和单侧结构线，是页面最醒目的
内容；提醒和关联题目与正文拉开距离，主题入口保持紧凑。

具体数值：正文 17px、行高 1.75、行宽 38em（约每行 38 个汉字）。长正文用衬线
字族，界面与标题仍是无衬线。阅读字面（衬线 / 无衬线）可以在外观设置里切换
（见第 10 章），字号与行距不随它变化。

知识点正文、题面、解析、Agent 长文走**同一套阅读刻度**（正文 17px / 行高 1.75 /
行长 38em / 段距 0.7em，标题 22·19·17px，左对齐不两端对齐）。**题面与知识点正文同档**
——题面也是 17px / 1.75 / 38em：这两个页面不同屏，不存在"正文必须大于题面"的竞争，
所以题面不会被降一档（所有者裁决 A-6）。界面上的一切（导航、按钮、表格、选项控件、
状态标签、统计数字、空态与错误文案、题号）则一律留在无衬线的界面字族里，不进阅读刻度。

顶部工具条：

- **排序**：课程顺序（默认，跟教材章节走）/ 名称 / 题目数量 / 学习状态 / 重要性，旁边的 ↑ 按钮在升序降序间切换。排序是稳定的：同值条目保持原有相对次序。排序纯视图操作，不写任何记录。
排序只改变列表呈现，不写任何记录，也不影响已保存 Paper。

**本章计数**：知识点页顶部有一条计数，写明当前范围里共有多少知识点，其中多少处在「重点练习」、多少处在「可以复习」、多少处在「掌握」。它们是**个数**，不是百分比、不是分数。列表里逐条的状态仍只用第 7.4 节那三个词（以颜色加形状表达，不写成文字标签）；这条计数只是把同一批当前状态按个数汇总，不作别的断言。计数按当前透镜口径给（关着 = 全课程，打开 = 本章）；它是数出来的既有事实，不额外写任何统计。顶栏的章下拉里只有章名，不带每章计数。

### 3.3 知识图谱页

左侧导航点「知识图谱」。本章知识点构成一张力导向图，连线是知识点之间的关系。可以做的事：

- **搜索**：按名称定位一个节点。
- **切换视图（投影）**：关系结构（默认，展示知识点之间的关系）/ 题目数量 / 重要性 / 学习状态——同一张图换着角度看，基于已有指标，不发明新指标。切换指标时节点不会瞬移或整图刷新，而会像气泡一样向新位置移动：指标越高，节点越大、越靠近中心，并按当前投影的**图谱色键**重新着色（关系结构用墨色三档；题目数量与重要性用同一条橙色深浅阶梯；学习状态用未学灰 / 复习琥珀 / 掌握橙 / 需突破砖红）。学习状态投影仍按关注优先级 `needs_work / review / null / mastered` 从中心向外排列（待加强最靠中心）。工具栏会同步说明当前视觉含义。
- **按学习状态筛选**：可以同时勾选重点练习、可以复习、已掌握、未标记中的一个或多个类别。没有勾选时显示全图；勾选后，不符合条件的节点和相关连线先淡出，保留节点按状态聚成一团或多团（淡出只是退场，不会改成别的颜色，存活节点保持原来的形状与配色）。多项筛选取并集，跨团关系仍显示。点「清除筛选」恢复全图。筛选和上面的视图投影可以同时使用，且都不改变练习范围或学习记录。
- **聚拢**：滑杆调整节点的聚散程度；「适应画布」一键缩放到全图可见；另有 ＋/− 逐步缩放。
- **聚焦节点**：点选节点会将其作为图谱当前焦点，学习看板显示名称、提醒词（重点练习/可以复习）、关联题数等**有限**信息，以及「打开知识点」进入详情。节点聚焦不建立 Paper 范围或选择题目。右侧 Agent 对话栏始终保持可用，节点聚焦不会切换或隐藏对话。

**图谱长什么样**（节点视觉语言已定稿、尚未落地；权威见 `graph-visual-language` spec）：

- **节点**：每个知识点是一枚**同心圆节点**——淡色内核套一圈同色相的实色外环，读作一枚带边的圆片；圆心只有一个数字，即该知识点关联的正式题数，四个投影下都是同一个数。节点上没有进度弧、仪表、状态文字或状态点，也没有阴影和光晕。
- **大小**：节点的直径与字号按**屏幕空间尺寸**给出（尺寸区间以 `graph-visual-language` spec 为准），不随缩放一起变小；把整张图缩放到「适应画布」后，节点的数字和名称仍然可以直接读。当前投影的量越大，节点越大、外环越粗。
- **颜色**：图谱有自有的**图谱暖色板**，与全站界面「蓝 = 主要动作 / 黄 = 当前与复习强调 / 红 = 失败与阻塞」的三个角色色不是同一套东西，也不受它们的配额约束——图谱是数据可视化区，不是操作界面。四个投影各有自己的**图谱色键**：关系结构下节点用墨色三档（颜色不表示类型，关系由连线样式表达）；题目数量与重要性用同一条橙色深浅阶梯，值越大颜色越重；学习状态用未学灰 / 复习琥珀 / 掌握橙 / 需突破砖红。
- **图例**：底部图例分两块——上半是关系线型（可点按显示或隐藏某类关系），下半是当前投影的节点颜色含义，并随投影切换；在关系结构投影下颜色不表示类型，下半块改为说明节点本身的结构（外环 / 内核 / 圆心数字）。
- **标签**：节点名称默认可见，字号比节点本身弱，不与节点抢眼。名字太长时换行显示全文，不截断、不加省略号；标签互相压住时自动让位——先按节点大小、再按重要性排优先级，次要的先隐藏，悬停或选中时立刻回来。完整标题始终可以在悬停提示与学习看板里读到。
- **选中与悬停**：选中的节点外环加粗变实、节点轻微放大；悬停或键盘聚焦时用同一套强调，但不改变选中状态。节点不再靠阴影或光晕表示「抬起」。
- **夜纸**：切到夜纸时图谱跟随夜纸——同一批色相换成更亮、更少饱和的夜纸值，节点填充、外环、连线与标签在深色底上都保持可读；亮色纸面下的可读性不低于改动之前。

图谱稳定后保持完全静止，只有拖拽、筛选、聚焦、切换投影、缩放或调聚拢时才重新布局。图不呼吸、不晃动；系统开启「减少动态效果」时，投影切换直接显示稳定终态，筛选直接显示稳定分群结果。

关系结构视图由自由力场求得布局，不保证减少交叉或最小化交叉。关系强度同时控制
单条连线的宽度和深浅；弱关系先绘制、强关系后绘制，因此重叠时较强关系显示在上层。
该效果只读取既有关系，不改写作者关系或学习记录。

关系线由 WebGL2 绘制，节点仍由可操作的页面节点呈现。浏览器不支持 WebGL2、图谱渲染无法启动，或布局计算中断时，状态提示会说明原因并停止本次图谱运行；不会切回旧 SVG，也不会改写知识内容或学习记录。使用支持 WebGL2 的浏览器并刷新页面后可以重新打开图谱。

图谱布局稳定后，工作台会尝试在浏览器 `localStorage` 为当前工作区保留一份可选的本地布局种子。节点 ID、关系起点和终点、关系类型与方向完全匹配时，坐标会直接采用，求解器停止；部分匹配时，已有坐标只作为首帧临时锚点，随后释放锚点并由同一 Worker 继续求解。筛选、选中、学习状态和作者内容不会随种子恢复。清除浏览器数据，或浏览器阻止本地存储，只会让图谱从初始布局开始，不影响知识内容、关系或学习记录。远离视口的节点可以只从当前画面隐藏，图谱成员和选择仍保留；低倍缩放时，屏幕内被选中、悬停或重点关注的节点仍显示标签。

每次进入图谱时，学习看板和图谱控件默认收起。点选节点会打开看板；点击画布空白处会清除选中并收起看板；拖动画布平移会保留选中。首次布局收敛后自动适配一次；看板或控件的开合不改变当前视口，之后仍可手动使用「适应画布」。

### 3.4 知识点详情页

从列表或图谱点进一个知识点，看到：正文（支持公式、图片、`[[知识点]]` 互链跳转）、行动提醒词（若有的话）、以及「关联题目」区——按主题分组折叠展示（点组名展开），每组内是题干与解析入口。

详情页是阅读入口，不提供将该知识点加入练习范围或直接组卷的按钮。需要围绕某个知识点练习时，可向 Agent 明确提出 authoring 请求。

### 3.5 一条铁律

阅读、图谱筛选与节点聚焦都不构成 Paper Assembly Scope，也不创建 Paper。Agent / CLI 可在明确 authoring 请求中使用 Scope；已有 Practice Run 的题目和顺序保持固定。Agent 的 `replace_practice_selection` 兼容动作只向 Agent authoring 提供范围，不直接创建或修改 Practice Run。

## 4. 建议与计划：系统怎么「多嘴」

**目标深度：详。完成度：✅ 首批成文。权威：daily-learning-plan spec、consolidate-practice-views。**

系统通过两个渠道提建议，共同原则只有一条：**只提醒、不强迫、不露参数、可无视。**

**每日建议**：每天第一次打开时，系统按你的目标、进度、覆盖情况算一次当日建议；也可以随时用建议区的「重新安排」手动重算。它最多只有三条，措辞是「覆盖仍低」这样的人话，不带「去做第 3.2 节」式的指令。计划失败时保留上一次的有效结果，不会给你看一个报错堆栈。每日计划和复习负荷放在默认收起的「目标与时间安排」详情中。

**到期建议**：你练过的内容会被排期复习（第 7 章讲机制）。到期和薄弱提示只供阅读，不加入待选清单、不改变 Paper，也不直接开始练习。

这些提醒只是只读信息：不会进入练习范围、改变某张 Paper 或启动组卷。系统不会弹窗、置顶催促，也不会因为你不理建议就加重语气或加倍推荐。

## 5. 目标与时间安排

**目标深度：详。完成度：✅ 首批成文。权威：calendar-workload spec。**

练习页的「目标与时间安排」默认收起；展开后可查看每日计划与全宽「时间安排」卡（标注了「实验视图」——形态还会迭代）。这些内容全部**只读**：它不写、不改、不重排你的任何数据。

**目标时间跑道**：当月月历中，每个有截止日期的目标是一条细轨道。填了开始日期时，轨道从开始日持续到截止日；没有开始日期的旧目标显示为截止日上的单日轨道。跨周目标按自然周换行并用箭头续接，仍然是同一个目标，但标题只在首个可见分段出现一次；时间重叠的目标自动占用上下不同的紧凑跑道，不会互相遮盖或合并。阶段目标用黄色，长期目标用蓝色，逾期目标只把结束端点变红；今天只高亮日期数字，不再涂满整格。完整标题和起止日期保留在每段的悬停提示与无障碍标签中。窄栏允许月历自身横向滚动，不挤压整页。

本月之外或没有截止日期的目标不会硬塞进日期格，而是在月历下方如实列出。没有任何目标且 14 天内也没有到期任务时，显示一句诚实的空态：「最近没有安排在日历上。」

**未来 14 天复习负荷**：从今天起 14 天，每天有多少项到期就画多高的柱。上方先汇总 14 天总量、峰值日期/数量和当前逾期数；每个非零值直接写在柱顶，所有日期固定在同一条基线上，零值只留日期、不画假的短柱。峰值柱用黄色强调；若它或其他日期达到非零日均的两倍，再加红点表示「这天恐怕练不完」。这里没有拟合线或预测线，只有真实到期数。

**让 Agent 看看**：出现「重」日时，卡片标题旁会出现这个按钮。点它把一句话预填进右侧 Agent 输入框——「最近几天任务偏重（最多的一天 N 项），帮我重排一下。」——**只是填进去，绝不替你发送**。发不发、怎么跟 Agent 商量，由你决定。

窄屏下时间安排仍然纵向显示；月历和 14 天日期轴各自在卡内横向滚动，不挤压整页。

## 6. 练习过程：一题一条流水线

**目标深度：极详。完成度：✅ 已成文。权威：free-navigation-paper-practice、review-workbench spec、micro-quiz-content spec、flash-card spec。**

### 6.1 通用节奏

普通 Paper 按题目自身的作答形式呈现，不需要整卷选择内容模式。新一轮开始前选择答案展示方式：「做一题显示一题」或「交卷后统一显示」；继续未完成轮次会恢复原方式。每道题都可用「上一题」「下一题」或题号点导航，题目顺序固定，首尾不会绕回。导航会保存位置和草稿，不会提交答案、判定或自评。题干可以带教材原图；图片仍按题目内容显示。

题面、解析与作答区各有各的样子：题面是**独立的一张纸**（左边缘一根 4px 的蓝色结构线、不加装饰性柔影，内文是 17px 衬线的阅读刻度）；解析是**与题面并列的另一块纸面**，衬线正文 + **沉底面**（浅底深字，靠 1px 内发丝线与卡面分开，不带柔影），只用小标题区隔——解析恰恰是最值得读的内容，不该比题面更弱；作答区是**一个独立块**，上方明确标着「**你的作答**」，与题面一眼分得开。题面与解析的正文同样是 17px、行高 1.75、行宽 38em（与知识点正文同档，见 3.2）。

### 6.2 做一题显示一题

单选题和判断题在选择答案时自动提交。多选题和文字作答先保留可编辑输入；点「提交答案」后才提交。成功后该题锁定，并展开可用的判定、参考答案和解析。显式标记「不会」会立即记录卡点 Attempt、展示可用参考材料并锁定该题。文字题、无答案键题不会被编造客观判定。保存尚未确认时，页面会标出状态并保留可恢复输入。

每题提交后仍可浏览其他题，但不能再改已锁定答案或重复标记「不会」。需要修正时，按现有流程让 Agent 提议更新 Paper 或题目；历史作答与评分不会被改写。

### 6.3 交卷后统一显示

作答和选项会自动保存，交卷前仍可编辑。题号状态只显示未答、已填写或标记「不会」，不提前透露对错，也不显示参考答案或解析。此模式不提供逐题「提交答案」按钮。

在交卷前显式点「不会」会立即展示可用参考材料并留下可改标记；之后输入新答案会清除该标记，但“曾看过参考材料”的事实仍保留。仅导航不会展开材料或改变标记。

### 6.4 提交试卷与判定边界

只有点「提交试卷」才会完成普通 Paper。提交会把尚未提交、且没有保留「不会」标记的非空草稿作为答案记录；空白题和仍标记为「不会」的题会记录为卡点 Attempt，后者的草稿仍保存在答卷中。系统随后锁定最终作答并归档本轮。没有额外的空题确认，也不必等自评。做完最后一题、浏览或暂停都不会自动提交。客观题有可用答案键时才显示判定；开放题与无答案键题保持未判定。判定和解析不会伪装成自评。

### 6.5 闪卡（flash_card）

已有闪卡和旧练习轮次保留原来的揭示、方向与移动语义；本次普通 Paper 流程不改变闪卡作答方式，也不增加闪卡创建入口。从知识点内容拆卡、方向选择和旧轮次行为仍按原闪卡契约处理。

单向卡揭示时向下展开。双向卡在视觉上叠成两张，揭示时像摊牌一样分别向左下、右下扇开；`⇄` 可在揭示前后交换当前提问面。最终自评记录的是**实际使用的方向**。系统减少动态效果时会直接显示展开后的状态，不播放位移动画。统一自评页也会按实际方向列出提示、答案和方向。

闪卡专用的「上一张 / 下一张」和揭示状态保持既有行为；普通 Paper 的答案展示方式不会改变这些旧语义。

### 6.6 可选自评

「练习显示自评」与答案展示方式是两件事。开启时，符合条件的已提交题目可以保存 1–5 分和可选备注；也可以跳过，之后再编辑同一轮已有评分。自评不控制导航、不锁定答案，也不会阻止提交试卷或完成页返回。关闭时不显示评分控件，既有客观判定处理规则保持不变。

### 6.7 中断与恢复

每张 Paper 的未完成 Practice Run 独立保存身份、固定题序、当前题、答案展示方式、输入草稿、提交/锁定状态和已显示参考材料的事实。刷新、重启或切到另一张 Paper 后都可继续原卷，不会重新组卷。切卷只暂停，不完成或放弃前一卷。

未提交输入作为执行草稿保存，不会生成 Attempt、反馈、信号、学习进度或排期。网络失败时状态会如实显示，输入保留；页面不会在服务端确认前声称提交成功。已经确认的作答和评分保持不变。

### 6.8 学习记录与判分边界

浏览、导航、草稿、展开参考材料和交卷本身都不会凭空制造自评。`per_item` 下的显式答案提交和「不会」会立即创建 Attempt；`on_submit` 下的「不会」只保存草稿标记，最终由整卷交卷创建 Attempt。整卷提交会把未提交答案以及空白或仍标记为「不会」的题写入作答记录。已记录的客观判定可按「练习显示自评」开关的既有关闭规则更新学习状态；自评开启时，你也可以另行给出 1–5 分。开放题和无答案键题不会自动评分。

手写长题（比如拍照交的证明题）仍可让 Agent 按你的明确要求转录或代录；这走 Agent 的作答记录流程，不会把页面里的草稿自动当成学习记录（第 8 章）。

### 6.9 一个综合题回合的完整例子

> 选「交卷后统一显示」，在文字题写下解法并跳到另一题检查题目。输入会保存但仍可改；判定和解析不会因导航出现。你可以点「不会」看参考材料，再回来补写答案。最后点击「提交试卷」，所有非空未提交答案一起记为作答，空白题记为「不会」，本轮随后归档。若网络结果未确认，页面保留输入并显示提交状态，不先显示完成页。

### 6.10 完成页与本次答卷

成功交卷后，完成页显示题目总数、可判客观题的对错数和「不会」数；仅在「练习显示自评」开启时显示待自评数。不把未知判定算错，也不把完成说成全对。点「查看本次答卷」可在同一张题目表中任意导航；答案和判定保持完成时状态，符合条件的自评仍可编辑。点「返回完成页」回到同一轮次的完成信息，不会重新交卷或再写 Attempt。点「再练一次」会用同一 Paper 建立新的执行，旧答卷与评分保留；也可回试卷列表。

查看答卷不会重开练习或覆盖历史作答。自评编辑仍按同一轮关联 Attempt 的覆盖规则处理，不增加重复作答或重复学习影响。

### 6.11 连对与断裂

练习页上常驻一个**连对计数器**，它记的是**这一轮里连续答对了几题**。计数器旁边是一簇**火苗**（最多 10 簇）：连对越长，点亮的火苗越多，连对的长度因此由**形状**承载，不只靠一个数字。数字本身是**滚**上去的，不是啪地一下跳到新值。

每逢连对数**跨过 5 的倍数**（5 连、10 连、15 连…），页面会插入**一份横幅**——所有倍数共用同一份横幅，区别只是里面的数字（一份横幅，数字作参数，不是每种连对各做一份）。

连对**超过 4** 时答错，会给出明确的负反馈（一次短促的横向摆动，不做屏幕级震动）并把计数归零，**不静默断掉**。新一轮从零重新计。

> 计数器的**三档色调**（零 = 灰、有连对 = 黄、最高档 = 黄到蓝的渐变）目前只有档位判定与几何已经落地，**配色规则仍在落地中**；**火苗的形状也还没画出来**（逐簇点亮的逻辑在跑，但看不见火苗本身）——这两件事都记在 §10.1 与 §10.1.1。当前能看到的是滚动的数字与横幅。
>
> ⚠️ 另：这套连对反馈目前只兑现在**兼容流程**的练习题呈现上，**试卷流尚未接入**（见 §10.1.1 第 14 条）。

### 6.12 交卷庆祝的两档

交卷成功后的庆祝分**两档**：

- **日常档**：完成页上的统计数字**逐位滚动**到它们的值。这是每一轮都有的。
- **里程碑档**：在日常档之上，额外出现**一圈几何爆点**与**几张纸片**从完成页里散开。里程碑档的条件是「**本轮全对**」**或**「**这一章第一次完成**」。

> **当前事实**：两个条件里**只有「本轮全对」能触发**。另一个条件（「章节首次完成」）目前**恒不成立**——练习轮次表里没有章列，也没有任何「首次完成」标志，这条事实没有数据来源（`contract-drift.md` CD-167）。裁决明确不许用任何代理指标（比如「比上次做得好」）去近似它，所以它宁可不做，也不假装做。里程碑档的爆点与音效落在同一拍上（约 400ms），纸片随后落下。
>
> 开了「减少动态效果」时，两档都直接落终态：不滚数字、不画爆点、不撒纸片，但数字和状态照常显示。

## 7. 记录与调度：你的评分去哪了

**目标深度：详。完成度：✅ 首批成文。权威：review-workbench spec。**

### 7.1 「练习显示自评」开启时的四项更新

「练习显示自评」开启时，首次显式保存自评会原子地做四件事：记一条**反馈事件**（评分 + 备注）、更新**学习信号**（低分会加强对应知识点的薄弱证据；信号只加强不自动消除）、更新**当前学习状态**（1–2 分 → 重点练习，3–4 分 → 可以复习，5 分 → 掌握）、更新**调度**（这道题的下次复习日期按新间隔推进）。这是一次写入，不多不少；2 分和 5 分留下的痕迹不同，但流程完全一样。可以跳过自评，交卷不等待评分。

Paper 回看中修改已有自评时，只原位覆盖关联反馈的评分和评语，不新增 Attempt 或反馈，也不再次更新学习信号、当前状态或调度。

**「练习显示自评」关闭时**：有答案键的客观题在作答被记录后，按既有关闭自评规则以答对 5 分、答错 2 分更新状态与排期；不写评分反馈，所以统计中不会出现你没有打过的分。开放题和无答案键题没有客观判定，不推导学习状态或自评分数。

图谱里显式编辑知识点状态也是一条独立写入口——按对应评分更新状态与调度，但**不**追加反馈历史。

### 7.1.1 提交作答本身也是一条记录

单题提交或整卷提交经服务端接受后，会保存作答文本、选中的选项文本、可用的客观题**判定**和对应 Attempt。`per_item` 标记「不会」会立即建立没有答案判定的卡点 Attempt；`on_submit` 标记「不会」仅保存可修改草稿，整卷交卷时仍空白或仍标「不会」才建立卡点 Attempt。提交尚未确认时，浏览器里已有答案不等于题库里已经有这条尝试。「练习显示自评」开启时，只有显式保存评分才记录评分反馈；关闭时，有判定的客观题按既有规则更新状态和排期，不能把这两种结果说成自评。

如果提交或保存自评后网络断开，练习页会保留当时的请求。刷新后用同一请求重试会取回该次保存的结果，不会因为响应丢失而重复写入；待迁移的旧题库会提示运行迁移命令。

### 7.1.2 记录中心：你做过什么

左侧「**记录**」现在是独立界面，有四个视图：**概览**看作答次数、完成练习数、客观题正确率、平均自评、最近 14 天作答量和 1–5 分布；**练习 / 试卷**按轮次看临时练习、保存试卷与 Agent 练习；**作答明细**保留逐题时间、判定、自评、评语和作答摘录；**错题**只收客观判错或明确卡住的记录。

记录中心里，**概览**是四张统计卡片（一主三辅，权重不同），每张带一个迷你图：作答次数配一条每天一个点的趋势线，完成练习配一排「实心 = 已完成 / 空心 = 未完成」的方块，客观题正确率配一个墨色占比环，平均自评配 1–5 分每档一根的条。下面是「最近 12 周」的**作答日历**（7 列 × 12 行的方块网格，每格见方、最小 18px）、「最近 14 天」的**作答量**柱图（所有柱共用一条基线，柱顶直接写数字），以及两张分布卡——**判定分布**（对 / 错 / 未判定）与 **1–5 分自评分布**。**作答明细**每条记录一张圆角小卡，不描边，靠留白与柔影分开，不摊平成表格的字段行；**错题**同样每条一张卡，带题面摘要与**错因摘要**（只说已经记下的事实：判定与作答状态，不发明新口径）。

**作答日历的五档**：当天作答次数分五档着色——**0 次**是底色，**1 次**、**2–3 次**、**4–7 次**、**8 次及以上**各深一档（越深越多）。这五档是**读数口径**，不是分数：日历只说「那天你做了几次」，不做任何评价。鼠标停在一个格子上（或用读屏读它）会告诉你「某日 · N 次作答」。

> 当前日历**只有填色这一重编码**（用格子高度再表达一次的那一重仍在落地中），也**还没有档位图例**——格子上方只有一句「颜色只表示当天的作答次数。」

概览里的**完成练习数**和**最近 14 天作答量**是纯计数：它们数的是已保存的轮次和已记录的作答，迷你图画的就是每天的作答量本身，不做预测、也不换算成任何百分比。

练习轮次只保存最小快照，不复制题目内容。真正的逐题学习证据仍是 attempts 与 feedback。题目 id 仍可用 `/w/{课}/records?problem=<题号>` 单独查看历史。

**旧池外键修复（操作者）**：已有数据库先备份并在隔离副本验证，再显式运行
`python pool/scripts/migrate-progress.py --db <副本数据库路径>`。该既有命令修正旧作答状态约束，
以及错误指向 `problem_attempts_widening_old` 的外键，保留现存记录。
若输出 `unresolved foreign keys` / `missing attempt IDs`，表示仍有缺失父记录；命令返回成功也不代表
历史作答已恢复。保留完整诊断，另行制定恢复方案；不要删除进度或编造作答来清空报告。
真实课程库的执行须另行授权，并比较副本迁移前后所有受影响行和非目标结构。

练习页里也有就地的一处：揭示解析后，**「历史作答 N 条」**折叠段列出这道题你做过的每次作答（日期、判定、评分、作答摘录）。同一道题做第二遍会新增作答，不覆盖第一遍。原作答与判定保留；本卷本轮回看中可以覆盖该次作答的自评分数和评语。

### 7.2 调度只做背景

每道练过的题有自己的复习排期。到期信息只作为只读建议出现，不会弹窗催你、把没练的题藏起来、拒绝你练任何东西，或把「间隔」「熟悉度」等参数摆到你面前。**调度永不锁题**；普通 Paper 中提交后的答案锁定由该轮的答案展示方式决定。

### 7.3 方向

双向闪卡按方向分别排期（比如中→英、英→中各一条进度，互不影响）。闪卡及旧会话的方向控件和方向记录保留现有行为；新普通 Paper 开始时不选择闪卡或其他内容模式。

### 7.4 你会看到的全部「评价词汇」

整个系统对你的学习状态只使用三个词：**重点练习**（有明确薄弱证据）、**可以复习**（到期待回看）、其余**保持沉默**。没有分数、没有百分比、没有「掌握度 73%」这类伪精确。系统对你的全部判断，都压缩成这三个词，其余交给你的自评和体感。（唯一的例外是知识点页顶部那条**本章计数**：它把同一批当前状态按**个数**汇总，不作断言、不给百分比。逐条的状态提醒仍只用这三个词。）

## 8. Agent 对话

**目标深度：详。完成度：✅ 已成文（2026-08-29；讲解/诊断一键任务同日经所有者决定移除，见 remove-explain-diagnose）。权威：ai-teacher-bridge spec、workbench-ui spec。**

右侧是 Agent 栏。它背后没有内置的 AI 内核——接的是你自己机器上的 Agent 命令行（Codex / Claude / Pi），配置归你，账单归你，Lesson Kit 只做桥。Pi 是三者里最轻的一个：同样的功能，harness 占用的 token 更少。

**新建对话与选择 Agent**：点「新建」会列出本机可用的 Agent（在 PATH 上发现的 Codex / Claude / Pi）。选中即创建对话，**之后这个对话固定用这个 Agent**——系统绝不会悄悄换一个，Agent 掉线、超时、退出都会如实报错，而不是装作一切正常。Agent 在自己进程里报的错也会被翻出来：即使进程是「正常退出」，只要它流里说了失败，这一轮就记为失败并附上它给的原因。历史对话列表就在右侧 Agent 栏的列表视图里，随时切回、重命名、删除。

桌面上可选项较多时，可在选项列表上用滚轮浏览；选择器标题和说明会留在原位。

**模型：显示名由你定，对话里随时换**。同一个 Agent 命令行可以挂多个模型，各自取一个你自己看得懂的名字（列表里显示的就是这个名字，不再是把 harness 和模型串拼在一起的 `pi · deepseek/…`）。配置一次即可：

```bash
lesson-kit bridge add-model "DeepSeek V4" --provider pi --model deepseek/deepseek-v4-flash
lesson-kit bridge list      # 看到的既是可执行文件来源，也是这些条目
```

新建对话时选中某个条目，对话就记住它用哪个模型；**对话头部的下拉框**可以随时换成同一个 Agent 上的另一个条目，**下一轮生效**（当前这一轮按它开始时的模型跑完，不打断）。换模型时会丢掉缓存的进程、重新拉起：如果这个服务不允许跨模型接着上一轮的原生会话，桥会开一个新会话并在对话流里写明一句——**本地镜像的历史一条都不会丢**。没配置任何条目时，选择器退回成「一个 Agent 一条」的老样子。轮次正在跑的时候不让换（会明确报错），免得你不知道哪一轮用了哪个模型。

**自由提问与练习页上下文**：对话里随便问。练习页发消息会带上**当前可见题目**、普通 Paper 的答案展示方式与进度，并可附带未提交的文字、选项、已确认状态和当前显示的图片；知识点页会带上当前知识点，图谱页会带上当前聚焦节点和只读筛选。导航后新消息使用当前可见题目，已接受消息仍保留提交时上下文。带上草稿只是为了这一轮问答更贴题：它不会自动成为作答或反馈记录。

练习页会把当前可解析的正式题作为**页面锚点**。如果它属于正在进行的练习，Agent 还会收到同一练习里最近最多四道已结算的前序正式题；明确问“上一题”或“前几题”时，**轮次焦点**会指向相应题目，但页面锚点不变。否定上一题、同时比较当前题与上一题等说法会保留当前题为默认焦点，让 Agent 结合这段有界上下文判断；可解析但不在当前练习里的题只携带自身，不借用另一轮的历史。未知题号或闪卡号不会被当作正式题焦点。重建上下文只读 Pool，不新增尝试、反馈、状态、排期，也不移动练习位置。

**详细操作契约按需读取**：每轮提示只带精简能力地图。Agent 可运行 `python -m workbench.bridge.agent_contracts list` 查看 `commands`（命令）、`attempts`（作答记录）、`practice`（选题组卷）、`actions`（界面动作）和 `content`（新增或修改内容）五个主题；执行某类专门操作前读取对应主题即可。该模块只输出静态说明，不是新的 `lesson-kit` 顶层命令，也不读取或写入学习数据。

**按需核对某个知识点的历史作答**：问题需要历史依据时，Agent 可以读取 `lesson-kit evidence <工作区> kp <知识点 id> [--limit 1..20]`。默认最多返回最近 8 条，并会说明是否还有更早记录。结果提供当前题面以及记录中实际存在的作答文字或选项、判定/状态、关联评分与评语、作答时间；缺少的记录不会由系统推断。题面来自当前题库内容，不是作答时的旧版本快照。该命令只读，不会自动把你归为薄弱、粗心或进步；工作区数据库缺失时会报错且不会新建数据库文件。

**什么才算「卡住」**：一轮回答**不按总时长判超时**，判据是「多久没动静」——只要 Agent 还在输出、还在推进步骤，这一轮跑十分钟也照跑；它正在跑一条安静的命令（编译、批处理、长脚本）时另有一份更宽的预算，不会因为命令不吭声就把它截停。反过来，真卡住（完全没有输出又超出预算）仍会如实报 `provider timed out`，绝不假装完成。两份预算可在配置 provider 时指定（`lesson-kit bridge add <provider> --command <路径> --timeout 秒 --tool-timeout 秒`，`lesson-kit bridge list` 显示当前生效值），默认静默 5 分钟、命令在跑 20 分钟。

**执行过程怎么看**：Codex/Claude 继续在一张「执行计划」中显示具体步骤。Pi 则把读取文件、更新文件、搜索、运行命令和操作 Lesson Kit 各自显示成一条紧凑消息；同一步从「进行中」原位更新为「已完成」或「失败」，不会刷重复消息。Pi 在工具前后说的话会分成前后两个气泡，顺序与实时事件一致。所有工具输出默认折叠，路径和经遮盖的命令可见，写入内容不拿来做摘要。底层协议名、通用处理阶段和隐藏推理都不显示；失败轮次也会恢复已记录的工具活动、真实状态与实际存在的部分回答，不补造缺失内容。Pi 每个对话只开一个**隐藏**的后台进程（不会弹终端窗口），空闲半小时自动回收，你点「停止」时先请它自己停下、失效才强杀；工作台关闭或删除对话都会一起清理。回答里的表格、公式、图片按同一套安全 Markdown 渲染，窄栏里表格自己横向滚动。

**Agent 栏的紧凑外观**：对话栏用短标签显示当前页面与上下文，输入框会随内容增高。学习页面仍是主要阅读区域。短时活动和持续任务都使用右上角 Activity Float 展示当前里程碑与最新状态；小型按钮可收起或重新展开，收起状态保持到本轮结束，新一轮自动恢复展示。没有活动时 Float 自动隐藏；失败时保留简短摘要，直到新一轮或切换对话，不会为进度面板预留底部空间。最新 Artifact 仍可通过独立的 Adaptive Split 显式预览。

**右栏独立于中间页面**：Agent 栏不跟着中间页面走——切到别的学习页、或者刷新当前页，右栏仍保持你刚打开的那个对话，不会把你踢回历史列表。回到列表是显式动作：点对话顶部的返回图标（「返回对话列表」）；此后换页或刷新就停在列表。如果这个对话已经不存在（比如在别处删掉了），右栏直接回落到列表，不会弹一屏报错，也不会顺手新建对话。如果读取暂时失败，右栏会保留当前对话并提示刷新页面重试。

**想聊某道题就直接聊**：你在练习页发消息，Agent 自动带着当前题目和你的作答上下文——想让它讲这道题、找卡点，用对话说就行，不需要专门的按钮。

**让 Agent 替你记下并批改手写作答**：手写证明题、写在纸上的推导、拍了三四页照片的答案，都可以交给 Agent。流程是这样：你先把自己存放答案照片的**目录**告诉它一次（命令行 `lesson-kit attempts <工作区> sources list` 能列出哪些目录已配置，`sources add --path <目录>` 添加；目录可以在工作区之外，纯只读）。之后你说「帮我把这道题的答案记下来」「按我的水平给个 1–5 的自评」，Agent 会读那些图片、把作答**转录成文字**、写下批改说明，然后通过 `lesson-kit attempts` 一次提交；它提交前可以先用 `check` 预检（零写入），失败会逐条告诉你哪一题哪里不对。

几条边界值得记住：

- **只有你要求，才会记。** 只发消息问问题、只让它读照片、只讨论草稿，都不会产生任何学习记录——尝试、信号、状态、排期一个字节都不动。
- **评分是你的分，不是它的分。** `rating` 用的就是你自己那套 1–5 学习自评量表（1–2 重点练习 / 3–4 可以复习 / 5 掌握），不是卷面分、不是百分比；它不能替你决定掌握程度，也可以选择**不打分**，只留一条转录。
- **一次可以交好几题。** 一页纸上有两道题、或者一题写了好几页，都不影响：一份清单可以同时含多道题，要么全部记下，要么一条都不记。
- **重发不会重复记分。** 网络断了、回答丢了，Agent 原样重发（同一份 `request_id`）只会拿回第一次的结果，不会多出一条记录。要真的再记一次（比如隔了一天又做了一遍），换一个新的 `request_id` 即可。
- **记错了可以改，但只改最近一次。** 你对 Agent 说「刚才那道题转录错了 / 评分改成 3」，它用 `lesson-kit attempts <工作区> correct <尝试 id>` 整体替换那一次尝试，并**撤销旧评分的影响后按新分重算**（不是叠加）。如果那次尝试之后你又练过这道题、或改过相关知识点状态，更正会被拒绝并告诉你重新记一次——它绝不会回头改写你后来的学习历史。
- **图片不留档。** 照片留在你自己的目录里，Lesson Kit 不复制、不建索引、不在尝试上记单图路径；池里只有 Agent 提交的**文字**。所以图片是「来源」，不是「附件」。

**没配 Agent 时的样子**：对话面板提示「暂无可用 Agent。请先配置一个提供方。」——**其他所有功能照常**，练习、记录、调度一点不受影响。配置动作是在命令行跑 `lesson-kit bridge add`——Agent 没配就是没配，界面不装。想知道到底解析到了哪个可执行文件（机器上装了两份同名 Agent 时尤其有用），跑 `lesson-kit bridge list`；它还会标出路径是否真的存在。要让某个 Agent 固定走某一份安装而不是听 PATH 的，用 `bridge add <名字> --command <绝对路径>` 钉死它。

**Agent 如何按范围 authoring**：你在消息里明确表达练习意图（比如「按这几个知识点组一张 Paper」）时，Agent 可将该范围保留为 authoring 上下文，并使用现有 Agent / CLI 组卷能力。浏览器不提供人工编辑范围、直接组卷或从阅读筛选中选题的入口；`replace_practice_selection` 只更新 Agent authoring 使用的范围，不会新建或修改 Practice Run。

**Agent 能帮你把内容搬进来吗（内容批次）**：能，但只在你要求时——你说「把这些题导进去 / 给这一章补知识点和插图」，Agent 会准备一份清单，可能同时包含知识点、正式题、微题、闪卡和题目必需的插图，条数不限（大清单先存在本对话目录里，回答里只引用文件名）。服务端**一次预检、一份备份**：字段、引用、出处、图片字节全过一遍才写；任何一条不合格或缺图，整批一个字节都不写，并把每条原因原样列出来让你和 Agent 一起改。**一份清单可以横跨好几章**（每道题/每个知识点自己写所属章；若单项和清单都没写章号，会点名拒收，不用当前章补齐），落盘时**按章各成一个批次**——所以「12 到 14 章一起导」一次就能说完，而回滚可以只撤其中一章。结果卡片每章一行，写清楚：批次号、所属章、各类资产数量、来源分布、工作区、备份位置，以及**当前**是否已回滚。

### 8.1 用本地作者内容仓库审阅字段修改

**目标深度：详。完成度：✅ 已成文（PR110 v1）。权威：ADR 0024、`json-content-repository-sync` change、FILE_CONTRACT。**

你可以用 Git 审阅知识池里的作者内容字段，并把经过校验的修改同步回当前课程。先准备一个本地作者内容仓库 checkout，然后显式指定它：

```bash
lesson-kit mirror <工作区> init --repo <仓库路径> [--entity <内容 id>] [--dry-run]
lesson-kit mirror <工作区> check --repo <仓库路径> [--entity <内容 id>]
lesson-kit mirror <工作区> status --repo <仓库路径> [--entity <内容 id>]
lesson-kit mirror <工作区> sync --repo <仓库路径> [--entity <内容 id>] [--dry-run]
```

`init` 是明确的首次对齐：它把池中受支持的内容写成修订号 1 的 JSON，并记住同一份作者内容；如果仓库里已有同 id、修订号与内容相符的文件，会沿用它的路径。池与仓库内容不同则该条会报告冲突，不会覆盖。可以先用 `--dry-run` 看计划，再去掉它执行。

`check` 校验仓库文件并分类差异，`status` 显示每条准备从哪边同步；两者只读。`sync --dry-run` 展示与真正同步相同的计划，也不写池或 JSON。普通 `sync` 按内容条目逐条处理：通过校验的条目可成功，冲突或无效条目会单独报告，不会撤销其他成功条目。题目编辑会走现有字段校验；例如接受的空 `exam_year` 会以规范化的空值同时写进池、同步记录和 JSON 文件。双边各自改成不同内容时必须先由你决定保留哪边。镜像只在你显式运行命令时作用于所选工作区和 checkout，不会后台改动课程内容。

修订号只表示作者内容的前进版本，不用哈希。删除仓库文件不会删池内容：若对应池记录仍在，`sync` 会在仓库恢复 JSON 并推进修订号。`delete-requests/` 中的删除请求只校验和报告，绝不执行物理删除。仓库里单独新建一个 id 也不会自动入池；v1 只同步已有且经 `init` 建立记录的知识点、正式题和知识关系。

JSON 投影还包括知识点和题目的 `figure_paths` 逻辑引用，以及正式题完整的四维客观难度组。引用路径须通过现有课程相对路径校验；镜像不会因此创建或传输图片文件，全仓库的图片命名策略也不由此决定。要同步已引用图片的原始字节，请单独使用下方的 `mirror figures` 命令。题目难度由四个维度决定；同步会重新校验维度并计算总分和模型，不能只改派生值。旧池不迁移缺少的字段列；题目内容修改仍可清除当前池里实际存在的难度字段，显式评级需要完整字段组。

字段扩展仍使用 `schema_version: 1`。旧工作区已有的 v1 文件可在 `check`/`status` 中预览升级方向；本地升级写入下一个修订号，另一工作区只有在收到完整且与当前池相同的下一修订投影时才能收敛并记录一次。错误修订号或双方内容不同会被拒绝/报告冲突，不会自动选边。

这些命令只读写你传入的本地 checkout 与该工作区知识池，不会替你 clone、pull、commit 或 push。无效项或冲突会输出机器可读报告并以退出码 2 结束；请先处理报告，再重新运行指定 id 或整课同步。

教材原题按原样进池：原题文字、数值、选项、作答形式都不改，出处（如「教材 第12章 习题12-5」）显示在题目下方；只有你明确要求「改成小测」才会变体，AI 自己生成的判断/选择题另标来源。教材给的短答案单独保留，详细解析按需生成，保留来源字段并在正常解析中显示，不另设「AI 生成解析」区；相同文本只显示一次，已有数据不会因此删除。入库插图按**原始字节**复制到工作区 `.lessonkit/figures/{course}/{chapter}/`，文件名由门禁按内容 SHA-256 生成；不裁剪不转换，缺必需插图的题目整批不写。

对结果不满意，点某一行上的「整批回滚」（或命令行 `lesson-kit ingest rollback --batch 批次号`）一次撤销**那一章**的全部内容，连该批创建且再没人引用的插图一起删；该批内容已经产生过练习/评价记录，或 apply 后相关内容又被改动时，回滚会拒绝并如实告诉你——不会偷偷删学习记录，也不会覆盖后续修改。安全检查在创建回滚备份之前完成。重新打开这个对话，回滚过的卡片会显示「已回滚」，回滚按钮不再出现。

**正文的排版检出**：内容清单的有效检查和成功写入结果会附带 `typesetting` 报告，Agent 的动作结果也保留它。入池后的既有 `pipeline/scripts/validate-pool.py` 文本报告和 `--json` 输出使用同一口径：正文按空行分段，计数时剔除公式与反引号代码，报告少于 40 或多于 300 可见字符的段落；两端都包括在区间内。只测 `body`，不测提醒与行动行，纯公式/代码留下零可见字符时也不算过短。过长段落的知识点先列出，只有过短段落的知识点随后列出；同时触发两侧的知识点只出现一次，并带两侧段数与最长/最短值。末尾统计知识点数、段落数、可见字符分位数及两侧占比。没有输入会明确说明，区别于检查完且无检出。它只报事实，不阻止写入，不改变正文，也不改变旧校验的退出码。

**重复内容会在入库前拦下**：题干按大小写、空格、标点、已知公式/标记写法和常见导出噪声做规范化，再和课程内所有章节及本次清单比较；比较完整题干，不截断。重复题会指出已有题号和出处，整份清单零写入；仅仅相似、但题干确实不同的题仍可保留。

**检查题库卫生**：运行 `lesson-kit data <工作区> audit` 可只读检查重复题、疑似题目片段、未标注练习模式的客观题、缺少展示标题的题和图片引用问题。默认执行所有检查；可用 `--check duplicates` 等重复选项缩小范围，用 `--json` 获取机器可读报告。无发现退出码为 0，有发现为 1；该命令不会修改池或文件。

题目不再拥有 `topic_label`：schema ensure 会删除旧题目表的这个列，历史值可从迁移前的
外部数据库备份恢复；当前池不另存替代列或表。其他题目字段和学习记录保留，闪卡的同名
标签继续使用。

**来源和难度怎么分**：每道新题同时记录“依据什么材料”（课本、小测、期中、期末等）和“它是原题、改编题还是基于材料生成的新题”。因此 AI 根据期末材料生成的新题仍能同时保留两层事实。**真题还可以带一个「考察年份」**（如 `2023` 或 `2023-2024秋冬`，可空）——它是第三个可选来源事实，导入真题时顺手写上，之后就能「把 2023 期末的题挑出来练」（`lesson-kit pull <工作区> --exam-year 2023`，按前缀匹配）。客观难度是独立、可空的四维评级，不随出题自动产生；只有你明确要求给指定题评级时，Agent 才能先预检再整批应用。未评级题完全照常使用，学生页面也不显示裸分或星级。

**普通对话绝不写学习记录**：聊天本身不产生任何学习写入——不打分、不改状态、不动调度。Agent 只有在**你明确要求记录或批改**并实际调用写入动作时才会记录；浏览和讨论页面草稿不会自动提交。对话留痕保存在工作区本地，作为过程记录，不是学习记录。作答、可选自评和图谱状态编辑分别遵循各自的显式写入规则。

### 8.2 同步已引用插图

作者内容仓库的 JSON 镜像不包含图片字节。若要在本地 checkout 中审阅或同步池里已经引用的插图，显式选择方向：

```bash
lesson-kit mirror <工作区> figures --repo <仓库路径> --direction check|push|pull [--dry-run]
```

图像同步只读取现有池数据库。该文件必须存在且为普通文件，并包含知识点、题目两张所有者表及各自 id 列；缺失数据库、所有者表或 id 列时命令以退出码 2 结束，不创建数据库或空索引。为兼容旧池，两张所有者表存在但尚无 `figure_paths` 列时会按零条图像引用处理，不做 schema 迁移。

命令只处理 `knowledge_points.figure_paths` 与 `problems.figure_paths` 已引用的图片。`check` 和 `--dry-run` 只读；通过旧身份检查后，`push` 优先使用工作区顶层 `figures/`，该副本缺失时使用现有 `.lessonkit/figures/`；`pull` 会把同一组原始字节写到这两个位置，以保留当前渲染和入库布局。`push` 会按当前池引用生成 `figures/<课程>/_index.json`，即使没有图片引用也会写一个空索引；该索引只是查找路径和所有者的导航文件，不能改变池内容。命令不删除未引用文件，也不执行 Git 网络操作。

工作区图像目录和本地 checkout 中的图像目录、目标文件及归属索引都必须解析在各自根目录内；通过 Windows junction 或 symlink 指向外部目录的路径会被拒绝。路径无效、身份冲突或索引无效时 CLI 以退出码 2 结束。每个文件单独使用临时文件替换；整个操作不承诺系统写入失败后的批次回滚，因此中途发生文件系统错误时，之前已替换的文件可能保留。

既有文件名主体为 64 个字符小写十六进制的图像仍按旧内容哈希身份处理。只要仓库、顶层工作区、旧运行时目录中任意已存在副本的字节不一致，push、pull 和 check 都会报告冲突，不会覆盖这些文件。若仓库有这种旧图片而两个工作区副本都缺失，pull 也会拒绝，因为本地没有可用的身份基线；请通过既有 figure-patch 门禁恢复。其他已有的非哈希逻辑路径仍可按显式方向修改字节。全仓库的图片命名策略仍未决定，本命令不改路径、不计算新名称。

### 8.3 Agent 工件：保存成功的试卷

Agent 只有在执行 `lesson-kit papers save` 并拿到成功回执后，才会在对话里放一张 **试卷工件卡**。卡上的标题和题数来自试卷页那份已保存 Paper 的本地记录，不是模型自己拿的数字；模型给的链接一律丢布。点「打开试卷页」才会跳到本工作区的试卷列表；卡片本身不抢你的当前页面，也不会自动跳走。最近这一张可以在中栂斧侧临时展开预览，页面仍在；对话里更早的工件卡不再自动展开。没有对应保存记录的 id 不会显示卡片。

当前预览会在同一标签、同一对话和同一路由下刷新后恢复；收起预览、发送新消息、切换对话或跳转到其他页面都会清除这次预览状态。

### 8.4 Agent 消息恢复与工具结果

发送前，工作台会先在浏览器本地保存消息、当时的页面上下文和发送标识，再清空输入框。在练习页发送时，随本轮明确附带的未提交答案、备注、选项和可见图片也会进入有界的本轮上下文快照；它们不会成为作答记录或反馈，也不会自动带到以后轮次。若服务端明确拒绝，消息会保存在本地供恢复；若网络或服务错误使接收状态不确定，页面会明确标出「状态未知」。刷新或重开对话后仍可恢复。点击「核对发送状态」会用原标识和原内容核对，已接收的消息不会因此再次运行。

已接收的消息即使 Agent 本轮失败或取消，仍会出现在对话历史中并标明真实状态；只在实际收到部分回答时展示该内容。若要重试已接收但失败或取消的消息，需显式发起新一轮；新轮会链接原消息，两轮都会保留。工作台不会自动重放 Agent 操作或写入。恢复消息也不会覆盖你后来写入输入框的新草稿。

工具结果卡会显示动作、实际状态和有证据支持的结果；没有证据时明确写「影响未知」。诊断信息默认折叠并经过脱敏。没有后端支持的单步恢复操作时，卡片不会显示选择性重试；你可以查看只读信息或另发新指令。

Agent 正在处理一条消息时，输入框仍可发送后续消息。默认把新消息排在当前轮次之后；发送选项可选「默认」「排队发送」或「中断后发送」，工作区设置中的默认值只影响之后提交的消息。选择排队的消息集中显示在输入框正上方，每条一行；超过四行时在列表内部滚动，空队列自动隐藏。拖动手柄可调整执行顺序，也可聚焦手柄后按上下方向键；默认从上到下执行。

开始执行前可在行内编辑或删除消息，长文本可读取完整内容。编辑保留原消息身份和提交时的页面上下文，取消编辑不改消息。点击「立即发送」把这一条从普通队列取出：有当前回复时先中断，确认停止并释放 worker 后直接处理这一条；其余排队消息保持暂停。若消息已开始或版本、队列顺序已变化，操作会提示冲突并刷新，不覆盖执行中的消息。

普通轮次成功后，未暂停的队列会继续执行。轮次失败、取消或服务恢复会暂停保留消息，需要显式选择「继续」；仅进度读取失败不会启动下一轮。「中断后发送」只显示正在停止当前回复的短状态，确认停止并释放 worker 后直接处理指定消息，不加入排队列表，也不要求点击继续。没有其他排队消息时不会出现队列；有旧队列时保留并暂停。等待停止期间不能再接受另一条不同的中断消息，未接受的文字仍可恢复。

未知或被拒绝的发送集中在一份可展开摘要中，不再连续铺开大恢复卡片；已接收且失败或取消的消息保留历史中的显式重试操作。同一条已接收消息按提交标识对账，不重复进入列表。核对未知发送会保留原请求的发送方式，不受当前下拉框或偏好变化影响。若正在编辑的待发消息已开始或移出队列，未保存的文字也会保留在本页的恢复入口，供你手动恢复；不会修改已经开始的消息。恢复原文不覆盖较新草稿；重试已编辑且失败的消息使用当前文字和原上下文，不自动重放旧操作或写入。

### 8.5 Agent 提议更新试卷

Agent 可以提议调整一张已有 Paper 的题目名单或顺序。右侧的「Paper 更新待确认」会显示目标试卷、当前与拟议题序、加入或移除的题目，以及本次会清除的未完成进度和草稿数量。只有你点击「批准更新」后，页面才会提交更新；批准只清除该 Paper 受影响的未完成进度和草稿，历史作答与评分、题目身份和其他 Paper 均保留。点击「取消更新」不写入 Paper。

待确认时输入框仍可使用；显式选择排队的新消息进入暂停队列。「中断后发送」和排队行的「立即发送」会被明确拒绝，文字或原队列项保留，不会改成排队，也不能绕过这项决定继续执行。若批准前 Paper 或练习进度发生变化，页面会显示刷新后的影响并要求你再次点击批准，旧确认不会写入；若操作版本已变，重新核对后再次选择原操作（批准或取消）。待确认状态在重开页面或对话后恢复；批准或取消后，队列仍保持暂停，需要你显式点击「继续」。

## 9. 数据安全边界

**目标深度：详。完成度：✅ 已成文（2026-08-29）。权威：ARCHITECTURE、workbench-content-governance spec。**

一句话版本：**系统只在你明确动作的那一刻写库，其余一切只读。**

**会写什么**（全部由你的显式动作触发）：

- **普通 Paper 作答**（逐题提交、显式标记「不会」或整卷提交并获服务端确认）：写入相应 Attempt / 状态；交卷时将剩余非空输入写成作答，空白题标记为「不会」。
- **1–5 自评**（仅在启用后由你显式保存）：一次原子写入反馈事件、学习信号、当前状态与调度（第 7.1 节）；可跳过，不阻止交卷或完成。
- **图谱状态编辑**：在图谱里显式改一个知识点的状态——按对应评分更新状态与调度，不追加反馈历史。
- **Agent 代录作答（`lesson-kit attempts`）**：你明确要求记录/批改、Agent 提交清单的那一刻——同一事务里写入尝试与（若带评分）反馈事件、信号、当前状态、进度、调度；换 `request_id` 重发才会再记一次，`correct` 只改指定尝试并撤销旧评分影响。只读草稿、只读图片、只预检都不写。
- **目标的增删改**：练习页目标表单里你填的长期/阶段目标。
- **Agent 出题入库（Check 管线）**：你明确要求出题/补池、Agent 产出通过门禁的那一刻——按批次记号入池，整批可回滚（第 8 章）。
- **题目难度评级**：你明确要求给指定题评级并确认执行时——完整四维清单整批写入；预检零写入。
- **作者内容投影同步**：你显式运行 `lesson-kit mirror ... sync` 时，所选本地仓库中的已有内容可经 `data.content` / 关系校验器写回池；每条内容与同步状态、日志同事务提交。`check`、`status` 与 `sync --dry-run` 不写内容。该通道不传输学习记录，也不运行 Git 网络命令。

**一次说清几章，就一次导完**：你已经说明范围（比如「把第 18–22 章导进去」）时，Agent 应当在同一轮里把这几章一起提交，不必每章等你再说一次「继续」；一轮回复里可以带一份跨章清单，也可以带几个区块，服务端逐个应用。**每一章各记一个批次**（因此可以只回滚某一章），但预检、备份和写入是整份清单一次——任何一条不合法就整份零写入，不会只丢那一章。

**已有题目可以原地改，不用删了重导**：题目导入之后照样能改——补答案键、把一道普通题改成判断题/小测（把选项从题面里拆进结构化选项）、补来源证据或教材短答案、改题面或解析。单题用 `lesson-kit data <工作区> update problem <题号> --input <文件>`；成批改让 Agent 出一份 `problem-patch` 清单（或你自己写），一次预检、一个事务、逐条报错，**记下每行改前的旧值**，所以整批可以用 `ingest rollback --batch` 原样还原。改的是属性，**题号不变**，你在这道题上的作答、反馈、进度、排期一条都不会丢；只有改题面/解析/知识点/学科形态时那道题的难度评级会按老规矩清空（改模式、改答案键、补来源不动评级）。批量修改也**不会自动发生**：只在你明确要求时才执行。

**题干长度**：判断题、单选题的题干不限长度；题源中的长题不应因此被改成综合题。

**题型（综合题 / 判断 / 小测）在入库时选**：不给 `quiz_type` 的普通题进**综合题**；给 `quiz_type: "yes_no"` 的是**判断题**；给 `single_choice`/`multiple_choice` 加 2–6 个选项的是**小测题**。判断题、单选题**即使题源里没有正确答案也能入库**：这类题不自动判分，练习页会写明「本题未录入答案键，请对照课本或解析」。你照常作答；可以按需自评 1–5，不评分时也不会伪造判定或自评分数。以后拿到答案，随时可以补上（让 Agent 补，或 `lesson-kit data <工作区> update problem <题号>` 写 `answer_key`），补上后就开始自动判分。**「题型」在这里指的是练习模式**；题目的学科形态（计算/证明/建模…，即 `problem_type`）是另一件事，判断题、单选题的学科形态写 `other`。

**绝不写什么**：浏览、题号导航、图谱筛选/聚焦、未提交作答草稿和普通对话不会生成 Attempt 或自评；未提交草稿不会因暂停、刷新或关闭标签而自动补成作答。整卷交卷和逐题提交则按上文明确写入。其他动作再频繁也不会多出学习记录。

**池数据库与备份机制**：全部题目、卡片、知识点、你的记录都在一个池数据库（新布局 `.lessonkit/pool/dmath.db`，旧布局 `pool/dmath.db`）里。内容入库只有一条合法通道——**确定性门禁配方**（Check 管线，`lesson-kit ingest` 或对话桥出题动作），任何一批内容 apply 之前都会先做可恢复备份，apply 在单事务里执行，失败即回滚、池子原样；每一批都带**批次 id**（内容行自带批次标记），一条命令（或结果卡上的按钮）即可整批撤销。所以「内容坏了」永远有得回滚。

**状态文件位置**：用户级工作区/Bridge 注册表在 `~/.lessonkit-workbench/`（答卷目录清单 `answer-sources.json` 同在这一层）；每个工作区自己的对话事件、轮次记录、成功镜像、计划和目标在项目下的 `.lessonkit/`。新建或显式迁移工作区的池在 `.lessonkit/pool/`，构建工件在 `.lessonkit/intermediate/`；未迁移旧课程继续使用原有布局。失败/取消的助手部分输出不会作为成功对话镜像写入；已接收用户消息、真实状态和实际存在的脱敏部分回答仍可从轮次记录恢复。浏览器本地发送箱保留未确认、被拒绝及已接收但失败且可显式重试的消息。

**收纳已有课程**：先运行 `lesson-kit workspace <工作区名> migrate-layout` 预览，确认后运行同一命令加 `--apply`。迁移只把根目录 `pool/`（含备份和批次清单）及 `intermediate/` 移入 `.lessonkit/` 并更新注册路径；保留历史，遇到目标冲突拒绝合并。运行中的消息或服务访问须先结束，再迁移并重启服务。课程资料、已导出的练习卷、外部工具目录及嵌套历史副本不自动移动。未指定外部导出位置的内部工作留在 `.lessonkit/`；用户明确指定的导出路径继续有效。

**旧课程的新内部工作**：未迁移池仍在原位，新建工作文件及默认结果也放入 `.lessonkit/`。工作台 `guard` 通过安装的适配入口读取工件，不要求课程目录里复制 `lessonkit.py`；同一门禁已有隐藏目录时检查隐藏目录，未生成隐藏工件时仍支持旧根目录。不会用旧目录的通过结果掩盖隐藏目录中尚未完成的工作。

**走查一律用副本**：开发与验收从不直接碰真实池——用隔离注册表（`LESSONKIT_WB_HOME` 指到临时目录）+ 拷贝的池副本 + 专用端口起服务，全部流程在副本上走一遍才算数。这条纪律对开发者和 Agent 一视同仁：作者内容入池只经过门禁，学习记录、目标等仍由各自明确的用户动作写入；走查本身永不写真实池。

Agent 对话**不重建**——对话、滚动位置和没发出去的草稿都留在原处。

**能改的四项**（都是偏好，不是学习事实）：

| 项 | 说明 |
|---|---|
| **主题偏好** | **暖纸**（浅奶油纸面）或**夜纸**（暖褐深底，同一套图标与插画自动反相）。**默认跟随系统**（系统开深色就用夜纸）；**你显式选过的优先**，把已存的选择删掉就回到跟随系统。 |

| **动效偏好** | 动效开或关，**默认跟随系统**的「减少动态效果」，**显式选择优先**。关掉后主题切换直接切、庆祝直接落终态，不做涟漪。 |
| **声音偏好** | 音效开或关，**默认开**。只有答对、答错、完成、里程碑四个时刻各有一条不到 200ms 的短音效。 |

**存在哪**：浏览器本地（`localStorage`），**按工作区分别保存**，跨标签页与重启保留。
它**不写池**，不产生任何学习记录，也不同步到别的工作区。

> **换工作区要重设外观**：四项偏好都存在**当前工作区自己那一份**记录里，**跨工作区互相独立**。从 A 工作区切到 B 工作区，B 有一份自己的偏好记录，**主题、阅读字面、动效与声音都要在 B 里重新选**——A 的选择不会跟过去。这是有意的：外观是「在这个工作区里怎么看」的个人偏好，不是全局设置。

**什么时候生效**：主题与阅读字面切换后立即生效（首屏也不会闪——主题在样式表之前就写进
页面了）；动效偏好影响此后触发的动效；声音偏好影响此后的关键音效，**关掉立即生效、不用刷新**。
第一次音效必须发生在你的一次点击之后——浏览器不允许页面自己出声。

**切主题时会发生什么**：一盏台灯从角落探出、点亮，暖色涟漪自灯下扩散铺满整页（切夜纸），
或反向收拢（切回暖纸），约 700ms（**台灯转场**）。涟漪只在内容**下面**扩散，不会把卡片压平。
系统开启「减少动态效果」时直接切换，不做涟漪。

**四个音效各自落在哪一刻**：答对 = 判定为对的那一拍；答错 = 判定为错的那一拍；
完成 = 这一轮结束、进入完成页的那一次响应；里程碑 = 进入里程碑档的那一拍，与几何爆点
**同拍**（约 400ms），不抢在爆点前面也不拖在后面。**其它任何界面变化都不发声**
（悬停、展开、导航、加载一律安静）。关掉声音后这四个时刻都不响，但**视觉反馈一个不少**
——庆祝动效与连对断裂的负反馈都照常。

**切页时会发生什么**：中栏切到另一个页面时，页面还没取回来之前显示一组**骨架屏**占位灰块
（完整动效档下有一层微光扫过；降级档改用同色的静态灰块，不扫光），内容到了再落进版面。
**知识图谱页不呈通用骨架屏**——它有自己的加载表达。

**和左栏「学习者设置」的区别**：左栏「设置」区里管学习行为的那几项（练习与组卷显示自评、
运行中发送方式）**留在左栏，不搬家**；设置视图只管外观。两处都是浏览器偏好、都按工作区存、
都只表达偏好，不是学习事实。

**1. 连对三档配色与火苗簇布局（`.lk-streak` / `.practice-streak` / `.lk-flames`）**
- **现象**：三个容器类名由练习流程产出并已挂到页面上，但样式表里**零命中** ⇒ 三档色调
  （零 = 灰 / 有连对 = 黄 / 最高档 = 黄→蓝渐变）与火苗簇的排版都没有样式。
- **涉及文件**：`workbench/server/static/workbench.css`（类名由 `practice-flow.js` 的
  `streakHtml()` 产出）
- **归哪一波**：排队的 CSS 补齐波
- **验收怎么看**：连对 3 题 ⇒ 计数器呈黄调；连对到最高档（连对数 ≥ 30）⇒ 呈黄→蓝渐变；
  火苗簇横向排开、不压住数字。

**2. 火苗形状不可见（`.lk-flame-off` / `.lk-flame-on`）**
- **现象**：这两层只有定位与透明度，**没有底色也没有形状** ⇒ 火苗簇整体**看不见**——
  逐簇点亮的逻辑在跑，眼睛看不到。这是这一批里最明显的一条。
- **涉及文件**：`workbench/server/static/workbench.css`（`.lk-flame` 一族）
- **归哪一波**：排队的 CSS 补齐波
- **验收怎么看**：连对 1 题起能看见**逐簇点亮**的火苗；没点亮的簇是灰层；
  连对超过 10 题时簇数封顶在 10。

**3. 完成页数字槽排版（`.lk-stat` / `.lk-stat__value` / `.lk-stat__label`）**
- **现象**：三个类名由完成页脚本产出，样式表里**零命中** ⇒ 那几个计数只是裸文字，
  数值与标签的分层没有样式。
- **涉及文件**：`workbench/server/static/workbench.css`（类名由 `paper-practice.js` 的
  完成页渲染产出）
- **归哪一波**：排队的 CSS 补齐波
- **验收怎么看**：完成页的五个计数各自成槽、标签与数值分开，读起来是统计块而不是一串字。

**4. 断裂负反馈的类规则（`.lk-error-nudge`）**
- **现象**：**只有同名关键帧、没有同名类规则**；实际那一下横向摆动由脚本内联
  `style.animation` 驱动 ⇒ 摆动**看得见**，但类名自己没有规则（降级档也没有对应处置）。
- **涉及文件**：`workbench/server/static/workbench.css`（`practice-flow.js` 的 `breakStreak`）
- **归哪一波**：排队的 CSS 补齐波
- **验收怎么看**：连对超过 4 题时答错 ⇒ 计数器横向摆一次并归零；
  开「减少动态效果」时不摆动，但计数照归零。

**5. 里程碑锚点的类规则（`.lk-celebrate-anchor`）**
- **现象**：样式表里**没有这个类名的规则**；不过**定位并没有因此坏掉**——脚本在挂锚点时
  用内联样式补上了 `position:absolute; inset:0`（并把完成页卡片设为 `position:relative`）
  ⇒ 爆点与纸片仍落在完成页范围内。缺的是这个类名**自己的规则**（尺寸、层级、降级档处置），
  以及「样式表 + 内联兜底」两处写法不一致。
- **涉及文件**：`workbench/server/static/workbench.css`（容器由 `pages.py` 的
  `#paper-completion-milestone` 产出；内联兜底在 `paper-practice.js` 的
  `ensureCelebrationAnchor()`）
- **归哪一波**：排队的 CSS 补齐波
- **验收怎么看**：交卷且本轮全对 ⇒ 爆点与纸片从完成页里散开、落在完成页范围内，
  不盖住「查看本次答卷」按钮；样式表里能查到 `.lk-celebrate-anchor` 的规则。

**6. 作答区沉底块与标签（`.paper-answer-block` / `.paper-answer-label`）**
- **现象**：两个类名已挂在作答区上，样式表里**零命中** ⇒「你的作答」目前是默认字号的裸文字，
  没有沉底面，也没有作为标签的样式。
- **涉及文件**：`workbench/server/static/workbench.css`（类名由 `pages.py` 的
  `_paper_practice_html` 产出；沉底面用 `--surface-sunken`，见 `component-spec.md`）
- **归哪一波**：排队的 CSS 补齐波
- **验收怎么看**：练习页「你的作答」是一块独立的沉底面（底色差 + 内发丝线、不带柔影），
  标签与题面一眼分得开。

**7. 题号大数字（`.paper-stem-index`）**
- **现象**：槽位 `<p id='paper-stem-index'>` 在页面上，但**没有任何脚本往里写题号**
  （全仓只有该元素本身与一条测试断言）⇒ 题号既没有内容也没有样式。
- **涉及文件**：`workbench/server/pages.py`（槽位）+ `workbench/server/static/workbench.css`
  （样式）+ `workbench/server/static/paper-practice.js`（**需要**由它写入题号）
- **归哪一波**：排队的 CSS 补齐波（样式）；写入逻辑**需另派**（脚本侧）
- **验收怎么看**：练习页题面上方有一个醒目但不抢戏的题号，且不与题面正文挤在一起。

**8. 日历 0 次档的规则（`.level-0`）**
- **现象**：格子会输出 `level-0`（当天 0 次作答），但样式表里只有 `.level-1` 到 `.level-4`
  ⇒ **0 次这一档没有自己的规则**，靠底色兜底。
- **涉及文件**：`workbench/server/static/workbench.css`（档号由 `records.py` 的
  `_calendar_level` 产出）
- **归哪一波**：排队的 CSS 补齐波
- **验收怎么看**：记录中心「最近 12 周」日历里，0 次的格子与 1 次的格子**看得见区别**，
  且 0 次不回落成背景色。

**9. 状态圆点的形状与颜色（`.lk-dot` / `.lk-dot--red` / `--yellow` / `--ink` /
`.lk-dot--cross` / `--dash` / `--check`）**
- **现象**：知识点列表与计数条里的状态标记已经按「颜色 + 几何」输出，样式表里这族**零命中**
  ⇒ 三种状态目前看不出区别。
- **涉及文件**：`workbench/server/static/workbench.css`（标记由 `pages.py` 的
  `_state_dot` 产出）
- **归哪一波**：排队的 CSS 补齐波
- **验收怎么看**：知识点列表里「重点练习 / 可以复习 / 掌握」三行分别显示三种几何
  （叉 / 横 / 勾）；读屏读到的仍是那三个词。

**10. 章节计数条的样式（`.knowledge-count-bar` / `__value` / `__item--*`）**
- **现象**：计数的文字与数字已可见（`_knowledge_count_bar`），样式表里**零命中**
  ⇒ 条本身没有样式，读起来是一行散字。
- **涉及文件**：`workbench/server/static/workbench.css`（计数由 `pages.py` 的
  `_knowledge_count_bar` 产出）
- **归哪一波**：排队的 CSS 补齐波
- **验收怎么看**：知识点页顶部那条计数读起来是**一条分隔线上的计数**，而不是一行散字。

**11. 完成页进度带的轨道（`.lk-progress`）**
- **现象**：只有 `.lk-progress__fill` 的 `transform: scaleX(1)`，**没有 `.lk-progress` 轨道规则**
  ⇒ 带子没有高度、没有底槽，看不见。
- **涉及文件**：`workbench/server/static/workbench.css`（带由 `pages.py` 的
  `#paper-completion` 内联产出）
- **归哪一波**：排队的 CSS 补齐波
- **验收怎么看**：完成页有一条满格的进度带；开「减少动态效果」时它**直接是满格**
  （不重放生长动画）。

**12. 完成页数字槽容器的类名（`.paper-completion-figures` / `.lk-stat-slot`）**
- **现象**：两个容器类名已挂在页面上，样式表里**零命中** ⇒ 数字槽容器没有自己的排版。
- **涉及文件**：`workbench/server/static/workbench.css`（容器由 `pages.py` 的
  `#paper-completion-figures` 产出）
- **归哪一波**：排队的 CSS 补齐波
- **验收怎么看**：五个计数横排铺开、间距均匀，不叠行。

**② 服务端侧**

**13. 作答日历的 fill + height 双编码 · 档位图例**
- **现象**：五档阈值**已提成具名常量**（`_CALENDAR_LEVELS` + `_calendar_level`，2026-10-22 已落地），
  但格子**仍然只有填色一重**（没有用高度再表达一次），页面**仍只有一句**
  「颜色只表示当天的作答次数。」，**没有档位图例**。
- **涉及文件**：`workbench/server/records.py`（`_activity_calendar`）
- **归哪一波**：**W3f2 波**（`records.py`）
- **验收怎么看**：记录中心日历里同一档的格子**颜色与高度都一致**、档位越高格子越高；
  日历旁出现五档图例（色块 + 刻度）；「0 次」是独立的一档、不回落底色。
- **备注**：CD-170 已登记此条（双编码缺一半 + 无图例）。

**③ 交互侧**

**14. 连对反馈补到试卷流（A-54）**
- **现象**：连对计数器 / 火苗簇 / 横幅 / 断裂负反馈目前只挂在**兼容流程**的练习题呈现上
  （`practice-flow.js` 的 `#stream` 区，在 `#legacy-practice` 内）；**试卷流**
  （`paper-practice.js`）里 `streak` / `combo` / `flame` **零命中** ⇒ 试卷流作答没有连对反馈。
- **涉及文件**：`workbench/server/static/paper-practice.js`（复用 `window.lkTicker` /
  `window.lkFlame` / 同一份横幅，**不得另造一套**）
- **归哪一波**：**W3g2 波**（`paper-practice.js` + `workbench.js`）
- **验收怎么看**：在**试卷流**里连对 3 题 ⇒ 计数器与火苗簇出现；连对跨过 5 的倍数
  ⇒ 同一份横幅出现；连对超过 4 题时答错 ⇒ 归零并给负反馈。
- **备注**：§6.11 说的是「练习页上**常驻**一个连对计数器」——按现状它只兑现在兼容流程上，
  试卷流这一侧待 A-54 接上后才对得上那句话。

**15. 降级档里程碑音效仍响（A-53）**
- **现象**：里程碑音效挂在**爆点元素出现**上，而降级档（开了「减少动态效果」）**根本不建爆点**
  ⇒ 那一档**完全无声无息**。
- **涉及文件**：`workbench/server/static/workbench.js`（`celebrateCompletion` / `cueBurst`）
- **归哪一波**：**W3g2 波**
- **验收怎么看**：开「减少动态效果」+ 本轮全对 ⇒ **仍听到里程碑那一声**（画面不画爆点、
  不撒纸片）；关掉声音偏好 ⇒ 四个时刻都不响，但视觉反馈一个不少。

**④ 结构侧**

**16. 知识点页「分组卡片」（18.1）**
- **现象**：规格要的是**分组**呈现，现状是 `pages.py` 的**扁平清单**（一个 `<ul>` 里一行一个
  知识点），没有分组。
- **涉及文件**：`workbench/server/pages.py`（知识点页构建函数）
- **归哪一波**：排队的「知识点分组卡片」波（`pages.py`；等该文件的 owner 收工后派）
- **验收怎么看**：知识点页按组呈现，每组有自己的组名与组内计数；组内仍是**完整名称**、
  不截断、不加省略号。

**⑤ 已登记漂移（这是账，不是本轮要修的清单）**

**17. CD-166 · 组卷报告显示 id 而不是知识点名**

  名字映射随早已退役的范围托盘一起下线，至今没有接上。
- **涉及文件**：`workbench/server/static/practice-flow.js`（组卷报告的知识点显示）
- **归哪一波**：**待所有者定**——要修得先定「名字从哪来」（复用已加载的知识点列表 / 扩 API 响应），
  会动请求序列，本轮明确不改。
- **验收怎么看**：组卷结果里那条提示显示知识点**名字**而不是 id。

**18. CD-167 · 里程碑第二个条件不可判定**
- **现象**：里程碑档的两个条件里，「章节首次完成」**恒不成立**——练习轮次表里没有章列，
  也没有任何「首次完成」标志，这条事实**没有数据来源**。
- **涉及文件**：`openspec/changes/workbench-visual-language-v2/contract-drift.md`（CD-167）；

  必须单开一个变更并同步 `docs/DATA_MODEL.md`。
- **验收怎么看**：某一章的**第一次**完成练习也会进里程碑档（今天不会）。

**19. CD-168 · 记录中心明细视图「几列」两份设计件互斥**

**20. CD-169 · 图谱页三栏 z-index 取舍**

- **验收怎么看**：图谱页与改造前逐像素零差异（守卫仍报 0）。
