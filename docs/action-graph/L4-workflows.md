# L4 · 工作流层（用户真实路径 + 全部意外分支）

> 本层是 v2 的灵魂：**不许只画 happy path**。用户会回退、放弃、跳过、直接关闭——
> 每个出口都要有分支和落点。每条边可回溯 L3 动作；每个写库节点可回溯 L0。

## W1 · Paper → Practice Run 练习回路

```mermaid
flowchart TD
  A[试卷页的已保存 Paper 列表] --> B{开始新轮还是继续?}
  B -- 新轮 --> C[选择答案展示方式<br/>per_item / on_submit]
  B -- 继续 --> D[恢复该 Paper 的游标·草稿·展示方式]
  C & D --> E[Practice Run<br/>Paper 题型各自呈现]
  E --> F[上一题 / 下一题 / 题号点<br/>可到达所有题目]
  F --> G{当前答案展示方式}
  G -- per_item --> H[单选/判断选择即提交<br/>多选/文字显式单题提交]
  H --> I[成功后锁定并显示可用结果/材料]
  G -- on_submit --> J[编辑并保存草稿<br/>结果等待整卷提交]
  F --> K[显式标记「不会」<br/>查看可用参考材料]
  K --> L{展示方式}
  L -- per_item --> I
  L -- on_submit --> J
  I & J --> F
  F --> M{显式提交整卷?}
  M -- 否 / 导航 / 暂停 --> Z[继续保留当前 Paper 进度]
  Z --> E
  M -- 是 --> N[提交未提交且未标卡点的答案<br/>空白或仍标卡点的题记卡点 Attempt 并锁定]
  N --> O{事务成功?}
  O -- 否 --> P[保留可恢复答案与轮次<br/>原位报错并重试] --> E
  O -- 是 --> Q[归档 Practice Run<br/>显示完成页]
  Q --> R[查看答卷]
  R --> S[返回同一完成页]
  Q --> T{再练一次?}
  T -- 是 --> U[创建独立新 Practice Run] --> C
  T -- 否 --> V[返回试卷列表]
  W[可选自评] -.可跳过，不影响交卷.-> Q
  X1[中途刷新或切换 Paper] -.保存位置、草稿与展示方式<br/>恢复各自 checkpoint.-> Z
  X2[闪卡 / 旧记录] -.继续使用既有兼容流程.-> LEGACY[旧语义保留]
  LEGACY -.同一套连对升级反馈·纯呈现零写入.-> STREAK[三级计数器 + 火苗簇 + 一份横幅 + 断裂负反馈]
  I[成功后锁定并显示可用结果/材料] -.连对升级反馈·纯呈现零写入.-> STREAK
  X3[练习页发消息问 Agent] -.只带页面焦点与许可上下文·零写入.-> Z
```

核心不变量：**浏览器从既有 Paper 开始或继续；自由导航只保存位置与草稿；普通 Paper 只在明确交卷成功后完成。**到最后一题、暂停、切卷或返回答卷都不会代替交卷。`per_item` 的单选/判断选择自动提交，多选/文字需显式提交；成功后锁定。`on_submit` 在整卷交卷前保留可编辑草稿。任一模式显式标记「不会」都会揭示可用参考材料；`per_item` 立即写卡点 Attempt 并锁题，`on_submit` 只保存可编辑标记，改答可清除卡点标记但保留看过参考材料的事实。交卷将未提交且未标卡点的答案作为作答，其余空白或仍标卡点的题写为卡点 Attempt 并锁定；完成后可读答卷并返回完成页，重练会新建独立轮次。普通 Paper 自评可以跳过；旧记录和闪卡沿用旧语义。

```mermaid

  A[新建对话] --> B{本机有 provider?}
  B -- 无 --> Z1[降级: 暂无可用 Agent 提示<br/>非 AI 功能全部照常]
  B -- 有 --> C[选 provider · 创建即锁定]
  C --> D[发消息 · 自动附页面上下文<br/>可见正式题 + 同一练习最多4道前序已结算正式题<br/>明确相对指代才改变轮次焦点]
  D -. 问题需要历史依据 .-> D1[CLI evidence<br/>按知识点读有界作答事实]
  D1 --> E
  D --> D0[浏览器先保存消息/上下文/提交标识<br/>再清空输入框]
  D0 --> Dsend[POST turns · 带 submission_id]
  Dsend -- accepted --> E[provider 原生运行 · 事件流回传]

  F1 --> Fpause[队列暂停<br/>需要显式继续]

  I0 -- 无终态确认 --> I2[waiting_for_stop<br/>不并发启动]
  E -- 点停止 --> F3[本轮 cancelled<br/>保留消息/状态及实际部分回答]

  G -- 提议调整既有 Paper 题目名单/顺序 --> P0[显示目标 Paper、题序与进度/草稿影响<br/>等待学习者决定；队列暂停，composer 可继续排队]

  P1 -- 批准 --> P3{Paper 与进度快照仍有效?}
  P3 -- 否 --> P4[零写入；刷新影响并要求再次点击批准]

  P3 -- 是 --> P5[复用现有 Paper writer<br/>仅清除目标卷受影响的未完成进度/草稿]
  P2 & P5 --> P6[队列仍暂停<br/>学习者显式继续]
  G -- 普通对话 --> I[绝不写任何学习记录]
  A5[工件动作 paper_artifact<br/>只按已保存试卷记录] --> A6[对话内工件卡<br/>最新一张可临时预览]

```

工具结果卡展示归一化的动作与终态；只有后端证据支持时才说明已知影响，否则标为未知。诊断折叠并脱敏；没有对应后端操作时不提供单步重试。

> 2026-10-12（agent-context）：当前可解析正式题是页面锚点；只有它属于同一 active practice 时才附前序题。否定或同时比较当前/上一题的表达保留页面默认焦点，未知题号与闪卡号不形成正式题焦点；这条上下文读取不写学习记录或移动游标。

> 2026-09-25（bridge-timeouts-follow-progress）：原 `E -- 掉线/超时/退出 --> F1` 拆成两条——
> **时长本身不构成超时**，只有静默超预算才失败。预算按静默计：任一输出行或归一事件重置时钟，
> 命令/工具在飞时改用更长的工具预算（`bridge add --timeout` / `--tool-timeout`，`bridge list`
> 报生效值），因此 3 分钟以上的回答与长时间安静的构建都不会被截停，也不会再把正在运行的命令
> 一起杀掉；真卡住时仍如实报 `provider timed out`。

工作区浏览器设置保存运行中发送的默认动作（默认排队）；composer 也可为单条消息选择「排队发送」或「中断后发送」。待处理列表显示顺序和状态，执行开始前可编辑或移除；暂停后须显式继续。`queued` 与 `waiting_for_stop` 都表示 provider 尚未开始。进度读取失败只表示状态未知，不会派发下一条。
