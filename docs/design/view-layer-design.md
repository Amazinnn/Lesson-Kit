# lesson-kit View Layer Design

**Status:** Current v1 view shape.

## Boundary

Pipeline extracts durable assets into `pool/{course}.db`. Views only query the
pool and render student-facing files. A view must not silently create new pool
assets.

## Current Views

### Knowledge Guide View

The first student-facing view. It renders a readable guide from
`knowledge_points` using `pool/scripts/print-graph.py`.

Historical note: some older files still use `first-pass` or `速览` language.
The canonical product term is knowledge guide view.

### Problem-Set View

Located at `views/problem-set/`.

It renders two files from `problems`:

- Problem set: no solutions, no `kp_id`, no internal fields.
- Solution file: same numbering as the problem set; missing solution text is
  shown as `待补`.

Defaults:

- `source_kind=textbook`.
- Coverage-first selection.
- Preserve source/problem order when coverage allows.
- Do not generate supplemental problems in v1.

### Knowledge Graph Preview

Generated by `pool/scripts/render-graph-html.py`.

It renders a static, read-only chapter map:

- Knowledge points are graph nodes.
- `knowledge_relations` are graph edges when present; older pools fall back to
  `related_kp_ids`.
- Node labels use `graph_label` when available.
- Linked problems are listed by current problem status.
- Solutions are not included in graph data.

### Focus Map View

Generated by `pool/scripts/query-focus-map.py`.

It renders no HTML. It returns a compact JSON packet for a future second graph
view or for agent-side planning:

- seed-centered local neighborhoods;
- optional shortest path from seed KPs to a target KP;
- shared one-step neighbors across multiple seeds;
- simple clusters by section and knowledge type;
- optional Signal Map overlays for learner-specific weak spots and relation
  gaps.

Focus Map may derive graph findings, but it must not persist them as durable
knowledge relations. If a finding becomes a true low-level relationship, it
must be audited through `relation-insert-manifest.json`.

### Editable Graph View

Served locally by `pool/scripts/serve-graph.py`.

It is a maintenance view over the pool, not a public web app. It may update:

- `knowledge_points.body`
- `knowledge_points.fragile`
- problem progress records

It must not create/delete knowledge points, edit relationships, or edit problem
text/solutions.

## Shared Query Interface

```bash
python pool/scripts/query-pool.py --db pool/{course}.db --chapter {course}-{chapter} --view problem-set --source-kind textbook
```

For problem-set views the JSON includes:

```json
{
  "kps": [],
  "questions": [],
  "problems": [],
  "progress": {
    "kp_states": {},
    "question_states": {},
    "problem_states": {}
  }
}
```

## Intermediate Path

Views use:

```text
intermediate/{course}-{chapter}/{view-name}/
├── 01_inputs/
├── 02_analysis/
├── 03_plans/
└── 04_checks/
```

Problem ingestion is not a view and uses:

```text
intermediate/{course}/problem_extraction/{chapter}/
```
