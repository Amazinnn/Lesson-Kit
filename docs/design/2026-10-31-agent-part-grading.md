# 单一作答入口与逐小问 Agent 批改

状态：需求讨论已确认；尚未实现，不代表当前能力或 schema。实施提案见 `openspec/changes/agent-part-grading/`。

## 已确认的交互

- 每个主观小问只提供一个学习者可编辑的过程／作答框。学习者无需另填最终答案，也不需要填写用于批改的辅助字段。
- 提交触发 Agent 批改。对于可以用简短结果表达的小问，Agent 从已提交作答中维护提炼答案，界面另行只读展示“你的答案”和参考答案。
- 最终结果与作答过程分别批改：各区域有什么就评价什么，允许部分正确或待确认，不由结果正确直接推断过程正确。
- 证明题或无法用简短答案表达的小问不强行生成提炼答案，展示原始过程、参考过程及批改说明。
- 点击“不会”保留已写过程，单独记录为“不会”，展示可用的参考答案与讲解。
- 综合大题允许混合判断、选择、计算、证明等小问；每个小问题面紧接对应作答控件，长内容支持鼠标滚轮上下浏览。
- 支持逐小问独立提交，也支持整题提交剩余小问。用户可以在设置中实时选择与更改提交粒度。
- 提炼错误时，学习者通过对话请求 Agent 重新提炼或复核。Agent 对提炼答案、判定与评语的修改及时反映到界面，保留原始作答及修改记录。

## 后续实施须协调的边界

### 补充确认（2026-10-31）

- Agent 在出题／整理时保存小问结构；旧的未拆分题可整题作答，执行中不自动拆分或重排。
- 提交粒度在设置中实时切换，答案揭晓时机独立控制；已经提交的答案可先批改，但整卷揭晓前不显示结论，“不会”仍可提前展示对应参考材料。
- 主观批改支持错误／部分正确回看，不自动驱动掌握度与复习；继续由现有评价机制处理学习影响。
- Agent 缺少参考材料时可独立推导并标明来源；无法可靠判断时标为待确认。
- 主观小问分别显示答案结论与过程结论，证明题只显示过程；不合成单一对错。
- 综合题展示完成进度与各类小问状态数量，不生成整题总判定；题号悬停临时预览各小问情况。
- 题号预览同时支持键盘聚焦与点击／触摸详情，长预览支持滚轮；预览不导航、不提交，整卷揭晓前不显示结论或泄露结果的颜色与计数。
- 点击“不会”保留标记和已有过程，Agent 仍可点评过程；没有写出的最终答案显示未作答，不能从参考答案反推学习者作答。

### 契约协调说明

- 当前“答案展示方式”在执行开始时固定，定义见 GLOSSARY 的 Answer Reveal Timing。新增的实时提交粒度不可默认为同一设置；若要联动修改披露或锁定行为，必须在 OpenSpec 中明确替代关系。
- 设置切换应保留草稿、已提交记录与批改结果；已查看参考材料的事实不能因切换而消失。已提交原始作答与 Agent 可修订的派生批改结果应分别处理。
- Agent 修改的对象是提炼答案和批改结果等明确授权内容；“实时呈现”不意味着用提炼答案覆盖学习者原始提交。
- 当前客观判定与可选 1–5 评价是不同概念。主观批改结果须关联确切的提交，且不自动影响学习投影和调度、不合成学习者评分。
- 字段、接口与刷新方案的规划见本 change 的 design.md 和 tasks.md；本文保留用户确认的产品语义，不代替持久字段契约或已实现说明。

## 实施方向

沿 Shell → Domain → Data 单向依赖组织实现，Domain 保持无 IO，Data 承担持久化；复用现有作答与 Agent 入口，兼容既有题目及历史记录。本轮仅记录设计，不修改业务代码、数据库或当前行为规范。
