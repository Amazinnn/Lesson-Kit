## 已实现模块及边界

### Domain

`workbench/domain/course_sync.py` 提供 `plan_exchange(base, local, incoming)`。输入为稳定资产身份到 envelope 的映射，输出 changes/outgoing/conflicts/errors/unchanged。只比较 kind/content/depends_on/deleted，忽略 presentation 和传输元数据。缺 tracked asset 报错，显式 deleted 才是删除。双侧相同变化收敛，独立事实并集，依赖错误传递，保留独立有效项，允许合法循环。输入不变，零 IO。

### Data 投影与预检

`workbench/data/course_sync.py` 目前提供以下基础能力。

- `export_course(pool, workspace, destination)`
- `read_exchange(source)`
- `inspect_exchange(pool, workspace, source)`
- `course_lock(root)`

导出使用内存 SQLite backup 快照，不导出未提交事务。未知表和缺失图片明确失败。列出实际字段，保存原始答案与文件字节。Windows 路径别名、越界和 symlink 受检查。格式 v1 的 envelope JSON 路径使用短编号，完整稳定身份在 manifest，避免嵌套身份造成 Windows 长路径失败。

课程和安装来源分开，来源不使用哈希。数值记录号转换成来源身份，声明的 attempt_id/execution_id 及部分 JSON 引用随之转换。引用主键如 part_attempt_context 也以稳定父记录身份构造。learner 的 answer/draft/choices/note 容器不做通用引用替换。

导出只在首次建立 base，反复导出本机更新不等于另一端已确认。last_export 保存最近导出投影。只读 inspect 不初始化课程或注册表，验证目标字段和主键。**完整共同基线/接收确认逻辑尚未完成**。当前 base_mismatch 是显式阻断，不能当作最终顺滑版本协调机制。

每次变化写新 generation envelope 后原子替换 manifest，不变化的 envelope 复用旧路径。manifest 成功后清理上一 manifest 不再引用的文件。失败发布保留旧 manifest 和引用文件。中断产生但从未被 manifest 引用的孤儿 generation 仍缺恢复/清理策略。
