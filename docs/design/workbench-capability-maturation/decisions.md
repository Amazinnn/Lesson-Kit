# 决策台账

## 已有明确指令

- 本轮系统性访谈至少 100 个有效问题，以功能体验为主要提问对象。
- 创建完整、详细、系统、可多轮迭代的指导文档树，供其他 Agent 实施。
- 保留现有功能，改善可拓展性、鲁棒性、模块成熟度，并扩展已有能力边界。
- 提供具体 benchmark，覆盖程序、仿真和实际用户交互体验。
- 允许随讨论查询与编辑规划文档。工程事实先查，能够自主决策的工程细节不交给所有者选择。

## 逐问记录格式

每个 Q 编号记录主题、完整问题、建议及理由、选项、所有者原始回答、规范化结论、适用范围、依赖、受影响工件、状态和替代关系。状态区分待回答、已确认、需澄清、已替代。暂定建议保持可辨识，不计入已确认决定。

问题为扩展 Lesson-Kit-Content 后最希望打通的主要使用场景。建议可复用课程材料与试卷在不同安装间共享，学习记录继续独立处理。

选项为共享材料与试卷、接续个人学习现场、远端 Agent 编辑。所有者原始回答为「换设备后接续自己的试卷、草稿和学习进度」。状态已确认。跨设备个人学习连续性进入计划范围，个人学习数据需要独立定义传输和访问边界，不能静默归入现行作者内容投影。影响同步范围、题目依赖、DATA_MODEL、FILE_CONTRACT 与后续场景。未决事项包括载体、隐私、多设备冲突与离线。

### Q003 教学分支的本轮规划边界

### Q004 真实体验验收的责任分配

问题为谁承担真实交互 benchmark。建议 Agent 完成隔离实操并留证，所有者只进行少量真实学习抽样及主观体验判断。

选项为Agent实操加本人抽样、本人逐包验收、Agent代验后反馈。所有者原始回答为「其实可以负责全部可以代为验收的部分，包括调用真实的LLM。只要是使用测试用的免费API即可。」状态已确认，替代题中建议的本人抽样要求。Agent 承担全部可代验内容，可调用测试用免费 API；不可假定付费调用或向模型发送真实课程私有资料已获授权。采用隔离/脱敏测试材料，主观体验以可观察代理指标及模型评价单独注明，不能冒称所有者实际感受。影响 benchmark 负责人、模型调用预算、证据要求和接受条件。免费测试 API 的具体可用来源待核查，不在此刻调用。
