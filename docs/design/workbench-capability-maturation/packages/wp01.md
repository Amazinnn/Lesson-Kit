## 实施单元

1. 对照 contract-reconciliation 建立本包实际入口与字段清单，核对活跃 change 和当前运行身份。
2. 先为本包每个反例建立针对性失败检查，夹具和目标与 benchmark 对齐。
3. 复用现有 writer、投影和版本身份，只新增缺少的正常入口或纯规则。
4. 每个独立修改单元完成后执行相关检查并提交，随后跑正常 CLI 或浏览器流程。
5. 同步受影响职责文件和 Agent 契约，记录旧数据迁移、实际验收及未完成项。

## 接受与停止条件

当前目标由 OpenSpec delta 给出。若当前代码已经实现，先验证入口再仅补必要差异。契约未协调、数据不一致、实际入口未验证或免费 API 受阻时，受影响交付不能标完整通过。其他独立包按各自证据推进。完整测试、真实环境与交付摘要按 execution-guide 执行。

首包按 data-exchange-matrix 全类别完成；禁止把课程学习文件、经验、学习偏好或原件以初期简化为由延后。纯文件交接与 Git 发布分开报告，GitHub 访问能力以真实宿主验证。
