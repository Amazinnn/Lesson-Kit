# 实施入口与维护协议

## 本轮基线

版本 1，2026-11-07，103 个有效回答。先读 README、decisions 的 S005–S010、traceability、contract-reconciliation、data-exchange-matrix 及本次 change。原始问答保留历史，当前执行结论由对应 change delta 和设计给出。当前程序事实仍由 live specs 和 DATA_MODEL 等职责文件描述。

## 开工顺序

1. 检查当前分支、工作树和已合入的相关 change。记录提交号与工作区路径，不根据任务勾选推断上线事实。
2. 读 AGENTS、ARCHITECTURE、lesson-kit-dev、目标 change 全部工件、其工作包卡及对应 benchmark。复述 Shell → Domain → Data、现有用户行为的已批准改动、具体文件范围。
3. 在隔离课程副本工作。实现任务先建立针对该回归的失败检查，再写最小实现。已有代码可满足时只接线与验证。
4. 契约先协调。已有职责冲突在 contract-reconciliation 登记结果，受影响字段与入口同提交同步。新行为未写 delta 时先补 delta，再改代码。
5. 每个可验证单元提交，add 与 commit 都明确列路径。工作包之间交付正常入口、输入输出、失败语义和复验步骤。
6. 逐条执行 benchmarks/catalog.md，提供真实 CLI、必要浏览器和免费真实 LLM 证据。测试完成、验收完成、切换部署分别记录。
7. 准备和验证通过后按 S008 直接切换。真实课程数据升级须先在副本证明保留性，并先生成可恢复备份。修错通过直接修正，成功批次撤销已退役。

## 依赖与整包完成

同步首包全部资产一同验收，含外部 Tutor 文件读写、课程学习文件、纯文件往返、Git 及定时执行。后续包不能成为首包的任意前置。首包需要的最小内容写入协调与无审批执行由首包局部落实，后续内容包扩展公共修改能力，审批包清除剩余产品入口。

内容包是知识点提炼与分类查询的基础。审批包优先于消息和练习包的最终浏览器验收，防止旧审批暂停干扰结果。后续教学包依赖内容和学习证据，但接线前须重新核对教学分支是否合入及接口。

## 文档迭代规则

- 调整行为先登记决策编号、受影响场景及替代关系，再更新 delta、design、tasks、工作包卡、benchmark 与追踪表。
- 不复制当前字段定义到多个权威文件。矩阵标明责任源和拟议变化，正式字段最终写 DATA_MODEL，工件写 FILE_CONTRACT。
- 任何新课程资产类型须同时登记交换矩阵、读写方、引用、删除、冲突、旧版本兼容及往返夹具。缺一项就不能声称“全部同步”。
- 每个新写入入口须进入 ACTION-GRAPH、surface 和 Agent 可见契约检查。每个新增 fallback 必须按 AGENTS 提供例外证据。
- 保留原始回答及资料副本。新结论只替代适用条款，不批量改写过去用户原话。

## 证据与交接

每包交接记录 commit/source_root、实际命令、数据集、环境、结果、证据位置及剩余限制。统一使用 passed、failed、blocked、not_run，免费 API 不可用为 blocked。Agent 模拟学习者与真实用户反馈分开。

交付简报写可用改进、操作变化、未完成项和证据链接。实施者完成确定性检查后，由另一独立验收角色复核真实环境和完整测试。后续会话调度独立验收按其适用规则执行，本规划阶段未派发子 Agent。
