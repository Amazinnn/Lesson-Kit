## 对使用模式的理解

协议把对话作为教学入口，以明确目标和课程范围组织推进，以逐题原始作答和误解修正改变教学决策，以参考资料及少量持久记录支撑跨次接续。教学循环包含主线、当前位置、临时插问及返回位置。题库内容、真实学习证据、教学判断和当前计划承担不同职责。

因此，GitHub 文件媒介的验收需考察另一端 Tutor 能否取得完整、可解释且可回写的学习资料。仅检查题目 JSON 出现在仓库，不能证明可接续同一学习目标。Q106 已确认课程旁 Markdown 及全部课程学习资产进入同一次完整交付。

## 应增加的实际体验 benchmark

| 编号 | 起点与操作 | 可观察成功条件 | 状态 |
|---|---|---|---|
| LP-01 | A 有目标、指定范围、原题/新模型和原始作答，导出文件到全新 B | B 正确识别课程及模型关联，内容/历史/草稿完整，Q102 偏好可用 | 核心数据范围已确认 |
| LP-02 | 外部 Tutor 只获得声明可携带文件，解释上次目标、已完成内容和下一步 | 没有依赖 A 的绝对路径；无必要信息时准确报告缺口，不能声称有完整原生会话 | Q105/Q106 已确认，执行 SYNC-07 |
| LP-03 | 诊断中包含猜对、未答、看解析后改答、稳定独立答对 | 原始选择、附注、揭晓事实各自正确；只看过讲解不能产生已掌握结论 | 后续教学包 |
| LP-04 | 学习中插问，处理后保存退出，再接续 | 返回课程正确位置，目标和待补项可找回；预算依据真实时间 | Q106 已确认，需实施正常文件路径 |
| LP-05 | 范围有核心/应用/拓展内容，已掌握和薄弱混合，预算受限 | 主线推进；低相关题比例与同类新题独立应用按 Q077 测量 | 后续教学包 |
| LP-06 | 分页选择、揭晓，再发送作答给 Tutor | 原始作答未被答案覆盖，Tutor 收到逐题结果而非只有总分；翻页不丢输入 | 实际宿主和接口待核查 |

每项最终记录数据规模、版本、真实操作、耗时/步骤、正确性标注、失败及返工，按 benchmarks.md 模板补齐。当前未测性能与长期收益，不填写虚构通过率。学习策略效果与文件交换完整性分开验收。
