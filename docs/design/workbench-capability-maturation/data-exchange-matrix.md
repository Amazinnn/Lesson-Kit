# 完整课程交换矩阵与边界

## 课程资产闭合规则

Q106 要求完整交付。实现时从注册工作区、实际 SQLite schema、课程内容目录及浏览器持久偏好列出逐项清单。每张表、每类文件均须记录归属、writer、consumer、文件投影、引用、删除、合并及往返证据。新增未知内容不静默遗漏，先报告尚不支持而使完整交换验收失败。显式选择子范围是另一个操作，不能将子范围成功标为全课程成功。

全课程包括已纳入课程管理的原始资料。未受管理的个人目录由用户在课程配置中明确纳入。机器凭据、可执行环境及 Provider 原生会话按既有边界独立处理；课程可读续接记录、学习偏好和参考文件均纳入。接收端不要求原机器绝对路径。

## 资产与状态矩阵

| 类别 | 现有承载/候选 | 导出与接收 | 修改/删除/冲突 |
|---|---|---|---|
| 知识点 | knowledge_points，含正文/分类/公式/图片 | 全字段按 DATA_MODEL 生命周期投影，旧兼容字段有显式处置 | 新建/修改/删除/恢复；删除先给定迁移或解除关联输入 |
| 正式关系 | knowledge_relations | 保存方向、类型、强度及双端身份 | 端点缺失为依赖阻断；不扩展 related_kp_ids 为新关系模型 |
| 正式题与小问 | problems、parts、micro_quiz、答案/来源等 | 原始题面、答案结构、来源、模式及引用完整 | 内容三方比较；删除移除当前卷引用，其他草稿保留 |
| 闪卡 | flash_cards | 正反面、方向、知识点和来源信息 | 引用完整，学习状态按方向标识合并 |
| 难度与显示元数据 | difficulty 字段组、display_metadata | 由各自现有契约投影 | 明确哪些由内容修改失效，不填默认难度 |
| 图片与附件 | .lessonkit/figures 及已管理附件 | 原始字节、逻辑路径、引用和所有者清单 | 路径校验、缺失报告，引用未解决的组保持原状 |
| 试卷 | practice_sets/paper 清单及导出文件 | 原 Paper 身份、顺序、说明、题目依赖 | 新增/修改/删除，保留未受影响题的执行与草稿 |
| 活动执行 | active_practice、active_practice_items、paper_progress | 执行身份、每题位置、草稿、揭晓事实与检查点 | 不同题修改合并；同题冲突选侧；迟到写入不能复活已清除执行 |
| 完成执行 | practice_runs 及其归档 | 历史完整，题目版本/当时原文快照可解释 | 独立新增并集，重复传输不增记录 |
| 原始作答 | problem_attempts、part_attempt_context | 原答案/小问/执行/内容版本和来源身份 | Q099 并集，已记录事实不因模型总结改写 |
| 反馈与修订 | feedback_events、part_grading_revisions | 原始评价、批改作者及修订语义 | 同事实双侧修改为冲突，主观批改不暗中产生学习者评分 |
| 学习信号/进度/排期 | learner_signals、learning_current_state、problem_progress、review_schedule | 每字段登记权威事实或派生投影 | 复用正式 writer，禁止把双侧派生数值直接相加或按本机时间覆盖 |
| 经验总结 | kp_experiences、kp_experience_problems | 正文、revision、题目关联 | 三方差异，保留原知识点身份，不与独立知识点混用 |
| 课程目标 | .lessonkit/goals.json | 可读目标与范围完整 | 文件损坏报告错误，不能被读错返回空列表解释为删除 |
| 学习偏好 | wb_settings_*，执行 reveal_timing 等 | 显式保存课程级副本，由正常入口发布/消费 | 冲突选侧，运行中执行级已冻结语义遵循当前契约 |
| 课程学习文件 | 目标、资料索引、参考、理解、误解、续接 Markdown/JSON | 任意已登记课程文件原文保真，首包全部支持 | 文件 CRUD，直接缺文件只报告，明确删除记录才传播 |
| 原始教材/讲义/试卷 | 纳入管理的 PDF 等 | 全字节及引用，记录体积、缺失和媒介拒绝 | 媒介不接受时报告未发布；不伪称完整同步 |
| 请求操作身份 | attempt_operations、practice_request_operations 等 | 保留必要来源身份及幂等映射 | 不把已完成操作重新派发；操作日志不是新学习事件 |
| 批改/Provider 运行作业 | part_grading_jobs、jobs 会话目录 | 仅导出课程可读成果和必要状态引用 | 不在新机器自动重放运行任务；原生会话迁移仍按 Q014 |
| 镜像和序列状态 | content_mirror_state/log、content_sequences、ingest_batches | 保存可解释版本映射和必要 provenance | 本机执行日志与跨端权威分开；目标生成器避免 ID 冲突 |
| 派生缓存 | plan.json、临时索引、锁和 PID 等 | 输入齐备后按正式规则重算 | 不把过期缓存导入成新的权威学习事实 |

表名以实施时 schema 实际清点为准。当前列举不足以替代真实清单，动态 ensure 表、旧库字段及课程旁文件都要进入闭合检查。历史读写兼容必须使用真实旧格式副本，不只新建数据库。

## 文件契约拟议结构

根 manifest 使用 `format_version`、`course`、`origin`、`export_id`、`assets[]` 和 `base`。assets 每项含稳定身份、类型、逻辑路径、可读 revision、依赖、明确删除标记及必要源版本。课程来源身份与本机自增行号分开，交换包的来源身份只分配一次，不采用哈希。正文和附件不被重新格式化。文件类型的 payload 由 FILE_CONTRACT 分节定义，schema 版本未知时明确拒绝受影响项。

受管理课程学习文件采用课程内相对路径，支持 UTF-8 Markdown、JSON 及二进制附件。无需每添加一种总结主题就发明新数据表。续接记录最小字段为目标引用、范围、主线位置、返回位置、完成/未完成引用及依据记录引用；时间记录必须说明起止/暂停，跨设备接续不把离线间隔算作学习时长。

## 比较与接收顺序

以共同基线分别比较本地与媒介的实际规范化内容。只读一侧改变时自动接受，不仅比较 revision。两侧相同改动直接协调版本。两侧独立作答合并，执行草稿按题判断冲突。两侧真实分歧、删除遇上修改需要结果选侧。只缺文件不形成删除。

校验 manifest、课程来源、路径及必要依赖后规划独立修改单元。每单元内引用完整并在事务提交，文件先暂存、发布结果须能在中断后按原操作身份续办。清单记录已完成单元，重试不重复写入，失败后直接修复剩余内容。单元间不使用全包撤销操作。

知识点章节迁移后保持实体稳定身份，章节归属须成为可独立读取的属性；旧带章号 ID 继续可解析。历史与外部引用不批量改号，旧消费者依赖 ID 推章号时必须同步修改。具体新增列沿 ensure_* 增量迁移，并在 DATA_MODEL 明确 writer/consumer。

## Git 与系统定时

Git 适配器先记录工作区与远端状态，拉取到可比较 checkout，再执行同一文件协调，提交仅受管理文件，推送后回读远端提交确认。没有变更不制造提交。真实 Git 分叉或推送竞态保留明确结果，不 force push、自动重写其他提交或代用户选内容侧。具体分支与 repo 来自显式课程配置。

每小时系统任务只调用同一 CLI 的已配置课程枚举入口。逐课程独立执行，某门受阻不阻断其他独立课程。手动/定时同一课程写入要串行；实现优先用现有同步/锁能力，需新增时以最小标准库实现。每课程保存最近一次完整回执，调度汇总仅指向该轮各课程结果。正常成功无系统通知，待选侧冲突按冲突身份只发一次短通知，重复小时触发不刷屏。

凭据读取沿现有 Git 环境，输出不含密钥。不在规划阶段创建真实任务或推送用户仓库。正式安装、更新、停用、删除任务均有 CLI 正常入口及验收。
