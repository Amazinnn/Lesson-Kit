# 文本糖（block markers）

**一句话：让"理解材料"的那个环节把它理解到的结构写下来，后面所有脚本环节就不必猜。**

源材料（试卷 md、PDF 抽文）没有稳定的题目边界：md 把整卷塞进 HTML 表格、标签打断句子、
选项有四五种写法、答案只在别处的答卷导出里。于是每个下游脚本都得猜——本次的代价是
字母数字骨架定位漏掉约 10% 的行、选项正则有五六种变体、纯公式碎片永远判不了。
这些都是**同一个病**：前面没吐糖，后面只能猜。

糖是**廉价的中间表示（IR）**，不是排版。规范如下，由"全局理解"环节（见 SKILL.md 阶段表 ①a）先定义，
由"写"的那一步产出；下游脚本**缺糖就报错，绝不猜**。

## 格式

```markdown
<!-- Q id=c02-ch07-prob-020 chapter=ch07 mode=single_choice fp=9f3ab21c -->
来源: 题库/期末/…Jun 22, 2022.md#L1472
来源题号: R2-19
考点: 主定理 (Master Theorem)
标题: 不可用主定理求解的递推式
题干: For each of the following recurrences, choose the one that we cannot apply Master Theorems to solve it.
续: （多行题干从这里续，一行一条）
选项:
A. $T(n) = 4T(n/2) + n/\lg n$
B. $T(n) = 4T(n/2) + n^2\lg n$
C. $T(n) = 3T(n/4) + n\lg n$
D. $T(n) = 3T(n/n) + n/\lg n$
答案证据: 题库原料/期末/…html#L11353 | R2-19 | checked=C + 评测「答案正确（3 分）」
<!-- /Q -->
```

## 每个字段为什么在

| 字段 | 谁用 | 省掉了什么 |
| --- | --- | --- |
| `id` / `chapter` / `mode`（开注释里） | 台账、批次、拉取 | 从文件名/位置反推章与题型 |
| `fp=`（内容指纹） | 幂等台账、全局去重 | 每次重跑都重新比对全文；跨章重复漏检 |
| `来源: <file>#L<n>` | 证据复验、人工抽查、锚点定位 | 骨架搜索（本次 10% 定位不到） |
| `来源题号` | 与答卷导出配对（`R2-19`） | 靠题干文本去匹配答卷，偶尔错配 |
| `题干:` / `续:` | 题面装配 | 从混排文本里猜哪段是题干 |
| `选项:` + 每行 `A. ` | 选项提取、题型判定（2–6 个→选择题） | `(A)`/`A.`/`• A.`/`A．` 的正则动物园 |
| `答案证据:` 三段（文件#行 \| 卷面题号 \| 信号） | 答案键推导与复验 | 键的出处丢失，无法审计 |
| `考点` / `标题` | 知识点绑定与显示 | 每行现编标题、绑定漂移 |
| `<!-- /Q -->` | 块切分 | 题目被切碎、碎片归属靠猜 |

## 两态：原文照抄 vs agent 的判断

材料烂到要"写第一版"时（见 SKILL.md ① 的第三档），糖必须把**两种字形分得开**：

| 形 | 含义 | 例 |
| --- | --- | --- |
| 直接写 | **原文照抄**，逐字不动（可选错字、可不通顺） | `选项: A. 直体~ B. 立即表~ C. 等图存器~ D. PC 相对~` |
| `?` 前缀或 `〔判〕` | **agent 的判断**，下游一律当作"待证" | `考点: ?寄存器间接寻址`、`标题: 〔判〕DMC 的缺点` |

硬约束三条：

1. **不许补、不许猜、不许润色**。原文缺的那个数就是答案（`变为原来的 倍`），
   顺手补成 `2 倍` 等于制造假内容，而且从结果里看不出来。
2. **不懂就留原样 + 标问**（`两个家长的得点数`／`算术有格`／`odd x30,x10,x30`）：留着，标记存疑，
   交给判定那一步或代填需求单，不要在写第一版时就"修好"——修好就再也追不回原文了。
3. **代填的题必须写明它不是原题**（来源写课本题，evidence 里记"替代了哪条回忆题"）：
   池子里出现"假真题"比缺题糟得多。

## 纪律

1. **缺糖就报错**：下游脚本遇到没有标记的块要停下并报错，不允许"尽力猜"。猜出来的东西会在
   下一次运行时给出不同答案（本次实测：同一条"碎片内容在不在目标里"，两个脚本给出了相反结论）。
2. **糖要可校验**：`scripts/sugar.py check` 会检查每个块是否闭合、题干/来源是否存在、
   选项数是否与 `mode` 相容、`fp` 是否写了。跑一遍只要几毫秒。
3. **重写文本时要保住糖**：任何重排/清理若覆盖了标记，必须重新生成同值的 `fp`（指纹取自内容，
   内容没变指纹就不该变；变了说明内容真变了，那正是你想知道的事）。
4. **糖由 ①a 定义**：不同课程的材料写法不同（有的用 `1-1` 题号、有的用 `R2-19`），
   标记里的"来源题号怎么取"属于**切分规则**，由那个超长上下文环节一次性定下来，写进课程画像。

## 工具

```bash
python scripts/sugar.py emit  questions.json  --out bank.md   # JSON → 带标记的 md
python scripts/sugar.py check bank.md                         # 校验（非零退出=有问题）
python scripts/sugar.py parse bank.md --out questions.json    # 带标记的 md → JSON
```

`考点:` 是中间表示里的可选描述，只帮助人工/Agent 绑定知识点；它不是持久化的 `topic_label`，也不能形成知识点与题目之间的新分组层。

`emit` 会为没有指纹的题现算 `fp`；`parse` 把 `续:` 接回题干、把折行的选项接回上一项。
本次用它把池里两题（判断题 + 单选题）emit→check→parse 走过一遍，题干/选项/来源/指纹四项全等。
