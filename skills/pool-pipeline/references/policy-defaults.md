# 默认策略（policy defaults）

除非课程工作区有自己的 `policy-override.md`，一律按这里执行。**这些规则是写死的，不要每次重新推敲。**

## 1. 题型判定

- 源里是**判断题**（T/F 标记、`checked` 态、陈述句判断题来源）→ `yes_no`
- 源里能取到 **2–6 个明确选项** → `single_choice`；选项明确为"多选/不定项/Select all"→ `multiple_choice`
- 程序填空 / 证明 / 建模 / 长情境且无选项 → `exam`（不给 quiz 载荷）
- **题干多长都不影响以上判定。**长度不是题型属性；长客观题照样进判断/小测。
- 选项取不回来的"选择题"→ **退回 `exam`**，并在报表里单列（不发没有选项的选择题）。
- 判断题**不给** `options`（前端自动补 是/否）。

## 2. 选项

- 逐字从源里取，**保留原标号顺序**（A→D 或 a→d），不改写文字、不改数值、公式原样。
- 题干里内联的选项要**搬出去**（题干只留提问部分）。
- 选项里若粘着下一个选项的标号（`...text\n\nB.`），剥掉标号留正文。

## 3. 答案键（只在源里能证明时给）

- **判断题**：源里 `checked` 单选态 + 判分"正确"→ 该选项即答案（写 `是`/`否`）；判分"错误"→ **取相反项**。
- **单选/多选**：只有判分"正确"时才能定；**写选中项的逐字文本**（多选为子集数组），
  **不要按字母**——同一题在不同卷里选项顺序会变。
- 跨源互证有效：同一句话在另一份答卷里判分正确，可定键。
- 推不出 → `answer_key = null`（契约允许"无答案键客观题"，练习时显示"未录入答案键"）。
- 答案键的**出处**写进行的 `source_answer`（源文件 + 卷面题号 + 用了哪个信号）。

## 4. 去重口径

- 归一化：剥掉 `![](…)` 图片、`` `…` `` 行内代码、`$…$` 公式、HTML 标签，再只留字母数字、转小写。
- **逐字节相同**（归一化后）→ 必删；保留信息最全的那行（有载荷 > 有答案键 > 有标题 > id 小）。
- **相似但不完全相同 → 保留**（"相似题"不是重复题）。
- 去重必须在**全局**做一次（跨章、跨批）；只在章内去重会漏掉跨章同题。
- 碎片合并：碎片内容**必须证在目标行的题干或选项里**（30 字符归一化探针足够），才允许删除碎片；
  证不出来 → 降级为"保留 + 登记"，**不报人**。
  两类证不出来是正常的，走升级：碎片是**纯公式**（归一化后为空）、碎片其实是目标的**某个选项**。

## 5. 标题与归属

- `display_title` ≤ 40 字，中文，说清"这题在问什么"（如「AVL 删除后判断结点关系」）。
- 不要写「（超 800 字留综合题）」这类**处理过程**的说明进标题。
- 不要创建题目分组摘要层；题目通过 `kp_ids` 直接归属一个或多个知识点。

## 6. 知识点

- 判断题 / 小测：`kp_ids` **恰好 1 个**；综合题可多个。
- 绑定的判据是**内容属于哪一章/哪个知识点**，不是题号前缀。跨章绑定允许且常见（题号不可改）。
- 绑不上 → 选最接近的一个，并在 notes 说明；不要硬塞。

## 7. 图片

- 题干引用必须能在工作区解析（`c02/<章>/<sha256>.<ext>`）；解析不了 → 登记为缺图，**不臆造**。
- 与题目无关的**错配图**：从题干移除（改字段前先确认那图确实属于别的题）。
- **无信息垃圾图**判据（可删）：整张纯黑/空白、只有空圈圈与连线没有标签、手写答案字母截图、
  趣味漫画/照片、只截到 UI 边框。删文件前先确认**没有别的行引用它**。
- 承载解题信息的图（树/堆/图/表/伪代码/博弈树）即使当前没被引用也**保留**。

## 8. 不可逆动作（删除）的硬证据类

只有这两类允许自动删除：
1. 归一化后**逐字节重复**（保留最全的一行）；
2. **内容已证在目标行里**（碎片合并）。

其余一律不删。删除必须：删前快照、按章独立、逐条核验"该行无学习记录"、写删除台账。

## 9. 降级为保留（不报人）

- 判不了归属的碎片、来源标注与内容不符、同一题在两份源里结论冲突且无法裁决 → 保留 + 报表计数。
- 目标是：**人工清单尽量短且每条都值一看**，不是"零清单"。

## 10. 缺陷结论的复验通则（2026-10-04 实测追加）

**判「缺失 / 多余 / 错位」这一类结论前，至少用两种独立口径复验。** 本轮实测中，
三条被机械规则判成"真数据缺陷"的东西**全部是假阳性**，而且**照着修会把正确的数据改坏**：

| 假结论 | 若照做 | 根因 |
| --- | --- | --- |
| 「4 条多选题缺第 5 选项」 | **删掉正确题目的选项** | 取数用了硬编码 `[A-D]` 正则，`E.` 数不到 |
| 「option 文本缺席 9 条」 | 同上 | 判"在不在题面"时**没先归一化** |
| 「stem-only 误判 → 移除内联块」 | 同上 | 行首字母正则把 `- **方案 A**：` 这种排版误判掉了 |

三条硬要求：

1. **不要写死字母上限。** 凡是用正则数「题面内联选项行数」的扫描器，
   必须用 `[A-J]` 或按 `len(options)` **动态生成字符类**，不得用 `[A-D]`。
2. **数行数与核文本必须同时做，且核文本要先声明归一化口径**（去 `**`、中英文引号、空白）。
   只比数量会漏掉"数量对但内容错位"；只做子串核验则会被归一化左右——
   同一批数据、同一段代码，仅归一化口径不同即可得 9 vs 0。
3. **结论依赖行数/文本匹配时，必须跨历史快照回捞。** 只看当前库无法区分
   「数据从未正确」与「扫描口径数不到」；要靠快照 + 生成器源码 + `updated_at` 三方交叉才钉得住。

**配套纪律**：

- 脚本打出的标签是**「可疑」不是「结论」**。从可疑到结论之间必须隔一次人工或第二种口径。
  本轮实测：一条被判「genuinely missing」的行，人工看下来是「选项被改写 + 多了一句非选项说明」，
  **仍然不是"删选项"的场景**。
- **报告里的"已干跑通过"，若其干跑依赖 `cd` 或未加 `--apply`，一律视为未验证**——
  不带 `--apply` 的 `ingest recipe` 根本不跑校验，`rc=0` 是空信号（详见 `traps-2026-10.md` §1）。
- **不要把任何一次扫描的具体条数当常数。** 同一个硬编码口径在池长大后会命中更多行
  （本轮原报告报 4 条，同口径在当天的池上翻盘 27 条，其中 26 条逐字确认无误）。

详细证据与可复跑片段见 `references/traps-2026-10.md` §2。
