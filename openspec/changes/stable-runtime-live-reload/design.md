## Context
The installed entry imports its editable checkout. service.repo_root follows __file__, daemon state has no source identity, and the HTTP process has no reload mechanism.
## Goals / Non-Goals
Immediate main-checkout use with safe source/asset reload; no implicit worktree switching, schema migration, data rewrite or interruption of Agent work.
## Decisions
Resolve default source using Git common directory from the installed package (primary checkout), fallback to package root when not in a source checkout. Explicit --project-root overrides only runtime commands. Spawn using target cwd AND PYTHONPATH to avoid displaying one source while importing another.
Use stdlib metadata snapshots of workbench/**/*.py, workbench/server/static and frontend/editable-graph/dist. Snapshot additions/deletions detect rollback too; ignore __pycache__. Debounce before validation/restart. Frontend sources need existing npm build/watch; backend does not invoke npm.
A stable supervisor owns the daemon PID; a worker owns the HTTP listener. Metadata exposes both source and actual worker identity plus generation/pending/error. Legacy daemon identity is unverified, never fabricated. Scope reload signalling to owned processes. Stop must terminate owned worker and supervisor safely on Windows.
Bridge admission and HTTP in-flight mutation coordination must be integrated before restart: hold the existing Bridge lock during idle decision/admission closure, respect queued/approval/action work, prevent new mutating requests, drain existing handlers, then shut down the worker. Do not use a polling zero-active observation alone. Broken-source validation keeps last usable worker with visible error and only retries for a changed snapshot.
Browser polls read-only runtime metadata. A source/asset generation change triggers draft-safe refresh; stash all unsubmitted fields under per-page session storage and restore only matching surfaces. Never emit submit/send on restore. An update pending/error notice is visible. Route ownership and CLI/API docs are reconciled.
## Risks / Trade-offs
Primary checkout discovery requires a non-bare Git source installation; installed wheels fall back to package root. No new watcher dependency or hashes. No native frontend bundling inference. Long-running Agent work deliberately delays reload.
## Implementation plan
1. TDD source selection, validation and metadata snapshot primitives.
2. Wire runtime commands, target imports, supervisor identity/status and legacy diagnostics.
3. TDD safe Bridge/request quiescence, reload and rollback; invalid-source preservation.
4. Browser generation polling, notices and draft-safe refresh, built assets watch command.
5. Focused subprocess/browser tests, docs reconciliation, independent full-suite and isolated acceptance.

## Concrete handoff interfaces
- Source primitives: workbench.cli.runtime_source.project_root(explicit=None, installed=None) returns resolved Path; snapshot(root) returns relative-path -> (mtime_ns,size); changed_kind(previous,current) returns None/python/assets; syntax_error(root) returns string or None, never imports or writes bytecode.
- CLI flags on serve, dashboard and daemon start: --project-root PATH and --no-reload. Default reload enabled. Non-runtime commands retain existing cwd behavior. CLI child imports must set PYTHONPATH to chosen source ahead of inherited entries, use target cwd, and hidden process flags. Internal worker launch uses environment LESSONKIT_RUNTIME_WORKER=1 to prevent recursion. Supervisor imports a fixed already-loaded orchestration module and keeps its PID stable across worker replacement.
- Public GET /api/runtime returns source_root, supervisor_pid, worker_pid, port, reload_enabled, generation, assets_generation, pending, error. generation/asset generations are readable monotonically increasing integers, not hashes. pending values are null, python, assets, or busy; error is null or concise diagnostic. Route is owned by the human runtime surface. Daemon JSON stores matching provenance and observed worker PID; clients verify live endpoint supervisor identity against recorded process, never assign trusted root to legacy records lacking evidence.
- Internal POST /api/runtime/prepare-reload is same-origin controlled and scoped to the owned supervisor/worker instance. It returns ready false while Bridge active/queued/approval/action work exists. A ready true response means admissions remain closed until worker exit; no application mutation can slip between check and shutdown. Busy checks belong in Bridge and use its existing lock; no Shell inspection of SQLite.
- Lock ordering: request-admission condition first closes mutation admission and waits for preexisting mutation handlers to drain WITHOUT holding the Bridge lock. Then acquire conversations._LOCK, inspect active turn plus queued/follow-up/approval/action ownership. If busy, reopen HTTP admission, return false, retain pending notice. If idle, close Bridge admission under the same lock so background queue admission cannot race. Return true only then. New mutation requests during the closed interval receive an explicit retryable update-pending response, never ambiguous partial success. Control/metadata requests bypass this admission gate. Existing GET handlers must finish before process shutdown too; ThreadingHTTPServer.server_close joins handler threads. New ordinary reads are also refused once final drain begins.
- Supervisor is sole owner of worker Popen; before prepare it validates settled Python source using syntax_error and an isolated import-preflight child using the target import path. A failed preflight leaves old worker alive, records error, and retries only on a new source snapshot. Once worker prepared, request graceful shutdown, wait for exit, then spawn next worker; no independent process may steal the port. On supervisor termination, owned worker cleanup must be explicit on Windows (a supervisor PID is not the listener PID). Reuse/stop acts only on verified owned identity. Legacy live service with unprovable ownership gets a diagnostic rather than a forced stop.
- Watch cadence 0.5s; accept a changed snapshot only after two identical observations (debounce >=0.5s). Asset-only changes increment assets_generation after safe/busy check, without replacing Python worker. Python/rollback changes increment generation only after new worker health succeeds. Missing/reappearing files count as changes; caches/jobs/pools/test outputs are excluded by primitive scope.
- Browser polls /api/runtime every 1s; old process generation remembered in memory, not persisted across manual navigation. For a generation change, snapshot non-password input/textarea/select values and selection keyed by stable id or existing data-turn-id+name/index into per-page sessionStorage, then refresh; restore only matching current surfaces, never disabled/read-only submitted answers, and never send/submit. Dynamic pending-message editors wait until their matching turn exists, rather than creating a new message. Existing draft persistence events may be used for editable draft restoration but must not create learning evidence. If an in-flight send/save is unresolved, defer refresh and show update pending until its identity is confirmed. Unpersisted inputs without stable restoration identity cause visible refresh deferral rather than loss.
- Existing frontend Vite build gets a documented watch:editor script using build:editor --watch; only served generated output triggers browser generation. No npm invocation from server and no claim raw frontend source hot-builds itself.
