## Why

图谱节点「丑」不是配色问题，是**缩放补偿缺失**、**视觉语言缺位**、**装饰层过载**三件事叠在一起。

**实证（离线复算 `pool/dmath.db` 的 dmath/ch06：31 节点 / 35 关系）**

- 舞台级 `scale()`（`workbench/server/static/workbench.js:1106`）把节点直径、字号、点径
  **全部按世界像素一起缩小**，零屏幕补偿。Fit 后 scale = 0.17–0.49 ⇒
  **圆直径仅 3–30px、标签 2.0–5.9px、可见标签 0–1 / 31**
  （`workbench.js:1290-1294` 的缩放阈值 + `:1222-1225` 的 Fit 口径）。
  节点成了「看不清的斑点」。
- **学习状态在图上实质不可辨**：唯一承载它的 `.node-wrap.in-scope .status-ring`
  （`workbench.css:1708`）是**死规则**——`graphSyncScope()`（`workbench.js:1077`）是空函数，
  全仓无 `classList.add("in-scope")`。真正在线的只有 7px 世界像素的 `.node-satellite`
  （`workbench.css:1693-1697`，缩放后约 1–2px），而 **28/31 个节点同为 `state-new`**（同一个灰）。
- 同一个视觉通道还塞了两个维度：`.metric-track` 的**弧长**编码当前投影指标，
  **弧色**却编码知识点重要度（`workbench.css:1651-1652` 的 `--kind-color`）——
  看图的人无法把颜色和数字对上。
- 与此同时，整块画布每帧重绘约 **600 个 alpha 混合色斑**
  （`workbench.js:1482-1488` / `:1538-1626`），**与图谱数据完全无关**，
  视觉重量压过数据本身。

**所有者的裁决原话（A-24）**

> 「**图谱的按钮感觉太……塑料**。可以看看 Obsidian 的实现。
> 干脆模仿它的显示方式吧，**字段与节点不重合（字段在点下方）**，而且**节点相对字段更细**。
> 我们对于颜色的设计仍然可以保留。」

**「塑料感」的出处已被定位**（A-24 的关键发现）：既不在配色，也不在形状，而在
**投影层**——阴影、描边、内高光、状态环、卫星点这一整套装饰。
参照实现里同样的病写在
`frontend/editable-graph/src/styles.css:295-300`：

```css
.node .core {
  fill: #5f625f;
  stroke: #464947;            /* 1.4px 描边 */
  stroke-width: 1.4;
  filter: drop-shadow(0 5px 10px rgba(25, 28, 31, 0.16));  /* 投影 */
}
```

本仓库的对应物是 `workbench.css:1676-1684` 的 `.node-face`
（`box-shadow: 0 2px 6px …` + `inset 0 0 0 1px rgba(255,255,255,.82)` 内高光 + 1px 描边）
与 `.node-face::before` 的径向高光。

**结论**：图谱今天既没有「可读」也没有「好看」。**先让它可读（屏幕空间缩放补偿），
再按 Obsidian 式重画节点（小实心圆点 · 标签在点下方 · 细线带箭头）**，
**并且一根手指都不许碰布局算法**（A-26）。

## What Changes

> **两条裁决的关系**：A-24 决定**画成什么样**；A-26 决定**哪些东西不许动**。
> A-24 的每一条都落在 A-26 的「允许改（纯绘制）」清单里；
> 凡是需要动到物理的地方，一律走「物理半径不动 + 绘制尺寸解耦」的路子。

### 一、节点形态：小实心圆点（A-24.1）

| 项 | 裁决 | 本变更的落点 |
|---|---|---|
| **A-28** | 节点 = **单层实心圆**，半径 **5–13 屏幕 px** | 节点 DOM 从「五层叠一个圆」（面 / 数字 / 度量弧 / 状态环 / 卫星点）改为**一枚单层实心圆点**；绘制半径 = 屏幕 px，**不随画布缩放变小**（G-24 / A-28.2 的屏幕空间补偿） |
| **A-28** | **无 drop-shadow、无描边**（常态） | 删 `.node-face` 的 `box-shadow` / `inset` 内高光 / 1px 描边 / `.node-face::before` 的径向高光；点**单层实心平涂**，不带任何投影与描边 —— 这是「塑料感」的来源（Obsidian 官方源码里节点只有一次 `beginFill` + `drawCircle`） |
| **A-28** | halo 只作命中区，不绘制 | 参照 Obsidian 移动端的透明命中圆（`r=500, alpha=0.0001`）与本地 `frontend/editable-graph/src/styles.css:288-293` 的 `.node .halo` —— 命中区可以大于可见点（**下限 24 屏幕 px**），但**不得有任何可见痕迹** |

### 二、标签：在点下方 5px（A-28 取代 A-24.2 的 18px）

| 项 | 裁决 | 本变更的落点 |
|---|---|---|
| **A-28** | 标签在**点下方 5px**（圆底到字顶），**与点不重合** | 照 Obsidian 官方源码：「文字顶部 = 节点中心 + `(size+5)·nodeScale`」⇒ 圆底到字顶 5px（`OBSIDIAN-GRAPH.md` §2.1）。〔作废〕本地参照实现的 `r + 18` |
| **A-28** | 标签按**屏幕像素**定尺（12px 恒定），不随画布缩放变小 | 标签字号 12 屏幕 px（A-15 / A-28 不变），点与标签的间距 5 屏幕 px；二者都用 `calc(… * var(--inv-scale))` 承载 |
| **A-28** | 标签**按对数淡出**：缩放 < 0.5 时淡出，而不是继续缩小 | 照 Obsidian 的 `textAlpha = clamp(log2(s) + 1 − fade, 0, 1)`，本项目取 `clamp(log2(s) + 2, 0, 1)` ⇒ s ≥ 0.5 全亮、0.25 ≤ s < 0.5 对数淡出、s ≤ 0.25 消失。**与被删掉的「按缩放阈值硬隐藏」不是一回事** |
| **A-24.2** | 标签常态可见、**不截断**、重叠时**隐藏次要标签** | 保留 G-5 / G-23 / A-10.3：删掉「按缩放阈值隐藏」，改为屏幕空间去冲突 pass + 可见标签预算 |

### 三、关系线：细线带箭头（A-24.3）

| 项 | 裁决 | 本变更的落点 |
|---|---|---|
| **A-24.3 + A-28** | 关系线 **屏幕恒定 1.25px**（= `1.25 / scale`）/ 基础 alpha 0.3 | 照 Obsidian 官方（`g = fLineSizeMult / zoom` ⇒ 屏幕线宽恒定）。**画法**改：`edgeStyle()`（`graph-physics-core.js:1326-1329`）的 `width`/`baseOpacity` 从「随强度变化」（1.05–3.4 / .15–.58）改为**统一 1.25 屏幕 px / 0.3**。**拓扑、类型、权重一律不动**（A-26） |
| **A-24.3 + A-28** | **直线 + 方向箭头**，五种关系的箭头语义要钉死；两端扣掉节点半径 | 先修（prereq）与应用（apply）**有向**、箭头指向后继 / 被应用方；对比（contrast）、相关（related）、隐含（legacy）**对称或无方向语义，无箭头**。箭头落在**绘制点的边缘**、**屏幕尺寸恒定**（A-26 允许改「端点落点」与箭头画法） |
| **A-28** | **非邻接元素降到 alpha 0.2**（现状节点 0.14–0.18 / 边 0.07 太狠） | 照 Obsidian 的常量 `fQ = .2`。**哪些元素被强调不变**（冻结的交互语义），改的只是**淡出的强度** |
| **A-24.3** | 关系类型仍可读 | 五类关系的**色相**（`graph-renderer.js:15-21` 的 `EDGE_COLORS`）与**虚实节奏**（`:288-298` 的分段绘制）保留；焦点强调仍可覆盖线宽与透明度（照 `styles.css:265-268` 的 `.edge.focused`） |

### 四、圆心数字：按投影决定（A-24.4）

| 投影 | 圆心 | 说明 |
|---|---|---|
| **关系结构**（structure） | **无数字** | 结构由**边**表达；点只负责定位与连缀 |
| **学习状态**（state） | **无数字** | 状态由**颜色**表达 |
| **题目数量**（problem_count） | **有数字** = 该节点的**正式题数** | 数字**就是该投影的量** |
| **重要性**（importance） | **有数字** = `round(importance × 100)` | 单位（%）由图例承载（现状 `.node-unit{display:none}` 从未显示过 `%`） |

- **有数字的两个投影：半径下限提到 13 屏幕 px**，以容下 12px 的字（A-28）。
  〔口径〕在 **5–13** 的区间里「下限 = 13」等价于**半径恒为 13px** ⇒
  这两档投影里量值由**数字 + 色阶**承载，半径不再承载量值；
  既有 `Metric projection morphology` 的「值越大点越大」由本变更的 delta **显式改写**。
- **推翻 G-9**（旧读法「圆心恒为正式题数、所有投影相同」）。

### 五、状态文字清零（A-24.5）

**任何投影的节点上都不得出现状态文字**（「新」「掌握」「重点练习」等一律不许）。
保留 G-6 的机制：删 `.meta` 行（`workbench.js:1072-1073`）、删 `STATE_SHORT` 单字写入
（`workbench.js:578`、`:1060`）；状态名仍留在**学习看板、悬浮提示与无障碍名**里。

### 六、颜色设计保留（A-24.6）

**四投影的色键一字不改**：关系结构 = 墨阶三档；题目数量 / 重要性 = 橙阶（单色阶）；
学习状态 = 未学中性灰 / 复习琥珀 / 掌握橙 / 需突破砖红。
图谱仍是**数据可视化区**，不受全站「蓝/黄/红三角色」配额约束（G-7 / G-16）。

### 七、选中态：点放大 + 标签提亮（A-24.7）

**不再「外环加粗」**。常态点**无描边**；交互态改为（A-28）：
- **换色**（走更实 / 最实的一档）；
- **1 屏幕 px 的描边环**（点在圈外 1px 处，线宽屏幕恒定 —— 照 Obsidian 官方的高亮环，
  **不是**本地参照实现那种 8px 宽 22% 透明的 halo）；
- **点放大**（绘制半径 × 1.12 / 悬停 × 1.06）—— 只改**绘制**，物理半径不动（A-26）；
- **标签提亮**（字重 650 → 700）；
- **无阴影、无光晕、无卫星点**。

### 八、屏幕空间缩放补偿（保留 G-24 的有效部分 + A-28.2）

节点的**绘制半径、标签字号、点下间距、关系线宽**全部用**屏幕像素**表达，
`scale()` 只负责**位置** —— **「缩放只改间距，不改尺寸」**（A-28.2）。
这条与 A-28 的节点 / 标签 / 边三条是同一件事的三个面。

### 九、底噪保留（G-4）

保留观感，把「每帧 600 个 alpha 混合光斑」改为**静态预渲染 / 降频**。

### 十、算法冻结（A-26 —— 本变更的**硬边界**）

**冻结（一律不动）**

- 力导向物理：力模型、迭代次数、收敛判据、阻尼、引力 / 斥力参数、节点间碰撞与分离逻辑；
- 布局与种子：布局种子读写、auto-fit **之外**的相机与布局逻辑；
- 邻接与边集合、边的类型与权重、筛选语义、投影语义与分档、指标计算；
- DOM 节点的身份与顺序、拖拽与聚焦的行为语义。

**允许改（纯绘制层）**

- 节点的绘制形状与颜色、**绘制尺寸（与物理半径解耦，物理半径一律不动）**、
  标签的绘制与位置、边的绘制（线宽 / 透明度 / 箭头 / 端点落点）、缩放补偿。

**可执行判据**：改造前后用**同一份输入**（同一章节、同一初始条件、同一迭代预算）
各跑一次力导向，**收敛后的节点坐标集合必须逐项一致（diff = 0）**。
对比脚本与两次运行的证据落在 `tasks.md` 第 14 组，门禁落在 `acceptance.md` §0.2 **SI-0**。

## Capabilities

### New Capabilities

- **`graph-visual-language`**：知识图谱**节点视觉语言**的自足契约，覆盖五件事——
  ① 屏幕空间可读性（节点绘制半径 / 字号 / 线宽的屏幕像素语义，**缩放只改间距**）；
  ② **Obsidian 式节点形态**（**单层实心圆点**、半径 5–13 屏幕 px、无描边无投影无光晕、
  标签在点下方 5px、12px 恒定、缩放 < 0.5 时对数淡出）；
  ③ **圆心数字按投影决定**（结构 / 状态投影无数字；题量 / 重要性投影有数字，半径取 13px）；
  ④ 四个投影各自的色键与随投影切换的图例；
  ⑤ **布局算法冻结**（力模型、迭代、收敛、阻尼、引力斥力、碰撞、种子、边集合、
  筛选与投影语义、指标、DOM 身份与顺序、拖拽与聚焦语义一律不动；
  **改造前后收敛坐标 diff = 0**）。
  **立为新能力而不是塞进 `workbench-ui` 的理由**：既有 `workbench-ui` 的图谱需求
  （`Metric projection morphology` 等）只约束了「半径随指标变大」这一条，
  从未定义节点的**形态、配色、图例与标签**，更从未定义**算法冻结**这条边界；
  这些事情有独立的可观察契约（谁在什么投影下是什么颜色、什么被隐藏、什么字不许出现、
  坐标是否动过），放在一个能力里才有一个可验收的整体。

### Modified Capabilities

- **`workbench-ui`**：六条既有需求的**可观察行为**发生变化，逐条理由如下。
  （`openspec/specs/workbench-ui/spec.md` 的行号）
  1. `Knowledge graph page`（`:121`）——节点绘制尺寸与字号改为屏幕像素语义；
     现有条款「Viewport culling and label/meta LOD SHALL affect paint only」仍然成立，
     但**标签的可见性判据从「缩放阈值」改为「重叠让位」**（G-23），
     且节点不再有 `meta` 行；节点形态从「同心圆 + 圆心题数」改为
     **单层实心圆点 + 按投影决定的圆心数字**；标签在**缩放 < 0.5** 时按对数淡出。
  2. `Living graph motion and readable labels`（`:464`）——现有条款
     「label/meta LOD」与「Node labels SHALL always display their complete text」
     需要与 G-5 / G-6 对齐：标签常态可见、屏幕像素字号、不截断；
     **只在重叠让位或超出可见标签预算时隐藏**，不再按缩放阈值隐藏；
     **节点上不再出现状态文字**，完整标题继续由悬浮与键盘聚焦承载。
  3. `Metric projection morphology`（`:591`）——现有条款
     「A metric projection SHALL map higher values to both a larger node radius and a target
     nearer the canvas center」中的**半径区间**改为 **5–13 屏幕像素**（A-28），
     并**删掉「外环粗细」这一条通道**；
     〔口径〕在**题目数量 / 重要性**两个投影里半径取 **13px**（A-28：容下 12px 的圆心数字）
     ⇒ 这两档投影的量值由**数字 + 色阶**承载，「值越大点越大」一句在该 delta 里
     **显式改写**；
     「restrained, distinguishable Mondrian palette」改为**图谱自有暖色板**
     （G-7 / G-12 / G-16 / G-20…G-22）；
     同时明确**圆心数字按投影决定**、节点上不画进度弧或仪表。
  4. `Redundant state cues`（`:749`）——现有条款
     「graph learning states … SHALL retain text, outline, position, or another geometric cue」
     与 G-6「节点上不许有状态文字」需要协调：**冗余通道改为几何（半径序 + 径向序）+
     图例 + 学习看板 + 无障碍名**，颜色不再是唯一载体，节点上也不再有状态文字。
  5. `Soft Mondrian visual foundation`（`:731`）——现有条款要求
     「restrained blue, yellow, and red accents」「Blue SHALL represent primary action…
     yellow… red…」。图谱的暖色板（琥珀 / 橙 / 砖红 / 中性灰 + 墨阶）是对三角色配额的
     **一处显式、限域的例外**，需要在该能力里写明例外范围。
     ⚠️ **并行冲突登记**：`workbench-visual-language-v2` 的 `workbench-ui` delta
     **已经 MODIFIED 了这一条**（`specs/workbench-ui/spec.md:317`，含场景
     「The knowledge graph page is unchanged」，`:367-371`）。该场景在本变更落地后
     **不再成立**，两处 delta 必须协调（建议：先合入 `workbench-visual-language-v2`，
     本变更在其之上追加「图谱例外」段落并退役该场景）。
     📎 **「亮色逐像素不变」这条约束按 A-12 从图谱的约束里拿掉**：
     v2 的 `acceptance.md:22` 的 G-5 原文已写明
     「图谱**不在该变更的验收范围内**…零差异不是一条待达成的门禁，
     而是『该变更根本没碰它』的证明」⇒ 它是**那个变更**的否定式断言，
     **只对 v2 有效**；本变更**不得引用一条不存在的门禁**。
     「亮色逐像素不变」在本变更里本来就不可能成立（节点本来就要重画，
     A-24 整个换掉了形态，A-28 又把半径区间定案为 5–13 屏幕 px）。
     本变更**自带**一份验收基线（`acceptance.md`，新建），判据是**结构不变量**
     **加上算法冻结**：节点集合 / 关系边集合 / 布局收敛性与确定性 / 投影语义 /
     交互行为 / **改造前后收敛坐标 diff = 0** 必须不变；
     **节点 / 标签 / 图例 / 底噪这四个区域允许变化**。
  6. `Graph detail is a learning dashboard`（`:406`）——**行为不变**，
     但学习看板成为 G-6 之后**唯一**在页面上呈现学习状态名称的位置之一，
     且看板的题数与节点圆心数字**不再总是同一个数**（结构 / 状态投影的圆心没有数字），
     需在 delta 中点明，避免被误读为「数字被删了」。
