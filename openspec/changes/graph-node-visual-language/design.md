> **A-28.1 的两个前提纠正（必须随参数一起记住）**
> 1. **Obsidian 的节点是「单层实心圆」**（无描边、无阴影、无渐变 —— 源码里只有一次
>    `beginFill` + `drawCircle`，raw@2212400）。我们仓库里的 `frontend/editable-graph`
>    是 **halo + core 双层 + 1.4px 描边 + `drop-shadow`** ——
>    **它不是 faithful 的 Obsidian 克隆，那才是「塑料感」的真正来源。**
> 2. **Obsidian 的标签随 √zoom 缩放**，保可读靠**对数淡出**（zoom < 0.5 直接淡出，
>    raw@2231690），只有被 hover 的那个标签才做屏幕空间反缩放（raw@2214489）。
>    **本项目按 A-28.2 取「屏幕恒定」**（标签 12px 恒定 + 缩放只改间距），
>    即**比 Obsidian 更简单的一档**，不引入 √zoom 次线性缩放。

> **硬边界（贯穿全文）**
> 1. **不新增任何学习事实、不新增任何持久字段、不改 API 请求序列与载荷。**
> 2. **只改绘制层**（A-26 的「允许改」清单）：节点的绘制形状 / 颜色 / 绘制尺寸
>    （**与物理半径解耦**）、标签的绘制与位置、边的绘制（线宽 / 透明度 / 箭头 /
>    端点落点）、缩放补偿。
> 3. **算法冻结**（A-26，**A-28.4 明确不受影响**）：力模型 / 迭代 / 收敛判据 /
>    阻尼 / 引力斥力 / 碰撞分离 / 布局种子 / 邻接与边集合 / 边类型与权重 /
>    筛选语义 / 投影语义与分档 / 指标计算 / DOM 节点身份与顺序 /
>    拖拽与聚焦的行为语义 —— **一律不动**；
>    **改造前后同一输入的收敛坐标必须 diff = 0**（D-13）。
> 4. **无框架、无构建步骤、无 npm、无 CDN、无外部图标字体** —— 纯 CSS + 原生 JS。
> 5. **状态不得只靠颜色**（`openspec/specs/workbench-ui/spec.md:749-764`）。
> 6. **节点上不出现任何状态文字**（G-6 / A-24.5）—— 无障碍名与学习看板仍保留状态名。
> 7. **图谱以外的一切不动。**

## Context

只需要解释方案所必需的现状（动机见 `proposal.md` 的 Why）：

1. **相机是唯一的缩放来源，且它把排版单位一起缩小。**
   `.graph-stage` 上一个 `transform: translate(...) scale(s)`
   （`workbench/server/static/workbench.js:1106`）作用于**整棵子树**；
   而 `--size`（`workbench.js:1309`）、`.node-value` 的 `clamp(11px, size*.28, 18px)`
   （`workbench.css:1690`）、`.label` 的 `12px`（`workbench.css:1711`）、
   `.node-satellite` 的 `7px`（`workbench.css:1694`）**全是世界像素**。
   〔实证〕Fit 后 `s = 0.17–0.49` ⇒ 圆直径 3–30px、标签 2.0–5.9px、可见标签 0–1/31
   （`workbench.css` 与 `workbench.js:1222-1225` 的离线复算，见审计 §7.3）。
2. **节点是五层叠一个圆。** `.metric-track`（度量弧）+ `.status-ring`（状态环）+
   `.node-face`（面）+ `.node-value`（数字）+ `.node-satellite`（状态点）
   （`workbench.js:957-1053` 的 DOM 结构），加下方 `.label` 与 `.meta`。
   〔实证〕`.status-ring` 的唯一变色分支 `.node-wrap.in-scope .status-ring`
   （`workbench.css:1708`）**永不命中** —— `graphSyncScope()`（`workbench.js:1077`）
   是空函数；`.node-wrap.warning`（`workbench.css:1653`）也没有任何 JS 会加。
3. **同环两维度。** 弧长 = 当前投影指标（`workbench.js:1067` 写 `--metric-angle`），
   弧色 = 知识点重要度（`workbench.css:1651-1652` 的 `--kind-color`）。
4. **学习状态实质不可辨。** 唯一在线通道是 7px 世界像素的卫星点，
   而 28/31 个节点同为 `state-new`（同一个灰）。
5. **「塑料感」在装饰层。** 〔实证〕`.node-face`（`workbench.css:1676-1684`）带
   `box-shadow: 0 2px 6px rgba(55,48,37,.055)`、
   `inset 0 0 0 1px rgba(255,255,255,.82)` 内高光、1px 描边与
   `.node-face::before` 的径向高光；参照实现里同样的病是
   `frontend/editable-graph/src/styles.css:295-300` 的 `drop-shadow` + 1.4px 描边。
6. **图谱自有 token，且与全站零耦合。** 12 个**裸名**变量声明在 `:root`
   （`workbench.css:1505-1518`）；〔实证〕图谱区段 `:1497-1884` 对
   `var(--lk-*)` / `var(--dsw-*)` 的引用 **0 次**，且这 12 个裸名在区段外的引用
   也 **0 次**（`awk 'NR<1497||NR>1884' workbench.css | grep -cE
   'var\(--(paper|ink|hair|blue|blueSoft|yellow|yellowSoft|red|redSoft|green|graphite|shadow)\b'` → 0）。
7. **图例与实况不符。** 图例「相关」色 `#aaa399`（`workbench.css:1796`），
   WebGL 实际线色 `rgb(117,112,104)` = `#757068`（`graph-renderer.js:15-21`）。
8. **底噪是每帧 600 个 alpha 混合光斑**（`workbench.js:1482-1488`、`:1538-1626`），
   与数据无关，只在节点周围挖洞（`:1515-1530`）。
9. **图例／图谱外壳是服务端渲染的**（`workbench/server/pages.py:410-481`），
   节点是 DOM（可访问、可交互），关系线是 WebGL2 canvas。
10. **物理半径已经是投影驱动的。** 〔实证〕`sizeFor(score)`（`graph-physics-core.js:60-61`）
    = `20 + 60·√score`（世界直径 20–80），而 `score` 来自
    `scoreFor(node, view)`（`:1463-1470`）——**结构投影取归一化度数、题量投影取正式题数、
    重要性投影取 `importance`、状态投影取 `stateAttention`**。
    ⇒ **物理半径随投影变**，而 A-26 冻结它 ⇒ 绘制半径必须**从物理半径单调映射**而来，
    不能另起一套与投影脱钩的度量（D-3）。
11. **Obsidian 官方是「混合缩放」：位置等比、点与字 ∝ √zoom、边宽屏幕恒定、
    缩小时标签按 log2 淡出**（`tmp/frontend-audit/OBSIDIAN-GRAPH.md` §4.1 / §4.4，
    源码锚点 raw@2231690 / raw@2216960 / raw@2214489）。
    〔口径〕**本项目按 A-28.2 取更简单的一档**：**节点、标签、边的屏幕尺寸恒定，
    画布缩放只改变节点之间的间距** —— 不引入 √zoom 次线性缩放，也不引入
    「hover 特例反缩放」。

## Goals

- **让图谱在任意画布尺寸下可读**：节点的绘制半径、字号、线宽、点下间距用**屏幕像素**表达，
  Fit 后不再是 3–14px 的斑点（复核 `proposal.md` 的 Why）。
- **给节点一套 Obsidian 式视觉语言**（A-24 决策链 + **A-28 的实测参数**）：
  **单层实心圆点**（半径 **5–13 屏幕 px**，无描边、无投影、无光晕）、
  **标签在点下方 5px、12 屏幕 px 恒定、缩放 < 0.5 时按对数淡出**、
  **关系线屏幕恒定 1.25px 带方向箭头**、
  **圆心数字按投影决定（有数字的两个投影半径取 13px）**、**四投影色键不变**。
- **让学习状态在图上可辨**，且**不靠颜色单独承载**（G-6 + G-21 + 冗余状态通道）。
- **一根手指不动图谱算法**（A-26 / A-28.4）：改造前后同一输入的**收敛坐标 diff = 0**。
- **夜纸下图谱跟随夜纸**（A-7 / A-8 / G-19），图谱自有一套夜纸值集。

## Non-Goals

- **不改图谱算法**（A-26）：力模型、迭代次数、收敛判据、阻尼、引力 / 斥力参数、
  节点间碰撞与分离、布局种子读写、auto-fit **之外**的相机与布局逻辑、
  邻接与边集合、边的类型与权重、筛选语义、投影语义与分档、指标计算、
  DOM 节点的身份与顺序、拖拽与聚焦的行为语义 —— **一律不动**。
  **物理半径（`sizeFor()`，`graph-physics-core.js:60-61`）不动**；
  `labelWidth()`（`:83-85`）与 `footprint()`（`:93-101`）不动。
- 不改边的**拓扑、类型与权重**；改的只是**画法**（线宽 / 透明度 / 箭头 / 端点落点）。
- 不改交互：搜索、筛选、缩放、平移、Fit、拖拽、聚焦、聚拢滑杆、详情看板。
- 不改投影语义：四个投影分别代表什么、各自的数值来自哪个字段，一律不变。
- 不新增任何后端字段、不新增任何学习事实、不改 API 与 CLI。
- 不碰图谱以外的任何页面。
- 不动 `openspec/changes/workbench-visual-language-v2/` 下的任何文件。

## Decisions

### D-1 屏幕空间缩放补偿（**前置，G-24 的有效部分 + A-28.2**）

**决策**

把节点的**绘制几何**从「世界像素」改成「**屏幕像素**」：
`scale()` 只负责**位置**，绘制半径、字号、点下间距、线宽**不再随相机缩小**。
〔A-28.2 的核心模型〕**「缩放只改间距，不改尺寸」** —— 节点、标签、边的屏幕尺寸恒定，
画布缩放只改变节点之间的间距。四个数值：

1. **绘制半径（屏幕 px）** = D-3 的 `R_screen`（区间 **5–13**；两个数值投影取 13）。
2. **标签字号** = **12 屏幕 px**（A-15 / A-28 不变）；**点与标签的间距** = **5 屏幕 px**（D-6）。
3. **关系线宽** = **1.25 屏幕 px**（= `1.25 / scale`，D-7.2）；**基础 alpha 0.3**。
4. **物理尺寸**（`node.size`）**一字不动**（A-26 / A-28.4）⇒ 物理、footprint、碰撞、
   端口间隙**全部照旧**；绘制尺寸与物理尺寸**解耦**（D-3）。

**实现落点**：JS（`graphPaintNodes()`，`workbench.js:1296-1325`）每帧写两个值：
`--node-d`（屏幕 px 的绘制直径，供字号换算与命中区）与 `--node-box`（舞台 px 的盒子尺寸
= `--node-d / s`）。盒子是透明的，只承载命中区与两个子层的定位。
`--inv-scale = 1 / var(--stage-scale)` 由 `graphApplyView()`（`workbench.js:1104-1107`）
在写 `transform` 的**同一次调用**里写到 `.graph-stage` 上 ——
**一次相机变化 = 一次变量写入**，不引入任何新状态、不引入逐节点的 JS 计算。
另写一个 `--label-alpha`（标签的对数淡出因子，D-6.5）。

**理由**

- G-24 的依据就是这个：*「现状 Fit 后 scale = 0.17–0.49，圆直径仅 3–30px、
  标签 2.0–5.9px、可见标签 0–1/31 —— 在这个尺寸上，新的配色与同心圆根本看不出来。」*
  不先修补偿，后面的圆点、暖色板、图例都白做。
- 〔实证〕Obsidian 官方正是这样处理边的：`g = fLineSizeMult / zoom`（世界单位）
  ⇒ **屏幕线宽恒定**（`OBSIDIAN-GRAPH.md` §3，raw@2216960）。
  节点与标签在官方那里是 ∝√zoom（次线性），**本项目按 A-28.2 取屏幕恒定**
  —— 更简单的一档，且与「放大只是拉开间距」的语义一致。
- 「绘制层用屏幕像素、世界层用世界像素」是唯一能同时满足三件事的做法：
  ① 物理与布局**零改动**（A-26）；② 排版、线宽、数字在任意缩放下**恒定可读**；
  ③ 节点的**相对大小**（量值感）仍在 —— 它由同一个 `scoreFor()` 连续映射而来（D-3）。
- 〔推断〕Obsidian 的图谱节点本身就是**近固定屏幕尺寸**（它用 √zoom 做次线性补偿），
  这与 A-28 的「5–13 屏幕 px 恒定」是同一件事。

**关键数字（〔实证〕离线复算 dmath/ch06，31 节点）**

| 画布（CSS px） | 现状 scale | 现状圆直径 | 现状标签字号 | 现状可见标签 | **新点直径** | **新标签字号** | **新可见标签** |
|---|---|---|---|---|---|---|---|
| 860 × 460 | 0.37 | 7–30px | 4.4px | 1 / 31 | **10–26px**（数值投影 26px） | **12px** | 全部渲染，重叠者让位 |
| 1140 × 600 | 0.49 | 10–39px | 5.9px | 12 / 31 | **10–26px** | **12px** | 同上 |
| 703 × 372 | 0.29 | 6–23px | 3.5px | 0 / 31 | **10–26px** | **12px** | 同上 |
| 411 × 230 | 0.17 | 3–14px | 2.0px | 0 / 31 | **10–26px** | **12px** | 同上 |

> 新三列与相机无关：绘制尺寸是屏幕像素，标签同理。
> 唯一随画布变化的是**节点的间距**（世界布局 × scale）与**拥挤度**（见 Risks R-1）。
> 〔说明〕「新点直径 10–26px」比现状更小，这是 A-28 的定案：Obsidian 的点就是**小而细**的，
> 「点相对字段更细」的观感正是由**小点 + 大字**的对比造成的
> （`OBSIDIAN-GRAPH.md` §2.2：「一个 size=8 的点屏幕直径 16px，标签字号 16px，
> 字和点一样大」）。物理预留的空间不变（A-26）⇒ **点更小、留白更大**。

**否掉的备选**

- **A. 把整个舞台的 `scale()` 去掉，改成 JS 逐节点换算屏幕坐标。**
  否掉：等于重写渲染栈（WebGL 画布在舞台内、`stageScale()` 反解变换、
  `routePath` 在世界空间），而 `calc()` 补偿能得到同样的像素结果。
- **B. 绘制半径 = 世界半径 × s（只把「过小」的部分抬到下限）。**
  否掉：这样**量值差会在低缩放下被压平**，且它读不出 A-28 的「5 → 13」这组数字。
- **C. 标签保持世界像素（不补偿），只补偿圆点。**
  否掉：标签才是「看不清」的主因（2.0–5.9px），且 A-24.2 / A-28 明确「标签屏幕恒定」。
- **D. 引入 Obsidian 的 √zoom 次线性缩放（点与字 ∝ √zoom）。**
  否掉：A-28.2 明确取「**屏幕尺寸恒定，缩放只改间距**」这一档；
  √zoom 会让「点的大小随缩放变」，与「放大只是拉开间距」的语义冲突。
- **E. 把标签移出舞台，单独做一个屏幕空间图层。**
  否掉：可行但要动 DOM 归属与命中区；`calc()` 补偿能得到同样的像素结果。

**代价**

- 世界层的 `labelWidth()`（`graph-physics-core.js:82-85`，按 **12px/字符**估算）
  与屏幕层 12px/字符的**实际标签宽度**在低缩放下不再匹配
  （s≈0.4 时实际标签的世界占位约为模型估算的 2.5 倍）。
  ⇒ 由 **D-6 的屏幕空间重叠让位**兜底，**不**改 `labelWidth()`
  （改了就是改布局物理 —— A-26 冻结碰撞分离）。
- **绘制点比物理预留小得多**：屏幕直径 10–26 vs 物理折算 7–30（现状可见圆盘）。
  Fit 视图下相邻点之间的空白会明显变大 ⇒ 图看起来更疏（Obsidian 式的观感）。
  **代价是同屏可见的信息密度下降**，缓解手段见 **Risks R-1**。
- 缩放变成纯粹的「拉开间距」：放大时节点**不变大**，只是彼此远离
  （D-11.4 交代了工具条文案）。

### D-2 节点形态：**单层实心圆**（无描边、无投影、无光晕）（**A-24.1 + A-28.1**）

**决策**

节点由**两件**构成，取代现在的五层：

| 层 | 元素 | 视觉 | 承担什么 |
|---|---|---|---|
| **点** | `.node-dot`，`border-radius: 50%` | **单层实心圆**：单一填充色，**无描边**、**无投影**、**无内高光**、**无渐变** | 节点本体；承载该投影的颜色与量值（半径） |
| **数字**（可选） | `.node-value` | 仅在**两个数值投影**下出现（见 D-3.4）；纸色 / 墨色的实心字 | 该投影的量值 |

- **命中区**（`.node` 盒）可以大于可见点（照 Obsidian 移动端的透明命中圆，
  `OBSIDIAN-GRAPH.md` §1.1 raw@2212446：`r=500, alpha=0.0001`；
  本地 `frontend/editable-graph/src/styles.css:288-293` 的 `.node .halo` 同理），
  但**不得有任何可见痕迹**（无填充、无描边、无光晕）。
- **删除**：`.node-face` 的 `box-shadow`（`workbench.css:1678`）、
  `inset 0 0 0 1px rgba(255,255,255,.82)` 内高光、1px 描边、
  `.node-face::before` 的径向高光（`:1684-1687`）、`.status-ring`、`.node-satellite`、
  `.metric-track`（D-10）。
- **不做**：外环、内核双层同心圆（推翻 G-1 / G-13）、度量弧（G-2 仍成立，但形式更彻底）。

**理由**

- A-24.1 的原文：「节点 = **小实心圆点**，半径…；**无 drop-shadow**（塑料感主因）、
  **无描边**、无 halo 视觉（halo 只作命中区）」。
- 〔实证〕**A-28.1 的纠正**：Obsidian 的节点是**单层实心圆** ——
  源码里只有一次 `beginFill` + `drawCircle`，**没有 `lineStyle`、没有 shadow、没有渐变**
  （`OBSIDIAN-GRAPH.md` §1.1，raw@2212400）。
  我们仓库里的 `frontend/editable-graph` 是 **halo + core 双层 + 1.4px 描边 +
  `drop-shadow`**（`styles.css:295-300`）——
  **它不是 faithful 的 Obsidian 克隆，那才是「塑料感」的真正来源。**
  ⇒ 本设计照**Obsidian 源码**做：**单层实心圆**。
- 〔实证〕塑料感在 Obsidian 那边也是同一个病：描边 + 投影 = 拟物，与图谱的
  「信息图」气质相反（`OBSIDIAN-GRAPH.md` §6.1）。
- 所有者原话：「**节点相对字段更细**」—— 实心小点（直径 10–26px）配 12px 恒定的字，
  视觉重量天然低于「带边、带影、带高光的圆片」。

**否掉的备选**

- **实心圆 + 一道描边**（保留边界感）：否掉，A-24.1 明写「**无描边**」；
  Obsidian 源码里也没有 `lineStyle`。
- **内核淡 + 外环深**（旧 D-2）：否掉，A-24 **推翻 G-13 / D-2**。
- **保留投影但减弱**（`drop-shadow` 的 alpha 减半）：否掉，
  A-24.1 的口径是**无 drop-shadow**，不是「更淡的 drop-shadow」。
- **照抄 `frontend/editable-graph` 的双层结构**：否掉 ——
  它自己就是「塑料感」的来源，**不是** faithful 的 Obsidian 克隆（A-28.1）。

**代价**

- 失去描边后，点与纸底的分离**全靠填充色** ⇒ 填充色对纸面的 **3:1** 门槛是硬要求（D-4）。
  〔实证〕关系结构投影的墨阶第三档必须因此从 `#ded6c6`（1.42:1）改到 `#9c9184`（3.04:1）。
- 失去描边与投影后，**小点更容易「消失」**（尤其在 5px 下限那一档）——
  靠填充色的对比度门槛与标签兜底（D-6）。

### D-3 尺寸映射：屏幕空间 **5–13px**，**与物理半径解耦**（**A-28 + A-26**）

**决策**

- **绘制半径**（屏幕 px），统一区间 **5 – 13**：

  | 投影 | 公式 | 区间 | 依据 |
  |---|---|---|---|
  | 关系结构 `structure` | `R = clamp(5 + 2.2·√degree, 5, 13)` | **5 – 13** | A-28：「关系结构投影用**度数**」；公式照 `OBSIDIAN-GRAPH.md` §6.1 的建议值（Obsidian 官方是 `3·√(weight+1)`，clamp 8–30，raw@2215420） |
  | 学习状态 `state` | `R = clamp(5 + 8·√score, 5, 13)` | **5 – 13** | `score` = `stateAttention(node.state)`（`graph-physics-core.js:1463-1470`） |
  | 题目数量 `problem_count` / 重要性 `importance` | **恒为 13**（见 D-3.4） | **13** | A-28：「半径下限提到 **13px** 才容得下 12px 的字」 |

- **`score` 就是 `scoreFor(node)`**（`graph-physics-core.js:1463-1470`）——
  **与物理半径同一个输入**（物理半径 = `sizeFor(score)` / 2）。
  ⇒ **绘制半径是物理半径的单调函数**（在每个投影内），这正是 A-26 要求的
  「绘制用的屏幕空间显示半径从物理半径单调映射而来」。
  〔实证〕`sizeFor()` 是 `√` 的严格单调函数 ⇒ `R_screen` 与 `node.size` 同序；
  结构投影用的是**原始度数**而非归一化 score，但归一化是度数的单调变换
  ⇒ 两者仍同序。
- **物理半径一律不动**：`sizeFor()`（`graph-physics-core.js:60-61`）**一行不改**
  （世界直径仍是 20–80）。**这是与旧 D-3 最大的差别**：旧设计把物理直径改成 28–60，
  那已经越过了 A-26 的冻结线，本设计**撤销**该改动。
- **命中区** = `max(绘制直径, 24 屏幕 px)`（照 Obsidian 移动端「大命中圆」的做法：
  可见点只有 10–26px，命中区不能跟着缩到 10px）。命中区**完全不可见**。
- 映射函数保持 `√`：〔实证〕现状注释（`graph-physics-core.js:48-59`）说明
  开平方是为了让中低分区间也够得着；换掉它会改变现有分布形状。

**为什么半径区间是 5–13 而不是别的数**

- A-28 的定案表：「节点半径 8–23px → **5–13px（屏幕像素）**」，
  依据是 `OBSIDIAN-GRAPH.md` §6.1：「我们节点更密、标签更长，点要比官方更小；
  官方 8–30 是为『大库少节点』调的」，建议式 `5 + 2.2·√degree`，clamp 到 [5, 13]。
- 旧设计的 14–30（A-10.1）与 A-24 的 8–23 **随之作废**。

**物理半径解耦的实现**

| 量 | 定义 | 归属 |
|---|---|---|
| `node.size`（世界直径 20–80） | `sizeFor(scoreFor(node))` | **物理**：参与碰撞、footprint、端口间隙、Fit 之外的布局 —— **冻结** |
| `R_screen`（屏幕半径 5–13） | D-3 的三条公式 | **绘制**：只决定点画多大、命中区多大、端点落在哪 |
| 两者关系 | `R_screen = f(node.size / 2)`，在同一投影内**同序** | — |

⇒ **布局看到的永远是物理半径**；**眼睛看到的永远是屏幕半径**。
布局不变 ⇒ A-26 的 diff = 0 判据成立（D-13.3）。

**度量弧被删之后，信息没有丢——逐项核对**

| 弧原来承载的 | 现在由谁承载 | 是否丢失 |
|---|---|---|
| 弧长 = 当前投影指标的归一化值 | **半径**（同一个 `scoreFor()`，同一个单调映射；两个数值投影除外，见 D-3.4） | 不丢（结构 / 状态投影） |
| 弧色 = 知识点重要度（core 蓝 / support 黄） | **无** | **丢**，见下 |
| 弧起点 215°、302° 弧长的固定缺口 | 无 | 不丢（纯装饰，读不出信息） |

〔推断〕**core / support 的视觉区分在四个投影中全部消失**。这是 G-2 的既定代价
（原话：「用颜色与大小表意即可」）。它的语义仍由「重要性」投影承载：
`importance` 投影的**量值**（`importance` 本身）决定该投影下节点的**色阶**
与**圆心数字** ⇒ 重要度**仍在图上可读**，只是不再有独立的蓝/黄两色。
〔待核〕实现时确认 `kind` 与 `importance` 的取值关系。

**D-3.4 两个数值投影的半径：恒为 13px（**A-28 的字面取值与其后果**）**

- A-28 的定案：「圈心数字…不变，但**半径下限提到 13px** 才容得下 12px 的字」。
  在 **5–13** 的区间里，「下限 = 13」等价于「**半径恒为 13px**」。
- **为什么必须是 13px 而不是 8px**：12px 的数字在圆里要放下，需要半径 ≥ 约 9px
  （12px 字的半高 6px + 半宽 3.5px ⇒ 角点距中心 ≈ 6.95px）；
  Obsidian 官方干脆**不往圆里写字**（`OBSIDIAN-GRAPH.md` §6.2：
  「官方证明了『圈心数字』不是解法：字号下限 14px 而半径下限 8px，**字比点还大**」）。
  本项目要保留圆心数字（owner 的 A-24.4），就必须给数字留出空间 ⇒ 取区间上限 13px。
- **后果（必须显式登记，不得藏起来）**：在**题目数量 / 重要性**这两个投影里，
  **半径不再承载量值** —— 量值由**圆心数字 + 色阶**承载。
  ⇒ 既有 `Metric projection morphology` 的「值越大 → 半径越大」这一句在这两个投影里
  **不再成立**，本变更的 `workbench-ui` delta **显式改写**该句（见该 delta）。
- **〔待裁决〕** 若 A-28 的「13px」原意是「下限抬到 8px」（即保留「值越大点越大」），
  则该句**无需改写**。**这一条作为待裁决项登记在 Open Questions 第 5 条**，
  实现时按裁决改。

**否掉的备选**

- **线性映射**（`R = 5 + 8·score`）：低端节点全挤在 5px，量值感尽失。
- **按 raw degree 给所有投影定半径**：否掉 —— 只有结构投影的量是度数；
  其余投影的量来自各自的字段（A-26 冻结了投影语义）。
- **把 `collisionRadius()`（`frontend/editable-graph/src/main.js:194-198`）搬过来**：
  否掉 —— 它是**布局量**（碰撞半径），A-26 **冻结碰撞分离**。
  **只借用它的「标签要占位」这一教训**，在**绘制层**用 D-6 的屏幕空间去冲突兜底。
- **把物理直径也改成 10–26 世界 px**：否掉 —— 那是改物理，越过 A-26 的冻结线。

**代价**

- 绘制点比物理预留**小**（屏幕直径 10–26 vs 物理折算 7–30）：点的**相对留白变大**，
  图看起来更疏（Obsidian 式的观感）。
- 两个数值投影里半径恒定（见 D-3.4）⇒ **那两档投影里「大小」这条通道让给了数字**。
- 物理半径与绘制半径**不再同步变化**：例如某个节点在物理上很大（题数多），
  绘制上仍受 13px 上限约束 ⇒ 极端值之间的视觉差被压平。
  这是「只改观感」的直接代价，**接受**（A-26 的取舍）。

### D-5 每个投影一套色键 + 图例随投影切换

**决策**

| 投影（`pages.py:411-412`） | 节点色键 | 性质 | 依据 |

- A-24.3 要求「箭头语义钉死」⇒ 图例是**钉住它的地方**（图上只能看到一条细线，

### D-6 标签系统：常态可见、**点在下方 5px**、12px 恒定、**缩放 < 0.5 对数淡出**、重叠让位

**决策**

1. **标签在点下方 5px**（A-28 的定案取代 A-24.2 的 18px）：
   〔实证〕Obsidian 官方「文字顶部 = 节点中心 + `(size+5)·nodeScale`」
   ⇒ **圆底到字顶的间隙 = 5px**（`OBSIDIAN-GRAPH.md` §2.1，raw@2214489）。
   ⇒ 实现上：`.node-wrap` 的 `gap` 从 8px 改为 **5 屏幕 px**
   （`calc(5px * var(--inv-scale))`），而 `.node` 盒高 = 绘制直径（屏幕 px），
   ⇒ 标签盒上缘与点下缘之间的净空恒为 **5 屏幕 px**，**与点不重合**。
   〔作废〕`frontend/editable-graph/src/main.js:602` 的 `r + 18` —— 那是**本地参照实现**，
   不是 Obsidian 的做法（A-28.1）；`OBSIDIAN-GRAPH.md` §6.1 也点名它
   「我们现在 r+18 太远，字和点『脱节』」。
2. **常态可见**（G-5）：标签默认渲染，**不再按缩放阈值隐藏**。
   现状的 `LABEL_MIN_RADIUS_PX = 14` 与 `labelScaleThreshold()`
   （`workbench.js:1290-1294`）+ `labelVisible` 判定（`:1319-1321`）**删除**；
   〔实证〕这条规则在 Fit 后（s = 0.17–0.49）让 30/31 个节点没有标签。
3. **字号与对比度**：**12 屏幕 px 恒定**（D-1 的 `calc(12px * var(--inv-scale))`；
   所有者裁决 **A-15** 定为 12px，**A-28 明确不变**），颜色 `#5c5549`（亮纸 7.24:1）/
   `#c9c2b5`（夜纸 9.82:1）—— 比现状的 `#2b2925`（≈15:1）**明显降一档**，
   但仍 ≥4.5:1（G-5「降低对比度不抢节点」）。
   保留纸色晕圈但**减薄**（`text-shadow: 0 1px 0 var(--paper), 0 0 3px var(--paper)`，
   现状 `workbench.css:1713` 是 `0 0 6px`）——
   〔依据〕`OBSIDIAN-GRAPH.md` §6.1：「官方没有光晕；我们的底色比官方杂乱，光晕有存在理由
   —— 但 4.4px 太粗，字会被『啃』一圈」；本地参照实现的 4.4px 描边同理。
4. **换行而非截断**：`.label` 保持 `max-width` 语义（现状 `168px`，`workbench.css:1711`）
   并**按屏幕像素补偿**（`calc(168px * var(--inv-scale))`），
   **不加** `text-overflow: ellipsis`、**不加** `-webkit-line-clamp`。
5. **重叠让位**（G-23）：一个**屏幕空间**的去冲突 pass：
   - 触发时机：相机变化（缩放/平移）、布局收敛、投影切换、选中变化 —— **不是每帧**。
   - 排序（谁让谁）：**半径降序 → 重要度降序 → 节点 id 升序**（确定性）。
   - 规则：标签矩形相交时，**排位靠后者隐藏**（`opacity: 0` + `aria-hidden`）。
   - **可见标签预算**：即使不重叠，同时绘制的标签也有上限。
     预算 = `floor(画布面积 / 9000)`（一个标签块 ≈ 66×30 屏幕 px，留一倍呼吸空间），
     860×460 ⇒ 43；dmath/ch06 的 31 个节点不会触顶，**大章节**（100+ 节点）会。
     超预算时按同一排序保留前 N 个。
   - **永不隐藏**：选中节点、悬停节点、其 1 跳邻居（与既有契约
     `workbench-ui:248`「selected, hovered, and high-focus labels SHALL remain visible」一致）；
     被隐藏的标签在**悬停/选中该节点时立刻恢复**（`opacity` 回到 1）。
   - 被隐藏者的**完整标题**仍在悬浮提示（`label.title = node.title`，
     `workbench.js:996`）与学习看板里可得。
6. **状态文字从节点上消失**（G-6 / A-24.5）：
   - 删除 `.meta` 行（内容由 `workbench.js:1072-1073` 写入「状态标签 · 投影名 值」）；
   - 删除「学习状态」投影写入圆心的单字「练/复/熟/新」
     （`STATE_SHORT`，`workbench.js:578`；写入点 `workbench.js:1060`）——
     状态投影**本来就没有数字**（D-3.4）。
   - 状态名仍保留在：**学习看板**（`pages.py:474-477`）、
     `button.title` / `label.title`（悬浮）、`aria-label`（`workbench.js:973`）。

**D-6.5 缩放时的标签淡出（**A-28 的定案，取代「不按缩放隐藏」的旧读法**）**

- 〔实证〕Obsidian 官方**用「淡出」代替「缩小」**：
  `textAlpha = clamp(log2(zoom) + 1 − textFadeMultiplier, 0, 1)`
  （`OBSIDIAN-GRAPH.md` §2.2，raw@2231690）—— 每级 zoom 减半，alpha 减 1。
  官方默认 `textFadeMultiplier = 0` ⇒ zoom = 1 时 alpha = 1、zoom = 0.5 时 alpha = 0。
- **本项目的取值**：标签字号**屏幕恒定 12px**（A-28.2），因此**唯一的缩放行为就是淡出**：

  ```
  labelAlpha = clamp(log2(s) + 2, 0, 1)      -- s = 舞台缩放
  ```

  ⇒ `s ≥ 0.5` 时 alpha = 1（**常态可见**）；`0.25 ≤ s < 0.5` 时**按对数线性淡出**；
  `s ≤ 0.25` 时完全消失。
  〔口径〕常数 **+2**（而不是官方的 +1）是因为**本项目的默认 Fit 缩放约 0.41–0.47**
  （D-11.2），官方的 +1 会让默认视图的标签 alpha = 0 —— 与「常态可见」（G-5）冲突。
  写成「**缩放 < 0.5 时按对数淡出**」正是 A-28 的原话。
- **这不是「按缩放阈值隐藏」**（被删掉的旧规则）：旧规则是**硬阈值**（`LABEL_MIN_RADIUS_PX`），
  在 Fit 后让 30/31 个节点**完全没有标签**；新规则是**连续的透明度曲线**，
  且在默认视图里 alpha = 1（标签照常可见），只用户主动缩得很远时才淡出。
- **与去冲突 pass 的关系**：两者**相乘** —— 重叠让位决定「画不画」，
  淡出决定「画多淡」。隐藏（`opacity: 0` + `aria-hidden`）优先于淡出。

**关于「完整文本」的契约漂移（显式登记）**

〔实证〕`workbench-ui:471-473` 写的是「Node labels SHALL always display their complete
text — wrapping to multiple lines instead of truncating」，
但实现里 JS 会把标题在**第一个标点处截断**（`graphTitleCut`，`workbench.js:806-817`），
标签显示的是**简称**。这是既有的**契约漂移**。
本变更**不删简称**（删了会让标签长 2–3 倍，且 `labelWidth()` 依赖 `shortTitle`
⇒ 改布局物理，越界），而是**在 `workbench-ui` 的 delta 里把条款限定为
「标签**显示时**呈现的是它自己的完整文本，无省略号、无字符上限，换行而不截断；
节点的完整标题由悬浮与键盘聚焦承载」**——与本变更的 `workbench-ui` delta 一致。

**A-10.3 确认（2026-10-22）：取「不截断」的一支**

G-5 原文是「截断改两行**或**悬浮显示全文」。「两行上限」与既有
`Complete primary learning text`（知识标题全文）**正面冲突**，因此取**不截断**的一支：
**标题换行显示全文**（不设行数上限、无省略号），完整标题在**悬浮 / 键盘聚焦**可达。
这与 **G-23（重叠时隐藏次要标签）** 是**两个不同机制** —— 前者管「怎么显示」，
后者管「什么时候不画」—— 互不冲突。

**否掉的备选**

- **保留缩放阈值隐藏，只把阈值调低**：否掉，G-23 明确「**不靠缩放**」；
  且阈值规则与屏幕像素字号互斥。**新规则是对数淡出，不是阈值隐藏**（见 D-6.5）。
- **两行截断（`-webkit-line-clamp: 2`）**：与 `workbench-ui:471-473` 冲突。
- **标签随缩放一起变大（不补偿）**：那就回到 D-1 的问题。
- **引入 Obsidian 的 √zoom 次线性字号**：否掉，A-28.2 取屏幕恒定。
- **去冲突 pass 在世界空间做**：世界空间不随相机变化，屏幕空间才是「重叠」的真实判据。
- **把标签放进点的下面而不是上方**：A-24.2 明确「**字段在点下方**」；
  Obsidian 官方也是正下方居中（`OBSIDIAN-GRAPH.md` §2.1，anchor = (0.5, 0)）。

**代价**

- 需要一次标签矩形测量（`getBoundingClientRect`）⇒ 必须**批量读**（一次读全部），
  否则触发强制回流。31 个节点 × 一次批量读，可接受。
- 标签在低缩放下占的世界空间是模型的 ~3 倍 ⇒ 视觉上标签会盖住邻点的圆点。
  〔推断〕为避免"标签压住别人的点"，去冲突 pass 同时判定
  「标签矩形 ∩ 邻点圆盘」——命中且该邻点未被隐藏时，**先藏标签**（标签让位于点）。
- 标签与点贴得更近（5px）⇒ **点多的图里标签更容易压到邻点** ⇒ 去冲突 pass 更必要。
- 简称仍然是简称（漂移已登记，未解决）。

### D-7 关系线：**1.25px / alpha 0.3** + **方向箭头** + 端点落在点缘

**决策**

- **D-7.1 端点落在绘制点的边缘**（A-26 允许改「端点落点」）：
  - 现状：物理核心用 `endpointRadius(node)`（`graph-physics-core.js:1345-1347`）=
    `size × (1 − 2×.07)/2 − 1`，即旧 `.node-face`（`inset: 7%`）的可见半径。
    〔实证〕该常量 `NODE_FACE_INSET = .07`（`:1343`）**与 CSS 的 `inset: 7%`
    是一对 coupled 的**，注释明说「If the face's inset ever changes, this constant
    has to change with it」。
  - 新形态下 `.node-face` 与 `inset: 7%` 都不存在了 ⇒ 端点半径改为**绘制点的边缘**，
    即 `R_world = R_screen / s`（`R_screen` = D-3 的绘制半径 5–13 屏幕 px）。
  - **实现位置在渲染层**：`graph-renderer.js` 已经读得到缩放
    （`var scale = stageScale(stage)`，`:267`），且路径已经被采样成 16 段（`:283-300`）。
    做法：按**采样点**从两端向节点中心回退，直到与节点中心的距离 ≥ 新的端点半径。
  - **共享函数**（避免两处漂移）：在 `graph-physics.js` 的门面
    （`workbench/server/static/graph-physics.js`，现有门面在 `:214-300`）上新增
    `nodeScreenRadius(node)`，**同时**被 `workbench.js`（画节点）与
    `graph-renderer.js`（修端点）使用。〔实证〕两端必须用同一个公式，
    否则线会与点错位。
- **D-7.2 线宽与透明度**（A-24.3 + A-28）：
  **1.25 屏幕 px（= `1.25 / scale`）/ 基础 alpha 0.3**。
  - 现状：`edgeStyle(edge)`（`graph-physics-core.js:1326-1329`）返回
    `{ width: 1.05 + score·2.35, baseOpacity: .15 + score·.43 }`
    ⇒ 线宽 1.05–3.4、alpha .15–.58，**随强度变化**。
  - 新形态：**统一** `width: 1.25`、`baseOpacity: .30`。
    〔口径〕`edgeStyle()` 是**绘制辅助函数**（唯一消费点是 `graph-renderer.js:274` 的
    `runtime.edgeStyle(edge)`），**不是物理参数** ⇒ 改它落在 A-26 的
    「允许改（纯绘制）：边的绘制（线宽/透明度）」之内。
    **边的类型与权重（`NEIGHBOR_WEIGHT` `:527`、`baseGapForStrength()` `:68-70`、
    `strength` 字段本身）一律不动** —— 强度仍然决定**布局距离与吸引**，只是不再改**画法**。
  - **线宽本就是屏幕像素**：现状 `graph-renderer.js:276` 的
    `style.width / Math.max(.25, scale)` 已经把线宽换算成屏幕像素 ⇒ 1.25 是同一口径下的换值。
    〔实证〕Obsidian 官方是同一个做法：`g = fLineSizeMult / zoom`（世界单位）
    ⇒ **屏幕线宽恒定**（`OBSIDIAN-GRAPH.md` §3，raw@2216960）。
- **D-7.3 五种关系的箭头语义（A-24.3 必须钉死，A-28 保留「直线 + 方向箭头」）**

  | 关系类型 | 方向语义 | 箭头 | 依据 |
  |---|---|---|---|
  | **先修 `prereq`** | **有向**：源 = 先修项，目标 = 后学项 | **画**，箭头指向**目标**（后学） | 现状已有（`graph-renderer.js:299`）；`direction === "symmetric"` 时不画 |
  | **应用 `apply`** | **有向**：源 = 应用方，目标 = 被应用的对象 | **画**，箭头指向**目标** | 同上；`symmetric` 时不画 |
  | **对比 `contrast`** | **对称**：两者互为对照 | **不画** | 现状不画；对比无方向语义 |
  | **相关 `related`** | **对称** | **不画** | 现状不画 |
  | **隐含 `legacy`** | **无方向语义** | **不画** | 现状不画 |

  - 箭头**落在目标点的绘制边缘**（D-7.1 的同一口径），随线宽与 alpha 一起淡出。
  - 箭头的**语义不改数据**：边的 `direction` 字段与拓扑**冻结**（A-26）。
    本决策只决定「哪些类型画箭头、箭头朝哪」。
  - 〔实证〕Obsidian 官方的箭头也是「贴在目标节点边缘外、朝向连线方向」的 V 形，
    **屏幕尺寸不随缩放变化**（`OBSIDIAN-GRAPH.md` §3，raw@2216200 / raw@2217524）——
    本设计照此：**箭头尺寸屏幕恒定**（约 2× 线宽）。
- **D-7.4 关系类型的可读性**：五类关系的**色相**（`graph-renderer.js:15-21` 的
  `EDGE_COLORS`，**亮色取值逐字节不变**）与**虚实节奏**
  （`:288-298` 的分段绘制：`contrast` 与 `legacy` 虚线，其余实线）保留。
  〔实证〕Obsidian 官方「连线粗细与两端节点度数/权重**无关**」
  （`OBSIDIAN-GRAPH.md` §3）⇒ 本设计与之一致。
- **D-7.5 聚焦时的淡化幅度**（A-28 的定案）：**非邻接元素降到 alpha 0.2**
  （Obsidian 的常量 `fQ = .2`，`OBSIDIAN-GRAPH.md` §1.3 raw@2210794）。
  - 现状：节点 dim 的 `opacity: .18`（`workbench.css:1645`）、

  - 新形态：边的「其余」系数 **0.07 → 0.2**（A-28：「现状 0.14 / 0.07 太狠」）；
    节点的 dim **0.18 → 0.2**；二跳邻域保持「次级」档（0.38 ⇒ 0.4，
    〔口径〕`workbench-ui` 的「two-hop neighbors remain secondary」是**既有契约**，
    不能与非邻接同档）。
  - **淡化的对象不变**（选中节点的关联边保持全亮、二跳次级、更远淡出）——
    **哪些元素被强调是冻结的交互语义**（A-26）；改的只是**淡出的强度**（绘制层）。

**理由**

- A-24.3 的原文：「**关系线 1.25px / alpha 0.3**…，**并加方向箭头**（各自的箭头语义要钉死）」。
  〔口径〕A-24 举的关系名是通用举例；**本仓库的五个类型是**
  `prereq / apply / contrast / related / legacy`（`graph-physics-core.js:1399`），
  故按本仓库的类型名钉死（D-7.3 的表）。
- 〔实证〕A-28 复核了 Obsidian 官方的边：**直线**、**屏幕恒定线宽**、
  **两端扣掉节点半径**、**箭头贴目标边缘**、**非邻接降到 0.2**
  （`OBSIDIAN-GRAPH.md` §3 / §4.1）—— 本设计逐条照它。
- G-18 的旧读法（「关系线本身的线型、粗细、颜色不改」）**被 A-24 覆盖**：
  粗细与透明度现在**要改**（1.25 / 0.3）。**颜色不改**这一半仍然成立
  （亮色 `EDGE_COLORS` 逐字节不变）。
- 屏幕像素的绘制点**永远比逻辑 footprint 小或大**（两者单位不同）⇒
  端点若仍按逻辑半径算，线会「够不着」或「插进」点里，肉眼可见。

**否掉的备选**

- **把缩放推进物理核心（Worker 知道 scale）**：否掉 —— 布局会随缩放变化 ⇒
  缩放会 reheat 求解器，违反 `workbench.js:1107-1108` 的
  「Camera movement never reheats the solver」与 `workbench-ui:155-158`
  「Fit without rewriting layout」。
- **端点保持旧半径，靠点盖住缺口**：缺口是 `R_screen − R_world·s` 屏幕 px
  —— 5–13px 的点盖不住，会露出一截短线。
- **把关系线画在节点之上**：会破坏「关系由线型承载」的可读性，也与
  现状 z-index（关系线 canvas = 1，`graph-renderer.js:147`；节点 = 2，`workbench.css:1646`）相反。
- **给每种关系一个不同的箭头形状**：否掉 —— A-24 只要求**语义钉死**，
  形状差异在小尺寸下不可读；**方向 + 图例**已足够。
- **按关系强度分档线宽**（社区插件做法）：否掉 —— Obsidian 官方「与度数/权重无关」，
  且 A-26 冻结了「边的类型与权重」在**布局**里的角色；本变更只改画法。

**代价**

- 渲染器多一段端点回退逻辑（约 20 行），且必须与画节点的公式共用同一实现。
- 边被**截短**一小段（端点从旧半径退到新点缘）⇒ 关系线的**可见长度**略变，
  但**几何拓扑不变**（同一对端点、同一控制点族）。
- **强度不再体现在线宽上** ⇒ 读者要靠**箭头 + 虚实 + 图例**读关系，
  「更强的关系画得更粗」这条旧线索消失。**这是 A-24 / A-28 的既定取舍**（细线 + 箭头）。
- 非邻接元素从「几乎消失」变成「可见但退后」⇒ 远端拓扑的视觉重量上升，
  密图里可能更吵。缓解：0.2 是 Obsidian 的定案值（`OBSIDIAN-GRAPH.md` §6.1）。

### D-8 选中 / 悬停 / 聚焦：**换色 + 1px 描边环 + 点放大 + 标签提亮**（**A-24.7 + A-28**）

**决策**

**不再「外环加粗」**（推翻 G-15 / 旧 D-8）。常态节点是**无描边的实心圆**；
**交互态才画出一圈 1px 的环**（A-28 的定案）。四件事：

| 状态 | 点 | 环 | 标签 | 其他 |
|---|---|---|---|---|
| 常态 | 绘制半径 `R_screen`（5–13），投影色 | **无** | 常亮度 | 无阴影、无描边、无光晕 |
| 悬停 | **× 1.06** + **换色**（走更实的一档） | **1 屏幕 px** 描边环（强调色） | **提亮**（字重 700） | 无阴影、无卫星点 |
| 选中 | **× 1.12** + **换色**（走最实的一档） | **1 屏幕 px** 描边环（强调色） | **提亮**（字重 700） | 标签**永不隐藏**（D-6） |
| 聚焦（1 跳 / 2 跳） | 沿用常态 | 无 | 沿用常态 | 沿用现有的 opacity / 权重机制（`workbench.js:1080-1105`）**不变** |

- **换色**：在**分类**投影下 = 同色相更饱和/更深的一档；在**量值**投影下 = 橙阶上
  **对比更强**的一档；关系结构投影下 = 墨阶的最深一档。
  〔实证〕Obsidian 官方的高亮就是**换色**（`getFillColor()` 命中高亮直接返回
  `colors.fillHighlight`，raw@2215080）。
- **1px 描边环**：照 Obsidian 官方的高亮环 —— `lineStyle(E, colors.circle.rgb, 1)`，
  半径 `size + E/2`（`OBSIDIAN-GRAPH.md` §1.3，raw@2214820–2214900）：
  **环在点外侧 1px 处**，**线宽屏幕恒定 1px**（缩小时不再变细）。
  实现：`.node-focus-ring` 绝对定位，`inset: calc(-1px * var(--inv-scale))`，
  `border: calc(1px * var(--inv-scale)) solid var(--graph-focus)`；
  常态 `display: none`（**不得**有 `opacity: 0` 的常驻环 —— 那是「halo」，不是环）。
- **点放大只作用于绘制半径**：实现为在 `R_screen` 之上乘一个系数，
  **物理半径不动**（A-26 / A-28.4）⇒ 布局不因选中/悬停而变。
- **标签提亮**用**字重**（650 → 700）实现，**不改颜色** ——
  这样「亮色主题下标签色不变」这条既有观感不受影响，
  且**字重**是屏幕像素无关的通道，在任何缩放下都成立。
  〔实证〕本地参照实现也是这么做的（`frontend/editable-graph/src/styles.css:341-344`）。
- **删除**：`.node-face` 的 `box-shadow`（`workbench.css:1678`）、
  `.node-satellite` 的 `box-shadow`（`:1696`）、选中时的卫星点光晕（`:1707`）、
  悬停时的 `translateY(-1px)` 抬升（`:1699`）、`.status-ring` 的 2px 蓝环（`:1708`）。
- **保留**：`.node-wrap.dragging { z-index: 6 }`（`:1650`）与拖拽行为。

**理由**

- A-24.7 的原文：「选中态随之改写：不再「外环加粗」，改为**点放大 + 标签提亮**」；
  **A-28 把它补全为「换色 + 1px 描边环 + 点放大 + 标签提亮」**。
- 〔实证〕**Obsidian 官方的高亮机制正是「换色 + 1px 描边环」**
  （`OBSIDIAN-GRAPH.md` §1.3）：它**不是**拟物的光晕，而是**贴在圈外 1px 处的描边**。
  我们仓库里的 `.node-wrap.selected .node-face`（`workbench.css:1701-1703`）是
  `box-shadow: … 0 0 0 2px var(--paper)` 的**光晕**，与官方不同 ⇒ 一并换掉。
- 「加粗外环」这条通道在新形态下**已经不存在**（常态点没有环）⇒ 必须换一条，
  而「换色 + 细环」正是官方的做法。
- 标签提亮用**字重**而不是**颜色**：颜色是投影的通道（改了就与色键冲突），
  字重是**独立**的强调通道；且它对色觉障碍与深色底都成立。

**否掉的备选**

- **保留阴影做高度**：A-24.1 明写**无 drop-shadow**。
- **用饱和度而不是字重表达「提亮」**：颜色是色键的载体，改它会与 D-4 冲突。
- **用 8px 宽、22% 透明的 halo 表达高亮**（本地参照实现的做法）：
  否掉 —— `OBSIDIAN-GRAPH.md` §6.1 点名它「几乎看不出」；官方是 1px 描边环。
- **选中态只换色不加环**：否掉 —— A-28 的定案是四件事齐上。

**代价**

- **常态与交互态的视觉差变小**（常态点无环）⇒ 选中态的可读性依赖
  「换色 + 细环 + 放大 + 标签提亮」四通道叠加；其中**标签提亮**是最强的一条
  （D-6 的「选中标签永不隐藏」与之叠加）。
- 放大后点可能与邻点**更近**（屏幕像素放大不改变物理间距）⇒ 极端密度的图里
  选中的点会压到邻点。〔推断〕选中的放大系数取 1.12 而不是更大，就是为了压住这个代价。
- 描边环是**绘制层**的新元素（多一个 DOM 子层）⇒ 31 个节点多 31 个元素，可忽略。

### D-9 底噪光斑：保留观感，改绘制方式

**决策**

`.graph-tide` **保留**（G-4 原话：「其实那个还挺好看的」），但**绘制方式**从
「每帧 600 个 alpha 混合光斑」改为「**预渲染 + 每帧一次 blit**」：

1. **预渲染**：把 5 条色带 + 尘埃点 + 短线段（`workbench.js:1482-1488`、`:1589-1622`）
   在**半分辨率**离屏画布上渲染一次（尺寸随 `graphTideResize()`，`:1501-1513`）。
   〔实证〕底噪是极低 alpha（0.018–0.13）的纹理，半分辨率放大后肉眼无差。
2. **每帧**：一次 `drawImage`（带缓慢的亚像素漂移，保留现状的「活纸纹」感）
   + **节点挖洞**用 `destination-out` 在**可见节点位置**画径向渐变
   （≤31 次渐变，而不是 600 个点 × 31 个节点的 18,600 次距离计算）。
3. **求解时的 surge**（`graphTideSurge()`，`:1497-1499`）改为对 blit 的整体
   alpha / 缩放施加，而不是重算 600 个点。
4. `prefers-reduced-motion` 下仍只画一帧（现状 `:1634`、`:1639`）—— 保持不变。

**理由**

- 〔实证〕诊断原文：「它是**每帧 600 个 alpha 混合光斑**的开销，
  与『纸纹底噪』这个功能相比代价过高 —— 建议改为**静态预渲染**或降频」。
- 〔实证〕挖洞遮罩（`graphTideNodeMask()`，`:1515-1530`）是底噪与数据的**唯一耦合**；
  把它从「每点计算」改成「每节点一次渐变」是等价且廉价的。
- G-4 要的是**观感**，不是**实现**；预渲染保留观感。

**否掉的备选**

- **删掉底噪**：G-4 明确保留。
- **原样保留每帧重绘**：把 18,600 次/帧的距离计算留着，正是诊断点名要治的病。
- **完全静态（不漂移）**：丢掉「活纸纹」的手感；折中方案是「预渲染 + 亚像素漂移」。

**代价**

- 底噪的**像素**与现状不再逐点相同（半分辨率 + 漂移方式不同）
  ⇒ 像素比对协议必须把 tide 画布列为**已知差异区**（D-12.3）。
- 挖洞的边缘在 ½ 分辨率下会略有柔化 —— 与「极淡底噪」的定位相符。

### D-11 相机与 Fit（**只改相机，不改世界坐标**）

**D-11.1 首次 Fit 之前：把初始相机改成「按 Fit 口径算出来的相机」**

- 现状：初始相机是硬编码 `{ scale: .7, panX: 52, panY: -18 }`（`workbench.js:703`），
  而种子簇摆在舞台中心（`graph-physics-core.js:1528-1530`）
  ⇒ 〔实证〕初始相机下 **31 个节点中 23 个落在画布外**，露出的 8 个挤在右下角
  （基线截图 `tmp/frontend-audit/10-baseline-graph.png` 正是这一帧），
  且这个状态要持续到求解收敛（数十秒级）。
- 决策：**初始相机用 `graphFit()` 的同一套公式，对「当前已有的节点范围」计算一次**
  （节点一创建完就调），而不是等 settle。这样**第一帧就是整图可见**；
  收敛后现有的那一次 auto-fit（`workbench.js:1406-1410`）照旧发生并微调相机。
- 否掉的备选：把 `scale` 从 0.7 改成别的常数 —— 只挪动问题；
  保持 0.7 不动 —— 23/31 在画布外的问题原样保留。
- 〔A-26 口径〕本条只改**相机**，**不写任何节点坐标** ⇒ 不影响 SI-0 的 diff = 0。

**D-11.2 Fit 改用「节点圆盘包围盒」，不再用「含标签留白的 footprint 包围盒」**

- 现状：`graphFit()`（`workbench.js:1203-1229`）用 `GraphPhysics.footprint(node)`
  （`graph-physics-core.js:93-101`）算包围盒，其中 `half = max(size/2 + 13, labelWidth/2)`
  ⇒ 〔实证〕包围盒 1142×1147 世界 px，而**节点圆心**只占 890×919。
  标签留白让整图缩到 0.37。
- 决策：Fit 的包围盒改为**节点圆盘**（`node.size` 的投影）**+ 固定屏幕边距**，
  **不再包含标签留白**。理由：标签现在有独立的屏幕空间去冲突 pass（D-6），
  它的宽度不该再决定整图的缩放。
  ⇒ 〔实证/估算〕包围盒从 1142×1147 缩到 ~890×919 ⇒ 860×460 画布下
  scale 从约 0.37 升到约 **0.41–0.47**，节点之间的**间距**整体放大约 20–35%。
  （节点的**大小**与缩放无关，见 D-1；这条改动放开的是间距，不是直径。）
- 〔A-26 口径〕`footprint()` 与 `labelWidth()` **本身不动**（它们是物理量，
  被碰撞分离使用）；改的只是 **`graphFit()` 用哪个包围盒**——**相机**。
- 代价：标签可能落到画布边缘之外 ⇒ 去冲突 pass 需要把「标签矩形超出画布」
  也算作一次冲突（先藏）。

**D-11.3 「中栏宽度一变整图缩放就变」—— 这是 fit-to-viewport 的固有性质，不是缺陷**

- 〔实证〕`graphFit()` 用 `graphCanvas.clientWidth/clientHeight`（`:1223-1224`）
  算缩放，中栏宽度变 ⇒ 画布变 ⇒ 整图缩放变（graph-isolation.md 的 F-22）。
  这**是**「适应画布」的语义，**不是**要修的 bug。
- 真正要修的是「缩放还被**标签文字长度**牵着走」（D-11.2 已解开）。
- 附带影响：整图缩放变化会让 WebGL 的 `width / scale` 补偿（`graph-renderer.js:282`）
  与 `graphTideResize()`（`workbench.js:1501`）一起变 —— 两者都是按当前 scale/dpr
  重算的，**无状态残留** ⇒ 安全。

**D-11.4 缩放条的行为变了（要交代）**

- 现状：`+` 每次 +0.09、上限 1.6（`workbench.js:1885`）；滚轮缩放的下限是 0.38、步长 ×0.92/×1.08（`:1762`）。
- 新语义：**放大不再让节点变大**（节点尺寸是屏幕 px，与缩放无关）⇒
  缩放的用途变成**拉开间距 / 看整体**，而「看清细节」改由**悬停与看板**承担。
  这也正好是 D-1 那个「拥挤时放大即分离」的对偶。
- 决策：**保留现有的量纲与上限**（0.09/档、1.6 上限），只把工具条的
  `title` 文案改成反映新语义（「拉开间距」），并在 PRODUCT-MANUAL 里同步。
  不改缩放档位（会改变 `workbench-ui` 的交互契约，且没有必要）。

**否掉的备选**

- **收敛过程中持续 Fit**：相机抖动，且违反「相机变化不 reheat」（`workbench.js:1107-1108`）。
- **把 Fit 的输入换成「标签实际测量宽度」**：那会让缩放依赖字体度量与换行，
  比现在更脆。

**代价**

- 首帧的相机从「固定 0.7」变成「按当前节点范围算出来」⇒ 第一次进入图谱页时
  相机值与现状不同（这正是要修的）。已有的 `localStorage` 布局种子
  （`graph-physics.js:43-48` 的 `lk_graph_layout_v1_<workspace>`）**不受影响**：
  种子里存的是节点 id 与坐标，节点数与坐标语义都没变（见 Migration Plan）。

1. **同一份输入**：同一章节（dmath/ch06）的图谱模型 JSON；

3. **判据**：`diff = 0` —— 逐节点比较，**坐标差必须为 0**（不是「≤0.1px 的取整误差」：
   同一份代码、同一个浏览器、同一份输入 ⇒ 结果**逐位相同**；
   若出现非零差，说明改动越界到了算法 ⇒ **必须回退**）。
   〔口径〕`acceptance.md` 的 **SI-3** 允许 ≤0.1px 的存储取整误差，
   那条针对的是「**同一实现**重跑两次」的确定性；
   **SI-0 针对的是「改造前 vs 改造后」的跨实现比较**，判据是**严格 0**。
4. **留证据**：脚本、两次的坐标 JSON、diff 报告各存一份，
   路径与复跑命令写进 `tasks.md` 第 14 组。
5. **脚本位置**：随本变更落地（`tools/` 或 `tests/` 下的只读脚本），
   **不得写池**（走 `acceptance.md` §5 的池副本协议）。

## Risks / Trade-offs

| # | 风险 | 缓解 |
|---|---|---|
| R-1 | **屏幕像素点只有 5–13px 半径（直径 10–26px）⇒ 画面可能「太空」**：〔实证/估算〕860×460 画布、Fit 后节点簇约 410×424 屏幕 px，31 枚半径 5–13 的圆合计约 3,900 px² ⇒ **覆盖率约 2%** —— 密度问题从「点太大」彻底转成了「**点太小 + 留白偏大**」：同屏能一眼看完的点更少，且小点的可点击性变差 | 四道缓解：① **点缩小 ⇒ 标签（12px 恒定）成为主导视觉层**，密度由标签让位（D-6）消化；② **命中区下限 24 屏幕 px**（D-3），保证小点仍可点；③ **物理间距不变**（A-26）⇒ 放大永远是有效的分离手段（且放大不改变点的大小，语义一致）；④ **兜底**：若走查判定过疏，唯一可调的是 D-3 的区间上界（一个常数），改动需同步改 spec。〔参照〕Obsidian 官方也是「点小 + 留白大」，且它的点同样小到 8px 下限（`OBSIDIAN-GRAPH.md` §1.2） |
| R-2 | **关系线在 alpha 0.3 下有效对比度只有 1.21–1.49**（〔实证〕混合后的实测值）—— 发丝线在浅纸上接近「若有若无」 | 〔诚实登记〕这是 A-24.3 的既定形态（Obsidian 式发丝线），**不是缺陷**；可读性由**色相 + 虚实节奏 + 箭头 + 图例**承担，焦点强调沿用现有的 `edgeFocus` 机制。若走查判定「读不出关系类型」，可选的调整是**只提高 `legacy` / `related` 两类的 alpha**（不动其余三类）—— 这属于**绘制层**，不触碰 A-26 的冻结线 |
| R-3 | **常态点无描边 ⇒ 选中态要靠四条通道叠加才显眼**（D-8） | 换色 + 1px 描边环 + 放大 + 标签提亮（字重 700）四通道；选中标签永不隐藏（D-6）；选中放大取 1.12 而非更大（D-8 的代价段）。〔参照〕这正是 Obsidian 官方的高亮机制（`OBSIDIAN-GRAPH.md` §1.3） |
| R-4 | **状态冗余通道变窄**：新形态没有「同心圆几何」可作冗余线索，颜色成了状态的**主要**通道 | 冗余改由**半径序 + 径向序**（状态投影的 `scoreFor` → `stateAttention` → 大小与到中心的距离）承担，**加上**图例、学习看板与无障碍名；A-26 冻结了投影语义 ⇒ 这两条几何通道**本来就是现成的**，不需要新增机制 |
| R-4b | **两个数值投影里半径恒为 13px**（D-3.4，A-28 的字面取值）⇒ 「值越大点越大」在这两档投影里**不再成立**，`Metric projection morphology` 的该句必须被本 delta **显式改写** | 已在本变更的 `workbench-ui` delta 里写明（量值由**圆心数字 + 色阶**承载）；**并作为待裁决项登记**（Open Questions 第 5 条）：若 A-28 的「13px」原意是「下限抬到 8px」，则该句无需改写，radius 恢复随量值变化 |
| R-4c | **标签的对数淡出与「常态可见」的张力**：Obsidian 的公式 `log2(s)+1` 会让本项目默认 Fit（s ≈ 0.41–0.47）的标签 alpha = 0 | 本设计把常数取 **+2**（D-6.5）⇒ `s ≥ 0.5` 时 alpha = 1（默认视图标签照常可见），`0.25 ≤ s < 0.5` 时按对数淡出，`s ≤ 0.25` 时消失。〔口径〕这是 A-28「缩放 < 0.5 时按对数淡出」的字面含义，且**与被删掉的「按缩放阈值硬隐藏」不是一回事** |

**Trade-offs（明确的取舍，不是缺陷）**

- **世界层保精度 vs 屏幕层保可读**：D-1 选了「逻辑层不动、绘制层屏幕化」。
  代价是标签的世界占位与模型脱节（R-3 的旧版），换来的是物理零改动。
- **保布局不变 vs 保点的大小层次**：D-3 选了「物理半径不动、绘制半径单调映射」。
  代价是极端值之间的视觉差被压平（见 D-3 的代价）。
- **保关系线统一 vs 保强度可见**：D-7 选了「1.25px / 0.3 统一 + 箭头」。
  代价是「更强的关系画得更粗」这条旧线索消失（R-2）。
- **保标签完整 vs 保画面干净**：D-6 选了「不截断 + 重叠让位」。
- **保底噪 vs 保帧率**：D-9 选了「保观感、砍实现成本」。
- **保亮色的关系线颜色不变 vs 夜纸的可读性**：D-12.2 选了「亮色不变、夜纸换值」。

## Migration Plan

1. **无数据迁移**：无 schema 变更、无 API 变更、无 CLI 变更、无持久化字段变更。
2. **部署顺序**：
   ① `workbench-visual-language-v2`（token 层 + 夜纸基色）先合入；
   ② 本变更再合入（`workbench-ui` delta 以 v2 之后的整块为准）。
3. **本地布局种子的兼容**：`localStorage` 的 `lk_graph_layout_v1_<workspace>`
   存的是节点 id 集合与坐标；本变更**不改变节点数、不改变坐标语义**
   ⇒ 旧种子继续有效，**不需要清缓存**。
4. **回滚**：纯前端静态资源改动 ⇒ 回滚 CSS / JS 提交即可，**无数据需要回滚**。
5. **静态资源缓存**：`app.py:214-232` 的 `_send_static` **不发** `Cache-Control` /
   `ETag` ⇒ 浏览器启发式缓存可能遮蔽新样式（graph-isolation.md F-18）。
   ⇒ 验证与截图前一律**硬刷新**；本次**不**顺手加长缓存（避免把缓存问题带进变更）。
6. **验证节奏**（每个可验证单元都跑）：
   ```bash
   python -m pytest tests -q
   python -m compileall -q lessonkit.py workbench pipeline pool tests
   openspec validate --specs --strict
   ```
   外加图谱专项：
   - graph-isolation.md §5.5 的只读自检脚本（区段零全局依赖 / 12 个裸名 /
     Georgia 5 处行号不变 / 关键值未改 / 128px 预留仍在 / reduced-motion 兜底仍在 /

   - D-10 的「死规则命中 0 次」断言；

   - **D-13.3 的 diff = 0 对比脚本**（改造前跑一次存档，改造后跑一次比对）。

## Open Questions

只放**可延后**、且**不改变规格 / 方案 / 任务拆分**的问题：

1. **底噪预渲染的分辨率倍率**：本设计取 ½。若 ½ 在低端机上仍不够，
   可降到 ⅓ —— 只影响实现参数，不影响观感判定与规格。
2. **标签让位的「让位对象」权重**：本设计用「半径 → 重要度 → id」。
   若实际使用中觉得「大节点更该保留标签」，可调换前两项 —— 属实现参数。
3. **量值分档的 4 档阈值**（`.25 / .5 / .75`）与结构投影的 3 档阈值：
   需用真实分布校准；若某一档在某章空置，可改用分位数分档 —— 不改「单色阶」这一规格。
4. **夜纸下 `.graph-tide` 的透明度**：夜纸的底噪需要单独压暗（亮纸下是
   `opacity: .92` + `multiply`）。取值属实现参数，但**必须在夜纸值集里显式给出**
   （不能沿用亮纸的 multiply 结果）—— 实施时定稿即可。
5. **关系线各类型的 alpha 是否需要分级**：本设计按 A-24.3 取统一的 0.3；
   若走查判定最弱的两类不可辨，可只提这两类（R-2 的可选调整，属绘制层）。
6. **〔待裁决，影响 delta 文本〕A-28 的「半径下限提到 13px」是否只针对「容下 12px 的字」这一个理由**：
   - 本设计按 **A-28 的字面取值**执行：在**题目数量 / 重要性**两个投影里，
     绘制半径**恒为 13px**（D-3.4）⇒ 这两档投影里「值越大点越大」不再成立，
     `workbench-ui` delta 的 `Metric projection morphology` 已按此**显式改写**。
   - **若 A-28 的原意是「下限抬到 8px」**（即 12px 的字在 16px 直径的圆里放得下），
     则半径恢复随量值变化（5→13），该句**无需改写**。
   - 〔口径〕两条路的**规格差别只有一处**：数值投影里半径是否随量值变化。
     **实施时按裁决改这一处即可**，其余（D-2/D-6/D-7/D-8、色板、冻结清单）不受影响。
7. **标签对数淡出的常数**（D-6.5）：本设计取 `clamp(log2(s) + 2, 0, 1)`。
   若走查判定默认 Fit 下标签仍偏淡，可把常数调到 +3（更早淡出）——
   属实现参数，不改「缩放 < 0.5 时按对数淡出」这一规格。
