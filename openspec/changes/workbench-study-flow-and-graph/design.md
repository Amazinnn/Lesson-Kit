## Context

已有池子已具备题目、知识点、反馈、信号和调度；问题在消费端。题目表没有短标题或主题，图谱是陈旧 HTML iframe，练习把单题消息追加成聊天记录，并在未反馈的操作中写 attempt。

## Decisions

1. 正式题和候选题增加 `display_title`、`topic_label` 两个可空增量列；现有 303 题先生成初稿，再通过长度、空值、重复和主题覆盖检查以及不少于 30 题人工抽检后回填。标题为 6–16 个中文字符，主题为 2–10 个中文字符。
2. 增加知识点与题目的覆盖式当前状态。状态为 `needs_work`、`review`、`mastered`；评分 1–2、3–4、5 分别映射到它们。评分照旧写 feedback、信号、进度和调度；图谱手动状态只覆盖当前状态并以等价评分更新调度，不写 feedback event 或 learner signal。
3. 图谱模型从当前 SQLite 数据构建，不读取输出目录中的静态 HTML。工作台中栏承载搜索、筛选、缩放和聚焦；右栏在“知识点详情”和“AI 教师”之间切换，避免嵌套三栏。
4. 练习开始前必须选择模式。会话只在浏览器 sessionStorage 中保存模式、已见题、未提交答案和待评分项；每次拉题将已见题传入 `exclude_ids`。跳题、显示解析、提前结束和未提交草稿不写池子。
5. 每题自评在“保存并下一题”时调用既有 feedback API；统一自评在会话末收集已完成题，并逐题复用相同 API。提前结束统一自评会话时进入集中评分；每题自评会话直接结束。

## Interfaces

- 既有 `/api/w/{workspace}/feedback` 请求体保持不变。
- 新增工作台内部 `GET /api/w/{workspace}/graph/model`，返回当前章节节点、边、状态和详情所需的安全字段。
- 新增工作台内部 `POST /api/w/{workspace}/graph/state`，接收 `item_type`、`item_id`、`state`，覆盖当前状态并更新调度。
- 既有路由和 `wb_session_*`、`wb_kps_*`、`wb_current_*` 语义保持；练习会话在现有 session 值中兼容地增加模式、已见题和待评分项。

## Risks and Migration

- 旧数据缺少标题与主题时，页面使用短截题干作为临时展示，不显示裸 ID 作为主文本；验收前必须完成实际题池回填。
- 新的当前状态表首次读取时从现有进度/反馈推导一份状态，不插入历史事件。
- 图谱可编辑范围仅限知识点正文、薄弱说明和题目/知识点当前状态；关系、题干、答案和删除操作不开放。

## Non-Goals

- 不增加优先级筛选、固定题数、学习目标、深色主题、拖拽栏宽、AI 多轮对话或新的 Bridge 操作。
