## 0. 一句话结论（先说最要紧的）

**「挑一版候选」这个框架是走偏的。候选路线应当作废，直接照 `layout-spec.md` 实现。**

理由（三条，都可验证）：

1. **版式早就被规格过了**：`design-notes/layout-spec.md`（1825 行《布局与线框规格书 ·
   柔和蒙德里安 v2》）对三栏几何、标题带、双轨测量、纸面层级、五个页面线框、
   30 行密度分区表逐条给了数值。**四版候选是重造了一个更弱的版本。**
2. **「样板基线」并不等于「规格的实现」**（本波最重要的实测发现，见 §3）：
   样板做于 2026-10-22 12:22–14:31，而**规格从当天 08:08 起就已经写死**
   `h1 30/38`、`卡高 56`、`组头 12px 三级灰` —— 样板却用了另一组数
   （`h1 28/36`、`卡高 48`、`组头 16px 强墨`）。
   ⇒ **样板是「与规格同源的另一代设计」，不是规格的忠实实现。**
   所有者觉得样板好看，**不是因为它更符合规格**，而是因为它的**构图**
   （章节分组、扁平行、留白、层级）与**三处数值**。
3. **候选相对规格没有一处系统性优势**：§3 的逐条对照显示，四版候选在
   **16 条规格条款**上合计**没有一条是「候选独有的优点」**，绝大多数条款是**偏离**。

⇒ **所以本波把板子的框架改了**：「样板基线 vs 现状」升为主框架，
候选**降级为附录**（逐条标注符合/偏离），并新增 **S5「规格实现」**——
照规格施工的那一版，可以直接拿去和样板并排看。

## 4. 四版候选要不要留？（**明确回答**）

**答：建议作废，但保留在板子的「附录」里作为「已经排除过的思路」，不要作为可选方案。**

**理由**：

1. **它们相对规格没有一处系统性优势。** 16 条规格条款逐条对照：
   - S1（一张纸）：偏离 8 条 / 部分 4 条 / 符合 4 条 —— **核心主张「版面层零卡面」与 §4.4
     正面冲突**（卡 = 12px 圆角 + 柔影 lv1，且「elev-1 第一层不能省」）。
   - S2（分带）：偏离 10 条 —— 「带」是规格里**没有的一层版式**（§4.4 只有底/卡/浮起/沉底）。
   - S3（分组卡）：偏离 7 条 —— 最接近规格（保留了组级卡面 + 柔影），但「组卡」仍是规格外的一层，
     且知识点**按规格就该是卡**（§5.4「知识点卡」），不是「组卡 + 行」。
   - S4（书页）：偏离 8 条 —— 「书页」是规格外的一层，且把中栏可用宽从 676 压到 580。
   - **没有任何一条「候选独有的优点」**：候选要解决的「31 个一样的卡」，
     规格的答案是**卡高 56 + 圆点左置 + 题数右置 + 组头带条目数 + 计数条**（**构图**），
     不是「去面化」。
2. **它们把「有影比例 73.9%」当成病**。但 §4.4 明写卡级纸面**就该带柔影 lv1**，
   真正的问题是**同一张卡被重复 31 次**。S5 落地后**有影比例仍是 76.1%**，
   但页面读起来已经不一样了 ⇒ **原诊断的「76.2% 带影」不是病因**（这是本波对诊断的一次修正）。
3. **S1–S4 全部没有解决 D3 的右栏空**（14% vs 地板 20%），因为那需要 C 路（交互变更）。

**保留它们的唯一价值**：作为「已经排除过的思路」留在附录，让所有者能一眼确认
「这四条路都试过了，都比规格弱」。

## 7. 诚实回报（哪些没做到 / 哪些仍不如样板）

### 7.1 没做到的

1. **S5 只是「纯 CSS 覆盖层」，不是真实现。** 它落在**真实产品 DOM** 上，
   因此凡是规格要求**改 markup** 的地方，它都做不到，只能标注：
   - §5.4 组头**右侧条目数**（产品 DOM 没有计数元素）
   - §4.1 ③ 标题带**摘要句** `.page-summary`（产品 DOM 没有）
   - §4.1 ④ 标题带**动作区** `.page-header-actions`（排序控件在标题带**下面**的独立条）
   - §5.6 记录中心**明细卡流 2 列网格**：产品的最近作答是纵向 `.record-run` 流，
     强行改网格会把不同题目的 run 混在一行 ⇒ **主动没做**，并在 CSS 里注明。
   ⇒ **要真正落地规格，这三处 markup 是必须的** ⇒ 应开一个独立 change。
2. **数据轨 1120 在 1440 视口下看不到效果**：中栏只有 740px，内容区 676px
   ⇒ 1120 的轨**装不下**，与样板在 1440 下也是 676（**两边一样**）。
   数据轨要到 **视口 ≥ 1884px** 才有区别。⇒ 板子的截图都是 1440，**看不出数据轨的价值**；
   这是 DRIFT-3 的现实影响，值得单独提请所有者注意。
3. **样板页的「整页」做不到**：file:// 下父页面**跨源**读不到 iframe 的文档
   （Chrome 把每个 file:// 文档当独立源）⇒ 样板只能 900 高 + 内部滚动，板上已注明。
4. **图谱页与壳层没有产品侧对应页** ⇒ 这两组只有样板一档（板上明说）。
5. **DRIFT-1 / DRIFT-4 未裁决** ⇒ 章透镜面板的计数槽仍是空的；章节名仍渲染载荷原值 `ch06`。
   **这不是我能定的**，已在板上单列。
6. **没跑全量 pytest**（理由见 §6）。

### 7.2 哪些仍然不如样板（明说，不粉饰）

- **S5 在知识页上已经非常接近样板**（轨宽 676 == 676、行内距 12/16 == 12/16、
  圆角 12 == 12、柔影 ✔、圆点左置 ✔、题数右置 ✔、列表 gap 8 == 8），
  **但仍有三处不如样板**：
  1. **组头没有条目数**（样板有「5 个」；产品 DOM 没有 ⇒ markup）
  2. **组头是 12px 三级灰，样板是 16px 强墨**（= 规格 vs 样板冲突，未裁决）
  3. **卡高 56 vs 样板 48**（= 规格 vs 样板冲突，未裁决）
- **S5 的左栏仍然是产品的 A-115 组件形态**（工作区下拉 + 页面导航 + 设置），
  **样板的左栏是更早的静态导航**（练习/试卷/知识点/图谱/记录）——
  ⇒ **这一处的「不如样板」不是候选的错，是组件形态的既有裁定（A-115 §4.30）**，
  板子**不能**、也不该动它。
- **S1–S4 相对样板全面更差**（去面化把样板的卡面语言也去掉了），
  **相对规格也更差**（§4.4 正面冲突）。
- **S5 的面块数与有影比例与现状几乎一样**（46 / 76.1% vs 46 / 73.9%）
  ⇒ **S5 不是「更少的面」，是「同样数量的面、但每一块都对**」**。
  如果所有者的验收标准是「面块数要降」，S5 不满足；**但那是原诊断的错指标**
  （§4.4 说卡就该带影）。
