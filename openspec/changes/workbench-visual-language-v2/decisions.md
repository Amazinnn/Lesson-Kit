### ⟲ 转向影响清单（2026-10-21 方向转向）

用户指出：枯燥乏味「一部分原因就是为了追求书纸质感而一味仿古」，要求**多参考多邻国
那种新潮圆润的操作风格**。标 ⟲ 的 14 条决定与此冲突，已在第 6 组重新拍板。

**第 6 组结论 —— 新基线（自此为准；⟲ 各条的旧值作废）：**

| 主题 | 新基线 | 相对旧决定的变化 |
|---|---|---|
| 整体气质 | **暖色 + 现代圆润** | 底色仍偏暖（这是与冷白工具的区分度），但骨架换掉：大圆角、饱和色块、无衬线、圆润图标、活泼动效。像多邻国但更沉稳学术 |
| 圆角 | **12px 大圆** | 取代「微圆 4–6px」。按钮/卡片/标签/输入框统一 12px |
| 色彩 | **三角色但更饱和** | 蓝/黄/红三角色保留（不引入第五色），但深蓝换成更亮的蓝、提高饱和与明度，让界面活起来 |
| 作答明细 | **圆角卡片流** | 取代「真表格」（用户原话：「表格还是太 nerd 了」）。每条记录一张圆角小卡，不描边，只靠留白与柔影分隔 |
| 纸与纸的区分 | **靠圆角 + 柔影分层，不用描边** | 取代「暖灰细线」；现代圆润风里描边会显旧 |
| 抬起的表达 | **大圆角 + 柔和阴影** | 取代「暖调阴影 + 淡墨线」；去掉墨线 |
| 纸纹 | **待定**（第 7 组） | 圆润风下纸纹可能反而显得旧 |
| 底色 / 墨色 / 正文字号 / 行高行宽 / 单侧结构线 | **待重选**（第 7 组） | 旧值作废 |
| 蓝/黄/红的**语义配额** | 保留：蓝=主按钮+链接+当前选中；黄=当前+复习强调；红=失败+阻塞 | 只改饱和度，不改语义 |
| 不加第五色 | 保留 | 但「已掌握/正确」仍需文案与几何表达 |

- 升级**不是**给每档写一套动画：一份横幅 + 4 个参数化输入 + 一个 trigger

- 结算页整屏换色（`COMBO_RUN`）属第二期。

### 多邻国调研结论（已固化）

来源：`tmp/frontend-audit/DUOLINGO-CELBRATION.md`（公开资料 50 个 URL，官方 12）、
`DUOLINGO-ANIM-IMPL.md`（反编译源码）、`DUOLINGO-PHILOSOPHY.md`（反编译源码）、
`DUOLINGO-FEEDBACK.md`（反编译源码）。

**可迁移的 craft**：
1. **庆祝是分层系统，不是一段固定动画**：官方博客明确有 *mid-lesson animations*
   （连对 N 题触发的中段奖励）；大庆祝只留给里程碑。第三方拆解原话：
   *"Most apps celebrate every action with the same animation; users see it twice and
   the third time it becomes wallpaper. Reserving the celebration for landmarks is
   what keeps it powerful."*
2. **标志性三件套 = 角色 + 滚动数字 + 进度条**；彩带只出现在少数里程碑级动画里。
3. **反馈要分级 + 随机不重复**（源码：11 档 `grade_correct_*` 字符串，教练按随机抽取）。
4. **错误是学习材料，当场回收再练**（源码：`shouldRecycle`、
   `SmarterMistakeRecycleTokens`、错题插队位置表）。
5. **答错后给一屏讲解，且节流 + 可被评价**（`SmartTipPolicy` 带
   `minimumTimeBetweenShows`）。
6. **提示是内联渐进披露**（`UnderlineSpan` + `numHintsTapped` 持久化）。
7. **难度双向可调、升级可见**（`great_job_lets_make_it_a_bit_harder`）。
8. **错误预算显式可见 + 临界预警**（`mistakesRemaining`、
   `checkpoint_test_one_mistake_coach`）。
9. **复习按知识成分粒度，错题有有效期**（`MistakesTracker` 28 天 / 84 天双档、
   `SkillProgress.isDecayed`）。
10. **学习循环与奖励循环分离**（源码：两套几乎不交叉的子系统）——这正是该抄的分层。

**明确不照搬**（会破坏 lesson-kit 自己的哲学，见 `docs/design/philosophy.md`）：
XP 与倍率、COMBO 连击、心/能量限流、连胜 streak + 冻结卡、每日目标、排行榜/联盟、
徽章 accolade（`SuperFast` 奖励「快」，与精读相悖）、宝石掉落、广告插播、拟人动画。

**反面教训**：强制动画引发大量反弹（11 条标题级证据，含 ADHD 用户要求彻底关闭）；
多邻国的解法是**分层 + 提供动画开关**，不是砍掉庆祝 —— 这正好落进我们已定的
「动效偏好（设置视图）」位置。

## 第 1 组 — 纸与墨：视觉语言的体温

### 1.1 纸的底色 → **灰卡纸**
- **微黄旧纸** `#f7f3e8`：像翻过的教材纸，比现在明显黄一度、沉一度；长时间看更舒服，也一眼和「另一个白底工具」区分开；风险是黄过头显脏。
- **纯暖白（现状）** `#fffdf7`：干净、克制、不出错；但正因为这样，它跟市面上任何一个白底工具没有区别。
- **冷调白** `#fbfcfd`：几乎不带黄，更接近显示器的白；干净利落、现代，但会把「纸」这个感觉抹掉，变成纯屏幕界面。
- **灰卡纸** ✅ `#f2efe6`：明显是纸的颜色，哑光；气质最接近印刷品；但墨字与背景的对比要重新配，全部文字颜色得跟着调。

### 1.2 墨色 → **暖炭褐**
- **暖炭褐** ✅ `#221f1a`：黑里带一点褐，和暖纸同源；字不刺眼，长时间阅读更融；对比度比纯黑略低但仍很高。
- **纯墨黑（现状）** `#171717`：对比最强、最锐利；但在暖纸上会有一点「黑」的异物感。
- **蓝黑** `#14161c`：略带蓝的黑，和暖纸形成冷暖对撞；更锐利、更有印刷感，但整体从「暖纸」偏向「冷器物」。
- **绝对黑** `#000000`：对比最强、最像油墨印刷；但大面积使用容易发闷发廉价，与米色纸搭配显生硬。

### 1.3 纸与纸的区分 → **中对比**
- **高对比**：卡片和底纸明度差拉大，一眼分得开；层级最清楚，但容易生硬、像卡片堆。
- **中对比** ✅：卡片只比底纸亮一点点，靠描边 + 阴影区分；柔和，像真的纸叠着纸——这是「柔和蒙德里安」最本分的做法。
- **低对比**：卡片和底纸几乎融在一起，靠留白和字重分区；最克制安静，但层级最弱，容易重新滑回「一片空白」。

### 1.4 纸纹 → **极淡噪点**
- **极淡噪点** ✅：3–5% 强度的噪点，远看是纯色、近看有颗粒；印刷品质的关键一笔，成本极低（一张内联 SVG 噪声图）。
- **无纹理（现状）**：纯色平涂；性能最好、最不干扰阅读，但页面会一直是「电子屏幕」的感觉。
- **可见纸纹**：能看出纤维与纹理；质感最强、最像真纸，但满屏铺开会干扰长文阅读，渲染开销也更高。

## 第 2 组 — 纸面层级与边缘

### 2.1 抬起的表达 → **暖调阴影 + 一根淡墨线**
- **暖调阴影 + 一根淡墨线** ✅：一层很淡的暖调阴影（不是纯黑）+ 一根 1px 淡墨线。最能读出「厚度」，又不会脏。
- **只投影**：不碰线，只用一层柔和阴影；像纸片离桌面 2 毫米。干净，但深色模式下阴影失效，需要另做一套。
- **只加粗墨线**：不投影，只把边缘线从 1px 加到 2px；极简、像框线印刷品；满屏粗框会显吵。
- **只靠底色差**：不投影、不描边，只靠卡片底色比页面亮一点；最轻最快，但层级最弱。

### 2.2 圆角 → **微圆 4–6px**
- **微圆** ✅：现状是 6px，保持微圆但可收成 4px；既有纸的柔和感，又不像消费级 App。
- **近乎直角 0–2px**：像裁切的书页，瑞士国际主义风；最锐利、最像印刷品，但满屏矩形会有点冷硬。
- **明显圆 10–14px**：像现代 App（现状里的 22px 其实是胶囊形状）；更「软件」、更亲和。
- **胶囊形**：按钮、标签、输入框全部全圆；消费级、亲和，但与「学术/印刷」气质直接冲突。

### 2.3 描边 → **暖灰细线**
- **暖灰细线** ✅ `#cfc7b4` 1px：像纸张裁切的毛边，与底色浑然一体；这是「印出来」的关键一笔。
- **深墨线** `#221f1a` 1px：结构感最强、一眼分得清；但满屏黑框会吵。
- **黑 alpha（现状）** `rgb(0 0 0 / 10%)`：中性灰；便宜，但与暖纸不同源，合成不出「纸」的感觉。
- **无描边，只靠阴影**：最干净；但夜纸模式下阴影基本失效，得换亮边，等于多写一套规则。

### 2.4 纸面层数 → **4 层**
- **4 层** ✅：页底（最深的纸）/ 卡片（略亮）/ 抬起（最亮 + 阴影）/ 墨块（深色，代码块与选中项）。层次刚好够用。
- **3 层**：只有页底 / 卡片 / 抬起；代码块、选中项、深色提示没有专属层，会开始硬挤。
- **5 层以上**：细分更多层；表现力最强，但 token 变多、后续维护容易走样。

## 第 3 组 — 色彩角色配额

### 3.1 学习蓝盖面 → **三处统一**
- **三处统一** ✅：主要动作（按钮）+ 可点文字（链接）+ 当前所在（选中项）。看到蓝就知道「这是能点的 / 这是你在这」。
- **再含焦点环与进度**：在三处基础上再把焦点环与进度条统一用蓝；一致性最高，但与「只做主按钮+链接+当前」的克制度冲突。
- **只做主按钮**：全站只允许一个主按钮是蓝的（现在满屏都是）；最克制、最像印刷品，但链接和选中项得另想办法。
- **只做主按钮，链接用墨线**：链接用墨色+下划线（像印刷品）；更像书，但链接不够显眼，且与选中态撞车。

### 3.2 阳光黄用法 → **当前 + 复习强调**
- **当前 + 复习强调** ✅：黄只出现在两处——当前正在做的那一项、到期可复习的东西。语义最锐利。
- **再加重点练习**：三处基础上再加「重点练习/需突破」；但试卷卡现在是**每一张**都顶一条 5px 黄带，等于把黄色降级成装订线——那必须改掉。
- **只做小面积点缀**：黄只出现在极小处（状态点、进度条端头、当前项小竖条）；非常克制、非常印刷。
- **当前 + 主按钮悬停**：黄也参与交互反馈；活泼，但黄色在暖纸上太浅，当悬停色看不清反馈。

### 3.3 注意红用法 → **失败 + 阻塞**
- **失败 + 阻塞** ✅：红只出现在「判错」与「阻塞原因」；最严肃，与「柔和」的整体气质最合。
- **再加警示数字**：再加「逾期 N 天」「连续错 3 次」；红能及时拉注意力，但会多到抢戏。
- **再加不可逆动作**：再加删除/回滚按钮；安全语义最清楚，但红会多到像报错界面。

### 3.4 第五色 → **不加**
- **不加** ✅：保持五色（暖纸/墨/蓝/黄/红）；「已掌握/正确」用文案与几何表达，不靠绿。角色少 = 一致性高。
- **加一个克制的绿** `#2f7a4d`：语义最直观，但多一个角色就多一套维护成本，且与蓝容易混。
- **灰阶承担次要**：不加新色相，次要信息交给灰阶层次；最经济，但「对了」缺一个颜色信号。

## 第 4 组 — 字体与排版

> 既有硬约束：`docs/PRODUCT-MANUAL.md:129-130` —— 知识点详情「正文使用更大的阅读字号、
> 宽行距和单侧结构线，是页面最醒目的内容；提醒和关联题目与正文拉开距离，主题入口保持紧凑」。
> 本组的所有决定必须服从这条。

### 4.1 正文字号 → **17px**
- **17px** ✅：比现状 14px 明显大一档，配 1.75 行高；最像「书上的正文」，也是八份审计三方收敛到的同一个数。
- **16px**：保守一档；表格/列表/记录页不受影响，但正文与界面的差距没那么大，纸感弱一些。
- **18px**：更接近纸书，长文最舒服；但表格与列表会跟着变松，且会挤压界面信息。
- **19px 以上**：过大反而会让正文侵占界面信息区。

### 4.2 行高 / 行宽 → **1.75 / 38em**
- **1.75 / 38em** ✅：行高 1.75、每行约 38 个汉字；最接近纸书节奏，长段落也不易看串行。
- **1.6 / 42em**：更紧凑，一屏信息更多；长文看久了容易累。
- **1.9 / 34em**：行最短、间隔最大，最像纸书；代价是每行字少、滚动变多。
- **1.75 / 42em**：行距舒服、字排得开，兼得两者。

### 4.3 标题字族 → **全无衬线**
- **标题全无衬线** ✅：页面大标题、区块标题、卡片标题全用无衬线，只有正文用衬线；字体切换本身就在说「这是标题 / 这是正文」，层次最清楚。
- **标题也用衬线**：最像一本书；但导航、卡片头这类界面标题会变软。
- **大标题衬线、区块标题无衬线**：层次最丰富，但规则更复杂、后续容易走样。

### 4.4 单侧结构线 → **墨色 2px**
- **墨色 2px** ✅：不占蓝色配额（蓝色已定为只管主按钮/链接/当前选中），且与「墨线为主体」一致。
- **暖灰 2px**：更安静，但存在感弱，可能读不出「这是一块正文」。
- **学习蓝 3px**：现状题面就是 4px 蓝左框（`workbench.css:924-932`），最醒目；但蓝色配额已定为三处，用在这里就超配了。
- **不用线，改浅底带**：安静统一，但会多一层色面，与「四层纸面」抢一个层。

## 第 13 组 — 图案系统（回应 P-2）

### 13.1 图标的形态 → **用户澄清：要「逻辑上与背景相映衬」的具象图标**
原话：「**我的意思是图标必须是逻辑上和背景相映衬，比如说背景是蓝天，那么按钮是白云**
（当然该主题不适用于当前）」。
⇒ 图标不是抽象几何占位符，而应当**指向它所代表的东西**，且整套图标彼此相映衬。

### 13.2 图标色彩 → **彩色圆底色块**
每个图标放在一个淡色/彩色圆底上（现代产品做法）。最活泼、最好认，但图标区会很花。

### 13.3 空态插画 → **要有实物艺术意义，不要抽象体**
原话：「**如果能够有实物艺术意义就好了，我不希望只是一堆抽象体。比如说花瓶、果篮、画布？
不一定是这些，但总得有实物意义。**」
⇒ 插画是**具象静物**，不是抽象几何团块。

### 13.4 背景图案 → **不用背景图案**
底色纯色，不铺任何纹理。图案全部交给元素本身。
（上一轮的「极淡噪点」作废 —— 圆润风下会显旧。）

## 第 14 组 — 图案系统（具象化）

### 14.1 图标具象度 → **具象静物**
每个导航项一个真实小物：练习=翻开的书、试卷=一叠纸、知识点=书签、记录=笔记本、
图谱=节点连线。与空态插画同一支笔、同一套线宽与圆角。
⚠️ 全部手写 SVG（不引图标库），成本随数量线性上升。

### 14.2 空态插画世界 → **学习器物静物**
一组静物：花瓶、果篮、画布、杯子、书本、台灯、钢笔…… 全用同一套线宽与圆角，
像同一支笔画的。与内容无关，只传递「此刻无事」。

### 14.3 笔触与上色 → **柔和渐变 + 高光**
图形本体带一点渐变与高光，更像「插画」而非「图标」。
⚠️ 边界：渐变只允许出现在**图标与插画**内部，不得用于背景或大面积表面；
必须定义一套有限的渐变语言（同一方向、同一组色阶），否则会与纯色圆底界面变成两套体系。

### 14.4 圆底色块颜色来源 → **只用三角色**
圆底色只在蓝/黄/红三角色里取，不同功能区对应不同角色色。守住配额，不会花。
（「每项一个独立色」被否，因为它等于新增一组角色色。）

## 第 15 组 — 庆祝、连对升级、数据层动效

### 15.1 庆祝规模 → **分层：日常轻 / 里程碑重**
日常交卷 = 轻庆祝（完成页入场 + 数字滚动 + 一声音效）；
只有「全对 / 破纪录 / 章节首次完成」才放大。
依据：多邻国结论 —— 每次都用同一段动画，用户看到第三次就变成壁纸。

### 15.2 庆祝形式 → **数字 + 进度 + 几何爆点 ＋ 彩带/纸片飞散（两套都要）**
没有吉祥物，就用我们有的：统计数字滚动 + 进度带从 0 走到 100% + 关键数字周围的柔和几何爆点
（圆环/纸片）；里程碑档再叠上彩带/纸片飞散。
借鉴多邻国「角色 + 滚动数字 + 进度条」三件套的**结构**，换成我们的素材。

### 15.3 连对升级 → **三级计数器 + 5/10 连插播；且进度本身是动效**
- 常驻计数器三档：**灰 → 黄 → 黄→蓝渐变**（对应多邻国的灰 → 绿 `#58cc02` →
  绿→蓝 `#58cc02`→`#1899d6`；我们没有绿，用黄承载「当前做得顺」）。
- 5 连 / 10 连时插播一条横幅；**横幅只做一份**，用参数化输入切不同数字
  （多邻国用同一份 `streakmidlesson_xinarow_31.riv` + 4 个输入）。
- **新增**：连对进度本身是一个动效化的指示器（如多邻国每日打卡的**火苗簇**）——
  随连对数增长，火苗逐簇点亮。
- ⚠️ 多邻国的负反馈规则：**combo > 4 时答错必须给明确负反馈**（`"COMBO LOST"`），
  不能沉默——这条我们要照做。

### 15.4 数据层动效 → **数据层也加微交互**
除负荷柱生长与日历扩散外，数字变化、统计块入场、图表切换都配动效。
（用户明确要求「数据层也加微交互」。）

## 第 16 组 — 夜纸（暗色主题）

### 16.1 夜纸基色 → **暖褐深 `#1c1a16`**
和暖纸同源：白天是米色纸，晚上是「台灯照着的纸」。

### 16.2 夜纸里的彩色圆底图标 → **圆底降饱和 + 提亮**
深底上饱和圆底容易刺眼，降饱和、提亮更柔和。
（代价：与亮色主题的图标不再是同一套颜色，需按主题各调一版。）

### 16.3 夜纸里的插画 → **同一套 SVG 换变量**
用 CSS 变量换前景/背景色，不重画、不多一份资产。

### 16.4 夜纸里的渐变 → **同一套渐变，换色阶**
渐变定义在变量里，夜纸换更暗的色阶与更弱的高光。

### 🔑 16.5 用户原创设计：台灯主题转场（**本轮最高光的想法**）
> 「切换时，会**探出一盏台灯**，然后它**点亮/熄灭**，周围的底色改变随之**呈涟漪状扩散**。」

要点：
- 台灯是**静物插画语言的一部分**（台灯本来就在器物清单里）——P-2 原则的完美落地。
- 动作序列：台灯从角落探出 → 点击/点亮 → 暖色涟漪自灯下扩散铺满（切夜纸）
  或反向收拢（切回暖纸）。
- 这不只是转场，它是**主题切换的叙事**：同一张桌子，灯亮了就进入夜间。
- 实现约束：涟漪扩散只能动 `transform`/`opacity`（用一层放大的径向渐变遮罩做 mask），
  不得阻塞交互、不得改请求时序；必须给 reduced-motion 降级（直接切换，不做涟漪）。

## 第 17 组 — 插画笔触、台灯转场、骨架屏、文案语气

### 17.1 插画笔触 → **写意线稿 + 淡彩**
松弛的手绘线条 + 一层很淡的水彩晕染，像速写本上翻到的那一页。

### 17.4 文案语气 → **简洁功能陈述；能删的界面注释尽量删**

## 追加裁决（2026-10-22，D-01 动效规格提出、所有者拍板）

| # | 待决项 | 裁决 |
|---|---|---|
| A-1 | **涟漪扩散时卡片怎么处理** | **不压平**。卡片全程不动，只有底色从灯下扩散；结构始终清晰，450ms 后一切如初 |
| A-2 | **用户显式动效设置 vs 系统 `prefers-reduced-motion`** | **用户显式设置优先**。在设置里显式开启动效即覆盖系统的减弱动效——那是用户主动做的选择，不是默认。系统设置仍作为**默认值**（默认跟随系统） |
| A-3 | **关键反馈音效的音色** | **清脆木琴 / 玻璃**（短促清脆的玻璃或木琴音），<200ms，不喧宾夺主 |

**由 A-2 派生的实现铁律**（来自 D-01 的实测发现）：
`workbench/server/static/workbench.css:1126-1131` 存在全局兜底
`@media (prefers-reduced-motion: reduce) { *, *::before, *::after { transition: none !important; animation: none !important; } }`。
因此 —— **动效的静态样式必须等于终态**，起始态（如 `opacity: 0`）只能写在
`@keyframes` 内部；否则降级后元素会永远停在「从未出现」的起始态而不可见。

**音效资产来源**：多邻国的 mp3 有版权，不可复用。四个关键反馈音效（答对 / 答错 /
完成 / 里程碑）**自制**，音色按 A-3，文件随本变更引入。

### A-4 「当前」的蓝/黄分工歧义裁决（D-03 提出，对 A-3 段的消歧）

3.1 与 3.2 都写了「当前」，直接照抄会导致状态解码失效（蓝与黄同时指向同一状态）。
裁决：**交互层 = 蓝，内容层 = 黄**。
- **蓝 = 交互层的「当前所在」**：导航选中项、当前题、当前选中的筛选项 —— 即
  「你在哪 / 你点了哪个」。
- **黄 = 内容层的「当前状态」**：当前复习项、当前连对进度、当前练习的到期强调 ——
  即「这个内容现在归你管」。
配套铁律：**黄色一律不承载文字**（黄底上的文字取 `--lk-ink`），黄色只承载面积与形状。

### A-5 自绘控件的载荷兼容铁律（D-03 提出，直接服务底线守卫 G-1）

把 8 处原生 `<select>` 换成自绘下拉，**会打断「请求序列与载荷键集合逐条相同」**这条
底线守卫。因此：**自绘下拉必须保留一个同名 hidden input 承载原来的 `name` / `value`**，

- ~~唯一的例外是亮色主题下图谱必须逐像素不变~~ —— **该例外按 A-12 改写**：
  「亮色逐像素不变」**从图谱的约束里拿掉**（它本来就不可能成立：节点本来就要重画，
  且 A-10.1 已把半径区间从 20–44px 改为 14–30px）；
  v2 的 `acceptance.md` G-5「图谱不在本变更的验收范围内」**只对 v2 有效**，
  图谱 change **不得引用一条不存在的门禁**。
  **图谱 change 自带一份验收基线**（`graph-node-visual-language/acceptance.md`），
  判据是**结构不变量**：节点集合、关系边集合、力导向布局的收敛性与确定性、
  投影语义、交互行为**必须不变**；

## 图谱现状的机制性诊断（来自 `tmp/frontend-audit/GRAPH-NODE-PIPELINE.md`，1114 行 / 180+ 处行号证据）

**「丑」的主因不是配色，是缩放补偿缺失。**

1. **舞台级 `scale()` 把所有排版单位一起缩小**：`workbench.js:1106` 对整个 `.graph-stage`
   做 `scale()`，而 `--size`、`.node-value` 字号、`.label` 12px、卫星点 7px 全是**世界像素**，
   零屏幕补偿。实测 Fit 后 scale = 0.17–0.49 ⇒ 圆直径 **3–30px**、标签 **2.0–5.9px**、
   可见标签 **0–1 / 31**。节点是「看不清的斑点」的直接原因。
2. **`.graph-tide` 每帧重绘约 600 个半透明色斑**（`workbench.js:1482-1488`，
   5 条斜带 × 2–4 车道 × 41–48 点，alpha .05–.13，>5.15px 还套 1.7 倍光晕，
   `mix-blend-mode: multiply`）。**它与图谱数据完全无关** —— 唯一耦合是在节点周围挖洞的遮罩
   （`workbench.js:1515-1530`）。所有者喜欢它（G-4 保留），但它是**每帧 600 个 alpha 混合光斑**
   的开销，与「纸纹底噪」这个功能相比代价过高 —— 建议改为**静态预渲染**或降频。
3. **节点无实体感**：`.node-face` 填充 58% 之外是纯 `--paper`，1px 边框缩放后只有 0.37px
   亚像素 ⇒ 白底上的一根发丝灰圈。
4. **同一视觉通道塞了两个维度**：弧长编码「关系数/题数」，弧色却是 `--kind-color`
   （core 蓝 / support 黄）—— 这正是 G-2「删掉度量弧」的由来。
5. **`.node-wrap.in-scope .status-ring` 是死规则**：`graphSyncScope()`（`workbench.js:1077`）
   是**空函数** ⇒ 唯一表达学习状态的通道只剩一个 2px 灰点，而 28/31 个节点同为 `state-new`。
   学习状态在图上**实质不可辨**。
6. **本章 35 条关系全是 `legacy`（共现隐含）且 `strength: low`** ⇒ 线宽 1.05px / alpha .15，
   是全图最淡一档；图例里的「先修 / 相关 / 应用 / 对比」在本章**一条都没有**，
   且图例的「相关」色 `#aaa399` 与 WebGL 实际线色 `rgb(117,112,104)` **不一致**。
7. **节点只占画布 38% 宽度**：布局包围盒近正方形（1142×1147）而画布宽扁，Fit 被高度卡住；
   且首次 Fit 前相机停在 `scale:.7 / pan(52,-18)`，种子簇在舞台中心 ⇒
   **23/31 节点在画布外**（基线截图正是这一帧）。

> 由此得出图谱 change 的**优先级**：先修 **屏幕空间缩放补偿**（G-24），再落视觉语言。
> 否则新配色做在一个 3px 的圆上看不出来。

### A-9 token 命名与取值的唯一权威（跨工件漂移裁决，2026-10-22）

### A-10 节点半径收窄 + 两个 change 的归档顺序（2026-10-22）

这仍在 G-5 的两个分支之内，且不与既有需求打架。与 G-23（重叠时**隐藏**次要标签）

### A-11 主题偏好的默认来源（覆盖审计发现的「三方冲突」）

### A-13 token 名必须归一；`--lk-*` 与仓库现状**同名**（覆盖审计发现的「第三族」）

覆盖审计发现 `design-notes/component-spec.md`（636 处）与 `design-notes/motion-spec.md`（92 处）
用了**第三套** token 命名族 `--lk-*`（`--lk-blue` / `--lk-ink` / `--lk-radius` / `--lk-ground` /
`--lk-ink-4` / `--lk-ease-out` / `--lk-dur-tap` / `--lk-fs-base` / `--lk-hairline` …）。

**危险在于它与仓库现状同名**：`workbench/server/static/workbench.css` 里现在就有
`--lk-paper:#fffdf7` · `--lk-paper-shade:#f3f1ea` · `--lk-ink:#171717` ·
`--lk-blue:#2457c5` · `--lk-yellow:#f2c94c` · `--lk-red:#d6453d`。
若实现者照抄 `component-spec.md` 的 42 段 CSS，这些新定义会**与现状同名但值不同** ——
CSS 不报错，只会**静默取到另一套值**。这正是 `design.md` D-1 自己指出的失效模式
（「裸名与将来任何新 token 撞车时不会报错，只会静默取到图谱的值」），
只不过这次撞的是**自己的旧 token**。

**裁决**：
1. 权威仍是 `design-notes/night-paper-tokens.md`（A-9）。
2. **第三族 `--lk-*` 整体退役**：`component-spec.md` / `motion-spec.md` / `asset-spec.md`
   里的 `--lk-*` 必须**按概念**映射到权威表的 token 名与取值
   （结构 token 在权威表 §2，值 token 在 §3）。**不得沿用 `--lk-*` 这个前缀。**
3. 映射是**按概念**而非按名字一对一（`--lk-radius` → 权威表的圆角 token、
   `--lk-dur-tap` → 某个时长 token，以权威表实际有的为准），**不得新造 token 名**。
4. 凡权威表里**没有对应物**的（如 `--lk-wash-neutral-strong` 这类中性洗底），
   要么映射到权威表里语义最近且确实存在的那个，要么**登记为待裁决**，不许硬造。
5. A-9 原来那句「多数工件（`component-spec.md` / `asset-spec.md` / `graph-isolation.md`）
   已经跟随权威表」**是错的** —— 那是本次审计纠正的事实，特此更正：
   `component-spec.md` 与 `motion-spec.md` 当时并不跟随权威表。

### A-14 G-5 的比对范围与可复现前提（原为未决项 W-15）

D-08 报告指出：G-5（图谱未被本变更触碰）的**比对范围**（整页 / 画布区域 / 抽样）
与**可比性前提**尚无定论。

**裁决**：
1. 范围取**整页**（最严）—— 零差异像素数必须为 0，不设容差带。
2. 比对**必须在 `prefers-reduced-motion: reduce` 下进行**。理由：图谱的
   "Living graph motion" 既有需求使运动中的帧不可比；而 D-07 / C-8 已实测
   **布局本身是确定性的**（`labelWidth` 等度量与字体无关，物理求解确定性），
   reduced-motion 下 `graph-renderer.js:309` 同步 `draw()`，因此静态帧可比。
3. **先自证基线可复现**：正式比对前，先连跑两次**改造前**基线截图并互比。
   若基线自身不可复现，则**自动降级**到「画布区域 + 固定采样点」，
   并把「基线不可复现」作为一条**待裁决**项登记 —— 而不是默默放宽标准。
4. 这个顺序（**先试最严 → 不可复现才降级 → 降级必须留痕**）比先让所有者拍一个
   可能不可行的方法更实用：方法先自证，不成立才降级。
