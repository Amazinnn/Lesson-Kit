## 1. 作用域与边界

### 1.1 主题属性的作用域

- **主题属性挂在 `<html>`（`document.documentElement`），不挂 `<body>`**。【推】
  理由（可验证）：
  1. `html` 的背景会**传播到画布**（viewport canvas）；若属性挂在 `body`，
     `html` 自身仍是 UA 默认白，滚动条外溢区/移动端地址栏会闪白。
  2. `color-scheme` 必须声明在 `:root`（即 `html`）上，UA 渲染的滚动条、原生控件才跟随。
  3. `:root` 就是 `html`，`:root[data-theme="night"]` 可直接改写 token 块；
     若挂在 `body`，整套 token 块就得搬到 `body[data-theme=…]`，且 `html` 的背景仍需单独特判。
- 现状锚点【锚】：`workbench/server/static/workbench.css:60-71`（`html, body { height:100% }` +
  `body { background: var(--dsw-bg-base) }`）——**底色现在挂在 `body` 上**，改造时必须同时给
  `html` 加 `background-color`，否则画布不跟随。
- 主题属性的取值域：`"day" | "night"`（两值，缺省 `day`）。

### 1.2 知识图谱页的固定边界（**硬约束**）

`SYNTH.md` 硬约束 2：图谱页观感必须与现在完全一致，新 token 层**不得改动图谱依赖的 token 值**。

- 图谱自有的裸名 token 在 `workbench/server/static/workbench.css:1505-1518`
  （`--paper/--ink/--hair/--blue/--yellow/--red/--shadow/--graphite/--green/--blueSoft/--yellowSoft/--redSoft`）
  —— **夜纸值集一律不重定义这些名字**（新 token 层用 `--surface-* / --ink-* / --role-*` 命名，
  与图谱零同名），因此图谱画布本身在两主题下**逐像素不变**。【实】
- 但图谱页是**跑在同一个外壳里**的（`workbench/server/pages.py:410-479` `graph_page()` →
  `shell(..., graph_mode=True)` → `pages.py:68-110`），外壳（顶栏/左栏）会随主题变暗，
  与浅色画布断裂。**因此图谱路由下必须把下面这组 token 钉回浅色值**（两个主题都钉）：【推】

  | 需钉回的 token | 浅色值 | 为什么 |
  |---|---|---|
  | `--surface-base` | `#fdf8ef` | 图谱画布周边底色 |
  | `--surface-card` | `#fffdf7` | 图谱页的卡片面 |
  | `--surface-raised` | `#ffffff` | 浮层 |
  | `--surface-ink` | `#221f1a` | 墨块 |
  | `--ink-strong` / `--ink-body` / `--ink-muted` / `--ink-faint` | `#221f1a` / `#3b3630` / `#6b6459` / `#8d8578` | 图谱内的字 |
  | `--rule-hair` / `--rule-structure` | `#e6dcc4` / `#221f1a` | 图谱内的线 |
  | `--role-blue` / `--role-yellow` / `--role-red` | `#2b62e8` / `#f5c518` / `#d1392b` | 图谱节点色 |

- **⚠️ 未决（需所有者拍板，不在本文件擅自决定）**：夜纸下知识图谱页是
  **(A) 保持浅色现状（本文件的实现前提）**，还是 **(B) 跟随夜纸**？
  (B) 会违反「图谱页观感必须与现在完全一致」的冻结条款，因此本文件按 (A) 写值；
  若选 (B)，必须另开一个 change 并同步 `decisions.md` 的范围条款。

## 4. 对比度实算（WCAG 2.x）

### 4.1 公式与可复现脚本

WCAG 2.x 相对亮度与对比度：

```
L = 0.2126·R' + 0.7152·G' + 0.0722·B'
R' = R/255 ≤ 0.04045 ? R/12.92 : ((R/255 + 0.055)/1.055)^2.4      （G'、B' 同理）
对比度 = (L_亮 + 0.05) / (L_暗 + 0.05)
```

**判定线**（本文件口径）：正文 ≥4.5:1 · 次要文字 ≥3:1 · 大字号 ≥3:1 ·
控件边界 ≥3:1 · 非文本图形 ≥3:1。（大字号 = ≥18.66px 粗体或 ≥24px。）

复现脚本（Python 3 标准库，无第三方依赖；把 §3 的值填进 `L` / `N` 两个字典即可重跑全表）：

```python
def hex2rgb(h):
    h = h.lstrip('#'); return tuple(int(h[i:i+2], 16) for i in (0, 2, 4))
def lin(c):
    c /= 255
    return c/12.92 if c <= 0.04045 else ((c + 0.055)/1.055) ** 2.4
def lum(h):
    r, g, b = hex2rgb(h)
    return 0.2126*lin(r) + 0.7152*lin(g) + 0.0722*lin(b)
def ratio(a, b):
    la, lb = lum(a), lum(b)
    hi, lo = max(la, lb), min(la, lb)
    return (hi + 0.05) / (lo + 0.05)
# ratio('#f4ede0', '#1c1a16') -> 14.9213...
```

## 5. 彩色圆底的夜纸版本（降饱和 + 提亮）

【决】`decisions.md:539-541`（16.2）：夜纸里彩色圆底**降饱和 + 提亮**。
算式（HSL，色相 H 保持不变，只动 S 与 L）：

```
H' = H
S' = S + ΔS      (ΔS < 0，降饱和)
L' = L + ΔL      (ΔL > 0，提亮)
```

| 角色 | 浅色值 | 浅色 HSL | ΔS / ΔL | 夜纸值 | 夜纸 HSL | 与夜纸底 `#1c1a16` 对比度 | 深墨 `#14120f` 压其上 |
|---|---|---|---|---|---|---|---|
| 学习蓝 | `#2b62e8` | H222.5 S80.4 L53.9 | **S−18 / L+12** | `#7291de` | H222.8 S62.1 L65.9 | **5.64:1** | 6.07:1 |
| 阳光黄 | `#f5c518` | H47.0 S91.7 L52.7 | **S−22 / L+7** | `#e0c151` | H47.0 S69.8 L59.8 | **9.86:1** | 10.61:1 |
| 注意红 | `#d1392b` | H5.1 S65.9 L49.4 | **S−11 / L+13** | `#d4736b` | H4.6 S55.0 L62.5 | **5.35:1** | 5.76:1 |

**为什么这组 ΔS/ΔL**：夜纸底 L*=9.35，若角色色不降饱和，同一饱和度的纯色圆底在深底上会
「发光过曝」（对比度冲到 15:1 以上反而刺眼，且与台灯的暖光语义打架）。降饱和 + 提亮后，
三个角色色与底色的对比度落在 5.3–9.9:1 区间——**够分辨、又不过曝**。【推】

**圆底上的字形颜色（关键反相）**：

| 圆底 | 浅色主题的字形 | 实测 | 夜纸主题的字形 | 实测 |
|---|---|---|---|---|
| 学习蓝圆底 | 纸色 `#fffdf7` | 5.14:1 ✅ | 深墨 `#14120f` | 6.07:1 ✅ |
| 阳光黄圆底 | **深墨 `#221f1a`** | 10.07:1 ✅（纸色只有 1.60:1 ❌） | 深墨 `#14120f` | 10.61:1 ✅ |
| 注意红圆底 | 纸色 `#fffdf7` | 4.77:1 ✅ | 深墨 `#14120f` | 5.76:1 ✅ |

> 即：**夜纸里三个圆底的字形统一翻成深墨；浅色主题里只有黄圆底用深墨，蓝/红用纸色。**
> 这是「图标圆底 = 降饱和 + 提亮」在字形层的必然推论，不是额外约定。【实】

## 6. 阴影在夜纸下的失效与替代

### 6.1 失效的实测（**不是「暗色下阴影看不见」这句空话**）

| 实测项 | 浅色 | 夜纸 | 结论 |
|---|---|---|---|
| 卡面与页面底的明度差 | ΔL\* = **1.58** | ΔL\* = **3.01** | 夜纸的**层级台阶大一倍**，纸面本身已能分层 |
| 阴影把页面底压暗后的落差 | `#fdf8ef` → `#f1ece3`，ΔL\* = **4.18** | `#1c1a16` → `#13120f`，ΔL\* = **3.88** | 落差相近，但方向相反 |
| 阴影最暗值与墨块值的撞色 | — | `#13120f` vs `#14120f`：**1.01:1**，ΔL\* = 0.09 | **夜纸的阴影与「墨块」同色** → 读作「一个洞」，不是「抬起」 |
| 顶光（inset 0 1px 0 白 5%） | — | `#2e2a22` vs 卡面：**1.14:1**，ΔL\* = **4.88** | 方向性亮边（光来自上方）→ 夜纸真正的抬升信号 |

**结论**【实】：
1. 浅色主题**不能去掉阴影**——卡面与页面底只差 ΔL\* 1.58，阴影承担了主要层级信息
   （这正是 F01 诊断的 D1/D7：`tmp/frontend-audit/F01.md:117-118`（D1 面同色）、
   `tmp/frontend-audit/F01.md:153-158`（D7 阴影 5% 黑肉眼不可见））。
2. 夜纸**必须换机制**——纸面台阶已经够大（ΔL\* 3.01），而阴影的最暗值与墨块撞色，
   会在卡下方压出一圈「洞」。
3. 夜纸的抬升信号应来自**顶光**（inset 亮边，ΔL\* 4.88）+ **明度阶**，而不是向下的黑影。

### 6.2 替代方案（三件套，全部落在 §3 的 token 里）

| 手段 | 浅色主题 | 夜纸主题 | 代价 |
|---|---|---|---|
| ① 明度阶（底→卡→浮起） | ΔL\* 1.58（弱，靠阴影补） | ΔL\* 3.01（强，主力） | 夜纸的卡比浅色更「亮」，需控制墨块别过暗 |
| ② 顶光（inset 1px 暖白） | 不需要（光从环境来） | `inset 0 1px 0 rgb(255 238 210 / 5~9%)` | 顶部多一条 1px 亮线，需与「无描边」语言共存（它不是描边） |
| ③ 暖辉（外发光，仅浮起/模态） | 不需要 | `0 0 24~32px rgb(255 236 200 / 5~6%)` | 与台灯暖光语义一致，但不可过量（会发灰） |
| ④ 向下柔影（保留但降权） | 主力 | `0 1~20px rgb(0 0 0 / 30~52%)`，只负责把浮层与背景分开 | 夜纸里阴影不再是层级主信号 |

> 全部用 `box-shadow`（外阴影 / 内阴影）实现，**不引入 `border`**——保持基线「不用描边」。
> 顶光 1px 亮边是内阴影，不是描边。【推】

### 6.3 对基线「不用描边」的例外声明（**必须显式承认**）

【决】`decisions.md:595,598`：「纸面分层靠圆角 + 柔影分层，不用描边」；

## 7. 插画与图标的反相规则

【决】`decisions.md:617-619,543-547`：
「插画与主题 = 同一套 SVG，用 CSS 变量换前景/背景色（暗色下自动反相）」；
「图标圆底 = 降饱和 + 提亮」；「渐变 = 同一套渐变，换色阶」。

### 7.1 元素 → 用色 对照表

| 元素 | 浅色主题 | 夜纸主题 | 判据 |
|---|---|---|---|
| 插画线稿（写意线） | `--art-ink` `#2a2620` | `--art-ink` `#e6ddcd` | **必须反相**：深底上深线稿不可见 |
| 插画纸底（器物本体） | `--art-paper` `#fffdf7` | `--art-paper` `#232019` | 与卡面同族；夜纸**不再用白纸**，否则插画会比界面更亮 |
| 插画淡彩（蓝/黄/红） | `--art-wash-*`（角色色混纸 12~18%） | `--art-wash-*`（角色色混夜纸 14~16%） | 同一色相、同一配方，只换混色底 |
| 插画高光 | `--art-highlight` 白 55% | `--art-highlight` 暖白 8% | 夜纸高光**减到 1/7**，否则塑料感 |
| 图标圆底（蓝/黄/红） | 饱和版角色色 | 降饱和 + 提亮版（§5） | 【决】16.2 |
| 圆底上的字形 | 蓝/红 → 纸色；黄 → 深墨 | 三个都是深墨 | 实测见 §5 表 |
| 图标内部渐变 | 角色色 → 混纸 22% + 顶部高光混白 30% | 角色色 → 混夜纸底 30% + 顶部高光混白 16% | 【决】16.4「同一套渐变，换色阶」 |
| 图标内部描边/结构线 | `--art-ink`（深） | `--art-ink`（浅） | 随线稿一起反相 |
| 台灯（转场资产） | 灯罩内侧暖光 `#ffcf7a` 系 | 同色但**外溢更强**（夜里灯是主角） | 台灯是叙事核心，两主题都要亮 |

### 7.2 渐变换阶表（**同一套渐变，只换色阶**）

渐变定义写一次（CSS 变量里定义方向与档位），两主题只换 stop 的颜色值：

| 角色 | 浅色 · 起 → 止 | 浅色 · 顶部高光 | 夜纸 · 起 → 止 | 夜纸 · 顶部高光 |
|---|---|---|---|---|
| 学习蓝 | `#2b62e8` → `#5983ea` | `#6b91ef` | `#7291de` → `#586da2` | `#89a3e3` |
| 阳光黄 | `#f5c518` → `#f7d047` | `#f8d65d` | `#e0c151` → `#a58f3f` | `#e5cb6d` |
| 注意红 | `#d1392b` → `#db6356` | `#df746b` | `#d4736b` → `#9d5852` | `#db8983` |

- 方向：**两主题完全一致**（自上而下，135°，高光在左上）——这是「同一套渐变」的硬要求。【推】
- 浅色的「止」= 角色色向**纸色**混 22%；夜纸的「止」= 角色色向**夜纸底**混 30%。
  两者的差别在于：**浅色靠高光提亮制造圆润，夜纸靠暗端收边制造圆润**（深色上高光过多会发塑料感）。【实】
- 实现上可只写一条渐变定义，用 `color-mix(in oklab, var(--role-blue) 78%, var(--surface-base))`
  让止色随主题自动换底——**一套渐变，两套色阶**，不需要第二份资产。【推】

### 7.3 「用前景色还是纸色」的判据（一句话规则）

> **先看这个元素是「被看见」还是「被看穿」**：
> 被看见（线稿、高光、字形在深色块上）→ 用**对比最强**的那一档；
> 被看穿（纸底、淡彩、渐变止色）→ 用**同族低对比**的那一档。

## 8. 焦点环在夜纸下的形态

| 项 | 浅色 | 夜纸 |
|---|---|---|
| 外圈颜色 | `#2b62e8`（角色蓝） | `#9dbcff`（角色蓝的夜纸提亮档） |
| 外圈宽度 | `2px` | `2px` |
| 外圈偏移 | `2px`（`outline-offset`） | `2px` |
| 光晕（可选） | `0 0 0 4px rgb(43 98 232 / 18%)` | `0 0 0 4px rgb(157 188 255 / 20%)` |
| 内圈（**仅角色填充控件**） | `#fffdf7` | `#14120f` |
| 与卡面对比度 | 5.14:1 ✅ | 8.57:1 ✅ |
| 与页面底对比度 | 4.94:1 ✅ | 9.16:1 ✅ |
| 压蓝按钮（双环内圈） | 5.14:1 ✅ | 6.07:1 ✅ |

**规则**【推】：
1. **默认控件**（透明底 / 卡面底）：单圈 = 外圈色，`outline: 2px solid var(--focus-outer);
   outline-offset: 2px`；偏移出的 2px 间隙露出本地表面，外圈因此始终与**周围表面**对比。
2. **角色填充控件**（主按钮、当前选中块）：**双圈** —— 内圈 2px 贴控件自身填色
   （`box-shadow: 0 0 0 2px var(--focus-inner)`，落在 outline-offset 的间隙里），
   外圈 2px 贴周围表面。这样两个相邻面都 ≥3:1。
3. **不得用 `outline: none`**。现状锚点【锚】：`workbench.css:1123` 已有
   `:focus-visible { outline: 2px solid var(--dsw-brand-accent); outline-offset: 1px }`，
   但仓库里另有三处 `outline: none` 把主路径上的焦点环压死（`proposal.md:16-17` 记为待修缺陷）。
   夜纸值表**不修复**这一点，但 §3.7 的 `--focus-*` 必须与之对齐（offset 由 1px 改 2px）。
4. 焦点环**不依赖主题**的颜色语义之外的东西：浅色用角色蓝、夜纸用角色蓝提亮档，
   两者的色相与浅色一致（仍是蓝），不引入新色相。【决】三角色配额。

## 9. 主题切换的落地约束（**不许引入构建步骤**）

### 9.1 属性挂在 `<html>`，不挂 `<body>`

理由见 §1.1。落地形态：

```html
<!-- pages.py:1096-1106 的 _base() 里，样式表之前插入这一段内联脚本 -->
<script>(function(){
  var ws = "__WS__";                    /* 由服务端注入工作区名 */
  var t = "day";
  try {
    var raw = localStorage.getItem("wb_settings_" + ws);
    var v = raw ? (JSON.parse(raw) || {}).theme : null;
    if (v === "night" || v === "day") { t = v; }
    else if (window.matchMedia &&
             window.matchMedia("(prefers-color-scheme: dark)").matches) { t = "night"; }
  } catch (e) {}
  document.documentElement.setAttribute("data-theme", t);
})();</script>
```

```css
:root              { color-scheme: light; /* §3 的浅色值 */ }
:root[data-theme="night"] { color-scheme: dark;  /* §3 的夜纸值 */ }
```

- **优先级**：显式选择 > 系统偏好（`prefers-color-scheme`）> `day`。这与「主题偏好」定义一致
  （亮/暗主题的浏览器偏好，按工作区存储）。
- 存储沿用现成的分工作区键 `wb_settings_<工作区>`
  （锚点：`workbench/server/static/workbench.js:165` `SETTINGS_KEY = "wb_settings_" + WS`，
  工作区名来自 `workbench.js:8` `layout.dataset.workspace`，由 `pages.py:94` 渲染）。
  **不新增持久化面、不碰池**（符合 G-6）。
- 服务端渲染的 HTML **不得硬写 `data-theme`**（否则与用户偏好相反时会先闪一下错的）；
  服务端只负责把**工作区名**注入脚本（`_base()` 需要新增一个 `workspace` 参数，
  `shell()` 在 `pages.py:110` 调用处已有该值）。

### 9.2 首屏代价（FOUC 方案与代价）

| 项 | 代价 |
|---|---|
| 新增请求 | **0**（内联脚本，不产生网络往返） |
| 新增字节 | 约 330 B（内联 JS）+ `data-theme` 属性 1 个 |
| 首屏执行耗时 | 同步解析执行 < 0.5 ms（无网络） |
| 构建步骤 | **0**（`_base()` 本来就是 Python 字符串拼接，`pages.py:1096-1106`） |
| 第三方依赖 | **0** |
| 降级 | JS 关闭 / `localStorage` 不可用（Safari 隐私模式）→ 落回 `day`，**与今天观感一致，无回退** |
| CSP | 仓库当前**未设 CSP 响应头**（已 grep `workbench/server/*.py` 无 `Content-Security-Policy`），内联脚本不会撞 CSP；将来若引入 CSP，需改用 nonce 或哈希并登记。 |

**为什么不闪烁**：样式表是渲染阻塞的；内联脚本位于 `<head>` 且在样式表**之前**，
浏览器在解析到样式表前不会绘制首帧，因此 `data-theme` 一定在首帧前生效 → **首帧即是最终主题**。
同时 `html` 自身要有 `background-color: var(--surface-base)`（见 §1.1），
使画布（含移动端地址栏、下拉回弹区）跟随主题。

**代价与风险**：
1. **主题值在 HTML 里不可见**（SEO/无 JS 场景无意义——这是纯工具界面，可接受）。
2. 工作区名必须由服务端注入：`_base()` 要加一个参数（**内部函数签名变更**，
   不是用户可感知行为，符合兼容边界）。
3. 主题切换本身**不重载页面**（纯属性翻转），因此 §9.1 的脚本只在**首屏**跑一次。

### 9.3 与台灯转场的关系（**时序**）

【决】台灯转场：探出（~180ms）→ 点亮 → 涟漪扩散铺满（~450ms）→ 灯收回，共 ~700ms
（`decisions.md:568-572`）。

- **属性翻转时机**：在**涟漪即将铺满、颜色被遮住的那一刻**翻转 `data-theme`，
  用户看不到中间态；涟漪用 `transform`/`opacity` 驱动，不阻塞交互、不改请求时序。
- **reduced-motion**：`prefers-reduced-motion: reduce` 时**直接翻转**，不做涟漪
  （`decisions.md:661`）。
- 主题切换**不触发任何请求**，不触碰冻结项（请求序列与载荷不变）。

### 9.4 与设置视图的关系

- 设置视图（`workbench-settings`）里的「主题」开关写的就是 `wb_settings_<ws>.theme`
  （`"day" | "night"`），与首屏脚本读同一个键 → **刷新与重启后保持**（验收 §3.2）。
- 首屏脚本读不到合法值时回落到系统偏好；一旦用户显式选择，写入即固定。
