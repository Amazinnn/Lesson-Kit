## 1. 三栏几何规格

### 1.1 现状：双源问题（本节是必须先解决的问题）

`#layout` 的列宽模板有**两个来源**，桌面端后者永远赢：

| 来源 | 位置 | 内容 | 实际效力 |
|---|---|---|---|
| CSS 规则 | `workbench/server/static/workbench.css:160` | `grid-template-columns: 280px minmax(0, 1fr) 420px;` | **从不生效**（被 inline style 覆盖） |
| JS inline style | `workbench/server/static/workbench.js:4587` | `layout.style.gridTemplateColumns = leftWidth + "px minmax(420px, 1fr) " + rightWidth + "px";` | **唯一生效**的模板 |

- 行内样式优先级高于任何选择器规则，因此 CSS 里那条 `minmax(0,1fr)` 在桌面端是**死规则**。
- `workbench.js:4580-4582` 在 `window.innerWidth < 1024` 时把行内模板清空
  （`layout.style.gridTemplateColumns = ""`），此时才短暂回到 CSS 那条
  `280px minmax(0,1fr) 420px`——但同一条 `@media (max-width:1023px)`
  （`workbench.css:1174-1207`）已把 `#layout` 改成单列，所以那条 CSS 模板在
  **任何视口下都从未真正决定过布局**。
- 后果一（**死亡带**）：JS 模板的最小总宽 = `280 + 420(min) + 420 = 1120px`。
  视口落在 **1024–1119px** 时，网格最小宽 1120 > 视口宽 → **横向溢出 + 横向滚动条**
  （`F08.md:137-144` 记为「1024–1279px 是三栏都挤的死亡带」；精确到像素，溢出区是 1024–1119）。
- 后果二（**中栏最小宽被钉死在 420**）：中栏永远收不到 420px 以下，
  于是「中栏读作一条缝」而不是「中栏可滚动」。
- 后果三（**拖拽上限写死在 JS**）：`workbench.js:4585-4586` 的 `leftWidth` 夹在 200–480、
  `rightWidth` 夹在 360–560，与 CSS 里的 `280/420` 是**两份独立数值**，
  改宽度必须同时改两个文件，否则出现「CSS 写的 280，JS 写的 260」这类漂移。

### 1.2 收敛方案：CSS 持有模板，JS 只写两个列宽变量

**结论（`design.md:740-786` D-10 的原文口径）：列宽模板由 CSS 声明，
JS 只写两个自定义属性，不再写 `grid-template-columns`。**

```css
/* ① 变量写在 #layout 上（不写 :root，避免波及图谱页同名变量） */
#layout {
  --wb-col-left: 280px;
  --wb-col-right: 420px;
  flex: 1;
  min-height: 0;
  display: grid;
  grid-template-columns:
    var(--wb-col-left) minmax(0, 1fr) var(--wb-col-right);
  grid-template-rows: 100%;
  overflow: hidden;
  transition: grid-template-columns 200ms ease;
}
#layout.is-resizing { transition: none; }
#layout[data-ai-collapsed] {
  grid-template-columns: var(--wb-col-left) minmax(0, 1fr) 0px;
}
```

```js
/* ② JS 只写两个数值变量（替换 workbench.js:4587） */
layout.style.setProperty("--wb-col-left", leftWidth + "px");
layout.style.setProperty("--wb-col-right", rightWidth + "px");
```

```css
/* ③ C 档（≤1279）：右栏出栅格 → 抽屉（新增的一条断点） */
@media (max-width: 1279px) {
  #layout,
  #layout[data-ai-collapsed] {
    grid-template-columns: var(--wb-col-left) minmax(0, 1fr);
  }
}
/* ④ D 档（≤1023）：左栏也出栅格（沿用现状 workbench.css:1174-1207 的写法，不动） */
@media (max-width: 1023px) {
  #layout,
  #layout[data-ai-collapsed] { grid-template-columns: 1fr; }
}
```

配套五条规则：

1. **媒体查询改「模板」，不改「变量」。** 断点处整条模板被重写，变量值保留但被夹紧；
   这样 CSS 变量不会因为 JS 残留的行内值而「赢过」断点。
   D-10 明确「媒体查询在窄屏覆盖整条 `grid-template-columns` 的写法**必须保留**
   （`workbench.css:1174-1207` 的 `1fr` 规则更晚、覆盖基础规则），这是既有行为，不动」。
2. **`minmax(0, 1fr)` 是首帧兜底，不是中栏不变式的承担者。**
   D-10 原文：「CSS 的 `minmax(0, 1fr)` 只是**变量未就位时（首帧）的兜底**，
   不承担该不变式」。中栏 ≥420px 由 JS 夹取维持（§1.3）。
3. **夹紧上限归 CSS 常量、JS 读它。** JS 用 `getComputedStyle` 读
   `--wb-col-left-max` / `--wb-col-right-max`，而不是把 200/480/360/560 写死在 JS 里
   （消除 §1.1 后果三）。
4. **旧行内模板必须清空。** `workbench.js:4580-4582` 的
   `layout.style.gridTemplateColumns = ""` 改为
   `layout.style.removeProperty("--wb-col-left")` + `removeProperty("--wb-col-right")`，
   否则迁移期新旧两套会同时存在。
5. **右栏折叠阈值从 1024 移到 1279。** `fitAiColumn()`（`workbench.js:4569-4573`）
   现在用 `window.innerWidth < 1024` 决定 `data-ai-collapsed`；按 §1.4 的 C 档，
   右栏在 **≤1279** 就转抽屉，阈值必须同步改，否则 1024–1279 会出现
   「CSS 模板是单列 + 行内变量仍是三栏」的混合态。

**代价（D-10 已登记，实现期必须处理）**：拖拽时列宽的变化从「整段 inline 样式」
变成「两个自定义属性」，`transition: grid-template-columns 200ms ease`
（`workbench.css:161`）仍生效 → **拖拽时可能出现过渡拖影**，
需在 `#layout.is-resizing` 上关掉过渡（现状已有这条规则位，`workbench.css:162`）。

**验收口径**（实现期必须逐条量测）：

- 视口 1440：`#layout` 的三列实际宽 = `280 / 740 / 420`（±1px）。
- 视口 1280：三列 = `248 / 652 / 380`（±1px）。

- 拖左栏到最左（200px）：右栏不降到 360px 以下，中栏不出现横向滚动条。
- 拖左栏到最右（480px，视口 1440）：右栏**自动收到 540px**、中栏落在 420px（§1.5）。
- 桌面端 `#layout` 的行内 `style` 属性**不含** `grid-template-columns`，
  只含 `--wb-col-left` / `--wb-col-right` 两个自定义属性。
- 拖拽柄在 `#left-column` 右缘 10px 内可命中（现状 `#left-resizer{right:-4px}`
  （`workbench.css:548-551`）骑界，被 `#left-column` 的 `overflow-y:auto` 裁掉一半，
  `F02.md:39`）——**把手柄整体收进栏内**。

### 1.3 夹取规则：中栏 ≥ 420px 的不变式

D-10 把这条不变式的承担者写死为 **JS 夹取**：
> 「「中栏不窄于 420px」的不变式由 JS 的夹取维持（现状 `workbench.js:4584-4586`
> 已按 `available = clientWidth - middleMinWidth` 夹取左右栏）」

`workbench.js:4574` 的常量 `var middleMinWidth = 420;` 就是这条不变式的**唯一数值来源**。
本节把它写成可逐条复核的规则。

**规则 R1（中栏底线）**

```
中栏实宽 M = 网格可用宽 A − 左栏 L − 右栏 R ，且 M ≥ 420
```

**规则 R2（夹取顺序，左右不可交换）**

```
A  = layout.clientWidth            // 网格可用宽
L' = clamp(L,  200, min(480, A − R − 420))     // 先夹左，用**当前** R
R' = clamp(R,  360, min(560, A − L' − 420))    // 再夹右，用**已夹好的** L'
```

- `clamp(v, lo, hi) = max(lo, min(hi, v))`。
- **顺序是「先左后右」**（与现状 `workbench.js:4585-4586` 一致）。
  换序会破坏不变式：若先夹右，左栏的可用空间就按「未夹紧的 L」算，
  中栏可能被挤到 420 以下。
- 两条 clamp 的下界（200 / 360）是**硬地板**：任何情况下左栏不得窄于 200、
  右栏不得窄于 360。若 `A − R − 420 < 200`，则 `L' = 200`，此时
  `M = A − 200 − R` **可能小于 420**——这是**三栏不成立**的信号，
  由**断点**接管（§1.4 的 C 档把右栏移出栅格），不由夹取硬撑。

**规则 R3（首帧）**

- CSS 模板首帧用 `minmax(0, 1fr)`，此时中栏 = `A − 280 − 420`；
  JS 首次 `applyColumnWidths()` 后变量就位，R1 立即生效。
- 首帧的 200ms 过渡（`workbench.css:161`）会从「CSS 默认宽」过渡到「JS 夹紧后的宽」，
  实现期应在首帧前就置好变量，或给 `#layout` 一次 `is-resizing` 抑制过渡。

**规则 R4（右栏折叠态）**

- `#layout[data-ai-collapsed]` 的模板是 `var(--wb-col-left) minmax(0, 1fr) 0px`
  —— 右栏宽 0，**中栏不吃 420 底线**（此时没有三栏）。
  因此 `fitAiColumn()` 折叠右栏时，**必须同时把 R 置 0 并跳过 R1/R2 的中栏夹取**，
  否则会算出一个「本该给右栏的 420px」。

**规则 R5（拖拽中）**

- 拖拽把手的实时宽度计算（`workbench.js:4607-4610`）也必须走 R2：
  `cap = side === "left" ? A − R − 420 : A − L' − 420`，
  现状写的是 `available - rightWidth` / `available - leftWidth`（`workbench.js:4607`），
  **少了减 420 那一项**——迁移时必须一并改，否则拖到极限会突破中栏底线。

**开关语义如何保留**：既有 spec 要求「a switch whose off state means the whole course
and whose on-state selects exactly one chapter」（`workbench-ui/spec.md:831-833`）。
本规格用**一个可见控件**（chip）同时承担「开关 + 选择」：

| 现状 | 新版 |
|---|---|
| `checkbox#chapter-lens-switch`（开关）+ 「章」span（标签）+ `select#chapter-lens-select`（选择）——**三件可见物** | **一个** chip（触发器兼状态显示）+ 一个浮层面板 |
| 关：`select` 隐藏（`pages.py:62`） | 关：chip 读「全部章节」，面板里只有「整门课」与章列表 |
| 开：`select` 可见，显示当前章 | 开：chip 读当前章（载荷原值），面板底行出现「回到整门课」 |

**写入路径零变更**：`workbench.js:60-64` 的 `applyChapter(chapter)` 向 `/chapter`
POST `{chapter: …}` 再 `refreshMiddle()`。自绘面板**必须走同一条路径**，
不得新增端点、不得改载荷键。

**载荷兼容铁律（A-5）**：自绘控件**必须保留同名 hidden input 承载原 `name` / `value`**。
本控件现状的 `checkbox#chapter-lens-switch` 与 `select#chapter-lens-select`
**都没有 `name` 属性**（`pages.py:57-63`），因此：

- 保留 `id="chapter-lens-select"` 的 **hidden input**，其 `value` 承载当前章 id
  （关态为空串，与 `applyChapter("")` 的语义一致）；
- `workbench.js:55-57` 的 `bindChapterLens()` 绑定**必须仍然能找到这两个 id**，
  否则 `if (!lens || !toggle || !select) return;` 会**静默 return**、章节切换整体失效——
  这是自绘化最容易踩的坑，实现期必须写一条断言。

> **语义零变更**：透镜仍是「关 = 整门课 / 开 = 恰好一章」
> （`openspec/specs/workbench-ui/spec.md:829-838`）。原生 `<select>` 的选项集合、
> `data-active` 标记与 `workbench.js` 的绑定逻辑不变，只是把控件**换成自绘面板**。
> 选项的**顺序**沿用 `pool.chapters()` 的返回顺序（现状即如此），本规格不改排序语义。

### 3.5 「工作台设置视图」入口的落位

#### 结论

**放在左栏「设置」分组内，作为该分组的第一行「外观设置」入口行——不是新增一行导航。**

```
设置分组
┌────────────────────────────────────────┐
│ ◐ 外观设置                          ▸   │  ← 新增：进入中栏「工作台设置视图」
│ 运行中发送方式              [排队发送▾]  │  ← 现状保留
│ ☑ 练习显示自评                           │  ← 现状保留
└────────────────────────────────────────┘
```

#### 理由

1. **proposal 的原文落点**：「A new middle-column settings view holds appearance
   preferences… The left rail opens and closes it」（`proposal.md:75-76`）。
   「左栏开关它」指**左栏里有开关**，不是「左栏导航多一项」。
2. **导航组的语义是「学习面」**。练习 / 试卷 / 知识点 / 知识图谱 / 记录 五个入口都是
   **学习内容的落点**；设置视图不承载学习内容，只承载外观偏好。
   把它混进导航组 = 把「环境」和「内容」画成同一级，破坏导航的语义分组。
3. **既有结构已就位**。左栏本来就有「设置」分组（`pages.py:662-670`，
   含「运行中发送方式」「练习显示自评」两项行为设置）。外观偏好天然属于同一分区。
4. **不改既有导航语义**。新增一行导航会让导航组变成 6 项、图标资产多一个、
   `middle-navigation.js:53-60` 的「按下标搬运 active」逻辑多一项——收益为零、风险全在。
5. **可发现性不降级**：设置视图虽不在导航组，但左栏「设置」分组整体在设置视图打开时
   显示**选中态**（分组标题墨色 600 + 分组底淡染 + 左缘蓝轨），
   顶栏段二同时显示「外观」，设置视图页内另有「返回」按钮。三条线索保证不迷路。

#### 该入口的交互规格

| 项 | 规格 |
|---|---|
| 位置 | 左栏「设置」分组第 1 行 |
| 形态 | 整行入口行（图标 28×28 + 文字 14px + 右端 `▸` 箭头），行高 40px，圆角 12，**与其他导航项同几何** |
| 点击 | 中栏切换到工作台设置视图；左栏「设置」分组进入选中态 |
| 退出 | 设置视图页内提供「返回」按钮（回到进入前的页面）；浏览器后退同样有效 |
| 焦点 | 新增 1 个可聚焦项；位置在现有导航项之后（`acceptance.md:26` G-8 允许的新增项） |
| 数据 | 只写浏览器偏好（localStorage，按工作区），**不写池**（`proposal.md:110-112`） |

#### 3.5.2 主题开关的落位

主题切换**不进设置分组**，放**顶栏段三**（§2.2），因为它是全局的、即时的、需要在任何页面
一键触发的（台灯转场是全局动效）。它与设置视图里的主题偏好**共用同一份存储键**，
属同一个偏好的两个入口，不构成第二真值。

② **页面标题带的底线**。其余所有分隔一律 1px `--wb-line-soft`。

### 4.2 内容最大宽度：双轨测量

现状：`max-width:800px` 居中缎带（`workbench.css:252-253`）+ 标题带右侧 128px 死预留
（`workbench.css:255`）。

规格：**一轨一档，页面级二选一；标题带与正文共用该页的同一条轨。**

| 轨 | 宽度 | 归属页面 | 理由 |
|---|---|---|---|
| **阅读轨** `--wb-measure` | **880px** | 练习页、知识点详情页 | 疏朗面：题面/正文/解析需要连续阅读的余量。**与 D-11 字面一致**（`design.md:801-804`） |
| **数据轨** `--wb-measure-wide` | **1120px** | 知识点列表页、试卷列表页、记录中心 | 紧凑面：列表与数据面需要并排比较的宽度。**属 D-11 未覆盖的扩展，见 DRIFT-3（§0.5）** |

**实现机制（一条变量承载一整页的轨）**：

```css
/* ① 页面级轨变量：默认阅读轨 */
#middle-page { --wb-track: var(--wb-measure); }
#middle-page.is-data-page { --wb-track: var(--wb-measure-wide); }

/* ② 标题带与正文读同一条轨 → 同一条上限、同一条对齐线 */
.page-header,
.page-content {
  max-width: min(100%, var(--wb-track));
  margin-inline: auto;

  --wb-track: var(--wb-measure-wide);
  width: min(100%, var(--wb-track));
  margin: 0 auto;

```

规则：

1. **同一页面内，标题带与页面内容共用同一轨**，左右边缘严格对齐；
   页面切换时轨道宽度随之切换（由 §动效的视图转场容器动画掩盖，不产生硬跳）。
2. **内容在轨内居中**（`margin-inline:auto`）。不左对齐——中栏本身是三栏中的中间一栏，
   左对齐会在超宽视口把内容甩向左栏、右侧留出大片无端点的空白
   （`F08.md:146-152` 记为「超宽视口下行宽失控」）。
3. **阅读面的行长另有限制**：`.wb-reading` 正文块 `max-width:38em`（17px 正文 ≈ 646px），
   左对齐于轨道左缘。轨道与行长之差是**有终点的阅读留白**（轨道右缘有结构线），
   不是现状那种无端点的死纸带。**D-11 第 3 条第 4 款明确「阅读 measure 仍由
   `.wb-reading` 自己管（38em / 42em），页面容器放宽不会把正文拉宽」。**
4. **轨道宽度不随视口无限增长**：≥1920 时轨道仍为 880 / 1120，多余空间表现为
   中栏内的对称留白。
5. **hub 标题带必须与 hub 网格共用同一条轨**。现状 `.hub-page .page-header
   { max-width: none; }`（`workbench.css:1109`）是一条**独立于统一规则的旁路**，
   D-11 把「hub 与工作台标题带规格不一致」列为缺陷（`F02 D2`）——
   修法是**删掉这条旁路**，让 hub 标题带走 §4.2 的同一条 `.page-header` 规则
   （在 `.hub-page` 的 `--wb-track` 上下文中解析出 1120）。

### 7.8 断点守卫：为什么四档都不会出现横向滚动条

把 §1.3 规则 R1/R2 与 §1.4 的档位放在一起，逐档验算「最坏姿态」：

| 档 | 视口下界 | 栅格列数 | 最小占用 | 结论 |
|---|---|---|---|---|
| A | 1440 | 3 | `200 + 360 + 420 = 980 ≤ 1440` | 剩余 460px 给中栏（`1fr`），**中栏 ≥ 420 恒成立** |
| B | 1280 | 3 | `200 + 340 + 420 = 960 ≤ 1280` | 剩余 320px 给中栏，**恒成立** |
| C | 1024 | 2（左 + 中） | `200 + 0 + 0 = 200 ≤ 1024` | 右栏在栅格外，**中栏 ≥ 704px** |
| D | 768 | 1 | `0 ≤ 768` | 双抽屉均为覆盖层，**不占栅格** |
| E | <768 | 1 | `0` | 同上 |

**横向滚动条的三条来源，逐条封堵**：

1. **栅格最小总宽超视口** → 封堵手段是 §1.3 的 R1/R2 夹取（把中栏压在 420）+ §1.4 的
   档位切换（C 档把右栏移出栅格）。A/B 档的最小总宽都远小于视口下界，**不成立**。
2. **中栏内容超宽**（长表格、长公式行） → 由 `.wb-reading` 的 38em / 42em 行长限制
   （D-11 第 3 条第 4 款）与卡片的 `min-width:0` 处理；**不由容器宽度兜底**。
3. **顶栏内容超宽**（长工作区名） → 段二工作区名 `max-width:36ch` + 省略号
   （§2.1），透镜 chip `max-width:200px` + 省略号，E 档品牌文字 `font-size:0`。

> **验收动作**（`acceptance.md:115`、`S-11`）：在 1440 / 1280 / 1024 / 768 四档，
> 各跑一次 `document.documentElement.scrollWidth <= window.innerWidth`，
> 且四档各出一张对照截图。**这是本节唯一的通过判据。**

> **判据（按内容的性质，不是一刀切）**：
> 这块内容是**拿来读**的，还是**拿来比**的。

| 区块垂直间距 | 32px（`--sp-6`） | 16–24px（`--sp-4`/`--sp-5`） |

| 正文字号 | 17px | 14px（界面文字档）/ 13px（列表） |

| 卡片阴影 | 柔影 lv1 | 柔影 lv1（**统一**） |
| 轨道 | 阅读轨 880 | 数据轨 1120（页面级二选一，非区块级） |

> **唯一随密度而变的轨道是页面级的，不是区块级的**：
> 一个页面在「疏朗」与「紧凑」之间切换时，**轨道不跟着切**——
> 页面级轨道由**页面的主要性质**决定（§5.0 总表），
> 页内个别区块的密度切换只改**间距与内边距**，不改轨道。
