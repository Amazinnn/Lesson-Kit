## 1. 三栏几何规格

### 1.1 现状：双源问题（本节是必须先解决的问题）

`#layout` 的列宽模板有**两个来源**，桌面端后者永远赢：

| 来源 | 位置 | 内容 | 实际效力 |
|---|---|---|---|
| CSS 规则 | `workbench/server/static/workbench.css:160` | `grid-template-columns: 280px minmax(0, 1fr) 420px;` | **从不生效**（被 inline style 覆盖） |
| JS inline style | `workbench/server/static/workbench.js:4587` | `layout.style.gridTemplateColumns = leftWidth + "px minmax(420px, 1fr) " + rightWidth + "px";` | **唯一生效**的模板 |

- 行内样式优先级高于任何选择器规则，因此 CSS 里那条 `minmax(0,1fr)` 在桌面端是**死规则**。
- `workbench.js:4581` 在 `window.innerWidth < 1024` 时把行内模板清空（`layout.style.gridTemplateColumns = ""`），
  此时才短暂回到 CSS 那条 `280px minmax(0,1fr) 420px`——但同一条 `@media (max-width:1023px)`
  已把 `#layout` 改成单列（`workbench.css:1174-1179`），所以那条 CSS 模板在**任何视口下都从未真正决定过布局**。
- 后果一（**死亡带**）：JS 模板的最小总宽 = `280 + 420(min) + 420 = 1120px`。
  视口落在 **1024–1119px** 时，网格最小宽 1120 > 视口宽 → **横向溢出 + 横向滚动条**
  （`F08.md:137-144` 记为「1024–1279px 是三栏都挤的死亡带」；精确到像素，溢出区是 1024–1119）。
- 后果二（**中栏最小宽被钉死在 420**）：中栏永远收不到 420px 以下，
  于是「中栏读作一条缝」而不是「中栏可滚动」。
- 后果三（**拖拽上限写死在 JS**）：`workbench.js:4576-4587` 的 `leftWidth` 夹在 200–480、
  `rightWidth` 夹在 360–560，与 CSS 里的 `280/420` 是**两份独立数值**，
  改宽度必须同时改两个文件，否则出现「CSS 写的 280，JS 写的 260」这类漂移。

### 1.2 收敛方案：CSS 变量单一来源

**结论：列宽模板由 CSS 声明，JS 只写两个自定义属性，不再写 `grid-template-columns`。**

```css
/* ① 默认值与上限只在 CSS 一处声明 */
:root {
  --col-left: 280px;
  --col-right: 420px;
  --col-middle-min: 640px;
  --col-left-max: 480px;   /* 可拖拽上限，随断点在媒体查询里收窄 */
  --col-right-max: 560px;
}

/* ② 模板只有这一条真值 */
#layout {
  flex: 1;
  min-height: 0;
  display: grid;
  grid-template-columns:
    var(--col-left) minmax(var(--col-middle-min), 1fr) var(--col-right);
  grid-template-rows: 100%;
  overflow: hidden;
  transition: grid-template-columns 200ms ease;
}
#layout.is-resizing { transition: none; }
#layout[data-ai-collapsed] {
  grid-template-columns: var(--col-left) minmax(0, 1fr) 0px;
}
```

```js
/* ③ JS 只写变量，不写模板（替换 workbench.js:4587） */
layout.style.setProperty("--col-left", leftWidth + "px");
layout.style.setProperty("--col-right", rightWidth + "px");
```

配套三条规则：

1. **媒体查询改「模板」，不改「变量」。** 断点处整条模板被重写，变量值保留但被夹紧；
   这样 CSS 变量不会因为 JS 残留的行内值而「赢过」断点。
2. **夹紧上限也归 CSS。** JS 用 `getComputedStyle` 读 `--col-left-max` / `--col-right-max`，
   而不是把 200/480/360/560 写死在 JS 里（消除 §1.1 后果三）。
3. **旧行内模板必须清空。** `workbench.js:4581` 的 `layout.style.gridTemplateColumns = ""`
   改为 `layout.style.removeProperty("--col-left")` + `removeProperty("--col-right")`，
   否则迁移期新旧两套会同时存在。
4. **右栏折叠阈值从 1024 移到 1279。** `fitAiColumn()`（`workbench.js:4569-4573`）
   现在用 `window.innerWidth < 1024` 决定 `data-ai-collapsed`；按 §1.3 的 C 档，
   右栏在 **≤1279** 就转抽屉，阈值必须同步改，否则 1024–1279 会出现
   「CSS 模板是单列 + 行内变量仍是三栏」的混合态。

**验收口径**（实现期必须逐条量测）：

- 视口 1440：`#layout` 的三列实际宽 = `280 / 740 / 420`（±1px）。
- 视口 1024：页面**无横向滚动条**（`document.documentElement.scrollWidth <= innerWidth`）。
- 视口 1280：三列 = `248 / 652 / 380`（±1px）。
- 拖左栏到最左（200px）：右栏不降到 360px 以下，中栏不出现横向滚动条。
- 桌面端 `#layout` 的行内 `style` 属性**不含** `grid-template-columns`。
- 拖拽柄在 `#left-column` 右缘 10px 内可命中（现状 `#left-resizer{right:-4px}`（`workbench.css:548-551`）骑界，
  被 `#left-column` 的 `overflow-y:auto` 裁掉一半，`F02.md:39`）——**把手柄整体收进栏内**。

### 3.5 「工作台设置视图」入口的落位

#### 结论

**放在左栏「设置」分组内，作为该分组的第一行「外观设置」入口行——不是新增一行导航。**

```
设置分组
┌────────────────────────────────────────┐
│ ◐ 外观设置                          ▸   │  ← 新增：进入中栏「工作台设置视图」
│ 运行中发送方式              [排队发送▾]  │  ← 现状保留
│ ☑ 练习显示自评                           │  ← 现状保留
└────────────────────────────────────────┘
```

#### 理由

1. **proposal 的原文落点**：「A new middle-column settings view holds appearance
   preferences… The left rail opens and closes it」（`proposal.md:75-76`）。
   「左栏开关它」指**左栏里有开关**，不是「左栏导航多一项」。
2. **导航组的语义是「学习面」**。练习 / 试卷 / 知识点 / 知识图谱 / 记录 五个入口都是
   **学习内容的落点**；设置视图不承载学习内容，只承载外观偏好。
   把它混进导航组 = 把「环境」和「内容」画成同一级，破坏导航的语义分组。
3. **既有结构已就位**。左栏本来就有「设置」分组（`pages.py:662-670`，
   含「运行中发送方式」「练习显示自评」两项行为设置）。外观偏好天然属于同一分区。
4. **不改既有导航语义**。新增一行导航会让导航组变成 6 项、图标资产多一个、
   `middle-navigation.js:53-60` 的「按下标搬运 active」逻辑多一项——收益为零、风险全在。
5. **可发现性不降级**：设置视图虽不在导航组，但左栏「设置」分组整体在设置视图打开时
   显示**选中态**（分组标题墨色 600 + 分组底淡染 + 左缘蓝轨），
   顶栏段二同时显示「外观」，设置视图页内另有「返回」按钮。三条线索保证不迷路。

#### 该入口的交互规格

| 项 | 规格 |
|---|---|
| 位置 | 左栏「设置」分组第 1 行 |
| 形态 | 整行入口行（图标 28×28 + 文字 14px + 右端 `▸` 箭头），行高 40px，圆角 12，**与其他导航项同几何** |
| 点击 | 中栏切换到工作台设置视图；左栏「设置」分组进入选中态 |
| 退出 | 设置视图页内提供「返回」按钮（回到进入前的页面）；浏览器后退同样有效 |
| 焦点 | 新增 1 个可聚焦项；位置在现有导航项之后（`acceptance.md:26` G-8 允许的新增项） |
| 数据 | 只写浏览器偏好（localStorage，按工作区），**不写池**（`proposal.md:110-112`） |

#### 3.5.2 主题开关的落位

主题切换**不进设置分组**，放**顶栏段三**（§2.2），因为它是全局的、即时的、需要在任何页面
一键触发的（台灯转场是全局动效）。它与设置视图里的主题偏好**共用同一份存储键**，
属同一个偏好的两个入口，不构成第二真值。

### 4.2 内容最大宽度：双轨测量

现状：`max-width:800px` 居中缎带 + 标题带右侧 128px 死预留。

规格：**一轨一档，页面级二选一。**

| 轨 | 宽度 | 归属页面 | 理由 |
|---|---|---|---|
| **阅读轨** `--measure` | **880px** | 练习页、知识点详情页 | 疏朗面：题面/正文/解析需要连续阅读的余量 |
| **数据轨** `--measure-wide` | **1120px** | 知识点列表页、试卷列表页、记录中心 | 紧凑面：列表与数据面需要并排比较的宽度 |

规则：

1. **同一页面内，标题带与页面内容共用同一轨**，左右边缘严格对齐；
   页面切换时轨道宽度随之切换（由 §动效的视图转场容器动画掩盖，不产生硬跳）。
2. **内容在轨内居中**（`margin-inline:auto`）。不左对齐——中栏本身是三栏中的中间一栏，
   左对齐会在超宽视口把内容甩向左栏、右侧留出大片无端点的空白
   （`F08.md:146-152` 记为「超宽视口下行宽失控」）。
3. **阅读面的行长另有限制**：`.reading` 正文块 `max-width:38em`（17px 正文 ≈ 646px），
   左对齐于轨道左缘。轨道与行长之差是**有终点的阅读留白**（轨道右缘有结构线），
   不是现状那种无端点的死纸带。

## 8. 密度分区规则表

### 8.1 判据

> **判据（按内容的性质，不是一刀切）**：
> 这块内容是**拿来读**的，还是**拿来比**的。
>
> - **拿来读** → 疏朗：连续、需要思考、一次只关注一件事的内容。
> - **拿来比** → 紧凑：需要扫视、排序、跨条目比较的内容。
> - **兜底**：**同一页面内可以混用**（练习页 = 疏朗题面 + 紧凑题号导航）。
>   密度是**区块级**属性，不是页面级属性。

两条不随密度变化的量：**字号档**（正文恒 17px，界面文字 13–14px）与**水平内边距**（卡片 16/24px）。
