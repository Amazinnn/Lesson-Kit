## 1. 诊断给出的前提（决定了候选怎么设计）

版式诊断员的第一批实测（暖夜一致）：

| 页面 | 面块数 | 高度 min/中位/max/σ | padding 档数 | 字号档数 | 有影比例 | 阴影档/圆角档 |
|---|---|---|---|---|---|---|
| 练习页（组卷） | 17 | 21/147/848/300 | 12 | 11 | 17.6% | 2/3 |
| 练习进行中 | 24 | 21/147/848/269 | 13 | 14 | 16.7% | 4/4 |
| 记录中心 | **36** | 8/128/848/209 | 10 | 10 | **61.1%** | 3/3 |
| 知识点列表 | **42** | 29/38/848/197（中列 σ=9.0） | 8 | 8 | **76.2%** | 2/3 |
| 试卷列表 | 13 | 32/123/848/302 | 8 | 9 | 38.5% | 2/2 |

以及最终的归一化裁决：

- 「面太多 vs 尺度不齐」的比值有**三个已知偏差**，**不能拿去定方向**：
  ① 「间距档」与「内距档」是同一件事的两种测法 ⇒ 尺度族被重复加权；
  ② 「间距取值档」是**样式表纪律指标**（含控件内部的 2/5/7px 内距），
  **只看中列面块之间的留白，每页只有 2–7 种取值** ⇒ 视觉节奏其实不乱；
  ③ 组件尺寸其实已经很齐：砖块群高度 **σ = 0.0**、字号 **96.9–99.3%** 命中 `--fs-*`。
- ⇒ **真正的病因是「同一个带影卡片被重复 8–31 次」**（知识点列表 42 个面里
  31 个是同一个 `knowledge-row`，660×38 / 圆角 12 / 带影）。
- ⇒ **「尺度不齐」只存在于两处**：① `--sp-1..8` 八档只用了 6 档，
  另有 **20–29 个散值**（1/2/5/6/7/9/14/18/20/22/26px）；
  ② 竖向节奏**两套**：章节级 **28–40px** vs 行堆级 **6–8px**（差 3.5–5 倍）。
- ⇒ **去面化与节奏合一是同一段 CSS**：去掉「每行一张卡」的面，
  **并且**把行缝从 6–8px 提到页面节奏那一档。只做一件都不彻底。

⇒ 所以每个候选都必须回答同一个问题：**长列表里，一行还是一条？**

## 2. 四版一览

| 代号 | 名字 | 哲学 | 一句话 |
|---|---|---|---|
| **S1** | 一张纸 | 去面化 | 整页是一张连续的纸；行落在纸上，行间只有发丝线。 |
| **S2** | 分带 | 横向分带 | 页面切成少数几条满宽带，带内共用同一条列轨。 |
| **S3** | 分组卡 | 卡只用在分组级 | 一个分组一张卡，组内的行不再各自成卡。 |
| **S4** | 书页 | 阅读优先 | 中栏是一页浮在桌面上的书页；数字块变账本行；两栏收成边注。 |

> ⚠️ **S3 已按诊断重述**：原案是「统一圆角 / 统一阴影的少数面」，被诊断否掉
> （那治不了重复：31 张 660×38 的一模一样带影卡，σ = 0），改成
> 「**卡只用在分组级，行不各自成卡**」。
> ⇒ 四个候选**主轴都是去面化**，差别在**面留在哪一级**。

## 3. 每版的六问

### S1「一张纸」

- **一行还是一条？** → **一条**。长列表不再一行一卡：行落在同一张纸上，
  行间只有 1px 发丝线（`.knowledge-group__cards > .knowledge-row`、
  `.record-row`、`.record-run` 全部撤掉底色 / 圆角 / 柔影）。
- **砍掉了什么** → 版面层**所有卡面**（底色 / 圆角 / 柔影）⇒ 0；行与行之间的
  8px 外边距 ⇒ 0（改发丝线）；左右栏分栏线由 1px 近黑降为 1px 发丝线；
  左栏的沉底纸也没了（代价，见下）。
- **靠什么建层级** → ① 纸面层级（纸 L1 / 桌面 L0 / 沉底 L3）② 规线（页头 2px
  单侧结构线 + 块间 1px 发丝线）③ 字号层级 ④ 竖向节奏（块距一律 32px）。
  **不靠更多阴影**（一版都不加阴影）。
- **代价** → 分组感变弱 ⇒ 靠标题层级 + 规线补；可点击行失去「一块」的指向
  ⇒ 靠 hover 洗底（`--veil-hover`）+ 选中蓝轨补；**左栏去掉沉底纸后，
  左栏的内容占用率从 82% 掉到 47%**（读起来更空）。
- **留白序列（合并后）** → `[32 段距, 16 章标题下, 0 行缝 + 1px 发丝线]`
  （现状 `[28, 16, 92, 8×30]`）。
- **对交互的影响** → **零**（§7）。

### S2「分带」

- **一行还是一条？** → **一条**（带内共享一个面的行）。
- **砍掉了什么** → 卡的圆角 ⇒ 0（带是**齐边**的）；柔影 ⇒ 0（带靠底色差分层）；
  卡与卡的 18px 外边距 ⇒ 0（带是连续的横条）；左栏的纸由「随内容收口」
  改成**满高**（一条到底的沉底带）。
- **靠什么建层级** → ① 纸面层级（带 L1 / 桌面 L0 / 沉底 L3）② 带边发丝线
  ③ 字号层级 ④ **共同列轨**（所有带的内容都落在 `--shell-measure` 这一条轨上，
  用 `padding-inline: max(--sp-7, (100% − 880px)/2)` 实现，**不加任何 DOM**）。
- **代价** → 一屏里同时出现 6 条以上带时会读成「条纹」而不是「章节」——
  区块多的页面（记录中心）最吃亏；带内不再有内缩的卡片，数据密度感下降；
  **带本身是面 ⇒ 中栏的面数比 S1/S3 多（10 vs 2/5）**。
- **留白序列（合并后）** → `[32 带内距, 16 带内元素, 0 行缝 + 1px 发丝线]`。
- **对交互的影响** → **零**（§7）。

### S3「分组卡」

- **一行还是一条？** → **组级一张卡 + 组内一条条**。
  一个**分组**（章节组 / 摘要组 / 仪表盘组 / 记录分区 / 工作区列表）= 一张卡面；
  组内的**行**落在卡面上，行间 1px 发丝线。
  - 知识点页：31 个 `knowledge-row` ⇒ 1 张组卡 + 31 条行。
  - 记录中心：4 个 `record-summary` ⇒ 1 张卡里 4 格（竖发丝线分隔）；
    8 个 `record-row` / 6 个 `record-run` ⇒ 所在分区一张卡 + 行。
  - 工作台首页：22 张工作区卡 ⇒ 1 张卡里 22 个格子。
- **砍掉了什么** → 行级卡面 ⇒ 0；组卡以外的阴影 ⇒ 0；圆角只剩 `--r-md` 一种；
  卡片内距 5 档（24/18/22/14/16）⇒ 2 档（24 / 12×16）；间距 6 档 ⇒ 3 档；
  **嵌套深度 3 → 2**。
- **靠什么建层级** → ① 纸面层级（组卡 L1 / 桌面 L0 / 沉底 L3）② 组卡内的发丝线
  ③ 12 列网格（组卡对齐到同一套列）④ 单一间距刻度。
- **代价** → 一屏里有几张组卡时**仍读出「几个盒子」**（只是盒子少了）；
  组间距变大，长列表翻起来更费力；保留卡面语言 ⇒ 比 S1/S2 安静。
- **留白序列（合并后）** → `[32 组间距, 24 组卡内距, 0 行缝 + 1px 发丝线]`。
- **对交互的影响** → **零**（§7）。

### S4「书页」

- **一行还是一条？** → **一条**（页上的行）；记录中心的四个数字块
  ⇒ 四行**账本**（标签左 / 数字右 / 横线分隔），像一本书的目录页。
- **砍掉了什么** → 中栏所有卡面 ⇒ 0；记录摘要 4 块卡 ⇒ 4 行账本；
  左右栏各自的纸 ⇒ 0（边注没有纸）；版面层阴影 ⇒ 只剩「纸浮在桌面」这一次。
- **靠什么建层级** → ① 一页纸（L1 卡面 + 唯一一次柔影）与桌面（L0）的落差
  ② 账本横线 + 页眉 2px 结构线 ③ 字号层级 ④ 段距 + 阅读面 1.75 衬线。
- **代价** → 屏幕占用更少（纸有边距）；边注更安静 ⇒ 左栏「优先回看」这类需
  扫读的信息权重下降（左栏内容占用率 82% → 48%）；**中栏的可用宽度没变**（660px），
  D3 的「右栏空」只能靠提示的分量解决，不能靠宽度。
- **留白序列（合并后）** → `[32 段距, 16 行内, 0 行缝 + 1px 发丝线, 48 纸的外边距]`。
- **对交互的影响** → **零**（§7）。

## 4. 右栏：空态怎么办（所有者截图里最刺眼的一处）

诊断实测：中栏内容只有 **660px**，而 `--shell-measure: 880px` **根本没被用上**
⇒ **瓶颈是列宽，不是内容轨宽**。右栏 420px，`#ai-column { min-width: 360px }`
与 `workbench.js:5714 COLUMN_MIN.right = 360` 都是**硬地板**。

三条路（诊断实测，知识点列表页）：

| 路径 | 中栏宽度 | 增量 | 代价 |
|---|---|---|---|
| A 现状 | 660px | — | — |
| **B 右栏落到地板 360px** | **720px** | **+60px** | 纯布局，**不动交互** |
| C 置 `data-ai-collapsed` | **880px** | **+220px** | ⚠️ 机制已存在（`workbench.css:725`），但 `workbench.js:5700-5704` **只在 <1024px 置位** ⇒ 1440px 下从不触发 ⇒ **需要新触发器 = 交互变更** |

⇒ **候选的处理**：

| 候选 | 右栏方案 | 旗标 |
|---|---|---|
| S1 | **B 路**：`grid-template-columns` 第三段 = `max(360px, calc(var(--wb-col-right) − 60px))` ⇒ 中栏 660 → **720（+60px）** | ⚠️ 右栏实际宽度与拖拽刻度差一个固定偏移 60px（拖拽仍生效） |
| S2 | **B 路**（同 S1）。⚠️ 空态**不能再收窄**：右栏硬地板 360px，再窄会把对话栏挤出布局（实测溢出 80px） | ⚠️ 同上 |
| S3 | **B 路**（同 S1） | ⚠️ 同上 |
| S4 | **不改列宽**（右栏保持 420，聊天需要宽度）：中栏改成「有页边距的一页纸」⇒ 行不再贴右缘 | ⚠️ 中栏可用宽度不变（还是 660px） |

- **C 路（+220px）四个候选都没做**：它需要给 `data-ai-collapsed` 加一个
  「无对话时置位」的触发器 ⇒ **属交互变更**，本轮越界。
  ⇒ 只在这里提出来，**等所有者决定**；**没有**用 CSS 硬做（那会伪造一个交互）。
- **独立于列宽**：右栏 419×848、占用率 **2.9%**（地板 20%）本身就是 D3 的问题。
  ⇒ **四版都做了同一件纯布局的事**：把那一行 13px 的「还没有对话」做成
  **有分量的空态**（14px 正文 + 24px 内距 + 次级墨）⇒ 实测右栏内容占用率
  **6% → 14%**。

## 7. 「对交互的影响 = 零」是怎么验的

评审板自带自检脚本：`tmp/frontend-audit/layout-board/_verify.mjs`
（`node tmp/frontend-audit/layout-board/_verify.mjs`，headless Chrome + CDP，
**file:// 口径**）。它做四件事：

1. **console errors = 0**，**网络失败 = 0**（file:// 下无 404、无 CORS）。
2. **候选 CSS 真的命中**：实测 `.knowledge-row` 的计算样式 ——
   S0 = `background: rgb(255,253,247)` / `radius: 12px` / 有影；
   S1/S2/S3/S4 = `background: transparent` / `radius: 0` / `box-shadow: none`。
3. **可交互元素清单逐条对比**：取 `a[href], button, input, select, textarea,
   [role=button], [role=link], [tabindex], [onclick]`，
   对 **标签 / id / class / 文本 / href / type / disabled / checked** 做签名。
   - 现状 S0 与 S1/S2/S3/S4 的签名 **全部 IDENTICAL**（知识点列表页 87 个可交互元素，
     数量一致、身份一致、顺序一致）⇒ **没有增删、没有移动、没有隐藏**。
   - 只有**几何**（宽高）变化 —— 这是版式候选本来该做的（行距 / 内距 / 列宽）。
4. **面块数与有影比例实测**（§6 的数字就是它跑出来的）。

此外：

- 候选表是**独立的 CSS 文件**，只覆盖版式 / 尺度 / 密度 / 视觉重量；
  产品样式表 `workbench.css` **一个字节都没动**（本轮不改产品代码）。
- 评审板的页面快照由**产品自己的 `pages.py` 渲染**（服务端渲染 + 真实池数据），
  只剥掉 `<script>`（file:// 下会 404）与重建 `<head>`（真 `<link>` 产品 CSS）。
- `<html class="js">` 标记与产品一致（`pages.py::_appearance_boot_script`），
  否则组件会退回「无 JS 态」。
- 页面数据来自**沙盒池副本**（`tmp/frontend-audit/layout-board/ws/`），
  **用户真库 `pool/dmath.db` 一个字节都没动**。
