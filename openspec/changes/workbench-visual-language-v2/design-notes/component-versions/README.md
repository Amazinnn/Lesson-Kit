# 组件设计版本地图

> **这份地图回答一个问题**：工作台的**组件形态**到目前为止有哪几个版本、各自还在哪、
> 哪个是权威、哪些**还有价值但差点被清掉**。
>
> 配套：**版式**侧见 `../mockup-baseline/`（V1 拼版）；**总地图**见
> `docs/STATUS-workbench-visual-language-v2-2026-10-23.md` §1.5。

## 0. 权威只有一处

| 层 | 工件 | 它定什么 |

| 根 | `decisions.md`「# 收口：最终基线」 | 视觉基线（色相 / 圆角 / 笔触 / 组件种类） |
| 形态 | `design-notes/component-spec.md` **§4.30** | **组件形态唯一权威**（A-115，28 条所有者手选） |

## 3. 保全说明（**这几份原本会被清掉**）

原件都在 `tmp/frontend-audit/`，而 `tmp/` **不入库** ⇒ 清一次就没了。

| 提升动作 | 改了什么 | 为什么只改这些 |

| `styleboard-v2/` → `styleboard-v2/` | **只改 4 条相对路径**（`index.html` 2 条 + `data.js` 2 条：`../../../workbench/...` → `../../../../../../workbench/...`） | 位置深了 3 层 ⇒ 不改就指不到产品的 CSS；**页面内容一字未动** |

**未提升的**：`layout-board/candidate-s{1..4}.css`（版式候选）—— 已判劣质，可清。

## 4. 怎么用这份地图

1. **想知道某个组件「本来还有别的样子」** → 开 `styleboard-v1-legacy/index.html`（103 个变体）。
2. **想知道「当时为什么选这个」** → 开 `styleboard-v2/index.html`（你挑的那张）+ `../styleboard-picks.md`（导出的原文）。
3. **想知道现在的形态是什么** → `../component-spec.md` §4.30（唯一权威）。
4. **想把某个组件换成 C-1 里的另一个变体** ⇒ 那是**新的形态裁定** ⇒ 走 `decisions.md`（A-115 的同一条路），**不要**直接改 CSS。
