### 0.4 给实现者的读法

- §1 是**全局规则**，画每一张图之前先读一遍，不必回读。
- §2 / §3 的每一项都写成同样的字段，逐条填即可；「坐标草图」是**示意**，

## 1. 统一 SVG 技术规格

> 以下条款对**全部**资产（图标 / 插画 / 台灯）生效。除非某一项另有明文说明。

### 1.1 画布与网格

| 资产类 | `viewBox` | 画幅（u） | 默认渲染尺寸（CSS px） | 1 u = | 网格 |
|---|---|---|---|---|---|
| 导航图标 | `0 0 48 48` | 48 × 48 | 24 × 24 | 0.50 px | **12 × 12 单元**，1 单元 = 4 u = 2 px |
| 空态插画 | `0 0 240 200` | 240 × 200 | 宽 180（高 150） | 0.75 px | **24 × 20 单元**，1 单元 = 10 u = 7.5 px |
| 台灯 | `0 0 240 240` | 240 × 240 | 132 × 132 | 0.55 px | **24 × 24 单元**，1 单元 = 10 u = 5.5 px |

- **u（unit）** 是本文件的唯一长度单位。所有坐标、线宽、半径都以 u 给出，实现时乘以上表的换算。
- 网格：部件端点尽量落在整单元或半单元上。允许半单元偏移（手绘感），
  但**不得**出现 1–3 u 的随机抖动。
- **安全区**：

  | 资产类 | 判据 |
  |---|---|
  | 导航图标 | ① 图形外接框 **≤ 30 × 30 u**（占圆底直径 62%）；② 外接框中心落在以 (24,24) 为心、**半径 3 u** 的小圆内（允许有意的偏转）；③ 外接框**最远顶点**距 (24,24) **≤ 21 u**（= 圆底半径的 87.5%）；④ 图形与圆底边缘的径向间隙 ≥ 3 u |
  | 空态插画 | ① 器物本体外接框**最长边 60–125 u**（画幅宽的 25%–52%）；② 器物本体外接框**高 ≤ 132 u**（画幅高 66%）；③ 左右留白 **≥ 40 u**；④ 器物底部与桌面横线（y = 168）相距 **0–3 u**（压线）；⑤ 水平居中：外接框中心与画幅中心的横向偏移 ≤ 6 u |
  | 台灯 | ① 灯座底缘 y = 226，正方画布底部留 14 u；② 灯座中心 x = 120 = 画幅中心，使 `transform-origin: 50% 100%`（= (120,240)）正落在灯座轴线上；③ 罩口与光晕不得超出画幅（光晕半径 60 u，罩口中心 (118,131)，最远点 118−60 = 58 > 0 ✓，131+60 = 191 < 240 ✓） |

- `preserveAspectRatio` 保持默认 `xMidYMid meet`；**禁止** `slice`（会裁掉笔画）。
- **禁止**在 `<svg>` 根上写 `width` / `height` 属性（尺寸由宿主 CSS 控制，见 §1.11）。

### 1.2 线宽阶

全组**同一组数值阶梯**，三类资产共用（渲染尺寸不同，阶梯结构相同）：

| 档 | u | 图标 @24px | 插画 @180px | 台灯 @132px | 用途 |
|---|---|---|---|---|---|
| **主** | 3 | 1.50 px | 2.25 px | 1.65 px | 形体外轮廓、封面、器物主壁、灯罩外壳 |
| **次** | 2 | 1.00 px | 1.50 px | 1.10 px | 内部结构线、书脊、部件分界、连接线、罩口 |
| **细** | 1.5 | 0.75 px | 1.125 px | 0.825 px | 纹理：页行、叶脉、灯罩棱 |

- 线宽比恒为 **3 : 2 : 1.5**。不得出现第四档。
- 每张资产**最多用三档**；用不到某档就不用，但不得自造新值。
- 角色分工：结构轮廓 = 主线；内部结构 = 次线；纹理 = 细线。
- **细线（1.5 u）是亚像素线**：图标尺寸下 0.75 CSS px、插画 1.125 px、台灯 0.825 px。
  规则：
  1. 细线只允许出现在"删掉也不损失识别"的位置（页行、叶脉、编织纹、地平线细节）；
  2. 若在目标浏览器里发虚，**把该处升到次线并同时删掉冗余纹理**，不得加粗到主线；
  3. **台灯在 132 px 下只允许主 + 次两档**——细线在该尺寸下不足 1 px，
     灯罩棱、罩口内壁等处一律用次线。
- **禁止**：hairline（< 1 u）、超粗线（> 4 u）、同一形体上混用两档线宽。

### 1.3 端点与连接

- 全组统一：`stroke-linecap="round"`、`stroke-linejoin="round"`。
  可写在最外层 `<g>` 上继承，**不要**每个 path 重复写。
- **禁止** `butt` 端点、`miter` 连接、`stroke-miterlimit`。
- `stroke-dasharray` **仅**允许用于图谱图标里那条「尚未连上」的卫星连线这一处语义，
  节奏为 `4 3`（u）。其余资产一律实线。

### 1.4 圆角档

圆角语言 = **局部短边的比例**，与界面 12px 圆角是同一种"语气"的不同尺度
（界面 12 px 是"不小于所作用边长的 1/16、且不用小圆角"；资产内部用比例表达同一件事）。

| 档 | 比例（局部短边） | 图标参考值 (u) | 插画参考值 (u) | 台灯参考值 (u) | 典型用途 |
|---|---|---|---|---|---|
| **锐** | 0 | 0 | 0 | 0 | 纸边、笔尖、硬折线、裁切边 |
| **微** | 1/16 | 1.5 | 4 | 4 | 小构件角：纸角、笔筒口沿、书签缺口 |
| **小** | 1/10 | 3 | 8 | 8 | 次级形体：书页、灯罩口、杯沿、画框内缘 |
| **中** | 1/6 | 6 | 16 | 16 | 主形体：书封面、笔记本、画布框、台灯底座 |
| **大** | 1/4 | 8 | 20 | 20 | 大件柔性形体：果篮、花瓶腹、灯罩外沿 |

- 规则：
  1. 任何角都不是直角；除"锐"档的明确纸边外，至少给到"微"。
  2. 主形体用"中"（1/6），次级用"小"（1/10），细节用"微"（1/16）。
  3. 自由曲线（杯口、篮沿、花器口、灯罩口）不设限，由造型自然决定。
  4. 同一套资产里，同类部件的圆角档必须一致（五个图标的"主形体圆角"必须读起来是同一种）。

### 1.5 描边与填充的关系

- **描边优先**：形体用「描边 + 透明或极淡填充」表达。
- 填充只承担三件事，且仅此三件：
  1. **淡彩晕染**（低饱和色面）；
  2. **彩色圆底**（仅图标）；
  3. **高光 / 亮部**（极小面积）。
- **禁止**「大面积实心填充 + 粗描边」的贴纸感。同一形体上，描边相对填充的对比度必须 ≥ 3:1
  （用 §1.7 的取值直接验算）。
- **淡彩用预混色，不用 alpha**（D-3）：
  - 蓝 / 黄 / 红三色淡彩直接用 `--art-wash-blue` / `--art-wash-yellow` / `--art-wash-red`
    （不透明，已按 token 层配方与纸色混好）；
  - 中性淡彩（背光面）用 `color-mix(in oklab, var(--art-ink) 10%, var(--art-paper))`；
  - 需要**中间档位**（例如"黄 16%"而非 token 给的 18%）时，
    写 `color-mix(in oklab, var(--role-yellow) 16%, var(--art-paper))`——**不要**写
    `fill: var(--role-yellow); fill-opacity: .16`（半透明色叠在不确定的背景上不可控）。
  - 晕染**不得盖过墨线**——永远先铺淡彩、后描线。
- **阴影**：
  - **禁止 SVG filter**（`feGaussianBlur` / `feDropShadow` / `feTurbulence` 一律不用）。
  - 柔影 = 「同形复制 + 2 u 偏移 + 3%–6% 不透明度 + 深一档色相」。
  - 接触阴影 = 一条 3–5 u 宽的横向淡色带（放在器物底下）。
- **禁止** `clipPath` 做复杂裁剪。需要裁切时优先直接画 `circle` / `rect rx` / 带 `Z` 的闭合路径。

### 1.6 淡彩与渐变语言

渐变**只允许出现在资产内部**（`decisions.md` §14.3），不得用于背景、卡片或任何大面积表面。
全组只允许下面 **3 组**渐变（D-9），方向统一 **135°**
（`objectBoundingBox`，`x1=0 y1=0 x2=1 y2=1`）：

| id 前缀 | 类型 | 停靠点 | 用途 |
|---|---|---|---|
| `gRole` | linear 135° | 起 = 角色色；止 = 角色色混纸 22%（浅）/ 混夜纸底 30%（夜）；顶 = 顶部高光（见下表） | 彩色圆底（**可选**，默认纯色） |
| `gSheen` | linear 135° | 起 = `--asset-highlight` 40% → 止 = 0% | 器物表面的柔光带（玻璃、陶、金属材质），一条 |
| `gLamp` | radial（中心 = 罩口中心，r = 60 u） | 起 = `--asset-lamp-warm` 55% → 止 = 0% | 台灯暖光晕（仅台灯） |

**`gRole` 的色阶表**（直接取 token 层 `night-paper-tokens.md` §7.2，两主题只换停靠点色阶）：

| 角色 | 浅色 起 → 止 | 浅色 顶部高光 | 夜纸 起 → 止 | 夜纸 顶部高光 |
|---|---|---|---|---|
| 学习蓝 | `#2b62e8` → `#5983ea` | `#6b91ef` | `#7291de` → `#586da2` | `#89a3e3` |
| 阳光黄 | `#f5c518` → `#f7d047` | `#f8d65d` | `#e0c151` → `#a58f3f` | `#e5cb6d` |
| 注意红 | `#d1392b` → `#db6356` | `#df746b` | `#d4736b` → `#9d5852` | `#db8983` |

- 同一资产内渐变**≤ 2 组**。
- 本套 16 件资产实际用到两组：`gRole`（图标圆底，**可选**，默认纯色）与 `gLamp`（台灯光晕）。
  `gSheen` 为**预留**——只在玻璃/陶/金属材质需要一条柔光带时用一次（如墨水瓶的玻璃盖），
  其余情况一律用 `--asset-highlight` 的高光弧代替。
- 渐变不得越出形体边界（需要时用同形闭合路径承载，而不是裁剪）。
- **夜纸不新建渐变**：同一 `<linearGradient>` 只换停靠点色阶（更暗的色相 + 更弱的高光），
  色阶由 CSS 变量给（§1.7），`gradientTransform` 不动。
- **淡彩面本身不用渐变**（D-3）——淡彩是预混的平色，渐变只留给圆底、柔光带和灯光。

——`workbench/server/app.py:136-137`、`:29`）：

**文件名规则**：`<kind>-<subject>[-<qualifier>].svg`，全小写 kebab-case。

| kind | 含义 |
|---|---|
| `icon` | 导航静物图标（圆底徽章式） |
| `empty` | 空态静物插画 |
| `lamp` | 台灯（motion 类唯一资产） |

**SVG 内部 id 命名空间**：所有 `id`（渐变、组）**必须**带资产前缀，
形如 `icon-practice-wash`、`empty-vase-gSheen`、`lamp-gLamp`。
理由：资产以 inline 方式进入同一文档，重复 id 会让 `url(#id)` 指到别的资产的定义。
**禁止**出现裸 id（如 `id="wash"`）。

> **id 前缀 = 文件名主干**：`icon-practice.svg` → 前缀 `icon-practice-`；
> `empty-vase.svg` → `empty-vase-`；`lamp.svg` → `lamp-`。
> 一个文件里所有 `id` 都用同一个前缀，天然保证全文档唯一。

**class 命名空间**（与宿主 CSS 的约定，**不得**自造第三套）：

| 资产 | 根 class | 内部组 class |
|---|---|---|
| 图标 | `asset asset-icon` | `asset-icon__ground` / `asset-icon__wash` / `asset-icon__line` / `asset-icon__highlight` |
| 插画 | `asset asset-empty` | `asset-empty__wash` / `asset-empty__line` / `asset-empty__highlight` / `asset-empty__shadow` |
| 台灯 | `lk-lamp`（**motion-spec 指定，不可改**） | `lk-lamp__body` / `lk-lamp__base` / `lk-lamp__stem` / `lk-lamp__arm` / `lk-lamp__shade` / `lk-lamp__glow` |

> 台灯根 class 必须是 `lk-lamp`：motion-spec §3.5 的 `.lk-lamp` 直接驱动
> `translate3d / scale / rotate` 与 `opacity`，改名即转场失效。
> 同理 `.lk-lamp__glow` 是"点亮"段的动画目标，必须保留该 class。

**根元素约定**：

```xml
<svg viewBox="0 0 48 48" class="asset asset-icon" xmlns="http://www.w3.org/2000/svg"
     role="img" aria-labelledby="icon-practice-title">
  <title id="icon-practice-title">练习</title>
  <defs>…</defs>
  <g class="asset-icon__ground">…</g>
  <g class="asset-icon__art">…</g>
</svg>
```

- 不写死 `width` / `height`，尺寸由宿主 CSS 的 `.asset-icon` / `.asset-empty` 控制。
- 必须写 `xmlns`（独立打开时也要合法）。
- 必须有 `<title>`（见 §5.5）。

### 1.9 class / `currentColor` / CSS 变量的用法规则

| 用途 | 用什么 | 不用什么 |
|---|---|---|
| 主题适配（暖纸 ↔ 夜纸） | **CSS 变量** `var(--asset-*, fallback)` | 不用 `prefers-color-scheme` 媒体查询（主题偏好是工作区级的浏览器偏好，不是系统级） |
| 跟随宿主文字色 | `currentColor`（仅限"跟随上下文文字"的装饰件，本套资产**未使用**） | 不用硬编码 hex |
| 颜色回退 | `var(--asset-ink, #2a2620)`，**每个 `var()` 都带回退值** | 不写无回退的 `var()` |
| 结构分组 | 语义 class：`__ground` / `__wash` / `__line` / `__highlight` / `__shadow` | 不写行内 `style="fill:#xxx"` |
| 派生混色 | `color-mix(in oklab, var(--role-blue) 16%, var(--art-paper))` | 不写 `fill-opacity` 叠半透明角色色 |

- **禁止**在 SVG 里写 `style` 属性、`class` 里塞颜色、`<style>` 块内定义颜色。
- 颜色只能出现在两处：`fill` / `stroke` 属性上的 `var(--asset-*)`，
  或 `<stop stop-color="var(--asset-*)">`。
- 主题切换时**只换变量值，不重画资产、不新增资产**（`acceptance.md` §3.2）。

### 1.10 双主题同文件机制（一份文件，两套主题）

> 这一节回答实现者最常问的一句：**"同一份 SVG 怎么同时给暖纸和夜纸用？"**

#### 1.10.1 机制原理

| 环节 | 事实 | 依据 |
|---|---|---|
| 变量从哪来 | CSS 自定义属性**继承**。`var()` 在 SVG 的 `fill` / `stroke` / `stop-color` 属性里**照常解析**——只要 SVG 在文档树里 | CSS Variables Level 1；SVG 2 |
| 变量在哪换 | 外壳 CSS 在 `:root` 与 `[data-theme="night"]` 两个作用域上重新赋值 `--asset-*`（见 §1.7 第二步） | token 层 §3 / §7 |
| 资产要不要改 | **不改**。文件数、几何、线宽、圆角、渐变 id 全部不变；只有**解析出来的颜色**变 | `decisions.md`「插画与主题：同一套 SVG，用 CSS 变量换前景/背景色」 |

一句话：**变的是变量，不是资产。** 资产里写的是 `var(--asset-ink, #2a2620)`，
暖纸下解析成 `#2a2620`，夜纸下解析成 `#e6ddcd`。

#### 1.10.2 什么会变 / 什么不变

| 会随主题变 | 不会随主题变 |
|---|---|
| 线稿色（`--asset-ink`） | 几何、坐标、路径 |
| 纸面色（`--asset-paper`） | 线宽三档 |
| 淡彩色域（`--art-wash-*` / 混色配方） | 圆角档 |
| 圆底色（`--role-*`，夜纸为降饱和+提亮版） | 渐变 id、停靠点**位置**、`gradientTransform` |
| 高光强度（浅色白 55% → 夜纸暖白 8%） | 透明度层级关系（先铺淡彩、后描线） |
| 圆底上的字形色（浅色蓝/红用纸色、黄用墨；夜纸统一深墨） | 元素的层序与数量 |

#### 1.10.3 一个完整的对照示例（讲清"同文件"到底同在哪）

```xml
<!-- 夜纸与暖纸共用这一段，一个字都不改 -->
<path class="asset-empty__line"
      d="M 120 96 C 94 96 94 152 120 152 C 146 152 146 96 120 96 Z"
      fill="var(--asset-wash-yellow, #fdf3cf)"
      stroke="var(--asset-ink, #2a2620)"
      stroke-width="3"/>
```

| 主题 | `fill` 解析为 | `stroke` 解析为 | 观感 |
|---|---|---|---|
| 暖纸 | `#fdf3cf`（黄 18% 混纸白） | `#2a2620`（暖炭褐） | 纸上的淡黄器物，深墨勾边 |
| 夜纸 | `#3d3721`（黄 14% 混夜纸卡面） | `#e6ddcd`（暖浅墨） | 夜纸上的暗黄器物，浅墨勾边 |

> 关键：**`stroke-width="3"` 没有变**，`d` 没有变，`fill` 指向的变量名没变。
> 变的只是那两个变量在当前主题下的取值。


#### 1.10.4 三种常见错误做法（都会导致验收 §3.2 第 4 条失败）

| 错误做法 | 后果 | 正确做法 |
|---|---|---|
| 用 `@media (prefers-color-scheme: dark)` 在 SVG 内写第二套色 | 主题偏好是**工作区级**设置，不等于系统偏好；用户显式切了主题，改不掉 | 全部走 `var(--asset-*)`，由外壳在 `[data-theme]` 作用域换值 |
| 为夜纸单独做一套 SVG（`*-night.svg`） | 文件数翻倍；两套资产会各自漂移，出现"同款插画不同形" | 一套文件，两套变量值 |
| 用 `<img src="*.svg">` 承载资产 | `<img>` 引用的是独立文档，外层 CSS 变量与 `currentColor` **穿不过去**，夜纸下仍是亮纸版本 | inline SVG（§1.11） |

#### 1.10.5 三步验证"同文件"

1. **文件数**：资产目录里的 `.svg` 数量恒为 **16**（§5.1）。切主题前后数一遍。
2. **解析值**：DevTools → 选中一个 `fill="var(--asset-ink, …)"` 的元素 → Computed 面板，
   暖纸下应为 `#2a2620`，夜纸下应为 `#e6ddcd`；**DOM 节点不变**（不发生替换）。
3. **截图对照**：同一页面的同一块区域，暖纸/夜纸各截一张，插画的**轮廓必须逐像素同构**，
   只有颜色不同。任何一处形状不同，说明有人给夜纸单独画了东西。

#### 1.10.6 边界情形

| 情形 | 处理 |
|---|---|
| 资产被独立打开（双击 `.svg`） | 变量走回退值 = **浅色主题**取值。这正是设计走查想要的形态 |
| `forced-colors: active`（Windows 高对比） | 浏览器会接管绘制；资产里的 `var()` 仍解析，但可能对比失真。**不要**为此特判资产 |
| 打印 | 浏览器打印样式表通常强制白底；资产走浅色回退值即可，**不做特判** |
| `color-scheme` | token 层已给 `--color-scheme: light|dark`；它影响原生控件与滚动条，**不影响**资产配色 |

### 1.11 交付形态：inline 是硬要求

- 资产必须以 **inline `<svg>`** 进入 DOM：
  - 服务端模板内联（读文件内容注入 HTML），**或**
  - 前端 `fetch('/static/assets/…')` → `DOMParser` / `<template>` → 注入并缓存。
- **禁止**用 `<img src="*.svg">` 承载需要主题适配的资产：
  `<img>` 引用的是独立文档，外层 CSS 变量与 `currentColor` **穿不过去**，
  会导致夜纸下资产仍是亮纸版本（直接违反 `acceptance.md` §3.2 第 4 条）。
- 独立打开 `.svg` 文件时，变量走回退值——这是**设计走查用的正常形态**，
  但夜纸检查必须在 inline 状态下做。
- 静态路由与 MIME 已就绪（`workbench/server/app.py:29` 的 `.svg` → `image/svg+xml`；
  `:136-137` 的 `/static/` 分支），**无需改服务端路由**。

### 1.12 禁止清单（资产内）

## 2. 导航静物图标集（5 个）

### 2.0 共用规则

- **徽章式**：每个图标文件 = **彩色圆底 + 图形**。圆底 = `<circle cx="24" cy="24" r="24">`，
  填充 `var(--asset-ground-*)`；圆底是纯色（不用渐变，除非愿意用 §1.6 的 `gRole`）。
- 图形是**具象静物**，不是抽象几何占位符（`decisions.md` §14.1）。
- 五个图标**同一支笔**：同一组线宽（主 3 / 次 2 / 细 1.5 u）、同一组圆角档、同一光源（左上 45°）、
  同一视角（略俯视、正对读者，允许 ≤3° 偏转）。
- **安全区**（D-7，可测判据）：
  ① 图形外接框 ≤ 30 × 30 u；② 外接框中心距 (24,24) ≤ 3 u；
  ③ 外接框最远顶点距 (24,24) ≤ 21 u；④ 与圆底边缘径向间隙 ≥ 3 u。
  每个图标的几何表末尾给出**实测外接框**与**最远顶点距离**，照抄后请复核这两个数。
- **墨色一色律**：一个图标只有一种线条颜色。淡彩只作为"面"出现。

**五个图标的圆底角色与前景色**（按基线的角色语义分配，不是为了彼此区分而分配）：

| 图标 | 圆底角色 | 前景（线条）色 | 浅色主题取值 | 夜纸主题取值 | 受光淡彩域 | 背光淡彩域 | 语义依据 |
|---|---|---|---|---|---|---|---|
| 练习 | 学习蓝 | 纸白 | `--asset-ink-on-blue` `#fffdf7` | `#14120f` | 阳光黄 16% | 中性 10% | 主行动 = 学习蓝 |
| 试卷 | 阳光黄 | 墨 | `--asset-ink-on-yellow` `#221f1a` | `#14120f` | 纸白 26% | 中性 12% | 阳光黄 = 当前/进行中的卷宗 |
| 知识点 | 学习蓝 | 纸白 | `#fffdf7` | `#14120f` | 阳光黄 18% | 中性 10% | 学习内容，与练习同族 |
| 知识图谱 | 学习蓝 | 纸白 | `#fffdf7` | `#14120f` | 阳光黄 22%（核心）/ 纸白 16%（卫星） | 中性 10% | 结构浏览，与练习同族 |
| 记录 | 阳光黄 | 墨 | `#221f1a` | `#14120f` | 纸白 24% | 中性 12% | 阳光黄 = 复习/回看强调 |

> **关于红色**：注意红**只**表示失败与阻塞，导航项不是失败，因此**导航圆底不用红**。
> 若所有者坚持五个圆底各不相同，唯一可接受的改法是把「记录」改为注意红
> （记录中心确实含失败与错题复盘），代价是红底与「失败」语义重叠，须明确裁决。
> 本规格的默认分配**不需要**第五种分法，也不需要新色相。

> **受光/背光的分工**：受光面（左上朝向）用**与底色不同的一层淡彩**，背光面（右下朝向）用**中性淡彩**。
> 在蓝底上，受光面是暖黄（在冷底上显暖）；在黄底上，受光面是纸白（白纸压在黄纸上显亮）。
> 两者都只承担"这是哪一面"，不承担状态语义。

**淡彩配方（图标专用，D-3：预混 / 混色，不用 alpha）**：

> 徽章底色是**角色色**，不是纸面，所以图标的淡彩一律**与底色相混**——
> 这样同一个配方在两主题下自动成立（底色换了值，配方的相对关系不变）。

| 简称 | CSS 表达式 | 用在哪 |
|---|---|---|
| `W-黄16` | `color-mix(in oklab, var(--role-yellow) 16%, var(--asset-ground-blue))` | 蓝底上的受光面 |
| `W-黄18` | `color-mix(in oklab, var(--role-yellow) 18%, var(--asset-ground-yellow))` | 黄底上的暖偏移面 |
| `W-黄22` | `color-mix(in oklab, var(--role-yellow) 22%, var(--asset-ground-blue))` | 蓝底上的核心受光面 |
| `W-墨10` | `color-mix(in oklab, var(--asset-ink) 10%, var(--asset-ground-blue))` | 蓝底上的背光面 |
| `W-墨12` | `color-mix(in oklab, var(--asset-ink) 12%, var(--asset-ground-yellow))` | 黄底上的背光面 |
| `W-纸16` | `color-mix(in oklab, var(--surface-card) 16%, var(--asset-ground-blue))` | 蓝底上的"纸"面（卫星节点） |
| `W-纸26` | `color-mix(in oklab, var(--surface-card) 26%, var(--asset-ground-yellow))` | 黄底上的"纸"面（顶层纸） |
| `W-纸24` | `color-mix(in oklab, var(--surface-card) 24%, var(--asset-ground-yellow))` | 黄底上的"纸"面（标签窗） |

> 规则记忆法：**受光面 = 另一角色色（或纸色）与底色相混；背光面 = 墨与底色相混**。
> 无论底色是蓝是黄，受光/背光的层次都自动成立，且不新增色相。
>
> **关于夜纸的反相**：夜纸下 `--art-ink` 反相为浅色，所以"墨混入底色"在夜纸表现为**提亮**而非压暗。
> 这与整套夜纸反相一致——夜纸的立体感由**暗端收边**（渐变止色）+ **克制高光**承担，
> 不靠明暗方向。因此夜纸下不要额外加深描边或加投影。

**高光**：统一用 `var(--asset-highlight)`（浅色白 55% / 夜纸暖白 8%），
**不使用**独立的 `var(--asset-highlight)` 渐变——渐变语言只有 §1.6 的 3 组。

### 2.6 五图并排检查

把五个图标并排放在一行，逐一确认：

1. **视觉重量相等**：没有一个明显更黑、更密或更大。
   判定法：把五个图标缩到 **16 px** 并排灰度化，五个块的**平均墨量**之差 ≤ 15%。
2. **圆底色读起来是一族**：蓝-黄-蓝-蓝-黄的节奏不刺眼；红底没有出现（除非走 §2.0 的备选裁决）。
3. **每个图形都能用一句话说出是什么**，且互相不混淆（书本 ≠ 纸堆 ≠ 书签 ≠ 节点 ≠ 本子）。
4. **线宽一致**：任何一个图标里的主线粗细与其它四个相同。
5. **淡彩密度一致**：没有一个图标是"白底素线"，另一个是"满身色块"。
6. **同一件图标的圆底色不随导航状态变**：选中态由**整行圆角色块**表达（`decisions.md`），
   不是把图标圆底换成另一种色。图标圆底**不承载状态**。

## 3. 空态静物插画集（10 个）

### 3.0 共用规则

- 每张画**一件器物**（允许器物自带的必要配件，如笔筒里的笔、杯子的碟），不出现第二件主题物。
- 器物必须是**学习器物或书房器物**：与内容无关，只表达「此刻无事」。
- **禁止**：人物、动物、文字、字母、品牌标识、抽象几何团块（`decisions.md` §13.3）。
- **桌面横线**：一条水平淡线（中性 8%–10%），长度取画幅宽的 60%–70%（144–168 u），
  **统一落在 y = 168**（D-10）。台面横线是这组插画的共同"地"，让它们读起来是同一张桌子上的东西；
  横线高度不统一会导致并排时地平线错位。
- **尺寸判据**（D-8，可测）：
  | 判据 | 取值 |
  |---|---|
  | 器物外接框（含必要配件，不含桌面横线/接触阴影/蒸汽/花枝等延伸元素）**最长边** | **60 – 125 u**（画幅宽的 25%–52%） |
  | 器物外接框**高** | **≤ 132 u**（画幅高 66%） |
  | 左右留白 | **≥ 40 u** |
  | 器物与桌面横线 | **压线**：最低点落在 y = 165–168 之间（留 0–3 u 触地感） |
  | 水平居中 | 外接框中心与画幅中心的横向偏移 **≤ 6 u** |
- **线宽**：主 3 u / 次 2 u / 细 1.5 u（= 2.25 / 1.5 / 1.125 px @180px 宽）。
- **墨色**：`var(--asset-ink)`（夜纸自动反相为暖浅色 `#e6ddcd`）。
- **淡彩**：**受光面 + 背光面**两个色域，色相只能来自学习蓝 / 阳光黄 / 注意红或中性色。
  写法见下方**配方速查表**（D-3：预混不透明色，不用 alpha）。
- **高光 ≤ 2 处**；接触阴影一条；阴影不透明度 ≤ 12%。
- 主体底部与桌面横线之间统一**压线**（不悬空）。

### 3.11 插画 × 使用场景对应表

**选择原则**（按此挑，不要按"哪个好看"挑）：

1. **气质匹配**：空态要传达的是「此刻无事，随时可以开始」，不是「缺东西、坏掉了」。
   因此不选残缺、倾倒、破损、脏乱的器物。
2. **同屏不重复**：同一页面内出现两个空态时，必须用不同的插画。
3. **不暗示任务内容**：不选会让人误以为"这里应该有某样东西"的画（如空杯子会像"你的茶被喝了"）。
4. **可替换**：插画可被换掉而不影响理解——文案与主按钮才是空态的主体（P-1 少字原则）。

## 4. 台灯的三姿态

> 台灯是**空态插画语言的一部分**（`decisions.md` §16.5 / §17.2），因此它与 §3 的插画共用：
> 同一套线宽（主 3 / 次 2 u）、同一套圆角档、同一光源。
> 差别有三点：① 它是**唯一的动效资产**；② 它是**单文件三姿态**；
> ③ 它是**叠在界面之上的角落浮层**，不是画在纸面上的器物（D-6）——所以它**不画桌面横线**。

### 4.1 画布与共用结构

- **画布**：`viewBox="0 0 240 240"`（正方）。宿主 `.lk-lamp` 为 `132 × 132 px`（`motion-spec` §3.5），
  正方画布 1:1 映射进正方盒子，**不产生信箱留白**。
- **换算**：1 u = 132 / 240 = **0.55 px**。主线 3 u = 1.65 px，次线 2 u = 1.10 px。
- **细线禁用**：台灯在 132 px 下**只允许主 + 次两档**（§1.2 规则 3）。灯罩棱、罩口内壁一律用次线。
- **旋转轴**：`motion-spec` 的 `.lk-lamp { transform-origin: 50% 100%; }` 对根 `<svg>` 而言，
  SVG 元素的 `transform-box` 初始值是 `view-box`，故原点 = 画布的 (120, 240)。
  因此**灯座中心必须落在 x = 120**，旋转才像"灯从底座转出来"，而不是绕着别处甩。
- **组结构**（class 名是宿主 CSS 的契约，**不得改**）：

```
<svg class="lk-lamp" viewBox="0 0 240 240" xmlns="..." aria-hidden="true" focusable="false">
  <defs><radialGradient id="lamp-gLamp">…</radialGradient></defs>
  <g class="lk-lamp__body">      ← 几何体，随根节点一起 transform
     base / stem / joint / arm / pivot / shade / rim
  </g>
  <g class="lk-lamp__glow">      ← 点亮段的动画目标（motion-spec 直接选它）
     inner / bulb / halo
  </g>
</svg>
```

| 组 class | 部件 | 线宽 | 坐标 / 形状 |
|---|---|---|---|
| `lk-lamp__base` | 底座 | 主 | 梯形 `M 88 226 L 98 196 L 142 196 L 152 226 Z`，圆角 4 u（微） |

- **光源例外**：灯是**画内光源**——它的光从罩口射向左下。
  这与 §1 的"左上 45° 环境光"规则**故意不同**，属已声明的例外：
  灯罩外壳仍按左上受光（外壳右上缘留一线高光），但**光晕与内壁暖色只出现在罩口一侧**。

### 4.2 姿态 A · 收（parked）

- **画面**：**灯不在画面里**。整盏灯停在视口右下角的**下缘之外**（`translate3d(0,120%,0)`），
  `opacity 0`，只留一个空着的右下角。
- **实现**：根节点处于 motion-spec `lk-lamp-lean-out` 关键帧的起始态：
  `opacity: 0; transform: translate3d(0,120%,0) scale(.86) rotate(-12deg);`
- **何时存在**：
  - **转场开始前**：节点**不创建**（motion-spec §4.2 在 reduced-motion 下整段跳过、灯不创建）；
  - **转场结束后**：节点**已 `remove()`**（第 ⑦ 段，700 ms）。
  - 因此常态下 DOM 里**没有**台灯——这是终态"干净"的一部分（`acceptance.md` M-1 第 6 帧）。
- **本姿态的语义**：「还没开始换主题」。它不是一个"可见的待机画面"。

> **D-5 裁决**：旧版本文件写「夜纸终态保留一盏微亮的台灯」。与 motion-spec §4.2/§4.6 冲突
> （700 ms 后三层全部 `remove()`；reduced-motion 下根本不创建）。**以 motion-spec 为准**：
> 台灯是**转场期资产**，不常驻。「夜里是台灯照着的纸」这句感受由**转场那一下**与夜纸自身的暖调承担，
> 不靠一盏常驻的灯。落地位置：§4.2、§4.5、§6-E6。

### 4.3 姿态 B · 探（peek）

- **画面**：灯从右下角**升起来并转正**，完整可见（底座 + 立柱 + 摇臂 + 灯罩），
  罩口朝向左下，光**还没有亮**——"咔哒"之前的那一瞬。
- **实现**：根节点处于 `lk-lamp-lean-out` 的终止态：
  `opacity: 1; transform: translate3d(0,0,0) scale(1) rotate(0deg);`
  `lk-lamp__glow` 仍为 `opacity 0`（灯泡不可见、罩内壁只有线没有暖色、光晕为 0）。
- **与 A 的关系**：只有**位置与朝向**变了（一个 `transform` 插值），
  几何本身不变——**不允许为 B 姿态另画一张灯**。
- **可读性检查**：132 px 下必须一眼看出"这是一盏台灯"（有底座、有立柱、有罩口朝左下），
  而不是"一根拐棍"。若认不出，八成是罩体画得太小或罩口没画出来。

### 4.4 姿态 C · 亮（lit）

- **画面**：灯罩内亮起（灯泡可见 + 罩内壁一圈暖色），暖光从罩口溢出成一团晕。
  灯的位置与 B 相同。
- **实现**：`lk-lamp__glow` 处于 `lk-lamp-light-up` 的终止态：
  `opacity: 1; transform: scale(1);`（动画过程中 `scale(.35→1.12→1)`）。
- **光的方向**：光从罩口（朝向左下）射出，因此**光晕偏左下**，
  不做对称发光——这与 §1 的左上环境光规则不同，是**画内光源**，属有意为之（§4.1）。
- **光斑**：**不在资产里**。落在界面上的"光斑"由宿主涟漪层（`.lk-ripple-glow`）承担（§4.6）。
- **终态含义**：亮态之后就是换肤与收灯（§4.5 的 ④–⑦ 段）。

### 4.5 姿态切换与时序

**权威时序表**（与 `motion-spec.md` §4.3 逐字一致；本表**不得**自行改数）：

| 段 | 起 (ms) | 止 (ms) | 时长 | 元素 | 动作 |
|---|---|---|---|---|---|
| ① 探出 | 0 | 140 | 140 | `.lk-lamp` | `translate3d(0,120%→0)` + `scale(.86→1)` + `rotate(-12°→0)`，`opacity 0→1` |
| ② 点亮 | 140 | 220 | 80 | `.lk-lamp__glow` | `opacity 0→1` + `scale(.35→1.12→1)`，暖色溢出 |
| ③ 涟漪扩散 | 140 | 590 | 450 | `.lk-ripple` | `scale(.06→4.8)`，`opacity 0→1`（前 18% 淡入） |
| ③' 暖光 | 140 | 590 | 450 | `.lk-ripple-glow` | `scale(.02→3.2)`，`opacity 0→1`，`mix-blend-mode: screen` |
| ④ 换肤 | 590 | 590 | 瞬时 | `<html data-theme>` | 属性切换（被不透明涟漪完全遮住，用户不可见） |
| ⑤ 涟漪退场 | 590 | 700 | 110 | `.lk-ripple` / `.lk-ripple-glow` | `opacity 1→0` |
| ⑥ 收灯 | 590 | 700 | 110 | `.lk-lamp` | `translate3d(0,0→-28%)` + `scale(1→.9)` + `rotate(0→8°)`，`opacity 1→0` |
| ⑦ 清理 | 700 | 700 | — | 三层 | `remove()`，终态干净 |

**姿态状态机**（相对时序；绝对毫秒见上表）：

```
   ①收 ──探出──▶ ②探 ──咔哒──▶ ③亮 ──涟漪+换肤──▶ ④收(终态·已移除)
     │            │            │
     │ 140ms      │ 80ms       │ 450ms 涟漪 + 110ms 收灯
     │            │            │
     └─ 反向：④收 ──探出──▶ ③亮 ──熄灭──▶ ②探 ──收回──▶ ①收
```

| 步 | 姿态 | 发生什么 | 备注 |
|---|---|---|---|
| 0 | A（收） | 节点不存在 | 常态 DOM 里没有台灯 |
| 1 | A → B | 灯体升起并转正（`transform` 插值） | 0–140 ms |
| 2 | B（探） | 静置一拍 | "咔哒"的静默，~60 ms |
| 3 | B → C | 灯泡亮 + 暖光溢出 | 140–220 ms |
| 4 | C（亮） | **涟漪层**从灯下扩散铺满全屏 | 140–590 ms；**不是资产**，见 §4.6 |
| 5 | 主题切换 | `data-theme` 属性瞬时切换（被涟漪遮住） | 590 ms |
| 6 | C → A | 灯上移淡出，涟漪淡出 | 590–700 ms |
| 终 | A | 节点已 `remove()`，主题已是新主题 | 700 ms，终态干净 |

**不变量**：

- 灯的**几何**在三姿态间不变（只有 `transform` 与 `opacity` 变化）。
- 灯罩始终是**同一支笔**画的：不因姿态切换而重画。
- 终态**没有台灯**（D-5）：常态 DOM 中不存在 `.lk-lamp` 节点。
- 降级（`prefers-reduced-motion: reduce`）：**整段跳过**——主题属性直接切换，
  台灯与涟漪层**根本不创建**（motion-spec §4.2 / §4.6：`display:none` + JS 提前 return）。

**验收采样帧**（`acceptance.md` M-1，六个时刻）：

| 帧 | 时刻 | 画面 |
|---|---|---|
| 1 | 0 ms | 台灯未入画（`opacity 0`，在画面下方） |
| 2 | 90 ms | 台灯探出约 2/3 |
| 3 | 180 ms | 台灯已探出、**已点亮**；涟漪刚起（前沿约 1/4 屏） |
| 4 | 330 ms | 涟漪推过大半，暖光在前沿外圈 |
| 5 | 500 ms | 涟漪接近铺满（几乎满屏新地面色） |
| 6 | 700 ms | **终态干净**：新主题、灯与涟漪层已移除 |

### 4.6 涟漪层（不是资产）

- 涟漪**不是 SVG 资产**，是宿主 CSS 的一层：一张放大的径向渐变遮罩
  （中心在灯位，当前写死 `88%` / `82%`；权威表无对应 token → 待裁决），用 `transform: scale()` + `opacity` 扩散。
- 约束（`decisions.md` §17.2 / motion-spec §4.5）：只动 `transform` / `opacity`；
  不阻塞交互（`pointer-events: none`）；不改请求时序。
- `prefers-reduced-motion` 下降级为**整段跳过**（灯与涟漪层都不创建）。
- 切回暖纸时，涟漪**反向收拢**（暖纸色由外向内铺满）。
- 涟漪的目标色读 `--surface-base`（权威表 §3.1 页面地面色；同名变量两套值），与资产无关。

### 4.7 宿主契约（宿主必须提供的 CSS 与钩子）

> 资产只提供**几何与 class**；时序、曲线、定位由宿主负责。实现时**照抄 motion-spec §3.5**，
> 资产侧只保证被选中的 class 存在。

```css
.lk-lamp {
  position: fixed;
  right: 2rem;
  bottom: 1.5rem;
  width: 132px;
  height: 132px;
  pointer-events: none;                 /* 装饰层不拦截交互 */
  opacity: 0;
  transform-origin: 50% 100%;
  z-index: 2147483001;
  will-change: transform, opacity;
}
.lk-lamp__glow {
  transform-box: fill-box;
  transform-origin: 50% 100%;
  opacity: 0;
}
```

**资产侧必须提供的钩子**：

| 钩子 | 谁用它 | 资产侧责任 |
|---|---|---|
| `svg.lk-lamp` | 探出/收灯两段动画 | 根元素 class 必须是 `lk-lamp` |
| `.lk-lamp__glow` | 点亮段动画 | 必须存在这个组，且只装"点亮的部分"（内壁暖色 + 灯泡 + 光晕） |
| `.lk-lamp__body` | （可选）整灯微调 | 几何体归组，便于日后整体位移 |
| `id="lamp-gLamp"` | 径向渐变引用 | 渐变 id 必须带 `lamp-` 前缀 |

> **不要**在资产里写 `<style>`、不要写 `style` 属性、不要写动画关键帧——
> 动画一律由宿主的 CSS 驱动（§1.12）。

**第 1 步：结构自检（浏览器 Console 脚本）**

```js
// 1) 禁止元素 / 外链 / 位图
const bad = ['image','script','foreignObject','text','tspan','animate','animateTransform',
             'set','filter','use','style','mask','clipPath'];
[...document.querySelectorAll('svg *')]
  .filter(el => bad.includes(el.tagName.toLowerCase()))
  .map(el => el.tagName + ' @ ' + el.outerHTML.slice(0, 60));

// 2) 外链与内联样式
[...document.querySelectorAll('svg [href], svg [xlink\\:href], svg [style]')];

// 3) id 唯一性
const ids = [...document.querySelectorAll('svg [id]')].map(e => e.id);
ids.length === new Set(ids).size;

// 4) 硬编码色值（应只剩 var() 的回退值）
[...document.querySelectorAll('svg [fill], svg [stroke], svg stop')]
  .map(e => e.getAttribute('fill') || e.getAttribute('stroke') ||
            e.getAttribute('stop-color'))
  .filter(v => v && /^#|rgb/i.test(v));

// 5) 根节点不得有 width/height（尺寸必须由宿主控制）
[...document.querySelectorAll('svg[width], svg[height]')];
```

**第 2 步：对比度自检**

- 图形对圆底：按 §1.7 的表逐组合验算（该表已算好，但**在 token 层取值落定后必须重算一次**，
  因为 `--asset-ground-*` 最终会引用 token 层的值）。
- 插画墨线对纸面：`--asset-ink` on `--asset-paper` 需 ≥ **4.5:1**
  （实测浅色 14.75:1 / 夜纸 12.06:1）。
- DevTools：选中元素 → Rendering 面板 → Contrast issues。
- **注意**：黄底图标里的图形必须是墨色（10.07:1）；若误用纸白（1.60:1），自查会直接报出来。
- **注意**：夜纸的三个圆底字形一律深墨；若在夜纸下看到蓝底上是白字，说明用了 §1.10 的旧规则。

**第 3 步：与 12px 圆角的相容性**

- 把图标放进一个 **12px 圆角的导航行**里看两件事：
  1. 圆底（正圆）与行块的 12px 圆角是否读起来是同一族——不出现"小圆角套大圆角"的割裂；
  2. 圆底直径与行高是否留够间隙（建议圆底直径 = 24 px，行高 ≥ 44 px，圆底与行块边缘间距 ≥ 8 px）。
- 圆底的柔影与卡片柔影用同一套 token（暖调柔影），不要图标自成一档。
- **P-2 图案适配原则**的落地核对：图标不是"贴上去的装饰"——
  它的圆角语言、线宽阶、色彩寄存器、笔触密度必须与界面同源；
  判据：把图标放进界面截图里，看不出它是"另一个世界"画出来的。

**第 4 步：夜纸可读性**

- 切到夜纸（`[data-theme="night"]`）后：
  1. 插画必须仍能一眼认出是什么器物（不是"一团线"）；
  2. 墨线反相为暖浅色后不得刺眼、不得比正文更亮（正文才是主角）；
  3. 圆底降饱和 + 提亮后，图形与圆底的对比仍 ≥ 3:1；
  4. **确认没有多出一套夜纸专用 SVG**——文件数应恒为 16；
  5. 选中一个 `fill="var(--asset-ink, …)"` 的元素，确认 Computed 值变成 `#e6ddcd`，
     且 **DOM 节点没有被替换**（替换说明有人写了第二套资产）。

**第 5 步：极限识别**

- 图标缩到 **16 px**：五个图标仍能分辨（书 / 纸 / 书签 / 节点 / 本子）。
  分辨不了就减线条，不是加线条。
- 浏览器 **200% 缩放**下检查：主线不断裂、细线不糊成一片。
- 插画缩到 **120 px**：器物仍可辨认；高光与接触阴影消失后形体仍完整。
- 台灯在 **132 px**：必须一眼认出是台灯（§4.3）。

**第 6 步：台灯分镜自查**（对应 `acceptance.md` §2 M-1）

- 按 0 / 90 / 180 / 330 / 500 / 700 ms 采样六帧，画面必须与 §4.5 的采样帧表一致：
  **探出 → 点亮 → 涟漪扩散 → 收回**，700 ms 后终态干净（无残留光晕、无残留遮罩、DOM 里无 `.lk-lamp`）。
- `prefers-reduced-motion: reduce` 下出一张对照帧：应为**整段跳过**——
  主题直切，灯与涟漪层**从未创建**（不是"快速播完"）。
- 用 DevTools 的 Animation 面板确认：只有 `transform` 与 `opacity` 在动（§3.7 性能项）。

| 5 | 自造第四档线宽 | 整套资产失去"同一支笔"的统一性 | 只有 3 : 2 : 1.5 三档（§1.2） |

| 7 | 图标挤满圆底 | 变成"贴纸"，与 12px 圆角的界面割裂 | 外接框 ≤ 30×30 u，留呼吸（§1.1） |
| 8 | 十个插画的桌面横线高度不一 | 并排时地平线错位，像不同桌子 | 统一 y = 168（§3.0） |
| 9 | 用红色表示"强调" | 注意红只表示失败与阻塞 | 插画里的角色色只作色彩分配（§3.0 注） |
| 10 | 台灯的灯座没居中 | 探出时像绕着别处甩 | 灯座中心 x = 120（§4.1） |
| 11 | 台灯画上桌面横线 | 浮在页面中间像一条 UI 横杠 | 台灯是角落浮层，不画横线（§4.6 / D-6） |
| 12 | 忘了 `<title>` 或 `aria-hidden` | 读屏软件念出一串路径 | 见 §5.5 |
