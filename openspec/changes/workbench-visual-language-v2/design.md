## Goals

- 用**一套结构 token + 两套主题值**替换被抄来的调色板，让间距、字号、圆角、抬升、
  动效、层级从「涌现」变成「声明」。
- 落地**暖色 + 现代圆润**基线：暖奶油底、12px 大圆角、饱和三角色色、纯色无纹理背景、
  靠圆角与柔影分层而不靠描边。
- 建立**双字族分工**与**共享阅读版式层**，让题面、解析、知识点正文、Agent 长文
  共用一套可执行的刻度，并把服务端 / 客户端两套 Markdown 渲染器**统一到同一份规则**。
- 让**状态有几何冗余通道**、**焦点处处可见**、**正文级文字全部 ≥ 4.5:1**。
- 建立**动效系统**（交互反馈 / 数据层 / 视图转场 / 里程碑仪式）与**降级路径**，
  并把「用户显式动效偏好」与「系统 reduced-motion」的关系写成可执行规则。
- 修**外壳几何**：三栏列宽单一真值、退役 128px 死预留、左栏图标化 + 整行圆角选中态、
  顶栏三段式、hub 卡片层级。
- 把**记录中心**从「98 张带边框便签 + 一屏 84 格空方块」改成圆角卡片流 + 可解码热力日历。
- 新增**工作台设置视图**（主题 / 阅读字面 / 动效 / 声音），偏好按工作区存浏览器，
  **不写池**。
- 登记审计暴露的**契约漂移**（只登记，不动实现）。

## Non-Goals

- **不做图谱页的任何改动**（渲染、物理、布局种子、观感），包括不借 token 改它的底色。
- **不做暗色下的图谱**：夜纸只覆盖工作台外壳与内容面；图谱页在夜纸下保持其现有观感
  （见 D-1 的「图谱兼容区」约束）。
- **不做全局背景动画 / 鼠标跟随 / 视差 / 光标辉光 / 背景 canvas**。
- **不引入前端框架、构建步骤、npm 依赖、CDN 资源、图标字体、雪碧图、Lottie**。
- **不做键盘快捷键体系**（`decisions.md` 5.3 已定「不做」）。
- **不引入第五色相**；「已掌握 / 正确」用文案与几何表达（`decisions.md` 3.4）。
- **不做玻璃拟态、霓虹外发光、彩色投影、多重投影**。
- **不做前端测试基建**：唯一的自动化是 D-6 的渲染器一致性 pytest。
- **不新建持久字段、不改 API、不改 CLI**。
- 不在本变更内**修复**已登记的契约漂移（只登记，见 D-15）。

## Decisions

### D-1 token 架构：一套结构 token + 两套主题值，旧 token 走别名期退役

**决策**

1. 新 token 全部落在 `--wb-*` 命名空间，与图谱的裸名（`--paper / --ink / --hair / --blue /
   --yellow / --red / --shadow / --graphite / --green / --blueSoft / --yellowSoft / --redSoft`，
   `workbench.css:1505-1518`）**零同名**。
2. **结构 token 唯一一套**、主题不变：间距阶、字号阶、行高阶、圆角阶（`--wb-radius-*`）、
   抬升阶（`--wb-shadow-*`）、动效时长与缓动（`--wb-dur-* / --wb-ease-*`）、
   z 层级（`--wb-z-*`）、阅读刻度（`--wb-read-*`）。
3. **主题值两套**、随主题整套替换：表面（`--wb-surface-*`）、墨（`--wb-ink-*`）、
   三角色（`--wb-role-*`）、线（`--wb-rule-*`）、控件边界。
   亮色写 `:root`，夜纸写 `:root[data-theme="night"]`（值见 D-2 / D-3）。
4. **旧 token 退役走别名期**：先把 `--lk-*` 与 `--dsw-*` 改成指向新 token 的别名
   （`--lk-blue: var(--wb-role-action)` 之类），**一个版本内**只做「值替换、不改引用点」；
   别名期结束后一次性删掉别名定义与引用点（收编表见 D-3）。
5. **图谱兼容区显式隔离**：新层里保留一个**只给图谱用**的 `--surface-sheet: #fffdf7`
   （值与今天完全一致），并新增
   `#layout[data-page="graph"] #middle { background: var(--surface-sheet); }`
   —— 页面底从暖奶油换成 `#fdf8ef` 之后，图谱页的中栏仍铺 `#fffdf7`，
   **图谱观感逐像素不变**。

**理由**

- 现有设计基座被劈成两半且没有命名空间隔离，这正是「纸板感能被随手复制粘贴出来」的根因
  （F01 D2）。新命名空间与图谱零交集，是「不动图谱」这条硬约束在 token 层的落地方式。
- 主题切换 = 换值，不换结构：所有尺寸类 token 只写一份，夜纸不需要重算任何几何
  （F07 §9.2 的同一原则）。
- 全仓 `prefers-color-scheme` 命中 **0** 处（F01 §1.3），所以没有「跟随系统」的既有行为要保；
  且收口基线要求「亮色 + 暗色**手动开关**」，跟随系统会让用户在自己没选的情况下被动进入
  夜纸（F08 §11.4 同此判断）。但 `color-scheme` 仍按主题声明，让原生控件与滚动条跟随
  （否则输入框下拉箭头、滚动条在夜纸下仍是亮色）。

**否掉的备选**

- *继续沿用 `--dsw-*` 改名而不换命名空间*：裸名撞车风险仍在，且图谱层仍与新层同域，
  隔离不了。
- *用 `prefers-color-scheme` 做暗色来源*：与「手动开关」冲突；且系统暗色用户打开工作台
  会看到与自己其它工具不一致的观感，却从未做过选择。
- *一次性删旧 token 不走别名期*：会同时改动 300+ 处引用点，爆炸半径不可控，出问题无法
  定位到是「值错了」还是「引用错了」。
- *把新层拆成独立 `tokens.css`*：`docs/ARCHITECTURE.md` 的静态资产结构会变动，
  而内联在 `workbench.css` 顶部少一个文件、少一条装载路径（F01 §5 的推荐，本变更沿用）。

**代价**

- 别名期意味着短期内 `:root` 里同时存在新旧两套名字，**必须**在别名定义处写注释标注
  「别名期，勿新增引用」，否则会重新长出第二套真值。
- `data-theme` 挂在 `<html>`（见 D-9），因此主题是**文档级**的；同一浏览器不同标签页
  各自独立（偏好按工作区存，见 D-9）。

### D-2 纸面层级模型：4 层，靠圆角 + 柔影分层，不用描边

**决策**

| 层 | token | 亮色 | 夜纸 | 圆角 | 抬升 | 描边 |
|---|---|---|---|---|---|---|
| 底 | `--wb-surface-ground` | `#fdf8ef` | `#1c1a16` | — | 无 | 无 |
| 卡 | `--wb-surface-card` | `#ffffff` | `#26231d` | 12px | `--wb-shadow-1` | 无 |
| 浮起 | `--wb-surface-raised` | `#ffffff` | `#302c25` | 12px | `--wb-shadow-3` | 无 |
| 墨块 | `--wb-surface-ink` | `#221f1a` | `#f2ece1` | 12px | 无 | 无 |

- 圆角统一 **12px**（按钮 / 卡片 / 标签 / 输入框），只有**几何形状**例外：
  状态圆点 50%、进度环 50%、图标圆底 50%。墨块是反色面，不带影子。
- 抬升用**暖调柔影**（非纯黑）：`--wb-shadow-1/2/3` 三档，色基 `rgba(120,92,48,α)`。
- **唯一的发丝线例外**是「控件边界」`--wb-rule-control`（亮色 `#8b8375`，对白卡 3.75:1；
  夜纸 `#6f6759`）—— 因为输入框 / 下拉框不描边就找不到边界。
- 单侧结构线 `--wb-rule-structure`（亮色 `#221f1a`、夜纸 `#6f6759`）**保留**，
  但它属于**内容层**（知识点正文 / 题面），不属于面分层。见 D-5。

**理由**

- 收口基线明确「纸与纸的区分 → 靠圆角 + 柔影分层，不用描边」「描边 → 不用（除非控件边界必须）」，
  并把「暖灰细线 `#cfc7b4`」与「抬起 = 暖调阴影 + 一根淡墨线」标为作废项。
- 分层不能只靠明度差：现状 `--dsw-bg-layer-1` 与页面底只差 `(0,−1,−3)`（F01 D1），
  差值小到不可见。新的做法是**明度差 + 柔影 + 圆角**三件套同时给：白卡对暖奶油底是
  1.06:1（肉眼几乎无差），但 12px 圆角 + `--wb-shadow-1` 让边界读得出来 —— 这正是
  现代圆润风的标准做法（内容从底上「浮起」），而不是仿古风的「描边分格」。
- 阴影必须暖调：现状阴影本来就是暖调（`rgba(61,52,37,…)` 系列），而描边是冷黑叠加
  （`rgb(0 0 0 / 4%|10%|12%)`，`workbench.css:31-33`，56 处引用）—— 真正「与纸不同源」的是
  描边不是阴影（F01 §1.3 的核实结论）。本变更把阴影统一成暖调三档、描边基本取消，
  方向与事实一致。

**否掉的备选**

- *沿用第 2 组的「暖灰细线 `#cfc7b4` + 淡墨线抬起」*：收口基线已否决（「现代圆润风里描边会显旧」）；
  且 `--dsw-border-l1` 一旦从 4% 黑换成暖灰，56 处分隔线会整体变明显，记录页 / 练习页分隔密度跳变
  （F01 Step 2 风险）。
- *靠底色差单独分层（无影子）*：F01 D1 的失败点 —— 层 1 与页面底差 3/255，等于没有层。
- *卡面用比底色更深的暖调而不是白*：那会把界面拉回「旧纸堆叠」，与「内容从底上跳出来」的
  现代观感相反。

**代价**

- 1.06:1 的卡 / 底明度差**低于**任何对比度阈值 —— 卡片边界**完全依赖阴影**，
  因此 `--wb-shadow-1` 的第一层（`0 1px 2px`）不能省；且在**低对比度显示器**或
  Windows 高对比度模式下，卡片边界会变得不可见（见 D-12 的 `prefers-contrast` 兜底）。
- 浮起与卡同色，**语义上只差影子**：`--wb-shadow-3` 相对 `--wb-shadow-1` 的差异必须在
  100% 缩放下可辨，否则浮层会读作「另一张卡」。
- 取消描边后，**所有以描边为分界的信息**（分组、表格线、引用块左边线）都要重新找载体：
  靠留白 + 圆角 + 字重，找不到的地方退回单侧结构线。

### D-3 色彩收编：22 个硬编码色归入三角色 + 墨阶 + 表面阶

**决策**

三角色（语义配额不变，只调饱和度与明度；`decisions.md` 收口「色彩」表）：

| 角色 | token | 亮色 | 夜纸 | 允许用于 | 禁止用于 |
|---|---|---|---|---|---|
| 学习蓝 | `--wb-role-action` | `#2f6fe4` | `#2f6fe4` | 主按钮、图标圆底、填充块 | 文字（用 `-ink` 变体） |
| 学习蓝（文字） | `--wb-role-action-ink` | `#2563eb` | `#86aaff` | 链接、链接式按钮 | 大面积底色 |
| 学习蓝（按下） | `--wb-role-action-deep` | `#1d4ed8` | `#7aa2f7` | `:active` | — |
| 阳光黄 | `--wb-role-current` | `#f5c518` | `#e6c46a` | 当前项、复习强调、连对进度、填充 | **承载文字** |
| 阳光黄（承载语义） | `--wb-role-current-ink` | `#7a5d00` | `#e6c46a` | 承载语义的文字 / 线条 | 大面积底色 |
| 注意红 | `--wb-role-needs-work` | `#c93a30` | `#e8837a` | 失败、阻塞 | 删除 / 回滚按钮 |

|---|---|---|---|
| 白字 on `--wb-role-action` | `#2f6fe4` | 4.65:1 | ✅ AA（正文级） |
| 链接文字 on 暖奶油底 | `#2563eb` | 4.89:1 | ✅ AA |
| 链接文字 on 白卡 | `#2563eb` | 5.17:1 | ✅ AA |
| 链接文字 on 夜纸 | `#86aaff` | 7.62:1 | ✅ AA |
| 黄色填充 on 暖奶油底 | `#f5c518` | 1.54:1 | ⚠️ **只承载面积 / 形状** |
| 黄语义文字 on 暖奶油底 | `#7a5d00` | 5.85:1 | ✅ AA |
| 红语义文字 on 暖奶油底 | `#c93a30` | 4.80:1 | ✅ AA |
| 红语义文字 on 夜纸 | `#e8837a` | 6.58:1 | ✅ AA |

一律走 `--wb-role-current-ink`（深金），黄色本身只做面积与形状。

### D-4 双字族分工：阅读面衬线 + 界面无衬线 + 等宽第三族

**决策**

| token | 值 | 用途 |
|---|---|---|
| `--wb-font-ui` | `-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", Helvetica, Arial, sans-serif` | 界面（现状 `--dsw-font-family`，`workbench.css:11-13`，**值不变，仅改名**） |
| `--wb-font-read` | `"Source Han Serif SC", "Noto Serif CJK SC", "Songti SC", "SimSun", serif` | 阅读面（新增，本地打包 woff2） |
| `--wb-font-mono` | 现状 `--dsw-font-code`（`workbench.css:14-15`）**补 `monospace` 兜底** | 代码 / 数字 id / 日期 |

**A 组（衬线）**：题面正文 `.practice-question-card`（`workbench.css:924-932`）、
知识点正文 `.knowledge-body`（`:493-500`）、解析 `.practice-solution`（`:933-940`）、
关联题面 `.linked-problem-text`（`:524`）、记录页作答原文 `.record-answer`（`:1467`）、
Agent 长文（现 `.rich-text`，`workbench.css:752`）。判据：**连续阅读 ≥ 3 行的内容**。

**B 组（无衬线）**：页面标题 `h1`、区块标题 `h2`、卡片标题 `h3`、顶栏 / 导航项、按钮、
表格、选项控件、状态标签、统计数字、自评星级、元信息、空态与错误文案、题号。

**等宽第三族**：代码、数字 id、日期时间。

**标题一律无衬线** —— 字体切换本身就是「这是标题 / 这是正文」的信号（`decisions.md` 4.3）。

**字体资产落地**

- `@font-face` 放在 `workbench.css` 顶部（`:root` 之前），文件名
  `workbench/server/static/fonts/SourceHanSerifSC-Regular.woff2` 与
  `-SemiBold.woff2`，`font-weight: 400 / 600`，`font-display: swap`
  （**不用** KaTeX 的 `block`，见 `static/katex/katex.min.css:1`）。
- 授权：SIL Open Font License 1.1，许可证文件与字体同目录
  `workbench/server/static/fonts/LICENSE-OFL.txt`，字体文件旁再放一份 `README.md`
  记录来源版本与子集化命令（仓库已有 woff2 先例：`static/katex/fonts/*.woff2` 20 个）。

**字集不可预知这个取舍（如实写明）**

- 全量思源宋体 CJK 的 woff2 实测量级是 **8–20 MB**（F08 S-12），不可接受。
- woff2 对 CJK 的压缩率实测在 **~130–200 字节/字**量级（按全量 8 MB / 约 65k 字反推）。
  由此：常用 3000 字 ≈ **0.4–0.6 MB/字重**；GB2312 全集 6763 字 ≈ **0.9–1.3 MB/字重**；
  2 个字重合计 **0.8–2.6 MB**。
- F08 S-12 里「≤300 KB/字重、2 字重 ≤600 KB」的估计**偏乐观**：按上面的压缩率，
  600 KB 只够约 2000–2500 字，连常用字表都覆盖不全。
- **本变更的目标定为：2 字重合计 ≤ 1.2 MB**，覆盖 **GB2312 一级字表 3755 + 中文标点 +
  数字 + 拉丁 + 常用符号**；超出子集的字（教材里的生僻字、姓名用字）落到 fallback
  （`Songti SC` / `SimSun`），**同一段文字内会出现两种字形**。
- 这是**已知且接受**的代价：字体是「读」的体验，而教材正文的字集不可预知
  （用户自建课程，字符集无法提前枚举）。完全消除它需要打包全量（8–20 MB）。
- 兜底链必须完整（`Source Han Serif SC → Noto Serif CJK SC → Songti SC → SimSun → serif`），
  `font-display: swap` 保证字体未到时**先显示 fallback 的可读文字**，不出现空白页。
- **体积待核**：上述压缩率是量级估算，实施时必须用
  `pyftsubset SourceHanSerifSC.otf --unicodes-file=gb2312.txt --flavor=woff2`
  实测，并把实测值回填到本节；子集字表若要更大，必须同步下调「≤1.2 MB」的承诺。

**否掉的备选**

- *打包全量思源宋体*：8–20 MB，首屏与仓库体积不可接受。
- *完全不打包，只用系统宋体*：零体积，但 Windows 之外的宋体形态不可控
  （`Songti SC` / `SimSun` 在各平台差异大），「阅读面衬线」的一致性会塌掉。
- *用无衬线做全部正文*：与已定的「阅读面衬线」冲突（`decisions.md` 7.4）。
- *把衬线打进正文变量、界面也用衬线*：与 4.3「标题全无衬线」冲突。

**代价**

- 仓库增加 0.8–2.6 MB 二进制；首次阅读会经历 fallback → 打包字体的替换（`swap`）。
- 教材正文中超出子集的字形不统一（见上）。
- 两字族的**字面高度差**需要实测校准：衬线在 17px 下视觉上比无衬线小，
  阅读面可能需要 +0.5–1px 的光学补偿。这属于实施期校准，不在本文固化。

### D-5 阅读版式规格：17 / 16 / 1.75 / 1.70 / 0.7em / 38em–42em，`.wb-reading` 自成一层

**决策**

新增**共享阅读版式层** `.wb-reading`（题面变体 `.wb-reading--stem`），
刻度全部用 token，消费 `--wb-font-read`：

| 项 | 正文（知识点） | 题面 / 解析（stem） |
|---|---|---|
| 字号 | **17px** | **16px** |
| 行高 | **1.75**（29.75px） | **1.70**（27.2px） |
| 段距 | **0.7em**（≈11.9px） | 同 |
| 行宽 measure | **38em**（≈646px） | **42em**（≈672px） |
| h2 / h3 / h4 | **22 / 19 / 17px**（行高 1.35） | 同 |
| 段落对齐 | `start`（**不 justify**） | 同 |

- **`.rich-text` 退役**，其全部消费方改挂 `.wb-reading`；不保留两套并行规则。
- `.wb-reading` **不**与 `.rich-text` 同挂一个元素（理由见下）。
- `.wb-reading` 自带 h1–h4 规则（h1 = 24px，仅作兜底），保证 h3(19px) > h4(17px)，
  消除 `pages.py:978` 把 `###` 映射成 `<h4>` 而 CSS 无 h4 规则造成的层级倒挂。

**为什么 `.wb-reading` 不能直接挂 `.rich-text`**

`.rich-text` 现存规则（`workbench.css:752-809`）与阅读层**逐项冲突**，且都是
`(0,1,0)` / `(0,1,1)` 的单类选择器 —— 谁赢只取决于**文件里的先后顺序**：

| `.rich-text` 现规则 | 与阅读层的冲突 |
|---|---|
| `:752` `line-height: 1.7` | 覆盖阅读层的 `1.75`，17px 下 28.9px ≠ 29.75px |
| `:758-760` `h1 21px / h2 18px / h3 16px` | 覆盖 22 / 19 → **h3 16px < h4 17px**，重建 F07 D-09 的倒挂 |
| `:761` `p { margin: 8px 0 }` | 覆盖 `0 0 0.7em`（11.9px），段距塌回 8px |
| `:766` `code { font-size: .92em }` | 阅读面要求 0.82em（≈14px），.92em 在 17px 下是 15.6px |
| `:786` `border: 1px solid var(--dsw-border-subtle)` | 该变量**从未定义**（F01 D8）→ 整条声明失效 → 边框色回落 `currentColor`，表格线变成正文色 |

一句话：**同挂会让 17px/1.75/0.7em 这条契约变成「取决于 CSS 文件顺序」**，
这正是审计反复指出的「约定靠作者记忆维持」的病根。正确做法是 `.rich-text` 整体退役、
阅读层自包含。

**出处与依据**

- `docs/PRODUCT-MANUAL.md:129-130`（知识点页硬约束）：「正文使用更大的阅读字号、
  宽行距和单侧结构线，是页面最醒目的内容」→ 正文 17px **必须大于**题面 16px。
  现状 `.practice-question-card` 也是 17px（`workbench.css:930-931`），
  与该硬约束**直接冲突** → 本变更把题面降到 16px（stem 档）。
- `openspec/specs/workbench-ui/spec.md:766-771`「Learning content is the visual anchor」：
  题面与知识点正文都用**主阅读节奏**（≥17px + 宽行高）、**各带一条结构强调边**、
  **不做装饰性阴影强调** → 对应 D-5 的 2px 单侧结构线与「卡片不靠阴影强调」。
- 行高 1.75/1.70、段距 0.7em、measure 38em/42em、标题 22/19/17 来自
  `tmp/frontend-audit/F07.md` §6.2 / §6.3（C-01…C-05 的裁决结论）。
- 标题全无衬线来自 `decisions.md` 4.3。

**否掉的备选**

- *题面也 17px*：与 `docs/PRODUCT-MANUAL.md:129-130` 的「正文更醒目」直接冲突
  （F07 C-01 已裁决）。
- *正文 18px*：会让表格与列表一起变松、挤压界面信息区（`decisions.md` 4.1 否决项）。
- *保留 `.rich-text` 作为 `.wb-reading` 的别名*：别名 = 两套规则仍在文件里，
  顺序依赖仍在，只是把问题推后。

**代价**

- 知识点正文的 h3 从 14px 升到 19px、h4 从 UA 默认 17px 升到有规则的 17px →
  含 `###` 的知识点正文会**变高**，中栏首屏行数变化，知识点列表页与详情页的折行需复核。
- 题面从 17px 降到 16px 是**用户可感知变化**（虽是为了兑现「正文更醒目」这条既有硬约束），
  必须写进 `docs/PRODUCT-MANUAL.md` 并在 spec delta 里显式说明。

### D-6 Markdown 双渲染器：统一到**服务端语义**，用 pytest 锁住两侧输出一致

**决策**

1. **统一到服务端语义**：正文内容里的 `#` → `<h2>`、`##` → `<h3>`、`###` → `<h4>`；
   即**正文标题永远从 h2 起步，h1 留给页面标题（壳层所有）**。
   理由：`pages.py:978`（`level = len(heading.group(1)) + 1`）已经在服务端这样做了，
   而服务端渲染的是**知识点正文**；页面自身的 `<h1>` 是知识点标题 / 试卷名。
   若统一到客户端语义（`#` → h1），练习页的正文会与页面标题**争 h1**，
   且 `docs/ARCHITECTURE.md:240`「普通 Paper 题目与知识正文共享主阅读层级」无法兑现。
2. **代码围栏语言标记两侧都保留**：服务端补上 `class='language-xx'`（今天 `pages.py:955` 丢掉了）。
3. **引用块两侧同规则**：统一成客户端的正则 `^\s*>\s?`（今天服务端用 `line.startswith(">")`，
   `pages.py:993`，行首空格会漏判）。
4. **两侧由同一条规则表定义，而不是同一份代码** —— Python 与 JS 之间无法共享代码
   （无构建步骤、不引 npm），所以「同一份规则」落成**可执行的等价性约束**：
   **新增 `tests/test_markdown_render_parity.py`**，用一份 Markdown 语料（标题 3 级、
   有 / 无语言标记的代码围栏、引用、有序 / 无序列表、GFM 表格、分隔线、行内数学）
   分别喂 `pages._render_markdown()`（服务端）与 `workbench.js` 的渲染函数（客户端，
   经 Node 调用同一份 JS 源），**断言两侧 HTML 逐字符相等**。
   语料与断言放在 `tests/` 下，不进产品目录。

**理由**

- 这是**既有契约未兑现**：`docs/ARCHITECTURE.md:240` 明写「普通 Paper 题目与知识正文
  共享主阅读层级」，今天服务端 h2 起步、客户端 h1 起步，同一篇内容跨页时标题层级跳一级
  （F07 D-08）。
- 属于冻结线内：只改**渲染函数产出的 HTML**，不动请求序列、不动载荷、不动持久化。
  proposal 的冻结条款明确允许 DOM 结构与顺序变化。
- 选服务端语义而不是客户端语义：**服务端渲染的是「正文」**（知识点详情），
  它的 h1 已经被页面标题占用；客户端渲染的题面同样处于某个页面之内。
  「内容标题从 h2 起步」是唯一能让两侧共享同一层级刻度的规则。

**否掉的备选**

- *让客户端调用服务端渲染（发一次请求）*：改变请求序列 → **违反冻结**。
- *把渲染器搬到一处（Python 侧输出 HTML，客户端只插入）*：练习页的题面 / 解析是
  客户端在作答过程中增量产出的，走网络会改请求时序 → 违反冻结。
- *保持两侧差异、各自调 CSS 让它们「看起来一样」*：层级语义仍然错位
  （正文里的 `#` 在一处是 h2、一处是 h1），而且阅读层的 h1 / h2 字号不同，
  视觉上必然对不齐。
- *统一到客户端语义（`#` → h1）*：正文标题会与页面标题同级，破坏页面层级。

**代价**

- 服务端渲染器要补代码围栏语言标记与引用正则，**产出 HTML 会变**（多一个 class）——
  属于表现层变化，不影响持久化；但需检查是否有测试断言了旧的 `<pre><code>` 形态。
- 客户端侧 `#` → h1 会变成 h2：**练习页里以 `#` 开头的题面，其标题字号会从 h1 档降到 h2 档**
  （22px 档）。这是本变更**唯一一次让既有可见文字变小**的地方，必须在验收里单列。
- pytest 需要能执行 JS（Node）。若 CI 无 Node，则退化为
  **把客户端渲染器抽成纯函数并由 Node 单测 + pytest 双跑**，或把 JS 侧的期望 HTML
  固化为 pytest 里的黄金样本（后者会退化成「人工同步」，需要写进风险表）。

### D-7 动效系统：CSS 为主、vanilla JS 为辅，四档时长 + 三档缓动 + 白/黑名单

**决策**

**时长四档**（收口基线「交互 120–180ms；场景 240–520ms」）：

| token | 值 | 用途 |
|---|---|---|
| `--wb-dur-1` | 120ms | 即时反馈（按下、勾选、圆点切换） |
| `--wb-dur-2` | 180ms | 微反馈（hover、focus 环、边框换色） |
| `--wb-dur-3` | 240ms | 进场 / 淡入 / 列表 stagger 单项 |
| `--wb-dur-4` | 520ms | 场景（挤压回弹、庆祝、台灯转场总长约 700ms，见下） |

**缓动三档**：`--wb-ease-out`（`cubic-bezier(.2,.8,.2,1)`）、`--wb-ease-soft`
（`cubic-bezier(.4,0,.2,1)`）、`--wb-ease-spring`（`cubic-bezier(.34,1.56,.64,1)`）。
**挤压回弹直接抄多邻国的 5 段关键帧 17 / 33 / 83 / 167 / 217 ms（总 517ms）+ 4 条贝塞尔**
（`decisions.md` 12.2），做成一条 `@keyframes`，落进 `--wb-dur-4` 的预算内。

**动效范围（收口基线）**：交互反馈 + 数据层 + 视图转场 + **里程碑仪式**。
**禁止**：全局背景 canvas、鼠标跟随、视差、光标辉光。

**白名单（动效只落在这里）**

1. 交互反馈：按钮 / 卡片的 hover 与按压、状态圆点切换、输入框聚焦抬起。
2. 数据层：负荷柱逐柱生长（错峰 24ms）、日历格扩散、数字滚动、统计块入场、图表切换
   （`decisions.md` 15.4 明确「数据层也加微交互」）。
3. 视图转场：**`#middle-page` 容器动画** + 骨架屏（灰块 + 微光扫过）。
4. 里程碑仪式：完成页入场 + 数字滚动 + 进度带 0→100% + 几何爆点；里程碑档再叠彩带 / 纸片。

**黑名单**：全局背景、鼠标跟随、视差、光标辉光、常驻循环动画、
`transition: all`、用 `width/height/top/left` 做过渡。

**为什么必须 CSS 为主、vanilla JS 为辅**

`workbench/server/static/middle-navigation.js` 每次切页**整体替换 `#middle-page` 的
innerHTML**（`middle-navigation.js:97` 起的 `installPageContent`）。因此**任何
「JS 给子元素加一次性进场类名」的方案在切页后立刻失效** —— 类名随 innerHTML 一起被冲掉。
同理，`nth-child` stagger（纯 CSS）与骨架屏也必须挂在**容器**上，而不是挂在
JS 临时插入的元素上。

- 容器动画：`#middle-page` 自身跑一条 `animation`（上浮 8–12px + 淡入，180–240ms），
  切页后由 CSS 自动重放，**不依赖任何 JS 类名**。
- 骨架屏：容器切页前先呈骨架，切页后容器动画接管。
- 只有三处需要 JS 编排，且都**只写已存在元素的 `textContent` / `style`**，不新增节点、
  不新增事件绑定：
  ① 统计数字滚动（rAF 写 `textContent`）；
  ② 连对计数器（写已有计数器的值与 class）；
  ③ 台灯转场（写一个已存在的装饰层的 `transform`）。

**性能预算**：只动 `transform` / `opacity`；单帧 ≤16ms；同屏合成层 ≤30；
`will-change` 只在动画期间加、结束后移除。

**否掉的备选**

- *纯 JS 编排（Web Animations API）*：切页即失效（上面已述）；且需要给每个元素
  挂一次性状态，DOM 规模 125 处构造点 / 130 处事件监听下维护成本高（F08 §8 开头）。
- *用 `prefers-reduced-motion` 下把动画时长设为 0.01ms 糊弄*：这是「变慢」不是「取消」，
  F08 R-2 明禁；降级必须是**状态直切**。
- *把动效限制在数据层（早前决策）*：收口基线已扩大到交互 + 数据 + 转场 + 里程碑，
  且 `decisions.md` 15.4 明确要求数据层也要微交互。

**代价**

- `transition` / `animation` 的取值必须全部收敛到 `--wb-dur-* / --wb-ease-*`；
  现状是 14 条 transition 散在 100/160/180/200/300ms 五档 + 三种自定义缓动（F01 D12）。
- 台灯转场约 700ms（探出 180ms + 点亮 + 涟漪 450ms + 收回），**超过 `--wb-dur-4`**，
  属例外预算，需要单独记账（它是「主题切换的叙事」，不是常规转场）。
- 骨架屏需要每个中栏页面知道「内容形状」→ 需要一套占位约定，实施成本不低。

### D-8 动效偏好与系统 reduced-motion：系统是硬底线，应用开关只在其之上收紧

**决策**

- **动效偏好**是**开 / 关**两态的浏览器偏好，默认**跟随系统** `prefers-reduced-motion`。
- **系统 `prefers-reduced-motion: reduce` 永远生效，应用内开关不能覆盖它**：
  在系统 reduce 下，即使用户把动效偏好设为「开」，也只启用**弱动效档**：
  - 允许：透明度变化、状态直切、无位移的淡入。
  - 禁止：台灯涟漪、彩带 / 纸片、挤压回弹、入场上浮位移、纸片飞散、骨架微光扫过。
- 用户显式设为「关」时，**全部动效直切**（比系统 reduce 更严）。

**理由**

- OS 级无障碍偏好是用户**整体环境**的一部分（晕动症、注意力障碍、某些辅助技术的默认行为）。
  应用内开关覆盖它，等于替用户撤销了一个可能与本应用无关的设置 —— 这是公认的
  可访问性反模式。多邻国调研里的反面教训（11 条标题级证据，含 ADHD 用户要求彻底关闭，
  `decisions.md`「多邻国调研结论」）支持的是**分层 + 提供开关**，不是「覆盖系统」。
- 收口基线的降级行原文是「`prefers-reduced-motion` 一律降级为状态直切；涟漪直接切、
  庆祝直接落终态」——「一律」意味着没有例外通道。
- 已有全局降级闸门可复用：`workbench.css:733` 与 `:1126-1131`
  （`*, *::before, *::after { transition: none !important; animation: none !important; }`），
  CSS 驱动的动效自动合规；JS 编排的三处需自行 `matchMedia`（参照 `workbench.js:1639`
  的既有写法）。

**否掉的备选**

- *让应用内「开」完全覆盖系统 reduce*：如上，属于可访问性反模式；且 OS 级设置常常
  是别的应用触发的，用户不会想到是这里。
- *做「自动 / 开 / 关」三态*：语义更完整，但与 `docs/GLOSSARY.md` 里
  「动效偏好 = 动效开 / 关的浏览器偏好，默认跟随系统 reduced-motion」的既有词条定义不符；
  两态 + 「系统是硬底线」已经能表达全部三种实际行为。

**代价**

- 「开」在系统 reduce 下**不等于「全开」**，用户可能困惑 → 设置视图必须**显示当前实际生效的档位**
  （这本身符合 P-1 少字原则：用几何 / 状态表达，而不是加一段解释文字）。
- 实现上需要**两套降级判断**：CSS 靠媒体查询，JS 靠 `matchMedia`；三处 JS 编排
  （数字滚动 / 连对 / 台灯）必须各自处理，漏一处就会在 reduce 下仍动。
- 现有全局闸门是 `!important` 全局关停（`:1126-1131`），它与「弱动效档」（允许透明度变化）
  冲突 → 需要把全局闸门从「一刀切 none」改成「分级降级」，这是一次**收紧既有行为之外的改动**，
  必须在 spec delta 里写明降级后**仍然可见的状态**（F08 R-2：状态永远是文字 / 几何，不是动画）。

### D-9 设置视图的形态与主题应用时机

**决策**

1. **主题属性挂在 `<html>`**：`document.documentElement.dataset.theme = "night" | ""`。
   理由：`:root` 就是 `html`，CSS 变量必须从根级联到整篇文档；
   挂到 `<body>` 会让 `html` 的画布底色**仍是暖奶油** → 视口边缘露白，
   主题切换时出现一圈白边。
2. **首屏防闪**：在 `pages.py` 的 `<head>` 内、样式表 `<link>` **之前**放一段内联脚本，
   同步读 `localStorage` 并写 `documentElement.dataset.theme`。
   脚本必须在首个绘制前执行 → 读到「夜纸」时**第一次绘制就是夜纸**，无闪白。
   **不使用 `prefers-color-scheme` 兜底**（手动开关是定案）；未设置偏好时默认暖奶油。
   同时按主题声明 `color-scheme`（`light` / `dark`），让原生控件与滚动条跟随。
3. **偏好存储**：沿用现有关键 **`wb_settings_<工作区>`**（`workbench.js:165`
   `var SETTINGS_KEY = "wb_settings_" + WS`，`WS` 来自 `layout.dataset.workspace`），
   把四个新偏好作为**同一 JSON 对象的四个新键**写入，与既有 `showRating`
   （`workbench.js:188`）和 `runningSendAction`（`:503`）并列。
   **不新增 localStorage 键、不落服务端、不写池**。
4. **设置视图形态**：中栏新增一个页面（**工作台设置视图**），由**左栏开关**打开；
   它是**同一工作区内的中栏路由**，走 `middle-navigation.js` 的同工作区导航路径
   → `#ai-column` 的 DOM 与 Agent 控制器**保持挂载**，
   满足 `openspec/specs/workbench-ui/spec.md:1289`「Same-workspace middle navigation
   preserves the Agent rail」。
5. 左栏现有设置区（`pages.py:659-668`，`.settings-section`）保留既有两项
   （运行中发送方式、练习显示自评）—— 它们是**行为偏好**，与新的**外观偏好**分属两处：
   外观偏好进设置视图，行为偏好留在左栏既有位置，避免把行为选项搬走（兼容性边界：
   用户可感知的位置不能无声搬动）。

**理由**

- 挂 `<html>`：主题是文档级属性；`<body>` 方案会在画布边缘露白。
- 内联脚本而不是 `prefers-color-scheme` 兜底：定案是「手动开关」；
  用系统兜底会在用户没选的情况下被动进入夜纸。
- 复用 `wb_settings_<工作区>`：既有关键已经是**按工作区**的浏览器偏好，
  新偏好同址同格式 → 不新增存储面、不碰 `docs/DATA_MODEL.md`。
- 走中栏同工作区路由：这是「不新增交互范式」的最小实现；也是唯一能**复用**既有
  `middle-navigation.js` 导航契约的路径。proposal 的冻结条款允许
  「beyond the additions this proposal names」的焦点顺序变化 —— 设置视图与左栏开关
  正是被点名的两处新增。

**否掉的备选**

- *主题类挂 `<body>`*：画布边缘露白；且 `html` 的 `background` 与 `body` 的会不一致。
- *用 `prefers-color-scheme` 做首屏兜底*：与「手动开关」冲突。
- *把主题写进服务端（按用户 / 工作区存库）*：新增持久字段 → 触碰 `docs/DATA_MODEL.md`、
  触碰冻结线「持久化不变」。定案是「浏览器偏好、按工作区存储」。
- *把外观偏好做成左栏下拉（不建设置视图）*：四类偏好（主题 / 阅读字面 / 动效 / 声音）
  塞进左栏会让左栏变成设置堆；且定案明确「中栏独立设置页，左栏开关」。
- *把既有行为偏好也搬进设置视图*：改变用户可感知的位置，且既有 spec
  `openspec/specs/workbench-ui/spec.md:1047`「Learner settings in the left rail」
  把自评开关明确钉在左栏 —— 搬走会与既有契约冲突。

**代价**

- 新增一条中栏路由 + 一个左栏开关 → **焦点顺序变化两处**（左栏开关位、
  设置视图内的控件），需要在 spec delta 里显式声明，且必须保证既有契约
  「同工作区导航保留 Agent 右栏」不被破坏。
- 内联脚本在 `<head>` 里 → 与「不用内联脚本」的洁癖冲突，但没有构建步骤、无法外部化
  一个小 JS 文件又不付出一次额外请求的代价 —— **内联 3 行是此约束下的正解**
  （同 F08 §11.4 的首屏防闪写法）。
- 偏好按工作区存 → 同一浏览器换工作区要重新设置外观。这是定案（「按工作区存储」），
  不是缺陷，但要写进 `docs/PRODUCT-MANUAL.md`。
- 主题偏好跨标签页不同步（各标签页独立读 `localStorage`）。若要跨标签同步需
  `storage` 事件监听 → 新增事件绑定；本变更**不做**，记入 Open Questions。

### D-10 三栏几何单一真值：CSS 持有模板，JS 只写两个列宽变量

**决策**

- **CSS 是模板的唯一持有者**：`#layout` 写
  `grid-template-columns: var(--wb-col-left, 280px) minmax(0, 1fr) var(--wb-col-right, 420px);`
  `#layout[data-ai-collapsed]` 用同样的变量、右栏置 0。
- **JS 只写两个数值变量**：`workbench.js:4587` 现在的
  `layout.style.gridTemplateColumns = leftWidth + "px minmax(420px, 1fr) " + rightWidth + "px"`
  改为 `layout.style.setProperty("--wb-col-left", …)` / `setProperty("--wb-col-right", …)`；
  窄屏分支（`workbench.js:4580-4582`）清变量而不是清整段 inline 样式。
- **「中栏不窄于 420px」的不变式由 JS 的夹取维持**（现状 `workbench.js:4584-4586`
  已按 `available = clientWidth - middleMinWidth` 夹取左右栏），CSS 的
  `minmax(0, 1fr)` 只是**变量未就位时（首帧）的兜底**，不承担该不变式。
- 拖拽侧栏的规格（`openspec/specs/workbench-ui/spec.md:524-531`「Resizable desktop
  sidebars」：只改当前页内存中的列宽、不导航、不持久化）**完全不变** —— 本决策只改
  **值的传递通道**，不改行为、不改边界、不改拖拽语义。

**理由**

- 现状是**双源**：CSS 写 `280px minmax(0, 1fr) 420px`（`workbench.css:160`），
  JS 每次都 inline 覆盖成 `280px minmax(420px, 1fr) 420px`（`workbench.js:4587`），
  **CSS 那条在桌面端从不生效**（F02 D12）。任何「改 CSS 就能改三栏几何」的直觉都是错的。
- 收敛后：「模板形状」只有一处（CSS），「具体宽度」只有一处（JS 的两个变量）。
  媒体查询在窄屏覆盖整条 `grid-template-columns` 的写法**必须保留**
  （`workbench.css:1174-1207` 的 `1fr` 规则更晚、覆盖基础规则），这是既有行为，不动。

**否掉的备选**

- *删掉 JS 的 inline 覆盖、只留 CSS*：拖拽就没有了（CSS 里没有宽度来源）。
- *把列宽也写进 CSS 变量、由 JS 写 `:root`*：等价方案，但写到 `#layout` 上更局部，
  不会影响图谱页的同名变量。
- *让 JS 继续整段覆盖、只删 CSS 那条*：那 CSS 就不是模板持有者；
  且媒体查询（窄屏 `1fr`）会被 JS 的 inline 覆盖**压过** —— 现状里 JS 靠
  `workbench.js:4580` 的 `window.innerWidth < 1024` 分支绕开，但那是**逻辑重复**，
  断点一旦和 CSS 媒体查询不一致就会错位。

**代价**

- 拖拽时列宽的变化从「整段 inline 样式」变成「两个自定义属性」，
  `transition: grid-template-columns 200ms ease`（`workbench.css:161`）仍然生效
  （`grid-template-columns` 引用了变量，变量变化会触发重算）→ **拖拽时可能出现过渡拖影**，
  需在 `#layout.is-resizing` 上关掉过渡（现状已有这条规则位）。
- `#layout[data-ai-collapsed]`（`workbench.css:164`）与 JS 折叠逻辑的配合点需一起改。

### D-12 焦点可见性与对比度：焦点环只在 `:focus:not(:focus-visible)` 时让位

**决策**

**焦点**

- 三处 `outline: none` 改为**只在非 `:focus-visible` 时**让位：
  `workbench.css:338`（`select:focus`）、`:427`（`textarea:focus, input:focus`）、
  `:833`（`#answer-box:focus`）。
  写法：`selector:focus:not(:focus-visible) { outline: none; }`，
  **不动**全局 `:focus-visible` 规则（`workbench.css:1123`：
  `outline: 2px solid var(--dsw-brand-accent); outline-offset: 1px`，
  改成 `--wb-role-action` + `outline-offset: 2px`）。
- 为什么现状会整体失效：`select:focus` 的特异性是 `(0,1,1)`，高于 `:focus-visible` 的
  `(0,1,0)`，且两者都命中 → **主路径控件的焦点环被完全吃掉**（F08 §8.5 P0，
  实测 `outlineStyle === "none"`）。

**对比度**

墨阶收敛为**4 级可用文字灰 + 1 级非文本灰**，全部 ≥ 4.5:1（底 = 亮色 `#fdf8ef` /
白卡 `#ffffff`；夜纸底 `#1c1a16` / 卡 `#26231d`）：

| 级别 | token | 亮色 | 对暖奶油底 | 对白卡 | 夜纸 | 对夜纸底 |
|---|---|---|---|---|---|---|
| 主墨 | `--wb-ink-strong` | `#221f1a` | 15.52 | 15.86 | `#f2ece1` | 14.78 |
| 正文墨 | `--wb-ink-body` | `#3d3830` | 10.99 | 11.24 | `#ded6c8` | 12.04 |
| 次级墨 | `--wb-ink-muted` | `#5d564b` | 6.85 | 7.02 | `#bdb5a7` | 8.55 |
| 三级墨 | `--wb-ink-faint` | `#776f61` | **4.69** | **4.96** | `#9c9384` | **5.73** |
| 非文本灰 | `--wb-ink-ghost` | `#b3aca0` | 2.13（非文本） | — | `#4e4941` | 1.95（非文本） |

- 现状不达标的四档被一次性收口：`--dsw-label-tertiary` 3.67:1（33 处引用）、
  `--dsw-label-caption` 2.12:1（5 处）、`--dsw-label-dimmed` 1.25:1（`::placeholder`，1 处）
  全部并入 `--wb-ink-faint`；`--dsw-state-warn` 3.20:1（2 处）并入
  `--wb-role-current-ink`（5.85:1）；`--dsw-state-success` 2.26:1（4 处）见 D-3 的绿例外。
- **`--wb-ink-faint` 仍保留 4 级可用层级**：三级墨 4.69:1 与次级墨 6.85:1 仍是两个
  可辨的台阶，只是台阶变窄了 —— 这是「4 级都要能用」与「4.5:1 底线」之间的唯一解。
- `::placeholder` 改用 `--wb-ink-faint`（现状靠 fallback `#68707b` 才活，
  `workbench.css:1051`）。

**否掉的备选**

- *只把三处 `outline: none` 删掉*：鼠标点击也会留下焦点环，视觉噪声大；
  `:focus:not(:focus-visible)` 是现代浏览器的标准解法。
- *把墨阶砍到 3 级*（F01 P08 的做法：caption 与 dimmed 合并进 faint）：
  那样就只剩 3 级文字灰，与本任务要求的「保持 4 级可用的视觉层级」不符。
  本方案通过**把 caption / dimmed / placeholder 三档合并进 faint** 达成 4 级
  （strong / body / muted / faint），而不是把 muted 也合并掉。
- *把 faint 提到 5:1 以留余量*：会让三级文字与次级文字太接近，层级反而塌掉。

**代价**

- 39 处三级文字（33 + 5 + 1）**变深** → 页面整体「比现在重」。
  因此同一批改动里**不得再叠加深色墨块**，否则会过重。
- 焦点环从 `outline-offset: 1px` 改成 2px → 12px 圆角控件的焦点环会略微外扩，
  在紧贴布局边缘的控件上可能被裁（左栏项、表格单元），需逐处看。
- 暗色下三级墨提到 5.73:1，比亮色更宽松 —— 两套主题的文字阶梯**不是同一组数值**，
  实现时不能共用一套变量名以外的常量。

### D-13 记录中心数据面：**圆角卡片流**（不是表格），六项字段一个不少

**决策**

- **形态**：每条作答记录一张**圆角小卡**（12px 圆角、**不描边**、靠留白与
  `--wb-shadow-1` 分隔），取代今天的 98 张带边框便签
  （`workbench.css:1457` `.record-row { margin: 0 0 12px; padding: 12px 14px; }`
  叠加基类 `.card`（`:447-453`，`border: 1px solid var(--lk-ink)` + 阴影 + 6px 圆角）；
  实测 `?view=attempts` 页高 **8895px**）。
- **六项字段一个不能少**（`openspec/specs/workbench-ui/spec.md:944-947`
  「Attempt rows SHALL retain the linked problem, honest verdict (对 / 错 / 未判定),
  linked rating, note, answer excerpt, and time」）：
  - 题目 + **评语 + 摘录**放卡片主区（评语与摘录作为题目下的第二、三行）；
  - **判定**用「结构块 + 几何符号 + 文字」三通道（**不再是绿药丸**，
    见 D-3）；**自评**用彩色圆点 + 星级形状（**几何冗余通道**，零文字标签）；
  - **时间**放卡片右上角（次级墨）。
- **错题视图**同样是卡片流（题面 + 错因摘要），与明细同族但视觉更重一档。
- **为什么不能用 `position: sticky`**：
  ① 卡片流**没有列头**，没有 sticky 的对象；
  ② 即便将来改成表格，`#middle`（`workbench.css:172-177`）是**唯一的滚动容器**
    （`overflow-y: auto`），表头 sticky 会脱离表格、粘到页面标题带下方 ——
    这正是 F05 P-05 的原始禁令，仍然成立；
  ③ sticky 在 `overflow: auto` 的祖先里会创建新的包含块，列头与表体可能错位。

**理由**

- 收口基线「页面与组件」表明写：作答明细 = **圆角卡片流**（不描边，靠留白与柔影分隔；
  **不用表格**），来源是用户对第 8 组 8.3「真表格」的直接否决（「表格还是太 nerd 了」）。
  **因此本条与审计提案相反** —— F05 P-05 的「真表格」方案作废，本设计给的是卡片流。
- 但「六项字段一个不能少」是**既有 spec 条款**，卡片流不能借「视觉简化」削字段。
- 判定徽章的绿（`workbench.css:1462`）是契约外第四色（F05 D-06），本变更一并处理。

**否掉的备选**

- *真 `<table>`*（F05 P-05）：已被用户否决；且 `table` 元素数现在就是 0
  （F05 D-05 实测），改表格会同时改变 DOM 结构与可访问性树。
- *继续用带边框的卡片*：那正是「98 张便签、页高 8895px」的现状。
- *用颜色点表示判定，但保留绿*：绿是契约外色相。

**代价**

- 页高不会像表格方案那样从 8895px 降到约 4400px —— 卡片流的密度仍低于表格，
  预计落在 **5500–6500px** 量级。这是「可扫读 vs 可对齐」的取舍，用户选了前者。
- 跨记录比较（同一天做了几道、判定分布）不再靠列对齐，要靠**统计区的仪表盘卡片**
  （收口基线「记录统计区 → 仪表盘卡片」）承担。→ 统计区必须补上这层聚合能力，
  否则卡片流把「对齐扫读」拿走却没还回来。
- 六项字段塞进一张卡 → 卡片信息密度高；需要靠字号阶梯（标题 18 / 字段 13 / 时间 12）
  与行距拉开，不能靠分隔线。

### D-14 作答日历：7 行 × 12 列、格 ~13px、填色 **且** 高度双编码

**决策**

最终形态（收口基线「作答日历 → 热力方块（7 行×12 列、~13px、填色 且 高度双编码）」）：

- **转置**为 7 行（周一–周日）× 12 列（周），与 GitHub 贡献图同构；
  格子从 70×70px 降到约 **13×13px**，整卡高度从 **1084px 降到 ~250px**。
- **强度双编码**：有数据的格子**同时**用**填充色**（蓝的 5 档）与**高度**
  （`transform: scaleY()` 或行内高度比）表达 —— 颜色不再是唯一载体
  （`openspec/specs/workbench-ui/spec.md:749`）。
- **5 档阈值显式化**：今天阈值只活在 `workbench/server/records.py:237`
  （`level = 0 if attempts == 0 else 1 if attempts == 1 else 2 if attempts <= 3
  else 3 if attempts <= 7 else 4`）→ 必须**变成可见契约**：
  ① CSS 里**补齐 `.level-0`**（今天只有 `.level-1..4`，`workbench.css:1420-1430`
  —— 「0 次」这一档**从来没有被设计过**）；② 页面给出**图例**（几档分别代表几次）；
  ③ 阈值本身写进 spec（否则又是一段只活在代码里的口径）。
- **加今天标记**（描边 + 端点几何）、**加月份刻度**（沿用时间视图日历已有的
  `today` 表达方式，`workbench.css:1260` `.calendar-cell.today`）。
- **无障碍**：`aria-label` 挂在有 `role` 的容器上（今天 84 个 `<span>` 带
  `aria-label` 却无 `role`，`records.py:242`）。

**理由**

- 实测：`.record-activity` = 520×922px、单格 70×70px、整卡 800×1084px ≈ 一屏；
  而 98 次作答只有 **3/84** 格有数据（F05 D-02 实测）→ 今天用户第一眼得到的是
  「我没练过」，而不是「我练过 98 次但集中在 3 天」。
- 「颜色不是状态的唯一载体」是**既有硬约束**（`spec.md:749`），今天的日历
  颜色是**唯一**载体（无图例、无高度、无形状），已经违约 —— 这一条不是新口味，
  是补既有契约。
- 加「今天」与「月份刻度」的理由同 F05 D-04：没有时间锚点的日历要靠数格子，
  而「最近一次是上周还是上个月」正是翻记录页最常见的诉求。

**否掉的备选**

- *保留 7 列 × 12 行的现状，只缩格子*：会丢掉「星期几」的横向可读性；
  转置是 GitHub 式的心智模型，7 行固定 = 星期。
- *点阵（只画有数据的日子）*：丢掉时间全貌，用户无法判断「整周都没练」。
- *折线 / 柱状*：丢掉「星期几」维度。
- *图例写成一句文字说明*（如今天的「颜色只表示当天的作答次数。」，`records.py:247`）：
  这是 P-1 少字原则的反面 —— 说明该由**图例本身**（色块 + 刻度）承担。

**代价**

- 13px 的格子**装不下文字**，所以所有信息必须走 `title` / `aria-label`；
  触屏上没有 `title` → 必须保证 `aria-label` 正确（图例 + 逐格标签）。
- 高度双编码意味着格子**不再是正方形**（高度随强度变）→ 布局从 `aspect-ratio: 1`
  （`workbench.css:1421`）改成显式的行高，需要重新定 7 行 × 12 列的网格。
- 阈值从代码搬进契约 → **这是一个 spec 变更**（`calendar-workload` 或
  `workbench-ui` 的 delta 必须写死 5 档的次数区间），不能只改 CSS。

  统计区的仪表盘卡片必须补上聚合（按日 / 按判定的分布），
  否则「对齐扫读」被拿走却没有还回来；这一条要作为记录中心交付的验收项。
- [Risk] **暖色 + 圆润的方向可能被误读成「消费级 App」，与学术气质冲突** → Mitigation：
  骨架保持「暖奶油底 + 暖炭褐墨 + 三角色色配额」，**不引入**消费级 App 的
  渐变按钮、圆形头像、玻璃拟态、emoji 导航；图标一律手写具象静物 SVG，
  不用图标库、不用 emoji。
- [Risk] **本变更登记的 128 处漂移在交付后依然存在** → Mitigation：
  登记表带优先级与归属；交接文档与 `docs/PENDING-DEFINITIONS.md` 显式提示
  「存在 N 条已登记漂移」；不允许把登记表当成「已处理」。

## Trade-offs

- **圆角 + 柔影分层（无描边） ↔ 低对比度显示器与高对比度模式**：卡片 / 底面明度差只有
  1.06:1，边界完全依赖阴影 → 接受边缘丢失，换取「现代圆润」的一致观感；
  兜底是 `@media (prefers-contrast: more)` 下给卡片补一条发丝线（该媒体查询全仓 0 命中，
  是新增而非修改）。
- **12px 统一圆角 ↔ 按钮的「药丸感」**：现代圆润风里按钮常做成全圆；本变更按定案用 12px，
  按钮显得更「方」→ 用更高的饱和填充色与更快的按压回弹补偿亲和力。
- **正文 17px / 题面 16px ↔ 练习页信息密度**：题面变小一行 → 每屏少一行题面文字；
  换来「正文是页面最醒目的内容」这条既有硬约束真正兑现。
- **记录中心卡片流 ↔ 页高与可扫读性**：页高停在 5500–6500px（表格方案本可到 4400px）；
  换来「表格太 nerd」之外的可读性与现代感，聚合能力由统计区补。
- **只做 4 级墨阶而非更多 ↔ 层级表达**：更亮的灰不能承载正文 →
  层级必须靠字号 + 留白 + 圆角承担，这正是 P-1 少字原则的必然结果。
- **手写具象静物 SVG ↔ 成本与一致性**：每个导航项一个实物插画，成本随数量线性上升
  （5 个导航项 + 6–8 个空态静物 + 台灯）→ 用同一套线宽与圆角语言压住一致性风险；
  不引图标库是硬约束。
- **系统 reduced-motion 不可被覆盖 ↔ 用户可能想要「就是要动」**：可能被少数用户抱怨；
  但这是可访问性底线，且用户仍可在别处（浏览器 / 系统）调整。
- **界面字号 / 字重 / 字族全用 system-ui（Windows 中文回退到微软雅黑）↔ 品牌一致性**：
  无 webfont 成本、加载零延迟，但雅黑偏「办公软件」感、字腔偏松，标题冲击力弱；
  缓解：标题 700 + letter-spacing -.02em~-.03em + 渐变填充（首屏 hub 卡标题）；
  且状态色（蓝黄红）承担品牌识别。

## Migration Plan

**总体顺序**：token 地基 → 单一面（练习页）→ 壳层 → 记录中心 → 设置视图与其余页面。
**样板线先行**（`decisions.md` 跨轮冻结表）：token 地基 + 外壳 + 练习页 + 知识点页 +
记录页 + 设置视图（含暗色与衬线），验收后铺开。

| 阶段 | 内容 | 出口判据 |
|---|---|---|
| **S0 token 地基** | 建 `--wb-*` 结构 token + 两套主题值；旧 `--lk-*`/`--dsw-*` 转别名；补 4 个未定义变量（单独提交）；建 `--wb-reading` 阅读层；建 `.wb-reading` 消费者迁移 | 四页基线截图比对通过；**图谱页逐像素一致**；`pytest` 全绿 |
| **S1 练习页（样板线）** | 题面 / 解析 / 作答区三件套、24px 大号题号、题号状态圆点、连对三级计数器、5/10 连横幅（一份参数化）、庆祝分层 | 练习流程 4 阶段截图 + 减少动效两套 |
| **S2 壳层** | 三栏单一真值（D-10）、128px 死预留退役（D-11）、左栏图标 + 整行圆角选中态、顶栏三段式、自绘章节透镜、hub 最近使用 + 卡片层级 | 三栏几何在 4 个视口截图比对；左栏选中态符合 `spec.md:749` |
| **S3 知识点页** | `.wb-reading` 接入知识点正文、单侧结构线 2px、关联题目重排、空态插画 + 满宽主按钮 | 正文 17px/1.75 生效；h3>h4 不倒挂 |
| **S4 记录中心** | 卡片流（D-13）、热力日历（D-14）、仪表盘统计卡、判定去绿、图例与阈值入契约 | 页高与图例截图；`calendar-workload` delta 写死 5 档阈值 |
| **S5 设置视图与暗色** | 中栏设置视图、左栏开关、4 个偏好、首屏内联防闪脚本、台灯转场、声音偏好 | 首屏无闪白（夜纸首帧截图）；reduce 降级截图；同工作区导航保留 Agent 右栏 |
| **S6 铺开** | Agent 右栏（会话列表滚动容器 + 分组、圆角消息卡、圆点时间线、贴底输入框）、练习页其余控件 | Agent 右栏与会话列表可滚 |

**回滚策略**

- **token 层可整体回退的前提**：所有旧 token 在别名期**仍然存在且仍指向原语义**
  （别名只是把定义改成 `var(--wb-*)`，引用点一个都没动）→ 回退 = 把别名定义改回原值，
  **一条提交即可**，不需要回滚引用点。
- 前提之二：**S0 之后的每个阶段都必须是可独立回退的提交**（禁止把多个阶段的改动混在一个提交里）。
- 前提之三：**新 token 只增不改**；一旦某个新 token 被引用点依赖，它就进入「不可删」集合，
  在 `workbench.css` 顶部用注释登记。
- S5（暗色 + 设置视图）**单独成链**：它引入内联脚本与新路由，回退它不影响 S0–S4。
- 字体与缓存：`workbench.css` 改动必须到达用户 → 静态资源缓存策略要复核
  （`workbench/server/app.py` 的 `_send_static`；今天无缓存策略，
  F08 D-11 / P15 指出 CSS 改动可能到不了用户）。**字体文件必须用内容哈希或长 max-age
  + 版本化 URL**，否则改字体要等缓存过期。截图里出现的字体未加载（fallback）必须被
  识别出来，不能误判为设计问题。

## Open Questions

以下都是**真正可以延后**的：它们不改变本变更的规格条款，也不改变任务拆分。

1. **夜纸下图标圆底色块的具体色阶**：方向已定（降饱和 + 提亮，`decisions.md` 16.2），
   但每个图标圆底落到三角色里的具体值、以及暗色下要不要再降一档，留到实施时按
   截图定；不影响「只用三角色」这条配额。
2. **思源宋体子集的确切字表与实测体积**：D-4 的「≤1.2 MB / 2 字重 / GB2312 一级字表」
   是**基于压缩率的量级估算**，不是实测。实施时用 `pyftsubset` 实测后回填；
   若实测显著超标，先砍字重（只留 400）而不是砍字表 —— 这条实施细节不改变契约。
3. **记录卡片流是否按日期分组**：今天每条记录带自己的时间戳但没有组头
   （F05 P-07 建议按日期分组）。分组与否只影响实现，不影响「六项字段 + 卡片形态」这条契约；
   收口基线未点名，故不新开议题。
4. **四个关键反馈音效的具体音频素材**：收口基线只定了「答对 / 答错 / 完成 / 里程碑，
   各 <200ms」与「需静音开关」；具体音色与文件留到实施期选型，不改变偏好契约。
5. **台灯插画的具体造型**：台灯是静物插画语言的一部分（`decisions.md` 16.5），
   但造型、探出角度与「点亮」时的暖色溢出强度留到实施期与其它静物一起定；
   转场的**时序与降级路径**已在 D-7 / D-8 定死。
6. **跨标签页的主题同步**：本变更不做 `storage` 事件监听（同浏览器两个标签页的主题
   各自独立）。是否值得做（需要新增事件绑定）留待后续；不影响本变更的规格。
