# calendar-workload 设计

## D1 一个端点，纯只读

`GET /api/w/{name}/calendar`：

```json
{
  "goals": [ {id, kind, title, deadline, description} ],   // 复用 goals 存储
  "days": [ {"date": "2026-08-29", "count": 4, "overdue": 0}, ... ]  // today..+13
}
```

days 由 `review_schedule.due_at` 按 `due_at[:10]` 分桶（含 direction 行，
一方向算一项——它确实是一次独立的复习动作）。无时区转换：日期即 ISO 前缀。

## D2 月历与曲线的渲染

- 月历：当月网格（周一起），目标按 `deadline` 日落格；一格多目标时纵向
  堆叠小卡（可重叠、不合并）；今天格用 accent 边框；跨月目标只在
  截止日所在月出现。无截止目标列于区块末尾一行文字，不占格。
- 曲线：14 根横向对齐的柱（纯 div 高度映射 count/max），柱下标相对日
  （今天/+1/+2…），`count >= 2 × 日均（非零日均值，至少 3）`的柱标
  「偏重」；点击「偏重」柱或区块内的「让 Agent 看看」按钮 →
  右侧对话输入框预填「最近几天任务偏重（最多的一天 N 项），帮我重排一下」
  并聚焦输入框。无排程逻辑改动。
- 空状态：无目标且 14 天无到期项 → 一句话「最近没有安排在日历上」。

## D3 位置与命名

区块放复习页底部（练习/复习之外的时间视角都指向"接下来"）；标题
「时间安排」；kicker「实验视图」。不新增导航项、不做翻月（当月 +
未来 14 天已覆盖决策视野；翻月等真实需要出现再说）。

## D4 明确不做

自动重排、任务量拟合曲线公式、学习模型选择、多月翻页、目标进度条
（coverage_progress 已在练习页展示）。
