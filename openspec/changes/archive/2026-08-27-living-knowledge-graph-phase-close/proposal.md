## Why

The current graph produces a tidy static arrangement, but component-local simulation, fixed bounds, uniform label pressure, and rapid cooling prevent it from behaving like a living knowledge network. This final proactive development change makes semantic distance, safe spacing, and direct manipulation legible before the project moves to maintenance driven by real study use.

## What Changes

- Use deterministic component layouts only as seeds, then run every visible node in one unbounded elastic field.
- Derive variable spring length from existing semantic attraction while enforcing independent minimum node clearance.
- Add bounded idle breathing, global drag propagation, edge-pan, session-only soft anchors, and local neighborhood expansion.
- Show labels progressively by importance, formal-problem count, zoom, search, hover, and focus.
- Route obstructed edges deterministically and let the graph fill the middle-column viewport.
- Freeze proactive feature development after this change; later work responds to observed study problems.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `knowledge-figures`: component layouts become deterministic seeds for a unified living graph.
- `review-workbench`: graph nodes expose their existing importance classification.
- `workbench-ui`: graph motion, spacing, labels, unbounded dragging, camera behavior, and reduced-motion behavior change.

## Impact

The change affects the graph query projection, the zero-dependency graph physics module, the existing browser graph controller, CSS, tests, and documentation. It adds no route, database field, dependency, persistent coordinate, interaction log, or learning write.
