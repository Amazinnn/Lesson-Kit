## Context
The Bridge already passes native session IDs and package Skill arguments. Page focus is currently privileged over conversation. See proposal for motivation.
## Goals / Non-Goals
Improve external harness prompts and discovery. No internal planner, task classifier, online install or provider-global mutations.
## Decisions
Use user-level agent-resources.json and managed-skills/ under registry.base_dir(), with atomic JSON replacement and an in-process lock. Keep Skill folders immutable between explicit replacements. Accept SKILL.md packages and Markdown entries; parse only name/description YAML scalars and simple block strings, preserving all body bytes. Plain Markdown uses first heading and first prose paragraph. Reject symlinks and recursive managed-source imports. Stage copies before swapping so failures retain originals. Built-in id uses its existing package name; copied ids use the registry identifier contract. Resource generation changes only on successful mutation.
At provider dispatch read a fresh resource snapshot and the last two successful completed exchanges from conversation files ordered by turn ID; filter out the current turn and later turns. Add original text to context without modifying queued submission context. Prompt wording treats all historical materials as data, and keeps explicit current messages and conversational continuation above page fallback. Global instructions and catalogs are read at dispatch, not at queue admission.
Pi gets native --skill arguments for enabled managed resources. Compare the effective managed resource generation between Pi turns; rebuild an idle process with the same session when changed, never during accepted work. Non-Pi gets the same catalog paths in prompt. Preserve unrelated flags. Preserve old package-path normalization helper compatibility.
Use workspace-scoped /api/w/{name}/agent-resources as a browser-only management entry, returning user-global resources after validating workspace identity. PATCH updates instructions; POST imports source_path with replace; GET returns catalog, GET /skills/{skill_id} returns body; PATCH changes enabled; DELETE removes only managed copies. Local service receives filesystem paths, not arbitrary HTML or script execution. UI uses DOM textContent, retains inputs on failure, and binds on dynamic settings mount.
## Risks / Trade-offs
Original two exchanges may be large: no silent truncation since agreed contract requires complete text; future budgets require an explicit contract revision. Metadata parsing intentionally supports YAML name/description scalars and folded/literal blocks, not arbitrary YAML evaluation. Built-in files remain read-only. Models can still ignore prompts: deterministic evidence is not model behavior acceptance.
## Migration Plan
No database migration. Missing config defaults to empty global text and enabled bundled Skill. Changes do not modify Pi global configuration or real registered resources. Tests set LESSONKIT_WB_HOME to temporary directories. No service deployment in this task.

## Implementation refinements
Managed copies are immutable per import. Active turns hold process-local references; replacement/deletion retires old files after the last active reader finishes. Plain Markdown remains readable through the catalog but is not passed as a falsely native-discoverable Pi skill. YAML parsing is metadata-only, not a general YAML interpreter. Setup/history read failure ends the turn explicitly rather than leaving it running without context. Turn ordering uses the existing numeric turn-ID helper.
