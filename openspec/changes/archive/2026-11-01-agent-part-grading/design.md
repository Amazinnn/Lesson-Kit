## Context

动机见 proposal。当前 `practice_submission` 只对可用客观答案键返回判定，`problem_attempts.verdict` 不表达主观批改。`paper-practice.js` 的做题情况主要从 `answered/stuck`、草稿与客观布尔判定推导。`practice-review` 将提交与揭晓绑定，整卷模式没有逐题提交。本变更跨越内容、作答、Agent、进度与展示，因此需要设计文档。

保持 Shell → Domain → Data 单向依赖；Domain 纯规则，无 IO；数据库写入只在 Data，Agent 通过现有 Bridge 旁挂。根 CONTEXT.md 已退役，术语继续写入 GLOSSARY。当前设计讨论记录见 `docs/design/2026-10-31-agent-part-grading.md`。

## Goals / Non-Goals

**Goals:** 在既有题目与 Attempt 身份上增量支持小问；原始提交与派生批改分离；由确定性规则管理提交、揭晓、重试和状态，Agent 只承担提炼与教学批改。无需 Agent 也可保存、导航和交卷。

**Non-Goals:** 自动考试打分、综合题总判定、主观批改自动驱动学习投影、训练新的判题模型、练习中自动拆题、第二个学习者最终答案输入框、历史记录重判或批量迁移内容。无需新依赖或新的设置页面。

## Decisions

### 1. 作者内容保存小问，执行绑定稳定身份与版本

通过既有受治理的题目内容入口，给题目添加有序小问集合，含可读局部 ID（如 `part-001`）、题面、交互类型、可选选项／答案键／参考材料，以及是否适合简短最终结果。类型复用现有客观交互，扩展计算和过程型自由作答；不把小问做成可独立组卷的顶层题目。Agent 在整理阶段决定拆分与短答适用性，执行时不推断。

沿 `ensure_*` 做显式幂等增量迁移。题目新增可空结构化 `parts`；Attempt 增加可空 `part_id/content_revision`，不改变原有主键或 objective verdict 枚举。每个被提交小问对应一条属于父题的 Attempt，保存原始文本／选择和小问定位。实现协调：历史未拆分行仍保留空标识；新未拆分主观提交使用虚拟局部 ID `whole`，以同一路径绑定独立批改，旧独立客观题保持原路径。此虚拟 ID 不改写题库或历史。活动／暂停／完成快照保存小问顺序及引用，旧历史没有结构时照旧展示。受治理内容修订沿现有版本检查仅使受影响未完成工作失效，不按位置把旧答案移给新小问。

不选“运行时按 Markdown 编号拆分”，因为编号可能嵌套或引用旧步骤，无法保证持久身份。也不在第一个小问提交时创建一条后续持续改写的父题作答，因为这会破坏原始提交不变的边界。缺少小问专属参考时的独立推导不豁免既有正式题入库的非空、受门控解析要求；不借本变更降低正式内容质量门槛。

### 2. 保存先于批改，提交单位独立于揭晓

默认逐小问提交并提供整题提交剩余小问；另一设置只显示整题提交。整题和最终交卷只处理尚未提交的部分。Data 在同一事务里保存提交、请求去重信息、执行关联与待批改标记；整题提交任一目标无效则本次批次不写，已有提交不受影响。数据库提交后才调用外部 Agent，不持有事务等待模型。

提交即提供对该份作答的批改写入意图；普通对话依旧只读。任务绑定 workspace/execution/problem/part/attempt/content version。使用现有 Bridge 的运行、失败与恢复机制，待批改标记提供进程重启后的恢复依据，不新增通用任务队列。使用现有 provider 与并发安排，忙时排队而不打断正在进行的教学对话。重试复用原提交与目标，失败不生成第二次 Attempt。

提交粒度进入原工作区设置存储，设置变化只更新控件和未提交部分。Answer Reveal Timing 保持运行级固定：per_item 确认后揭晓；on_submit 可提前保存并后台批改，但直到 Paper 显式交卷才显示。已提交部分立即锁定，不因隐藏结果变成可修改；未提交草稿仍可改。保留旧的客观独立题选择即提交行为，但仅在逐小问提交＋逐题揭晓组合下执行。整题按钮不等于 Paper 完成按钮。

不选“切换粒度同时切换揭晓”，避免实时偏好变化意外披露结果。`不会` 仍是明确的提前参考披露：保留原过程；已提交的不会标记不能被批改覆盖。整卷模式尚未提交的不会草稿继续允许新作答清除，已看材料事实持续保留。只有提交或已锁定的不会才产生批改请求，不批改每次草稿输入。

### 3. 独立保存批改当前版本与修订历史

新增以 Attempt 为目标的批改记录，通过版本号链接追加式修订历史。当前记录含批改进度、可空提炼答案、参考结果／过程及 `source` 或 `agent_derived` 来源、答案结论、过程结论、说明与版本；历史保留修订前后内容、操作者、操作 ID 和时间。create/update/withdraw 与修订记录同事务写入。withdraw 是撤回派生内容的当前版本，保留原始提交与审计，不硬删历史。操作 ID 与载荷比较复用现有可读请求去重机制，不引入哈希。

Agent 专用接口与 CLI 共用 Data 事务、目标验证和 expected revision 校验。界面只读展示，无可编辑提炼答案框；修改由对话请求触发。保留 `attempts`/`practice`/`content` 按需契约，增补 `grading` 契约主题与 `lesson-kit grading` 命令族，补 help、命令发现和动作登记；它只管理独立批改，不扩张为自动教学 CLI。这里的“Agent 专用”是产品 writer 边界，沿用本地工具权限模型，不为本轮新增认证系统。

若内容版本、目标绑定或 expected revision 过时，拒绝整次结果发布，并报告原因。批改创建或修改不走 `attempts correct`，不触碰原始答案、不重放学习投影。参考答案由 Agent 独立推导时只附属于批改；不自动改写题库来源答案。

### 4. 三类状态按维度表达，不增加总对错

| 维度 | 存储／投影值 | UI 含义 |
| --- | --- | --- |
| 作答 | unprovided / draft / submitted，另有 stuck 与 reference_viewed 事实 | 未作答／草稿／已提交，可并列不会 |
| 批改进度 | not_requested / pending / running / completed / failed | 未请求／待批改／批改中／已批改／失败可重试 |
| 最终答案 | correct / wrong / needs_confirmation / unprovided；不适用为空 | 正确／错误／待确认／未作答 |
| 过程 | correct / partially_correct / wrong / needs_confirmation / unprovided；不适用为空 | 正确／部分正确／错误／待确认／未提供过程 |

`不会` 是学习者结论，不由批改删除；failed 是操作失败，needs_confirmation 是学术判断不确定。计算题没有写出结果时显示未作答，不能把参考值放进提炼答案。证明题的答案维度不适用，直接省略；客观小问不强行评价不存在的过程。计算题只给出数值但未给过程时，过程可显示未提供，不猜测推导。

父题只投影提交数／总小问数、不会数、批改进度以及允许揭晓的各维结论计数。答案正确和过程错误可能属于同一小问，因此计数必须带“答案／过程”标签，不把它们相加成互斥总题数。未拆分主观题按同一状态模型展示，无需先改成综合题。

不选十几个混排的单枚举状态，也不选“最差小问决定整题对错”，因为都无法表达部分提交、等待批改和相互矛盾的答案／过程结论。

### 5. 统一揭晓投影保护预览与回看

由 Domain 根据执行揭晓状态计算可显示数据，Server 对学习者读取返回投影；模板、题号、悬停卡片、颜色、ARIA 文本、摘要、错误筛选统一消费它，不能仅用 CSS 隐藏已传给浏览器的结论。Agent 工作读取使用原始授权数据，与学习者投影分开。`不会` 的参考材料披露针对当前小问，不能意外发送整题所有兄弟小问参考。

复用现有 Agent 完成通知与局部刷新通路，读取批改 revision；必要时用现有刷新节奏拉取当前执行状态，不新增 WebSocket 或框架。只更新状态和只读结果节点，不重建编辑器。跨题响应始终更新原目标；导航、草稿、选区、滚动不受干扰。交卷不用等待模型，已完成答卷仍可接受与其提交绑定的晚到批改。

错误／部分正确回看采用当前已揭晓各维结论；不确定、空白、不会、失败各自独立。修改或撤回后查询自然改变，不额外写一份错误标记。独立 legacy 客观题原有 off-mode 行为继续保留；小问状态与主观批改不合成新的父题学习结论，不自动向同一道题重复提交多份学习评价。

### 6. 题号预览与长题 UI

做题情况保留紧凑题号与可读图例，主观小问展示各维标签，父题展示进度／数量。悬停或 focus 展示临时详情卡，小问按保存顺序排列；指针移入详情后仍可阅读与滚动，离开触发点和卡片后关闭，Escape 关闭。点击／触摸可展开持久详情，避免把关键信息限制在 hover。

小问题面与其控件放在同一阅读流，作答框在提交前可编辑，提炼答案仅在揭晓后出现；证明题不留空答案框。长题、长预览有可见滚动区域，不吞掉滚轮或截断控件。状态与批改更新避免滚动跳动、焦点丢失和卡片闪烁。通过真实浏览器验收，不将其他视觉改版 change 的任务算成本变更完成。

## Risks / Trade-offs

- [Agent 推导错误] → 标明参考来源，独立保存原始作答，允许待确认与对话复核，带版本修订。
- [状态维度增多] → 主界面紧凑概览，预览展示细节；使用文字与图例而非仅靠颜色。
- [隐藏模式泄露结果] → 共享服务端投影，验收响应体、计数、样式、ARIA 和过滤行为。
- [旧内容与并行变更] → 空小问结构按旧题读取；迁移不自动拆题；协调已有 evaluation、adaptive-paper、live-display changes 的当前事实，不修改它们的任务完成状态。
- [自动批改增加延迟和成本] → 保存和交卷不等待 Agent；仅提交触发，不随输入触发；失败提供明确重试。

## Migration Plan

1. 实施前将字段与 writer/consumer 约定落入 DATA_MODEL，操作载荷落入 FILE_CONTRACT；通过现有显式迁移入口部署幂等增量结构，在隔离池验证旧表与历史兼容。
2. 先完成 Domain/Data 与 CLI 操作及安装态契约，再接入提交后的 Bridge 请求和浏览器局部刷新，最后接入状态、预览与设置。
3. 使用混合题隔离数据覆盖正常、失败、并发、晚到、撤回、双维矛盾结论和揭晓组合；不向真实用户题库或作答记录写测试数据。
4. 回退时停用新增批改调度与 UI，保留已追加的原始作答和修订数据；不通过删除新增表或列回滚学习历史。旧运行读取不了新增结构时明确要求受支持版本，不降级伪造整题答案。
5. 实施交付同步职责文档；独立验收记录聚焦测试、全套检查、安装态与 GUI 的实际通过／未执行结果。提案阶段不执行迁移或业务代码修改。
