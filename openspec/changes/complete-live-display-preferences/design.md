## Context

设置提交已 rebase 到 main。原实现只用 CSS 隐藏已有节点，但来源关闭时没有节点，自评还受起卷 rating_mode 限制。用户已撤回保留坏引用的方案，要求删除不存在题目及其引用，试卷作为独立容器保留。

## Goals / Non-Goals

兑现显示偏好并合并部署；按题目身份清理 co 悬空引用，保留有效题目与容器。不上线“保留坏引用暂停”功能，不自动推断旧题和替换题等价，不改 legacy 卡片的评分生命周期。

## Decisions

渲染可用来源与符合条件的普通 Paper 自评，由已有根属性/CSS 即时显隐，不重渲染作答。showSource 默认 false，同一函数同步两处控件，storage 只处理同工作区设置键。保留记录模式和客观判定语义，自评仍须显式提交。

数据清理先离线备份/试跑，再停止服务并在真实库事务内清理四个已证实不存在的 ID。现存容器不删除；当前执行按容器题序保留相同 ID 的进度，新增有效 ID 为 pending。清理失效的调度/修订/镜像引用，不给新题绑定旧答案。检查每个现有 Attempt 链接；不修改有效题的历史学习记录。清理完成后的执行可由现有正常暂停/恢复路径保存。

## Risks / Trade-offs

已有浏览器缓存仍带旧题序 → 清理时更新结构版本，旧写入被拒绝，用户刷新。保留原库与试卷文件副本以便回滚。

## Migration Plan

先跑 Node 回归与仓库四项检查，审查后 fast-forward main、push，停止 3081，在备份副本验证清理，再清理真实 co 数据并重启。通过实际 API 验证 ps-001 和其他卷就绪、正常暂停与续练，以及所有目标 ID 的引用数为零。
