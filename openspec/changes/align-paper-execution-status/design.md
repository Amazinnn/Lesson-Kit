## Context

同一 ps-001 被历史 70 项执行和新版 22 项容器共用。summary 原先仅按 source_ref 关联进度，而 start_saved 比较有序题号后拒绝，导致读取、按钮与实际操作矛盾。

## Decisions

复用现有 Data 读取和版本检查，为 API 提供统一的 continuation 和 can_start。只改前端不能修复错误的 API 摘要；建立新进度存储会重复事实，因此修复现有摘要关联及共享校验。

continuation 核验执行与当前卷的有序题目身份、内容可用性、结构版本、作答内容版本和清单校验。旧执行不匹配时不附作当前卷进度，旧计数和不可用题号放入独立折叠详情，不改历史数据。

目标卷自己的 continuation 与当前选中卷能否暂停是两个条件。当前卷不能暂停时，目标卷通过 start_block_reason 报告原因，不继承当前卷的执行或进度。开始动作重新校验，失败不能清除或更换活动执行。

列表和练习页都使用后端结果。开始被拒绝时重新 GET，原位更新题数、进度、开始/继续文字、禁用状态及原因，不整体替换卡片或丢失本地编辑。有效容器的导出、改名、删除独立判断。

用户明确不需要旧卷时，可以使用既有 clear/start 保留历史并结束旧执行，再按当前卷创建新执行；这不是读取操作的自动副作用。删除试卷仅删除容器及其未完成状态，保留题目、逐题证据和历史轮次。CO 当前 ps-001 已是新版，不能误删。

## Scope and acceptance

不恢复 CO 的旧题或缺失尝试父记录，不增加新存储系统。实施不写真实课程库。

隔离回归覆盖题数不同、题数相同但题号或顺序不同、活动与暂停执行、缺题、版本变化、清单无效、当前卷不能暂停及有效继续。浏览器验收检查真实按钮、折叠详情、错误后的状态刷新、编辑保留和独立管理动作；失败操作前后比较数据库与清单。独立完整验收通过后，才由 OpenSpec CLI 同步规范并归档。
