## Why

主观题目前缺少与原始作答分离的结构化批改结果，综合题也不能逐小问表达不同题型和做题情况。学习者需要只输入一次作答，由 Agent 提炼简短答案、分别批改结果与过程，并在练习页实时查看各小问状态。

## What Changes

- Agent 在题目整理阶段保存有稳定身份的小问结构，支持判断、单选、多选、计算和证明／开放作答混排；旧题保留整题作答能力。
- 每个主观小问只有一个可编辑作答框。提交后请求 Agent 批改，可选提炼答案只读展示；证明题不强行生成简短答案。
- 作答情况、批改进度和批改结论分别表达；计算题分别显示答案与过程结论，不合成为单一对错。显式“不会”保留作答并可与过程点评并列。
- 提交粒度与答案揭晓时机分离。设置中实时切换逐小问／整题提交；整题按钮提交剩余小问，不等于整卷交卷。整卷揭晓前隐藏批改结论及一切泄露结果的汇总。
- Agent 可通过专用操作新增、修订或撤回提炼答案和批改结果，带版本校验与修订记录；界面及时更新，保留原始作答。
- 缺少参考答案时允许 Agent 独立推导并标明来源；不能可靠判断时保持待确认。批改失败不丢作答，允许重试。
- “做题情况”展示主观题与各小问状态；综合题汇总完成进度及状态数量，不生成整题总判定。题号悬停或键盘聚焦临时预览小问详情，支持点击／触摸展开及滚轮浏览。
- 主观错误／部分正确可回看，但本轮不自动折算掌握度、信号或复习排期；既有评价机制与独立客观题判定保持兼容。

## Capabilities

### New Capabilities

- `agent-part-grading`: 小问结构、单一主观作答入口、异步 Agent 批改、独立结果／过程结论、修订与学习状态边界。

### Modified Capabilities

- `review-workbench`: 主观提交的持久化及批改触发，分离 Attempt 与派生批改结果。
- `practice-review`: 独立提交与揭晓、不会标记、逐小问回看和错误筛选。
- `workbench-ui`: 实时提交粒度设置、主观与综合题做题情况、题号详情预览及长题滚动。

## Impact

- 影响 `workbench/data` 的题目内容、Attempt、执行进度和新增批改记录，以及 `pool_schema.py` 的增量迁移；Domain 负责纯校验与状态投影。
- Browser/Server、Agent Bridge、CLI、已安装的按需契约需支持同一批改操作、恢复与即时刷新。复用既有 Agent provider、工作区设置与刷新机制，不新增 AI 内核或依赖。
- 实施时同步 DATA_MODEL、GLOSSARY、FILE_CONTRACT、ARCHITECTURE、PRODUCT-MANUAL 与 ACTION-GRAPH；本提案不将未来行为写成已实现事实。
- 明确协调现有“综合题 verdict 为空”“整卷模式不允许逐题提交”与本方案的关系；旧 objective verdict 不承担主观双维结论，历史记录不重判、不迁造成新作答。
